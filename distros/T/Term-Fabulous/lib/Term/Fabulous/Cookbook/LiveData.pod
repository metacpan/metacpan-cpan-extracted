=head1 NAME

Term::Fabulous::Cookbook::LiveData - Recipes: timers, logs and the output of commands

=head1 DESCRIPTION

This page is part of L<Term::Fabulous::Cookbook>. Previous page: L<Term::Fabulous::Cookbook::KeyboardAndMouse>. Next page: L<Term::Fabulous::Cookbook::Forms>.

This page shows programs whose screen changes while the user does
nothing: a clock updated by a timer, a log that grows, a view that
follows the newest line of the log, and the output of a command that
runs in the background. They use L<IO::Async> timers and processes
together with L<Term::Fabulous::Widget::ScrollBox> and
L<Term::Fabulous::Widget::Text>. How the event loop, timers and frames
work together is explained in
L<the timers section of the programs chapter|Term::Fabulous::Manual::Programs/Timers and other asynchronous work>;
scrolling in L<the scrolling section of the events chapter|Term::Fabulous::Manual::Events/SCROLLING>. For charts
that follow new data, see
L<Term::Fabulous::Cookbook::ChartTechniques/A live chart that follows new data (append, max_points, span)>.

The recipes on this page:

=over

=item *

L</Update the screen from a timer (a clock)>

=item *

L</Add lines to a scrolling log (ScrollBox)>

=item *

L</Scroll a ScrollBox from code (keep a log at the newest line)>

=item *

L</Show the output of a running command>

=back

=head1 Update the screen from a timer (a clock)

Goal: change what the screen shows at regular intervals, here a clock
in the middle of the terminal.

This program is shipped as F<examples/cookbook/clock.pl>.

=for code-from examples/cookbook/clock.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use IO::Async::Loop;
	use IO::Async::Timer::Periodic;
	use POSIX qw(strftime);
	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_ALIGN_X_CENTER CLAY_ALIGN_Y_CENTER);

	my $clock = Term::Fabulous::Widget::Text->new( text => '--:--:--', text_color => [ 255, 200, 80, 255 ] );
	my $root  = Term::Fabulous::Widget::Box->new(
		layout => {
			sizing          => { width => sizing_grow(),       height => sizing_grow() },
			child_alignment => { x     => CLAY_ALIGN_X_CENTER, y      => CLAY_ALIGN_Y_CENTER },
		},
	);
	$root->add_child($clock);

	my $timer = IO::Async::Timer::Periodic->new(
		interval       => 1,
		first_interval => 0,
		on_tick        => sub { $clock->text( strftime( '%H:%M:%S', localtime ) ) },
	);
	$timer->start;
	IO::Async::Loop->new->add($timer);

	Term::Fabulous->new( root => $root, width => 80, height => 24 )->run;

=end html

=over

=item *

C<run> uses the process-wide L<IO::Async::Loop>, which
C<< IO::Async::Loop->new >> returns. Timers, sockets and other
L<IO::Async> notifiers added to it run while the user interface runs.
Add them before C<run>, or later from any listener. See
L<Term::Fabulous::Manual::Programs/Timers and other asynchronous work>.

=item *

You never redraw by hand: Term::Fabulous checks 30 times per second
whether a widget changed and then draws a new frame, so changing a
widget (here the text) is all a timer has to do.

=item *

C<first_interval =E<gt> 0> makes the first tick happen at once instead of
after one second.

=item *

C<child_alignment> centers the clock in the root box. See
L<Term::Fabulous::Manual::Layout/Aligning and centering children>.

=back

=head1 Add lines to a scrolling log (ScrollBox)

Goal: a box that receives a new line every half second, can be
scrolled with the mouse wheel, and never holds more than 500 lines.

This program is shipped as F<examples/cookbook/scrolling-log.pl>.

=for code-from examples/cookbook/scrolling-log.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use IO::Async::Loop;
	use IO::Async::Timer::Periodic;
	use POSIX qw(strftime);
	use Term::Fabulous;
	use Term::Fabulous::Enum::BorderStyle;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::ScrollBox;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	use constant MAX_LINES => 500;

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 1,             right  => 1 },
		},
	);

	# A ScrollBox needs an id: Clay keeps the scroll position by id.
	my $log = Term::Fabulous::Widget::ScrollBox->new(
		id               => 'log',
		background_color => [ 30, 35, 50, 255 ],
		bordered         => 1,
		border_color     => [ 120, 160, 220, 255 ],
		border_style     => Term::Fabulous::Enum::BorderStyle->Round,
		layout           => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 1,             right  => 1 },
		},
	);
	$root->add_child($log);

	my $count = 0;
	my $timer = IO::Async::Timer::Periodic->new(
		interval => 0.5,
		on_tick  => sub {
			$count++;
			$log->add_child(
				Term::Fabulous::Widget::Text->new(
					text       => strftime( '%H:%M:%S', localtime ) . " event number $count",
					text_color => [ 200, 210, 230, 255 ],
				)
			);

			# Keep the log from growing forever: drop the oldest line.
			my $oldest = $log->children->[0];
			$log->remove_child($oldest) if @{ $log->children } > MAX_LINES;
			return;
		},
	);
	$timer->start;
	IO::Async::Loop->new->add($timer);

	Term::Fabulous->new( root => $root, width => 80, height => 24 )->run;

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.05/screenshots/cookbook-scrolling-log.svg" alt="A framed log with ten timestamped lines"></p>

=end html

=over

=item *

L<Term::Fabulous::Widget::ScrollBox> clips its content to its box and
scrolls it vertically. It needs an C<id>, because the scroll position
is stored by id. The mouse wheel scrolls the scroll box under the
pointer by three rows per notch. See L<Term::Fabulous::Manual::Events/SCROLLING>.

=item *

Widgets added with C<add_child> appear in the next frame, at the end
of the box. The scroll position does not follow new lines
automatically: the view stays where the user scrolled to, unless the
box has C<follow_end>, as in the next recipe,
L</Scroll a ScrollBox from code (keep a log at the newest line)>.

=item *

C<remove_child> removes the widgets it is given from the box. A
removed widget can be added again, to the same box or another
one, and keeps its children and its state. See
L<Term::Fabulous::Manual::Layout/Changing the tree>.

=back

=head1 Scroll a ScrollBox from code (keep a log at the newest line)

Goal: a log that always shows its newest line, until the user scrolls
up to read older lines; keys that scroll the log up, down and sideways.

This program is shipped as F<examples/cookbook/follow-log.pl>.

=for code-from examples/cookbook/follow-log.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use IO::Async::Loop;
	use IO::Async::Timer::Periodic;
	use Term::Fabulous;
	use Term::Fabulous::Enum::BorderStyle;
	use Term::Fabulous::Scrolling qw(scroll_by_columns scroll_by_rows scroll_to_end);
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::ScrollBox;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 1,             right  => 1 },
		},
	);
	$root->add_child(
		Term::Fabulous::Widget::Text->new(
			text       => 'Wheel or Up/Down scroll, Left/Right scroll sideways, Home goes to the top, End follows the newest line.',
			text_color => [ 230, 230, 230, 255 ],
		)
	);

	# follow_end keeps the newest line in view until the user scrolls up;
	# back at the end, the box follows again.
	my $log = Term::Fabulous::Widget::ScrollBox->new(
		id               => 'log',
		horizontal       => 1,    # vertical scrolling is on by default
		follow_end       => 1,
		background_color => [ 30, 35, 50, 255 ],
		bordered         => 1,
		border_color     => [ 120, 160, 220, 255 ],
		border_style     => Term::Fabulous::Enum::BorderStyle->Round,
		layout           => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
		},
	);
	$root->add_child($log);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );

	# The moves stop at the edges of the content. Moving up leaves the end,
	# which stops the following; End goes back to it, which resumes it.
	my %action_by_key = (
		Up    => sub { scroll_by_rows( $ui, $log, -1 ) },
		Down  => sub { scroll_by_rows( $ui, $log,  1 ) },
		Left  => sub { scroll_by_columns( $ui, $log, -4 ) },
		Right => sub { scroll_by_columns( $ui, $log,  4 ) },
		Home  => sub { $ui->scroll_to( $log, { x => 0, y => 0 } ) },
		End   => sub { scroll_to_end( $ui, $log ) },
	);
	$root->on(
		KeyPress => sub ($event) {
			my $action = $action_by_key{ $event->main_key_name // '' } or return;
			$action->();
			return;
		}
	);

	my $count = 0;
	my $loop  = IO::Async::Loop->new;
	$loop->add(
		IO::Async::Timer::Periodic->new(
			interval => 0.25,
			on_tick  => sub {
				$count++;
				my $text = sprintf 'Line %4d', $count;
				$text .= ' ' . ( '-' x 150 ) . ' a wide line' if $count % 5 == 0;    # wider than the box
				$log->add_child( Term::Fabulous::Widget::Text->new( text => $text, text_color => [ 200, 210, 230, 255 ] ) );
				return;
			},
		)->start
	);

	$ui->run;

=over

=item *

C<< follow_end =E<gt> 1 >> makes the box follow the end of its content
(see L<Term::Fabulous::Widget::ScrollBox/follow_end>): while it shows
the last row, a line added at the bottom scrolls into view. The size of
a new line is known only after the frame that lays it out, so the box
moves after that frame and the newest line shows one frame later, which
is due at once. The box stops following as soon as the user scrolls up,
with the wheel, the scrollbar or a key, and follows again once it shows
the last row, here with C<End>.

=item *

L<Term::Fabulous::Scrolling> moves the view by rows
(C<scroll_by_rows>), by columns (C<scroll_by_columns>) and to the end
(C<scroll_to_end>). The moves stop at the edges of the content and do
nothing before the first frame has laid the box out. For the full set
of pager keys in one call, see
L<scroll_by_key|Term::Fabulous::Scrolling/scroll_by_key> and the recipe
L<Term::Fabulous::Cookbook::DocumentTechniques/Scroll any scroll box like a pager (Term::Fabulous::Scrolling)>.

=item *

C<< $ui->scroll_to( $scroll_box, { x =E<gt> 0, y =E<gt> 0 } ) >> sets
the position directly, here the top left corner; an axis left out keeps
its position. It makes a frame due, which shows the new position even
when nothing else changed. See L<Clay::UI/scroll_to> and, for the
position of the last frame, L<Clay::UI/scroll_state>; L<Term::Fabulous>
inherits both from L<Clay::UI>.

=item *

C<< horizontal =E<gt> 1 >> lets the content be wider than the box. A
horizontal wheel (or a sideways tilt of the wheel) scrolls it by three
columns per notch; for a mouse without one, add code such as the Left
and Right keys here.

=item *

To position the content entirely yourself, set the scroll box's
C<child_offset> to C<< { x =E<gt> ..., y =E<gt> ... } >> (negative
values, as Clay keeps the scroll position:
C<< { x =E<gt> 0, y =E<gt> -3 } >> shows the content from its fourth
row). While it is set, it alone decides what is shown; the wheel and
C<scroll_to> still move the scroll position, which shows again once
C<child_offset> is set back to C<undef>. See
L<Term::Fabulous::Widget::ScrollBox> and
L<Term::Fabulous::Manual::Events/SCROLLING>.

=back

=head1 Show the output of a running command

Goal: run a command, show its output and its errors line by line while
it runs, and its exit status when it ends.

This program is shipped as F<examples/cookbook/show-output.pl>.

=for code-from examples/cookbook/show-output.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Encode qw(decode);
	use IO::Async::Loop;
	use IO::Async::Process;
	use Term::Fabulous;
	use Term::Fabulous::Enum::BorderStyle;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::ScrollBox;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	# The command to run: the program's arguments, or a default.
	my @command = @ARGV ? @ARGV : ( 'ls', '-l', '/' );

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 1,             right  => 1 },
		},
	);

	# The arguments are bytes, like the command's output.
	my $title = Term::Fabulous::Widget::Text->new( text => decode( 'UTF-8', "Running: @command" ), text_color => [ 255, 200, 80, 255 ] );

	# follow_end keeps the newest line in view (see the recipe "Scroll a
	# ScrollBox from code").
	my $output = Term::Fabulous::Widget::ScrollBox->new(
		id               => 'output',
		follow_end       => 1,
		background_color => [ 30, 35, 50, 255 ],
		bordered         => 1,
		border_color     => [ 120, 160, 220, 255 ],
		border_style     => Term::Fabulous::Enum::BorderStyle->Round,
		layout           => { layout_direction => CLAY_TOP_TO_BOTTOM, sizing => { width => sizing_grow(), height => sizing_grow() } },
	);
	$root->add_child( $title, $output );

	sub add_line ( $line, $color = [ 200, 210, 230, 255 ] ) {
		$output->add_child( Term::Fabulous::Widget::Text->new( text => $line, text_color => $color ) );
		return;
	}

	# Turns the bytes of one output line into a character string; bytes
	# that are not valid UTF-8 become U+FFFD.
	sub clean ($bytes) {
		$bytes =~ s/\r\z//;
		return decode( 'UTF-8', $bytes );
	}

	# Hands every complete line of a stream to add_line.
	sub line_reader ($color) {
		return sub ( $stream, $buffer_ref, $eof ) {
			add_line( clean($1), $color ) while $$buffer_ref =~ s/\A([^\n]*)\n//;
			if ( $eof && length $$buffer_ref ) {    # a last line without a line break
				add_line( clean($$buffer_ref), $color );
				$$buffer_ref = '';
			}
			return 0;
		};
	}

	my $loop    = IO::Async::Loop->new;
	my $process = IO::Async::Process->new(
		command   => \@command,
		stdin     => { from    => '' },    # the command must not read the terminal
		stdout    => { on_read => line_reader( [ 200, 210, 230, 255 ] ) },
		stderr    => { on_read => line_reader( [ 255, 110, 110, 255 ] ) },
		on_finish => sub ( $process, $exit_code ) {
			add_line( sprintf( 'Finished with exit status %d. Press Ctrl+C to quit.', $exit_code >> 8 ), [ 255, 200, 80, 255 ] );
			return;
		},
		on_exception => sub ( $process, $exception, $errno, $exit_code ) {

			# A failed exec leaves $exception empty and the reason in $errno.
			my $reason = length( $exception // '' ) ? $exception : "$errno";
			add_line( "Could not run the command: $reason", [ 255, 110, 110, 255 ] );
			return;
		},
	);
	$loop->add($process);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );

	$ui->run;

=end html

Run it with a command and its arguments, for example
C<perl examples/cookbook/show-output.pl ping -c 5 localhost>; without
arguments it runs C<ls -l />. The picture shows it running
C<seq -f 'Line %g' 1 40>.

=over

=item *

L<IO::Async::Process> runs the command in the event loop that
L<Term::Fabulous> uses, so the screen stays responsive while the
command runs. Its C<on_read> callbacks get the output as it arrives,
which may be several lines or part of a line at a time; the reader
takes complete lines out of the buffer and keeps the rest for the next
call.

=item *

C<< stdin =E<gt> { from =E<gt> '' } >> gives the command an empty input.
Without it the command would share the terminal with the program and
could read the user's key presses.

=item *

Command output is bytes, and Text widgets take character strings, so
C<clean> decodes every line. Decoding also turns bytes that are not
valid UTF-8 into U+FFFD. The same decoded lines can go into a
L<Term::Fabulous::Widget::TextArea> or a canvas.

=item *

Errors (C<stderr>) are shown in red. C<on_finish> reports the exit
status, C<on_exception> a command that could not be started.

=item *

C<< follow_end =E<gt> 1 >> keeps the newest line in view, as explained
in L</Scroll a ScrollBox from code (keep a log at the newest line)>;
scrolling up stops it, scrolling back to the end resumes it.

=back
