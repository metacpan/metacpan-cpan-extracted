=head1 NAME

Ekorn::Pipeline::Manual::Reference - Ekorn::Pipeline reference

=head1 DESCRIPTION

Stages for any function: let the caller finish the job.

A function that hands out values takes a list of I<stages> from its
caller, as its last arguments, and runs each value through them. A
stage can change a value, drop it, or turn it into several. It can
also stop the pipeline early, so the function makes no more values
than its caller wants.

This reference describes every module, function and method, and how a
pipeline behaves, with examples. L<The user guide|Ekorn::Pipeline::Manual::HowTo> tours the
package from the bottom up, with recipes for what each part can do.
Notes marked B<For stage authors> are for people writing stages for
others; L<Writing stages|/"Writing stages"> collects them. Each module's
POD says the same more briefly, and is the authority where they
differ.

Ekorn::Pipeline needs Perl 5.36 or later. Its version is 0.x, so the
interface may still change before 1.0, but the version number says
when. A release that only fixes or adds moves the last number, as in
v0.1.1. One that changes how stages behave, or drops or renames a
name, moves the middle number, as in v0.2.0. L<Changes|https://metacpan.org/dist/Ekorn-Pipeline/changes>
says what each release changed.

=head1 At a glance

    use v5.36;
    use Ekorn::Pipeline;
    use Ekorn::Pipeline::Tooling qw(:all);    # every stage, source, sink and word

    # A pipeline: a list of stages. A stage is a code reference given one
    # value, in $_ and as its argument, returning nothing, one value or
    # several; or another pipeline, standing for its stages.
    my $p = Ekorn::Pipeline->new(
        sub { $_ % 3 ? $_ : () },    # filter: drop multiples of 3
        sub { $_ * 10 },             # map: ten times each
        sub { ($_, -$_) },           # flatMap: each, and its negative
    );

    # Pushed: called with values, it returns what comes out.
    say join ' ', $p->(1 .. 4);    # 10 -10 20 -20 40 -40

    # Pulled: given a source, it hands out the results one per call.
    my $n    = 0;
    my $next = Ekorn::Pipeline->new(
        sub { $_ * $_ },
        take(3),
    )->iterator(sub { ++$n });
    my @squares;
    while (my($square) = $next->()) { push @squares, $square }
    say "@squares";    # 1 4 9

    # Fed: given values as they arrive, a push at a time, it returns what
    # comes out of each; close gives what's held back, and ends the run.
    my $feed = Ekorn::Pipeline->new(batch(2))->feed;
    my @batches = map { $feed->push($_) } 1 .. 3;
    push @batches, $feed->close;
    say join ' ', map { "[@$_]" } @batches;    # [1 2] [3]

    # A function of your own, taking stages from its caller.
    sub numbers (@stages) { Ekorn::Pipeline->new(@stages)->(1 .. 10) }
    say join ' ', numbers(
        drop(2),
        take(3),
    );
    # 3 4 5

=head1 Terms

=over 4

=item *

B<Value:> anything a pipeline is given, or a stage returns. C<undef>,
0 and the empty string are values.

=item *

B<Stage:> a code reference, another pipeline, or a part made for
each run. A code reference is called with one value, and returns a
list of values: none, one or several. A pipeline stands for its own
stages (see L<A pipeline as a stage|/"A pipeline as a stage">). A part
made for each run is a gather, a sink, or anything offering a
stage's or a sink's role method (see L<Delivering parts for
Ekorn|/"Delivering parts for Ekorn">).

=item *

B<Pipeline:> a list of stages, made with C<< Ekorn::Pipeline->new >>
or the word C<pipeline>.

=item *

B<Name:> a name a pipeline is kept under, with C<named>, so that
C<pipeline> and C<named> can take it where they take a stage. A name
is in a package, which says whose it is (see L<Named
pipelines|/"Named pipelines">).

=item *

B<Word:> a short function that makes one of Ekorn's types, such as
C<pipeline> or C<source {...}>, from Ekorn::Pipeline::Factories.

=item *

B<Run:> one call of a pipeline with values, or one iterator or feed
made from it. Gathers, sources and sinks are made afresh for each
run.

=item *

B<Feed:> a run you give values to as they arrive, with C<push>, and
end with C<close> (see L<Feeds|/"Feeds: Ekorn::Pipeline::Feed">).

=item *

B<Source:> what an iterator pulls values from: a code reference,
called with nothing, returning the next value or values, or an empty
list when there are no more; or a source made for each run, which is
told when the run ends (see L<Sources|/"Sources: Ekorn::Pipeline::Source">).

=item *

B<Sink:> a part that consumes every value and, when they run out,
gives its result: one value, such as a count, for a sink of one, or a
list, such as every value, for a sink of many. Usually the last
stage, when its result is what the run gives (see
L<Sinks|/"Sinks: Ekorn::Pipeline::Sink">).

=item *

B<Made for a run:> made afresh at the start of each run, by a
set-up block, so that each run has state of its own. Gathers,
sources and sinks are.

=item *

B<Result:> a value that comes out of the last stage.

=item *

B<Stop:> the exception a stage throws to end its run early, with
C<Stop> or C<< Ekorn::Pipeline::Stop->throw >>.

=item *

B<Flush:> what a gather or a sink does when its input runs out:
what it returns goes on through the stages after it. A gather's held
values, a sink's result. v0.2.0 called a gather's flush its I<end
function>.

=item *

B<End:> a function a gather, a source or a sink can have, called
once, when the run has ended, told how.

=item *

B<How a run ended:> C<done>, C<stopped> or C<died>, as each part of
the run sees it from where it stands (see L<How a run
ends|/"How a run ends">).

=back

=head1 Pipelines: Ekorn::Pipeline

    use Ekorn::Pipeline;
    use Ekorn::Pipeline v0.1.3 qw(is_stage);
    use Ekorn::Pipeline v0.3.0 qw(is_sink);

It exports nothing by default, and C<is_stage> and C<is_sink> on
request. C<is_stage> is new in v0.1.3, so ask for that version on the
C<use> line, as above. Without it, C<use Ekorn::Pipeline qw(is_stage)>
compiles under v0.1.2, which has no C<import>, and fails only when
C<is_stage> is called. The word C<pipeline>, which makes a pipeline
whose stages can be names, is in
L<Factories|/"Words: Ekorn::Pipeline::Factories">.

A subclass inherits its C<import>, Exporter's, so C<use My::Pipeline;>
imports nothing, and C<use My::Pipeline qw(name)> croaks unless the
subclass exports C<name> itself. Before v0.1.3, a subclass ignored the
list.

=head2 Making and calling a pipeline

A pipeline is made once, from its stages, and called as often as it's
needed, each call a run of its own. Any code reference will do for a
stage: an anonymous C<sub>, a reference to a named one such as
C<\&trim>, or a stage made by a function such as C<take(10)>. So will a
stage made with C<gather>, and a sink, usually last (see
L<Sinks|/"Sinks: Ekorn::Pipeline::Sink">).

The examples from here on use a small catalogue of tracks, each a hash
with a C<title>, an C<artist> and how many C<plays> it has had:

    my @tracks = (
        {title => 'Dancing Queen',           artist => 'ABBA',  plays => 9100},
        {title => 'Knowing Me, Knowing You', artist => 'ABBA',  plays => 4200},
        {title => 'Girls & Boys',            artist => 'Blur',  plays => 6100},
        {title => 'Parklife',                artist => 'Blur',  plays => 5800},
        {title => 'Sunshine of Your Love',   artist => 'Cream', plays => 7700},
        {title => 'Country House',           artist => 'Blur',  plays => 3900},
    );

    my $hits = Ekorn::Pipeline->new(
        sub { $_->{plays} > 6000 ? $_ : () },
        sub { $_->{title} },
    );
    my @hits  = $hits->(@tracks);
    my $count = $hits->(@tracks);
    say "$count hits: ", join ', ', @hits;    # 3 hits: Dancing Queen, Girls & Boys, Sunshine of Your Love

A pipeline ending in a sink gives the sink's result instead. In list
context, that's the sink's list, or a sink of one's one value. In
scalar context, a sink of one gives its value, and a sink of many its
list as an array reference:

    use Ekorn::Pipeline::Sinks qw(count_items keep_all);

    my $n    = Ekorn::Pipeline->new(count_items)->('a', 'b');
    my $kept = Ekorn::Pipeline->new(keep_all)->('a', 'b');
    say "$n: @$kept";    # 2: a b

You can call a pipeline even from inside one of its own stages. With
no stages, it returns its values unchanged, so a function that takes
stages from its caller needs nothing special for a caller who gives
none.

=head2 A pipeline as a stage

You can give C<new> a pipeline wherever it takes a stage. Its stages
are spliced in where it stands:

    my $clean = Ekorn::Pipeline->new(
        sub { s( \A \s+ | \s+ \z )()xgr },
        sub { length ? $_ : () },
    );
    say join '|', Ekorn::Pipeline->new(
        $clean,
        take(2),
    )->(' a ', '  ', 'b ', 'c');
    # a|b

This runs exactly like C<< Ekorn::Pipeline->new($clean->stages, take(2)) >>.
The spliced stages belong to the new pipeline's run, so a C<take>
inside C<$clean> limits the whole run, not each value. Pipelines can be
nested this way to any depth, and a pipeline of a subclass of
Ekorn::Pipeline works too.

The only difference is in error messages. Given C<$clean> itself, a
stage inside it is named by its position in each pipeline: the third
stage of a pipeline given second is C<#2.3>, and three levels down,
C<#1.2.3>. Given C<< $clean->stages >>, it's named by its position in the
combined list: C<#4>, if one stage came before it.

The stages spliced in are whatever the pipeline's L<stages|/"stages">
method returns, so a subclass can override it. If the override returns
a different list, its stages are named by their position in that list.

To run a pipeline on each value separately instead, call it from a
stage, as L<Calling a pipeline from a
stage|/"Calling a pipeline from a stage"> shows.

=head2 iterator

Pull values through a pipeline, rather than push them, when they're
made one at a time, from a file, a socket or a database, or without
end: the source is asked for more only as results are wanted, so a
stage that stops, such as C<take>, saves the work of making the rest.

    my $n    = 0;
    my $next = Ekorn::Pipeline->new(
        sub { $_ * $_ },
        take_if { $_ % 2 },
        take(3),
    )->iterator(sub { ++$n });
    while (my($square) = $next->()) { say $square }
    # 1
    # 9
    # 25
    say "$n numbers read";    # 5 numbers read

The source here counts without end, and is read five times: once for
each number up to the fifth, whose square is the third odd one, where
C<take(3)> stops the run.

=over 4

=item *

The source is called only when a result is wanted, and only once the
values from its last call have all gone through the stages. A source
reading a file, a socket or a database reads no more than its caller
asks for.

=item *

The iterator returns one result per call. Once the results run out,
it returns an empty list, on every call. Read it in list context, as
C<< my($x) = $next->() >>, so that a result of C<undef>, 0 or C<''> isn't
taken for the end.

=item *

Once the source has returned an empty list, or a stage has stopped
the pipeline, the source isn't called again.

=item *

The flushes of gathers and sinks are called once their input runs
out, before the iterator returns an empty list, and the ends as the
run ends (see L<Runs and how they end|/"Runs and how they end">).

=item *

If a stage or a flush dies, the call dies with it, and the iterator
has ended, as a pushed run does. Every call after returns an empty
list. Nothing waiting goes on, no flush is called, and the source
isn't called again; each end is told C<died>. So a flush such as
C<collect>'s never reports on a run that lost values. To skip a bad
value and carry on, catch the error inside the stage, as in the
user guide's "Catch errors in a stage, but let a stop through".

=item *

The iterator has methods to read every value still to come, or only
the first, to end the run early, and to say how it ended (see
L<Iterators|/"Iterators: Ekorn::Pipeline::Iterator">).

=back

Each iterator is a run of its own. Two iterators from one pipeline can
be read in turn, and each has its own C<gather> stages:

    my $numbered = Ekorn::Pipeline->new(gather { my $n = 0; sub { ++$n . $_ } });
    my @a = qw(a b);
    my @b = qw(x y);
    my $first  = $numbered->iterator(sub { @a ? shift @a : () });
    my $second = $numbered->iterator(sub { @b ? shift @b : () });
    say join ' ', $first->(), $second->(), $first->(), $second->();    # 1a 1x 2b 2y

A source that returns C<shift @queue // ()> ends at the first C<undef> in
the queue; C<@queue ? shift @queue : ()> doesn't. Read a filehandle in
scalar context, C<< sub { scalar(<$fh>) // () } >>, so that each call reads
one line.

=head2 feed

Use a feed where the values don't come from you, all at once, and
can't be pulled, but arrive a value at a time: from a library calling
back for each row, record or file it finds, from an event loop, or
from a stage that runs its values through another pipeline, as a
C<tee> does. Between pushes, the run's C<gather> stages keep their
state, so C<take(5)> takes five values from all that are pushed, and
C<batch(3)> fills its batches across pushes:

    my $feed = Ekorn::Pipeline->new(sub { $_->{title} }, batch(2))->feed;
    my @pages;
    for my $track (@tracks) {    # as if each arrived on its own
        push @pages, $feed->push($track);
    }
    push @pages, $feed->close;
    say for map { join ' / ', @$_ } @pages;
    # Dancing Queen / Knowing Me, Knowing You
    # Girls & Boys / Parklife
    # Sunshine of Your Love / Country House

Fed the same values, a feed gives what a call gives, in the same
order, a push at a time. The run is made when C<feed> is called, so a
C<gather>'s block is called then, and an error in it is thrown then.
L<Feeds|/"Feeds: Ekorn::Pipeline::Feed"> says more of its methods, and how
its run ends.

=head2 stages

A pipeline's stages are for splicing into another pipeline, or giving
to a function that takes stages, where a pipeline itself won't do.
The list can go anywhere stages go. Each is one of Ekorn's types, an object called as a code
reference: a code reference given to C<new> comes back as an
Ekorn::Pipeline::Stage of it (see L<Stages and
elements|/"Stages and elements">). So a function that takes only plain
code references, testing them with C<is_coderef> or C<ref>, won't take
them; v0.2.0 gave the code references themselves. To give C<new> the
pipeline itself, see L<A pipeline as a stage|/"A pipeline as a stage">.

    my $clean = Ekorn::Pipeline->new(
        sub { s( \A \s+ | \s+ \z )()xgr },
        sub { length ? $_ : () },
    );
    say join '|', Ekorn::Pipeline->new(
        $clean->stages,
        take(2),
    )->(' a ', '  ', 'b ', 'c');
    # a|b

Either way, the stages run as if they had been written out in full:

=over 4

=item *

A stop in one of them ends the whole run, and the source isn't called
again.

=item *

A C<gather> stage starts afresh on each run, so pipelines that share
it, or use it twice, don't share its state. A plain closure is the
same code reference wherever it goes, so anything it keeps is
shared. Keep state in C<gather> instead.

=item *

A stage that dies is named by its position, as L<A pipeline as a
stage|/"A pipeline as a stage"> describes.

=back

Calling a pipeline from a stage is different: each call is a run of
its own, as L<Calling a pipeline from a
stage|/"Calling a pipeline from a stage"> explains.

=head2 pipeline_in

Call C<pipeline_in> from code the user calls directly, passing the
user's package, as the word L<pipeline|/"Named pipelines"> does with
C<scalar caller>: for a word of your own, say, making a pipeline of
your subclass from stages and names the user writes.

    package My::Playlist {
        use parent -norequire, 'Ekorn::Pipeline';

        sub playlist (@stages) { My::Playlist->pipeline_in(scalar caller, @stages) }
    }

    Ekorn::Pipeline->named(loud => sub { uc $_->{title} });
    my $set = My::Playlist::playlist('loud', take(2));
    say ref $set, ': ', join ', ', $set->(@tracks);    # My::Playlist: DANCING QUEEN, KNOWING ME, KNOWING YOU

Code that passes stages through, such as a function taking stages
from its caller, gives them to C<new>, which reads no names: the user
has already turned any names into pipelines with C<pipeline>, where
they wrote them. If C<new> read names, it would look them up in the
package of whatever called it, which, for a function passing its
caller's stages on, isn't the caller's.

=head2 Named pipelines

Name a pipeline that's used in several places, or that another module
should be able to use, and give its name wherever C<pipeline> and
C<named> take a stage, as a stage in its own right. A named pipeline is
kept for the life of the program, in a package, which says whose name
it is:

    use Ekorn::Pipeline::Factories qw(pipeline);

    Ekorn::Pipeline->named(hits   => sub { $_->{plays} > 6000 ? $_ : () });
    Ekorn::Pipeline->named(titles => sub { $_->{title} });
    Ekorn::Pipeline->named(hit_titles =>
        'hits',
        'titles',
    );

    say join ', ', pipeline('hit_titles', take(2))->(@tracks);    # Dancing Queen, Girls & Boys
    say pipeline('hit_titles')->name;    # main::hit_titles

A pipeline already made is named in place, and returned, so it can be
named as it's made: C<< my $clean = Ekorn::Pipeline->new(...)->named('clean') >>.
Its first name is the one errors in its stages give (see L<When a stage
dies|/"When a stage dies">).

These rules say which pipeline a name means:

=over 4

=item *

B<A name is kept per package.> C<named> keeps it in the package that
called it, and C<pipeline> and C<named> look it up in the package that
called them, so two modules can each have a C<clean> of their own.

=item *

B<A qualified name is another package's.> C<My::Module::clean> names
C<clean> in My::Module, wherever it's used. Code that names or looks
up pipelines on another package's behalf qualifies them:
C<pipeline("${package}::clean")>.

=item *

B<A name is resolved when the pipeline is made,> not when it runs.
The pipeline it names is spliced in, as a pipeline given to C<new>
is, and its stages are named in messages by their places in each:
C<#1.2>. A name alone, C<pipeline('clean')>, gives that pipeline
itself, so it adds no level of its own. C<named> on a class always
makes a new pipeline, even of one name, so a name never aliases
another.

=item *

B<A name can't be defined twice.> Defining it again croaks: "A
pipeline named main::clean is already defined", whatever class
C<named> was called on. Naming the same pipeline again, with
C<< $p->named('clean') >>, is no mistake. But C<named> on a class always
makes a new pipeline, even from a single pipeline, so
C<< Ekorn::Pipeline->named(clean => $p) >> twice croaks.

=item *

B<A name can't be removed.> Define each once, as a program or module
loads, not in a sub that may be called again.

=item *

B<A pipeline, once made, keeps what it found.> As a name is looked
up when the pipeline is made, a name defined or overridden later
never changes a pipeline already made.

=item *

**Only C<pipeline_in>, which the word C<pipeline> calls, and C<named>
read names.** C<new> doesn't, and C<is_stage> is false for a string, so
a function finding its stages with C<is_stage> never takes a value
such as C<'clean'> for one.

=back

=head2 ending

C<ending> is for a stage that treats what a flush gives apart from the
values that went into it, as a total or a last batch isn't one of
them, and for code that tells its stages more about each value, such
as where it came from: a value a flush makes from many values, as a
total is, has no such origin. DBIx::Squirrel, for instance, tells its
stages which row a value was made from, and has no row to give for
one. A value that a stage that holds values back gives from its flush,
as C<take_last> does, came from one value, and has its original while
C<ending> is true (see L<Stages that hold values
back|/"Stages that hold values back">). Here the last stage sets out the
titles and their total differently:

    my @lines = Ekorn::Pipeline->new(
        gather {
            my $plays = 0;    # this run's
            return (
                sub ($track) { $plays += $track->{plays}; $track->{title} },
                sub ()       { $plays },
            );
        },
        sub { Ekorn::Pipeline::ending() ? "Total plays: $_" : "  $_" },
    )->(@tracks[0 .. 2]);
    say for @lines;
    #   Dancing Queen
    #   Knowing Me, Knowing You
    #   Girls & Boys
    # Total plays: 19400

A pipeline run inside a stage has its own C<ending>. In a pipeline
called from a stage while C<ending> is true, C<ending> is false until
one of the inner pipeline's own flushes is called.

=head1 Words: Ekorn::Pipeline::Factories

    use Ekorn::Pipeline::Factories qw(pipeline stage gather source generator yield sink_one sink_many);
    use Ekorn::Pipeline::Factories qw(:all);

The words make Ekorn's types, from what you write. Each is a short,
keyword-like function, one line over a class method: syntax, not
behaviour, so it lives here, not in the class it makes. A package
built on Ekorn uses them as they are (see L<Delivering parts for
Ekorn|/"Delivering parts for Ekorn">). Nothing is exported by default.

=over 4

=item C<pipeline(@stages)>

B<Makes:> a pipeline

B<Its block:> (takes a list)

=item C<stage {...}>

B<Makes:> a Stage

B<Its block:> the stage itself

=item C<gather {...}>

B<Makes:> a Gather

B<Its block:> a set-up, returning the step, and, optionally, the flush and the end

=item C<source {...}>

B<Makes:> a Source

B<Its block:> a set-up, returning the step, and, optionally, the end, a context and an original

=item C<generator {...}>

B<Makes:> a Source

B<Its block:> a block, called once each run, giving every value it passes to C<yield>

=item C<sink_one {...}>

B<Makes:> a Sink of one

B<Its block:> a set-up, returning the step, the flush, giving the result, one value, and, optionally, the end

=item C<sink_many {...}>

B<Makes:> a Sink of many

B<Its block:> the same, its flush giving a list

=back

A word given something other than a block or code reference croaks
"Expected a code reference". Each passes on the messages of the class
it makes.

C<gather {...}> is the same C<gather> that Ekorn::Pipeline::Gather
exports, as it always has, and is described with it (see
L<gather|/"gather">). C<pipeline> is C<new> that reads the names of
pipelines, and is described with them (see L<Named
pipelines|/"Named pipelines">).

=head2 stage

A plain C<sub> is a stage already, and needs no word. Use C<stage> where
a stage must be one of Ekorn's types as it's written: at the start of
a chain, where C<sub {...} | sub {...}> would be Perl's bitwise OR of
two addresses (see L<Operators|/"Operators: Ekorn::Pipeline::Operators">):

    use Ekorn::Pipeline::Operators;

    my $shout = stage { uc $_->{title} } | stage { "$_!" };
    say join ' ', $shout->(@tracks[0, 2]);    # DANCING QUEEN! GIRLS & BOYS!

To give it a signature, give it a sub: C<stage sub ($track) {...}>. A
Stage keeps what it's given, so C<stage(\&trim)> never changes C<trim>
itself.

=head2 source

A source with something to set up for each run, such as a count to
start from the beginning, or a file to open and close, is made with
C<source>: its set-up runs as each run starts. A source with nothing to
set up or end needs no word, as any code reference is a source.

    sub up_to ($last) {
        return source {
            my $n = 0;    # this run's
            return sub () { $n < $last ? ++$n : () };
        };
    }

    my $discs = Ekorn::Pipeline->new(sub { "Disc $_" });
    say join ', ', $discs->iterator(up_to(3))->all;    # Disc 1, Disc 2, Disc 3
    say join ', ', $discs->iterator(up_to(2))->all;    # Disc 1, Disc 2

Each run counts from 1 again, as the set-up runs at its start. The
source in L<Made for a run|/"Made for a run"> has an end, closing its
file, and the one in L<A source, with the word
C<source>|/"A source, with the word source"> gives its stages a context
too. With a context but no end, give C<undef> for the end.

=head2 generator and yield

Where values are easiest to make in loops, as the pairs of nested
loops are, write a generator, and C<yield> each value where the loop
makes it:

    my @artists  = qw(ABBA Blur Cream);
    my $pairings = generator {
        for my $i (0 .. $#artists) {
            yield "$artists[$i] & $_" for @artists[$i + 1 .. $#artists];
        }
    };
    say join ', ', Ekorn::Pipeline->new->iterator($pairings)->all;    # ABBA & Blur, ABBA & Cream, Blur & Cream

Perl can't pause a sub at C<yield>, as a Python generator does, so each
run calls the block once, to its end, and gives every value it yielded
in one step: the block mustn't loop without end, and runs to its end
even when a stage after it takes only some. For a producer without
end, write a C<source {...}> whose step gives a value each call. A
generator read inside another's block keeps its own C<yield>s.

An empty block, C<generator {}>, reads as an empty hash: write
C<generator { return }>.

=head2 sink_one and sink_many

Write a sink with these words when a run's result is something no
L<ready-made sink|/"Sinks: Ekorn::Pipeline::Sinks"> gives, such as the most
played track, or the artists, each once. Choose the word by the
result: C<sink_one> for one value, and C<sink_many> for a list, which a
pipeline asked for one value gives as an array reference, so it's
never taken for a count.

    my $most_played = sink_one {
        my $top;    # this run's
        return (
            sub ($track) { $top = $track if !$top || $track->{plays} > $top->{plays} },
            sub ()       { $top && $top->{title} },
        );
    };
    my $artists = sink_many {
        my %seen;    # this run's
        return (
            sub ($track) { $seen{ $track->{artist} }++ },
            sub ()       { sort keys %seen },
        );
    };

    say Ekorn::Pipeline->new($most_played)->(@tracks);    # Dancing Queen
    say join ', ', Ekorn::Pipeline->new($artists)->(@tracks);    # ABBA, Blur, Cream

=head1 Named at compile time: Ekorn::Pipeline::Sugar

    use Ekorn::Pipeline::Sugar pipeline => {
        titles => [sub { $_->{title} }],
        top    => ['titles', take(3)],
    };

    my @top  = top(@tracks);                                     # the first three titles
    my @loud = top(@tracks, pipeline(sub { uc }));                # and more stages
    my $next = pipeline('top')->iterator(from_array(@tracks));    # pulled

C<use Ekorn::Pipeline::Sugar> takes C<pipeline> and the definitions after
it, each a name and an array of stages: a hash, C<{...}>, or an array of
pairs, C<[...]>, to read in order. Each pipeline is named in the package
that uses the module, as C<named> names one, so C<pipeline('name')> finds
it, and the package gets a function of each name.

=over 4

=item *

B<The function> runs the values it's given through the pipeline, and
returns what comes out, in the caller's context, as calling the
pipeline does: a list in list context; in scalar context, a sink's
result, or how many came out. Given a pipeline last, it runs them
through that too, after its own. Only a pipeline last is taken for
stages; any other value, a code reference included, is a value. The
two are joined once for the pipeline given, and joined again only
when another is given, so a pipeline kept in a variable and given
again, as in a loop, costs less than one made in each call. The
function holds the last one given until it's given another.

=item *

B<A string where a stage goes names a pipeline,> as in C<pipeline>
and C<named>: one from the same C<use>, or one defined before it. A
definition can name any other in the same C<use>, in either order:
each is defined once those it names are.

=item *

B<A name> is a word, of letters, digits and underscores, not starting
with a digit, as a function's must be.

=item *

**Mistakes croak as the C<use> compiles,** at its line: a name that
can't be a function's, one given twice, one the package has a
function of already, its own or one it inherits, one a pipeline has
already, a definition that isn't an array, pipelines that name each
other in a circle, and a name defined nowhere. A pipeline's stages
are checked as C<pipeline> checks them.

=back

A sub covers what it doesn't: a pipeline that makes its own values
is C<< sub recent (@stages) { pipeline('top', @stages)->(load_recent()) } >>.

=head2 Sugar of your own

A module whose own C<use> line takes pipelines, and hands them on to
the package using it, does so with C<import_into>, so they're named in,
and their functions given to, that package, not the module. This one
puts a stage of its own before each pipeline it's given, so its users
write only what follows the titles:

    package My::Titles {
        use Ekorn::Pipeline::Sugar ();

        sub import ($class, %pipelines) {
            Ekorn::Pipeline::Sugar->import_into(
                scalar caller,
                pipeline => {map { ($_ => [sub { $_->{title} }, @{ $pipelines{$_} }]) } keys %pipelines},
            );
        }
    }

    BEGIN { My::Titles->import(opening => [take(2)], shouted => [sub { uc }]) }

    say join ', ', opening(@tracks);    # Dancing Queen, Knowing Me, Knowing You
    say join ', ', shouted(@tracks[4, 5]);    # SUNSHINE OF YOUR LOVE, COUNTRY HOUSE

The C<BEGIN> block stands for C<use My::Titles ...> in a program of its
own. C<import_into> checks the names, and the package's functions,
before it defines anything, but finds a bad stage, or a name another
pipeline has, only as it makes that definition, so those before it
stay defined: no matter for C<use>, as the program stops, but worth
knowing for an C<eval>.

=head1 How values go through stages

This section describes stages that are code references. A pipeline
given as a stage stands for its stages, and each of them behaves as
described here.

=head2 One value at a time

Each value goes through every stage before the next one starts, as it
would in a C<for> loop. The results come out in order, and each stage
sees the values in order. Nothing is held between stages, except by a
stage that holds values itself, such as C<batch> or C<collect>.

When a stage returns several values, the first goes through the rest
of the stages, then the second, and so on. Only then does the next
value come from the source or the caller:

    my @trace;
    Ekorn::Pipeline->new(
        sub { push @trace, "1:$_"; ("$_.1", "$_.2") },
        sub { push @trace, "2:$_"; $_ },
    )->(qw(a b));
    say "@trace";    # 1:a 2:a.1 2:a.2 1:b 2:b.1 2:b.2

=head2 What a stage is given

A stage is called with one value, both as its only argument and in
C<$_>. It can name the value with a signature, C<sub ($track) { ... }>,
or use C<$_>, C<sub { ... }>.

=over 4

=item *

C<$_> is local to each call. The caller's C<$_> is left alone, and a
stage can call code that uses C<$_> itself.

=item *

The values a pipeline is called with are copied. Assigning to C<$_>
or C<$_[0]> changes the pipeline's copy, not the caller's variable.

=item *

A reference is copied as a reference. A stage that changes the hash
or array it's given changes the caller's.

=back

=over 4

B<For stage authors:> a stage is always called with exactly one
argument, so a one-argument signature is safe. Don't change the
value you're given; return a new value instead. The exception is a
stage whose job, as documented, is to change it.

=back

=head2 What a stage returns

A stage returns a list, and what it returns is all that goes on:

=over 4

=item an empty list

B<Its kind:> a filter

B<What goes on:> nothing: the value is dropped, and the stages after it don't see it

=item one value

B<Its kind:> a map

B<What goes on:> that value, in place of the one it was given

=item several values

B<Its kind:> a flatMap

B<What goes on:> each of them, in order, through the rest of the stages

=back

C<undef>, 0 and C<''> are values, so C<return undef> passes on C<undef>.
A stage ending in a test, such as C<< sub { $_ > 2 } >>, passes on what the
test returns, not the value. To drop a value, return an empty list:
C<return;> or C<()>.

=over 4

B<For stage authors:> a stage run for its side effects, such as
logging, must return the value it was given, as C<peek> does, or the
value is dropped.

=back

=head2 Runs

Each call of a pipeline with values is a run, and so is each iterator
or feed made from it. At the start of each run, the set-up of every
gather, source and sink is called, so what they keep starts afresh
(see L<Made for a run|/"Made for a run">). An iterator's run starts when
the iterator is made, not when it's first read, and a feed's when it's
made, not at its first push.

A stage not made with C<gather> is the same code reference on every
run. Whatever it keeps in a closure stays there from one run to the
next:

    my $count = 0;
    my $plain = Ekorn::Pipeline->new(sub { ++$count });
    my @first  = $plain->(qw(a b));
    my @second = $plain->(qw(a b));
    say "@first / @second";    # 1 2 / 3 4

=over 4

B<For stage authors:> put anything a stage keeps, even a count, in
a C<gather> block. A stage made once may be given to several
pipelines, run more than once, or run by two iterators at once.

=back

=head2 Calling a pipeline from a stage

A stage can run a pipeline of its own, so stages can be built from
stages:

    my $trim = Ekorn::Pipeline->new(
        sub { s( \A \s+ | \s+ \z )()xgr },
        sub { length ? $_ : () },
    );
    say join '|', Ekorn::Pipeline->new(sub { $trim->($_) })->(' a ', '  ', 'b ');    # a|b

Each call of the inner pipeline is a run of its own. Its C<gather>
stages start afresh on each value the outer stage is given, and its
flushes and ends are called at the end of each call. A stop in it ends
only that call, not the outer pipeline. To run its stages in the outer
pipeline's run instead, give the pipeline itself as a stage (see
L<A pipeline as a stage|/"A pipeline as a stage">). To run them beside
the outer run, as one run of their own over every value the stage is
given, have a C<gather> make a feed of the pipeline for each run, push
each value into it, close it in the flush and finish it in the end
(see L<Feeds|/"Feeds: Ekorn::Pipeline::Feed">).

=head1 Runs and how they end

A run is one call of a pipeline with values, or one iterator or feed
made from it. Each run has its own state. A part of the pipeline that needs
state, such as a batch it's filling or a file it has open, is made
afresh for each run, and can be told when the run ends, however it
ends, so it can close the file, or commit what it wrote.

=head2 Made for a run

A gather, a source or a sink, made with a
L<word|/"Words: Ekorn::Pipeline::Factories">, has a block that's its
B<set-up>. The set-up runs at the start of each run. It declares
whatever the run needs, with C<my>, and returns closures sharing what
it declared:

=over 4

=item *

B<the step,> called with each value (a gather or a sink), or each
time the source is pulled (a source);

=item *

B<the flush,> for a gather or a sink, called once its input runs
out, what it returns going on through the stages after it. A sink's
gives its result, and is required;

=item *

B<the end,> called once, when the run has ended, told how. It's
optional;

=item *

B<a context,> for a source only, and optional: anything its stages
may ask for with L<C<run_context>|/"Stages that ask about their run">.

=item *

B<an original,> for a source only, and optional: called with
nothing, it returns the original of the value the source gave last,
which L<C<result_original>|/"Which result: Ekorn::Pipeline::Context"> gives.

=item *

B<holds,> for a gather or a stage's own C<EKORN_STAGE>, by name only,
and optional: true for a stage that holds values back, which then
says where each value it gives came from (see L<Stages that hold
values back|/"Stages that hold values back">). Not code, but a flag.
New in v0.5.0.

=back

    use Ekorn::Pipeline::Factories qw(source);

    sub lines_of ($path) {
        return source {
            open my $fh, '<', $path or die "Can't read $path: $!\n";    # this run's
            return (
                sub ()     { my $line = readline $fh; defined $line ? $line : () },
                sub ($how) { close $fh },
            );
        };
    }

Two iterators of the same pipeline each get their own filehandle, from
their own call of the set-up. A plain code reference is never made for
a run: it's the same code, with the same closure, in every run.

The set-up returns its parts as a list, in the order above, leaving
out those it doesn't give from the end, and giving C<undef> for one it
leaves out before one it gives. Or it returns them B<by name,> as a
hash reference whose keys are C<step>, C<flush>, C<end>, C<context>,
C<original> and C<holds>, giving only those it has, in any order. C<holds>
is given only by name, so a list keeps its three parts, and the
messages that say so:

    use Ekorn::Pipeline::Factories qw(gather);

    sub counted_into ($total) {
        return gather {
            my $n = 0;    # this run's
            return {
                step => sub ($x)   { $n++; $x },
                end  => sub ($how) { $$total = $n },
            };
        };
    }

    my $count;
    Ekorn::Pipeline->new(counted_into(\$count))->(qw(a b c));
    say $count;    # 3

A key Ekorn doesn't read is ignored, and a hash without what its part
needs, a step, and a sink's flush, croaks, as a list without them
does. Only a plain hash reference returned alone is taken for parts by
name. So a misspelt key, such as C<hold>, is ignored without a word: a
stage that means to hold values back, but misspells it, is taken for
one that doesn't. A sink gives nothing to stages after it, so its
C<holds> is ignored too.

=head2 How a run ends

A run ends in one of three ways, and each part's end is told which,
from where the part stands: C<died> if the run died, anywhere, before
it ended; C<stopped> if its input was cut short, by a stop at or after
it, or by the run being ended from outside; and C<done> if its input
ran out, and the run didn't die. A part whose input had run out before
a stop is told C<done>, and so is a sink that stops the run itself. For
the commonest runs:

=over 4

=item ran out of values

B<The source, and the stages up to and including the one that stopped:> C<done>

B<The stages after it:> C<done>

=item was stopped by a stage

B<The source, and the stages up to and including the one that stopped:> C<stopped>, if it still had values to come

B<The stages after it:> C<done>

=item had a stage or an end die

B<The source, and the stages up to and including the one that stopped:> C<died>

B<The stages after it:> C<died>

=back

A stop ends the stream early for what's before it, and normally for
what's after it. So in

    use Ekorn::Pipeline::Sinks qw(count_items);

    my $n = Ekorn::Pipeline->new(
        take(5),
        count_items,
    )->iterator(lines_of('setlist.txt'))->();

the file is closed, told C<stopped>, and C<count_items>, after C<take(5)>,
is told C<done>, and gives 5.

=head2 Flushes and ends

A flush, a gather's or a sink's, is called once its input runs out
normally: when the values ran out, after a stop in a stage before it,
or, for a sink, when the sink stopped the run itself. What it returns
goes on through the stages after it, and while it runs, and they do,
L<C<ending>|/"ending"> is true. The flush of a sink of one gives one
value, C<undef> if it has none. It isn't told how the run ended, as the
run hasn't.

An end:

=over 4

=item *

B<always runs, once, when the run has ended,> however it ended, and
is given how, as its argument: C<done>, C<stopped> or C<died>. A run
has ended as soon as nothing in it can still act on a value, so with
a sink last, it ends as the sink's result is ready, and a sink that
commits only when told C<done> commits then, and never for a run that
dies after it;

=item *

B<gives nothing:> what it returns is dropped;

=item *

B<runs in order:> the source's end first, then each stage's, first
stage first, so a source that fails to close is known before any
sink commits.

=back

After a stage dies, every end still runs, told C<died>, and then the
error is thrown again, as it would have been. An end that dies then is
reported as a warning, naming its stage, and the first error is kept.
An end that dies in a run that hadn't died ends the run with its error,
"Pipeline end of stage #2 failed at ...", and the ends after it are
told C<died>.

=head2 Sources: Ekorn::Pipeline::Source

A source is made for each run so that what it opens is that run's,
and is closed as that run ends, however it ends. Its step can also
stop the run, with C<Stop>, when it's had enough: the values its stop
carries are its last, and it's told C<done>. This one reads a setlist
up to its encore:

    use Ekorn::Pipeline::Source;

    my @setlist  = ('Intro', 'Parklife', 'Song 2', 'encore', 'Tender');
    my $main_set = Ekorn::Pipeline::Source->new(sub {
        my $i = 0;    # this run's
        return sub () {
            return if $i > $#setlist;
            my $song = $setlist[$i++];
            Stop() if $song eq 'encore';
            return $song;
        };
    });
    say join ', ', Ekorn::Pipeline->new->iterator($main_set)->all;    # Intro, Parklife, Song 2

The word L<source|/"source"> makes one from a block. A source goes to
L<iterator|/"iterator">. It isn't a stage, and given to C<new> as one, it
croaks. Called directly, as a code reference, it croaks "Expected a
source to be read through iterator": a run of its own would never be
ended, so what it opened would stay open.

=head2 Sinks: Ekorn::Pipeline::Sink

A sink is usually a pipeline's last stage, so that its result is what
a run gives (see L<Making and calling a
pipeline|/"Making and calling a pipeline">). Anywhere else, its result
goes on through the stages after it. Its step can stop the run, with
C<Stop>, once it has all it wants: it still gives its result, and is
told C<done>.

    use Ekorn::Pipeline::Sink;

    my $total_plays = Ekorn::Pipeline::Sink->new_sink_one(sub {
        my $sum = 0;    # this run's
        return (sub ($track) { $sum += $track->{plays} }, sub () { $sum });
    });

    my $blur = Ekorn::Pipeline->new(
        take_if { $_->{artist} eq 'Blur' },
        $total_plays,
    );
    say scalar $blur->(@tracks);           # 15800
    say scalar $total_plays->(@tracks);    # 36800

A sink can be called as a code reference with values, as the second
call does, as a pipeline of the one sink would be, and gives its
result, from a fresh sink of its set-up each time. The words
L<sink_one and sink_many|/"sink_one and sink_many"> make sinks from a
block.

=head2 Iterators: Ekorn::Pipeline::Iterator

An iterator, made by L<iterator|/"iterator">, is one run. Called as a
code reference, C<< $next->() >>, it hands out the next value. Its methods
read the rest at once, or only what's wanted, end the run early, and
say how it ended. A setlist, read up to its encore:

    use Ekorn::Pipeline::Sources qw(from_array);

    my @setlist = ('Intro', 'Parklife', 'Song 2', 'encore', 'Tender');
    my $next    = Ekorn::Pipeline->new(take_while { $_ ne 'encore' })->iterator(from_array(@setlist));
    my($opener) = $next->();
    my @rest    = $next->all;
    say "$opener, then @rest: ", $next->ended;    # Intro, then Parklife Song 2: stopped

C<ended> says C<stopped>, as C<take_while> cut the reading short, with
C<Tender> still to come.

C<next> does what a call does, so a loop can be written either way:
C<< while (my($song) = $next->next) { ... } >>.

C<all> gives an array reference only in scalar context: in a hash, a
list or an argument, its values are flattened into it. C<all_arrayref>
gives the reference whatever the context:

    use Ekorn::Pipeline::Sources qw(from_array);

    my %gig = (
        venue => 'Wembley',
        songs => Ekorn::Pipeline->new->iterator(from_array('Intro', 'Parklife', 'Song 2'))->all_arrayref,
    );
    say "$gig{venue}: @{ $gig{songs} }";    # Wembley: Intro Parklife Song 2

C<first> and C<single> read a value and end the run, so nothing more is
read, and a source holding a resource, such as a file or a statement's
lock, lets it go. C<single> reads one more, to warn if there's another:
for when one value is meant, and a mistake could give more.

    my @setlist  = ('Intro', 'Parklife', 'Song 2', 'encore', 'Tender');
    my $numbered = Ekorn::Pipeline->new(take_if { m( \d )x });
    say $numbered->iterator(from_array(@setlist))->single;    # Song 2

Stopping reading isn't ending the run. C<finish> ends it where you
stop, rather than when the iterator goes, so a file is closed then:

    my $next = Ekorn::Pipeline->new->iterator(from_file('setlist.txt'));
    while (my($song) = $next->()) {
        last if $song eq 'encore';
        say $song;
    }
    # Intro
    # Parklife
    # Song 2
    $next->finish;    # the file is closed now

An iterator that's dropped before its values run out ends its run when
the last reference to it goes, as C<finish> does:

    my($first) = Ekorn::Pipeline->new(sub { uc })->iterator(from_file('setlist.txt'))->();
    # the file is closed here, as the iterator has gone

Perl destroys a lexical iterator as soon as it goes out of scope. One
kept until the program ends is destroyed during global destruction,
when the order of destruction isn't guaranteed, so an end mustn't rely
on other objects then.

Each C<< $next->() >> goes through Perl's overloading of C<&{}> to find the
iterator's code. A loop pulling many values can take the code
reference once, and call it directly:

    my $pull = \&$next;    # the iterator's code, found once
    while (my($value) = $pull->()) { ... }

Keep C<$next> while you use C<$pull>: the code reference doesn't keep
the iterator, and an iterator let go ends its run, after which C<$pull>
gives nothing. Over 300,000 values, this saves about 0.02 s.

An iterator is a source too, so it can be given to another pipeline's
C<iterator>. Its values go through the second pipeline's stages, its
run ends when the second run ends, and the second run's stages see its
run's context. It's one run, so it can be a source only once, before
it has handed out everything it will; after, it croaks "Expected a
source with values still to give: an iterator is one run, and this one
is spent".

=head2 Feeds: Ekorn::Pipeline::Feed

A feed, made by L<feed|/"feed">, is one run, which you give values as
they arrive, with C<push>, and end with C<close>. A caller feeding
values asks C<ended> after each push, and stops once it's defined, so
it can tell whoever is sending the values to stop too:

    my $feed = Ekorn::Pipeline->new(
        take_if { $_->{plays} > 6000 },
        sub { $_->{title} },
        take(2),
    )->feed;
    my @hits;
    for my $track (@tracks) {    # as if each arrived on its own
        push @hits, $feed->push($track);
        last if defined $feed->ended;
    }
    say join(', ', @hits), ': ', $feed->ended;    # Dancing Queen, Girls & Boys: stopped

A stop, from a stage, a flush or a sink, such as C<take>'s, ends the run
in the push that meets it, as it ends any run. The values it carries
go on, the flushes of the stages after it are called, then every end,
and that push returns all of it. The values after the one that met the
stop are dropped. A stage that dies kills the run, and the push dies
with it, named as a run names it.

Once the run has ended, however it ended, C<push> and C<close> croak
"Expected a feed still open, but its run has ended", with the reason,
so values can't go nowhere unnoticed. A feed let go before it's closed
is finished as the last reference to it goes, as an iterator let go
is.

A feed has no context of its own. Its stages and ends see the context
of the code pushing into it, through C<run_context>: none, pushed from
outside any run, or, pushed from a stage, that stage's run's, such as
a statement's columns. So a stage that feeds a branch passes its run's
context on to it. A C<push>, C<close> or C<finish> from inside the feed's
own run, such as from one of its stages, croaks: a stage can push into
another pipeline's feed, but not its own. Each feed is a run of its
own, so a stage can keep feeds of several pipelines, or several feeds
of one, as the user guide's tee and its run for each key do.

=head2 Stages and elements

You needn't think about these classes to use Ekorn, but they're what
you see when you look at a pipeline's parts. C<new> keeps each code
reference it's given as an B<Ekorn::Pipeline::Stage>, so that every
part of a pipeline is one of Ekorn's types, and each of those called
as code, a pipeline, a stage, a gather, a source, a sink and an
iterator, is an B<Ekorn::Pipeline::Element>: an object called as a
code reference, which holds the closure it's called as, so it's freed
as soon as nothing else holds it. A feed is used only by its methods,
so it isn't one.

    my($shout) = Ekorn::Pipeline->new(sub ($title) { uc "$title!" })->stages;
    say ref $shout;                    # Ekorn::Pipeline::Stage
    say $shout->call('Parklife');      # PARKLIFE!
    say $shout->code->('Song 2');      # SONG 2!

Called directly, a stage calls its code with what it's given, but
doesn't set C<$_>: only a run does, so the stage here names its value.

=head1 Stopping a pipeline: Ekorn::Pipeline::Stop

    use Ekorn::Pipeline::Stop;       # Stop
    use Ekorn::Pipeline::Stop ();    # nothing: call Ekorn::Pipeline::Stop->throw

A stop is the exception that ends a run early and quietly.

=head2 What a stop does

A stage stops the run when no more values are wanted: it has found
what it was looking for, or passed on as many as it was asked to. A
stop ends the run quietly, as an error doesn't, and saves the work of
making more. This stage passes on titles until it comes to the first
by Cream, which it passes on with the stop:

    my @titles = Ekorn::Pipeline->new(
        sub { $_->{artist} eq 'Cream' ? Stop($_->{title}) : $_->{title} },
        sub { "* $_" },
    )->(@tracks);
    say for @titles;
    # * Dancing Queen
    # * Knowing Me, Knowing You
    # * Girls & Boys
    # * Parklife
    # * Sunshine of Your Love

When a stage throws a stop:

=over 4

=item *

The rest of the stage that threw it doesn't run.

=item *

The results already out are kept: returned by a pushed run, or
already handed out by an iterator.

=item *

The values the stop carries go on through the stages after the one
that threw it, as that stage's last values.

=item *

Nothing else is processed. Values waiting to go through the stages
are dropped: the rest of the values a pipeline was called with, the
rest of what a source returned in one call, and the rest of what a
stage returned as a flatMap. The source isn't called again.

=item *

The flushes of the stages after the one that stopped are called, in
order. They get the values from before the stop, and the values it
carries. The flushes of the stage that stopped, and of the stages
before it, aren't called. Every end is, as the run ends: told
C<stopped> up to the stage that stopped, if its input was cut short,
and C<done> after it (see L<How a run ends|/"How a run ends">).

=back

A flush can stop the pipeline too. The values its stop carries go on
through the stages after it, and the flushes after it are still
called. An end can't: the run has ended, and a stop there is an error,
"Expected no stop in an end, as the run has ended".

A module of stages, which mustn't put C<Stop> among its own functions,
loads Ekorn::Pipeline::Stop with an empty list, and calls
C<< Ekorn::Pipeline::Stop->throw >>, as the stage in L<Writing
stages|/"Writing stages"> does. C<throw> throws a stop of the class it's
called on, so a subclass's stops are its own (see
L<Subclasses|/"Subclasses">).

=head2 The stop object

A stop is an array reference, blessed into its class. Its first
element is that class, and the rest are the values it was thrown with:

    eval { Ekorn::Pipeline::Stop->throw(1, 2) };
    say ref $@, ' ', "@{$@}[1 .. $#{$@}]";    # Ekorn::Pipeline::Stop 1 2

As a string, a stop is "Stop used outside a pipeline", with a newline.
That's what a user sees if one is thrown with no pipeline to catch it.

A stop that isn't an array, made without C<throw> (by blessing a hash
into the class, say), still stops the pipeline, but carries nothing.

=head2 Subclasses

A pipeline recognises a stop with C<isa>, so a stop of a subclass of
Ekorn::Pipeline::Stop works in exactly the same way.

=head2 Catching errors in a stage

A stop is an exception, so a stage that catches errors itself, with
C<eval> or C<try>, catches stops too, including stops from stages it
runs, such as C<take>'s. It must throw them again:

    use experimental qw(try);

    my @out = Ekorn::Pipeline->new(sub ($x) {
        try {
            Stop() if $x > 2;
            return 10 / $x;
        }
        catch ($e) {
            die $e if $e isa 'Ekorn::Pipeline::Stop';
            return 'n/a';
        }
    })->(0, 1, 2, 3);
    say "@out";    # n/a 10 5

Test with C<isa 'Ekorn::Pipeline::Stop'>, not with C<ref>, so that a stop
of a subclass is thrown again too.

=head1 Gathering: Ekorn::Pipeline::Gather

    use Ekorn::Pipeline::Gather;       # gather
    use Ekorn::Pipeline::Gather ();    # nothing: call Ekorn::Pipeline::Gather::gather

A plain stage can't tell when the last value has gone by, and whatever
it keeps stays from one run to the next. A stage that gathers values,
to give them in batches or all together, needs both: fresh state on
each run, and a call when its values run out. C<gather> makes such a
stage.

=head2 gather

The block is a set-up: it's called as each run starts, when the
pipeline is called with values, or an iterator or a feed is made from
it, not when C<gather> is called. So whatever it declares is that
run's, as a running total starting from nothing on every run is:

    sub running_total () {
        return gather {
            my $total = 0;    # this run's
            return sub ($track) { $total += $track->{plays} };
        };
    }

    my $p = Ekorn::Pipeline->new(running_total());
    say join ' ', $p->(@tracks[0 .. 2]);    # 9100 13300 19400
    say join ' ', $p->(@tracks[3 .. 5]);    # 5800 13500 17400

The block returns the stage's step, and, optionally, its flush and its
end (see L<Made for a run|/"Made for a run">), or a pipeline in place of
the step (see L<A pipeline as the stage|/"A pipeline as the stage">). A
block that returns anything else is reported as the run starts:
"Expected stage #%s, made with gather, to return a code reference or a
pipeline, and optionally a flush and an end". By name, it can say the
stage holds values back, with C<holds> (see L<Stages that hold values
back|/"Stages that hold values back">), but not beside a pipeline:
"Expected stage #%s, made with gather, to hold values back in its step,
not in a pipeline".

=head2 The flush

A gather's flush is called with no arguments, and with C<$_> undefined,
once its input runs out. In a pushed run, that's after the last value
has gone through. With an iterator, it's once the source returns an
empty list, or after a stop before it. What it returns goes on through
the stages after its own, just like what a stage returns: nothing, one
value, or several. It's what v0.2.0 called the I<end function>, and a
gather written for v0.2.0 works as it did.

=over 4

=item *

It's called even when no values went by, so a flush can give an
empty result, such as C<[]>, or nothing at all.

=item *

The flushes are called in order, first stage first. What one returns
goes through the stages after it, and their flushes see it, before
the next flush is called. So a C<collect> after a C<batch> gets
C<batch>'s last, short batch.

=item *

After a stop, only the flushes of the stages after the one that
stopped are called (see L<What a stop does|/"What a stop does">).

=item *

While the values a flush returns go through the stages,
L<C<ending>|/"ending"> is true.

=item *

A flush that dies is reported as its stage would be, by the stage's
position.

=back

A gather's end, its third, is told how the run ended, as every end is
(see L<Flushes and ends|/"Flushes and ends">).

    sub average () {
        return gather {
            my($sum, $n) = (0, 0);
            my $step  = sub ($x) { $sum += $x; $n++; return };
            my $flush = sub ()   { $n ? $sum / $n : () };
            return ($step, $flush);
        };
    }

    say Ekorn::Pipeline->new(average())->(2, 4, 9);    # 5
    say scalar Ekorn::Pipeline->new(average())->();    # 0

The second line prints 0, the number of results. With no values, the
flush returns nothing.

=head2 A pipeline as the stage

A pipeline returned by a C<gather> block as its stage has its stages
made for the run in its place, as if they had been given there. A
C<gather> stage inside it is made afresh too, and a stop inside it ends
the whole run. So the block can build a pipeline for each run, or
choose one:

    my $run   = 0;
    my $alter = Ekorn::Pipeline->new(gather {
        Ekorn::Pipeline->new(
            $run++ % 2 ? sub { uc } : sub { lc },
            take(2),
        );
    });
    say join ' ', $alter->(qw(A b C));    # a b
    say join ' ', $alter->(qw(A b C));    # A B

The block's flush, if it returns one, is called after the flushes of
the pipeline's own stages, and its end after their ends. A stage
inside the pipeline is named in messages by its position in each, as
C<#2.3> for the third stage of the pipeline returned by stage #2.

=over 4

B<For stage authors:> a stage that holds values should give them
up in its flush, as C<batch> and C<collect> do, so none are lost when
the values run out. Give the flush an empty signature, C<sub ()>.

=back

=head1 pipe and tap: Ekorn::Pipeline::Pipes

A parent class that gives its children two methods, C<pipe> and C<tap>,
so that a caller can run one of its objects through stages of their
own, in the middle of a chain of method calls: C<pipe> to take
something from the object and go on with that, and C<tap> to do
something on the side and go on with the object. The first stage is
given the object, in C<$_> and as its argument. DBIx::Squirrel's
database and statement handles have the same two methods.

    package Playlist {
        use parent 'Ekorn::Pipeline::Pipes';

        sub new ($class, @tracks) { bless {tracks => [@tracks]}, $class }
        sub add ($self, @tracks) { push @{ $self->{tracks} }, @tracks; $self }
        sub tracks ($self) { @{ $self->{tracks} } }
    }

    my $list = Playlist->new(@tracks[0, 1])
        ->tap(sub { say 'Starting with ', scalar $_->tracks, ' tracks' })    # Starting with 2 tracks
        ->add($tracks[4]);
    say join ', ', $list->pipe(sub { $_->tracks }, sub { $_->{artist} });    # ABBA, ABBA, Cream
    say scalar $list->pipe(sub { $_->tracks }, take_if { $_->{plays} < 5000 });    # 1
    say $list->pipe(sub { $_->tracks }, take_if { $_->{plays} < 5000 }, sub { $_->{title} }, keep_first);    # Knowing Me, Knowing You

C<pipe> gives what a pipeline of its stages, called with the object,
gives, in either context: in scalar context, how many results came
out, or a sink's result. So for one value, end with a sink of one,
such as C<keep_first>, or read it in list context, C<< my($title) =
$list->pipe(...) >>. Until v0.4.0, in scalar context, C<pipe> gave the
first result instead, unlike a pipeline.

=head1 Canned stages

Stages for any values, whatever they are and wherever they come from,
in three modules. Each is a function that returns a stage. It checks
its arguments when it's called, not on each value, and croaks at the
caller's line if they're wrong. Those that keep state or hold values
are made with C<gather>, so they start afresh on each run.

Each stage is an object, an Ekorn::Pipeline::Stage or, for those made
with C<gather>, an Ekorn::Pipeline::Gather, called as a code reference,
so it goes wherever a stage goes (see L<Stages and
elements|/"Stages and elements">). Code testing one with C<ref> or
C<is_coderef> sees an object: v0.2.0 gave code references.

Each C<keep> sink but C<keep_all> has a C<take> stage that passes on what
the sink would give as its result, so the stages after it can go on:
C<take($n)> is C<keep($n)>'s, and C<take_first>, C<take_last> and
C<take_single> are C<keep_first>'s, C<keep_last>'s and C<keep_single>'s.
C<keep_all>'s would pass every value on: no stage at all. A pipeline
ending in a C<take> stage, where its sink was forgotten, gives the
values in list context, and how many in scalar context, never a wrong
one.

Each module exports its defaults with a plain C<use>, and every stage
it has with C<:all>. To get the defaults and one more, name C<:DEFAULT>
too:

    use Ekorn::Pipeline::Stages::Flow qw(:DEFAULT take_while);

=head2 Taking and dropping: Ekorn::Pipeline::Stages::Flow

Flow's stages decide which values go on, by their place or by a test.
A stage that stops the run stops the reading too, so an iterator asks
its source for no more values than are wanted.

B<By place.> C<take> and C<drop> give a page: C<drop(20), take(10)>
passes on the 21st to the 30th. C<take> passes its last value on with
its stop, so the source isn't asked for one more than is wanted:

    my $page = Ekorn::Pipeline->new(sub { $_->{title} }, drop(2), take(2));
    say join ', ', $page->(@tracks);    # Girls & Boys, Parklife

    my $read  = 0;
    my @three = Ekorn::Pipeline->new(take(3))->iterator(sub { $read++ < @tracks ? $tracks[$read - 1] : () })->all;
    say scalar @three, " tracks, $read read";    # 3 tracks, 3 read

C<take_first>, C<take_last> and C<take_single> each pass on one value,
and are the stages of the sinks C<keep_first>, C<keep_last> and
C<keep_single>, so a pipeline can go on after them. C<take_last> reads
every value to find the last, and holds it back, saying where it came
from, so the stages after it get its original (see L<Stages that hold
values back|/"Stages that hold values back">). C<take_single> is for when
one value is meant: at a second, it warns and stops, so a forgotten
limit is found.

    my $last_quiet = Ekorn::Pipeline->new(
        take_if { $_->{plays} < 5000 },
        take_last,
        sub { "$_->{title} ($_->{plays})" },
    );
    say $last_quiet->(@tracks);    # Country House (3900)

    sub only_by ($artist) {
        return Ekorn::Pipeline->new(take_if { $_->{artist} eq $artist }, take_single, sub { $_->{title} });
    }
    say only_by('Cream')->(@tracks);    # Sunshine of Your Love
    say only_by('ABBA')->(@tracks);     # Dancing Queen, with a warning

B<By a test.> C<take_if> and C<drop_if> test every value, as C<grep>
does, and never stop the run. A plain stage ending in a test passes on
what the test returns, true or false; C<take_if> passes on the value:

    my $hits  = Ekorn::Pipeline->new(take_if { $_->{plays} > 6000 }, sub { $_->{title} });
    my $quiet = Ekorn::Pipeline->new(drop_if { $_->{plays} > 6000 }, sub { $_->{title} });
    say join ', ', $hits->(@tracks);     # Dancing Queen, Girls & Boys, Sunshine of Your Love
    say join ', ', $quiet->(@tracks);    # Knowing Me, Knowing You, Parklife, Country House

C<take_while> and C<drop_while> test values only until the first that
fails, so they suit values in the order the test reads. C<take_while>
stops the run there, and reads no further, where C<take_if> would read
every value; C<drop_while> passes on everything from there, without
testing again:

    my @by_plays = sort { $b->{plays} <=> $a->{plays} } @tracks;
    my $top  = Ekorn::Pipeline->new(take_while { $_->{plays} > 6000 }, sub { $_->{title} });
    my $rest = Ekorn::Pipeline->new(drop_while { $_->{plays} > 6000 }, sub { $_->{title} });
    say join ', ', $top->(@by_plays);     # Dancing Queen, Sunshine of Your Love, Girls & Boys
    say join ', ', $rest->(@by_plays);    # Parklife, Knowing Me, Knowing You, Country House

=head2 Batching and collecting: Ekorn::Pipeline::Stages::Batch

C<batch> and C<collect> hold values and pass them on together: C<batch>
a few at a time, as for pages, or inserts of a hundred rows each, and
C<collect> all of them once they've all come, for what needs them all,
such as a sort or a total. Both give up what they hold in their flush,
once the values run out, so none is lost.

    my $pages = Ekorn::Pipeline->new(sub { $_->{title} }, batch(4));
    say join ' / ', @$_ for $pages->(@tracks);
    # Dancing Queen / Knowing Me, Knowing You / Girls & Boys / Parklife
    # Sunshine of Your Love / Country House

    my $most_played = Ekorn::Pipeline->new(
        collect { sort { $b->{plays} <=> $a->{plays} } @_ },
        sub { $_->{title} },
        take(2),
    );
    say join ', ', $most_played->(@tracks);    # Dancing Queen, Sunshine of Your Love

C<collect> holds every value until the end, so the whole result is in
memory at once; C<batch> holds no more than one batch. What either gives
is made from many values, so has no original (see L<Stages that hold
values back|/"Stages that hold values back">).

=head2 Taps: Ekorn::Pipeline::Stages::Taps

Taps look at each value as it goes by, and pass it on unchanged, for
logging, counting or debugging. C<peek> and C<count_into> each do one
thing; C<dump_to> writes each value out, its secrets redacted; and
C<tee> takes stages, so a tap can be anything a pipeline can do.

    my $count;
    my @titles = Ekorn::Pipeline->new(
        take_if { $_->{artist} eq 'Blur' },
        count_into(\$count),
        peek { say "  queued $_->{title}" },
        sub { $_->{title} },
    )->(@tracks);
    say "$count by Blur";
    #   queued Girls & Boys
    #   queued Parklife
    #   queued Country House
    # 3 by Blur

C<count_into> sets its count to 0 as each run starts, so after a run it
holds how many values went by in that run, even if none did.

=head3 dump_to

C<dump_to> is for seeing values as they are, while debugging. It
writes each with Data::Dumper, keys sorted and indented by two.

When L<Text::Redact::Secrets|https://metacpan.org/pod/Text::Redact::Secrets>
is installed, a v1.x, each secret it finds in what's written, such as
a password, a token or the password in a DSN, is written as
C<*REDACTED*>:

    my $dsn = join '', 'postgres://app:', 'Zq8vR2mX', 'kP4wL9nT', '@db/app';
    Ekorn::Pipeline->new(dump_to)->({dsn => $dsn});
    # {
    #   'dsn' => 'postgres://app:*REDACTED*@db/app'
    # }

Only the dump is redacted: the value passed on is as it came. Without
the module, values are written as they are, and it isn't a dependency:
C<cpanfile> recommends it, so installers that take recommendations
install it.

The module is looked for once, at the first dump, and tested then: it
must load, be a v1.x, the versions whose C<redact> C<dump_to> knows, and
redact a few made-up secrets in a dump, a password, a DSN's password
and an AWS access key id. The answer is kept for the process. If the
module is there but fails any of these, C<dump_to> croaks, on that dump
and each after, rather than write a dump that may hold secrets, saying
why, and how to dump without redacting. A broken redactor would
otherwise let secrets through as if they were safe.

To write secrets as they are, set
C<$Ekorn::Pipeline::Stages::Taps::DumpSecrets> true, with C<local>, for
as long as you need it:

    {
        local $Ekorn::Pipeline::Stages::Taps::DumpSecrets = 1;
        $pipeline->(@rows);
    }

It's read as each value is dumped, not when the stage is made, so a
C<local> around a run, or set in a stage before C<dump_to>, takes effect.
While it's true, the module is neither loaded nor tested. It's
C<dump_to>'s alone.

It's for debugging. Text::Redact::Secrets finds the secrets its rules
know, not every secret, so a dump can still hold some. It doesn't
escape control characters in strings, so a value from outside can send
escape sequences to a terminal.

=head3 tee

Where C<peek> does one thing with each value, a tee's branch can look
only at some values, or the first few, batch them, total them when the
values run out, or write them through a sink:

    my @hits;
    my @titles = Ekorn::Pipeline->new(
        tee(take_if { $_ > 6000 }, take(2), sub { push @hits, $_; () }),
        sub { "$_ plays" },
    )->(9100, 4200, 6100, 5800, 7700);
    say scalar @titles, ' titles; first hits: ', join ', ', @hits;    # 5 titles; first hits: 9100, 6100

The branch is one run of its own, beside the main run, fed a value at
a time by a L<feed|/"feed"> the tee makes for each main run. So the
branch's stages see every value the tee does, in order, and keep
their state across them; each main run gets a fresh branch.

=over 4

=item *

B<A stop> in the branch, such as C<take(2)>'s, ends only the branch.
The tee passes the values after it on, without running them through
the branch.

=item *

B<A death> in the branch kills the main run, as any stage's error
does. Its message names the tee's stage, then, within it, the
branch's, as below.

=item *

B<The branch's flushes> are called in the tee's flush, which closes
the branch: once the main run's values have run out, before the
stages after the tee are flushed. A total, a last batch or a sink's
result is given then, as below. If a stop after the tee ends the
main run first, such as C<take>'s or an iterator's C<first>, the tee's
flush isn't called, so the tee closes the branch in its end: a stop
ends the branch's input as much as running out would, so a writer in
the branch keeps what it holds. That's new in v0.3.10; before, the
branch's flushes weren't called, and what they held was lost. A
branch's flush that dies there kills the run, as an end that dies
does.

=item *

B<The branch's ends> are called as its run ends, each told how it
ended from where it stands: in the push that met a stop or a death
in the branch; or as the tee closes it, in its flush or its end. If
the main run died, the tee's end doesn't close the branch, but
finishes it, its flushes not called, and its ends told C<stopped>, as
the branch's input was cut short, as they are for an iterator read
as a source by a run that dies.

=item *

B<The value itself> goes into the branch, not a copy, as it goes to
C<peek>'s block. A branch that changes a hash changes it for the main
run too.

=item *

B<The main run's context> is the branch's: in the branch,
C<run_context> gives what it gives in the main run, such as a
statement's columns.

=back

A death in the branch, its stage #2, of a tee given as stage #1:

    Pipeline stage #1 failed at app.pl line 12:
        Pipeline stage #2 failed at app.pl line 12:
            bad value

A branch totalling what it saw, in its flush:

    my $total = 0;
    my @values = Ekorn::Pipeline->new(
        tee(collect { $total += $_ for @_; () }),
        sub { $_ * 2 },
    )->(1 .. 4);
    say "@values; total $total";    # 2 4 6 8; total 10

Each value costs a push into the branch: about 1.3 microseconds a
value through a branch of one plain stage, against C<peek>'s 0.4, on
Perl 5.36. A tee has a flush and an end only if its branch needs
them, so a branch of plain stages leaves the main run on the plain
loop. A branch with a flush, such as C<batch>'s, puts the main run on
the full path, and costs about 2.2 microseconds a value. It's for
logging, debugging and side jobs, not a hot loop.

=head1 Sources: Ekorn::Pipeline::Sources

Ready-made sources, needing nothing beyond Perl, for
L<iterator|/"iterator">: the values you give, numbers counting on
without end, and the records of a file or a filehandle. Each is made
afresh for each run, so each run reads from the start. Nothing is
exported by default.

    use Ekorn::Pipeline::Sources qw(from_array from_fh from_file counter);
    use Ekorn::Pipeline::Sources qw(:all);

A file is read only as far as the stages want, and closed as the run
ends, however it ends; C<counter> needs a stage that stops, such as
C<take>, as it never runs out:

    my $next = Ekorn::Pipeline->new(take(2))->iterator(from_file('setlist.txt'));
    # reads two lines, then closes the file

    my @offsets = Ekorn::Pipeline->new(take(3))->iterator(counter(0, 20))->all;
    say "@offsets";    # 0 20 40

C<from_array> makes a source of values you already have, for code that
wants one, such as a chain (see
L<Operators|/"Operators: Ekorn::Pipeline::Operators">). A hash's pairs are
C<from_array(map { [$_, $hash{$_}] } keys %hash)>.

C<from_fh> and C<from_file> read with C<$/> as it is at each read, as
C<readline> does, so a caller can read a file's paragraphs, or records
of their own, by setting it while they pull:

    local $/ = '';    # paragraph mode
    my $next = Ekorn::Pipeline->new(take(3))->iterator(from_file('lyrics.txt'));
    while (my($verse) = $next->()) { say "$verse\n" }    # the first three verses

With C<$/> undefined, both slurp: what's left is one record, and an
empty file gives none, though Perl's C<readline> gives one empty
string. A binary file is read with C<':raw'> and records of a fixed
size, C<local $/ = \4096>, which C<chomp> leaves whole.

C<from_file> opens its file as the run starts, and croaks "Can't read
%s: %s" there if it can't. Without layers, Perl opens it as it does by
default, which on Windows translates line endings, and so corrupts a
binary file. C<from_fh> croaks "Expected an open filehandle" given
anything else, and C<counter> "Expected a number to start from, and one
to step by".

=head1 Sinks: Ekorn::Pipeline::Sinks

Ready-made sinks, usually given last in a pipeline, so that a sink's
result is what the run gives (see L<Sinks|/"Sinks: Ekorn::Pipeline::Sink">).
Each is made afresh for each run. Nothing is exported by default.

    use Ekorn::Pipeline::Sinks qw(keep_all count_items keep_first);
    use Ekorn::Pipeline::Sinks qw(:all);

They come in two families. Those named for what they give, an item
being a value, have names that can't clash with Perl's built-ins or
List::Util's, which is why they're C<keep_first> and C<keep_all>, not
C<first> and C<all>. The containers, named for where the items go, are
the C<to_> sinks, each the counterpart of a C<from_> source: what one
reads, the other writes.

The first family keeps what's wanted, or counts it. One that needs no
more items, as C<keep_first> and C<keep($n)> don't once they have
theirs, stops the pull, so the source is read no further, and is told
C<done>: it decided the run had enough. The source and the stages
before it are told C<stopped>.

    my $blur = Ekorn::Pipeline->new(take_if { $_->{artist} eq 'Blur' }, sub { $_->{title} });
    say scalar pipeline($blur, keep_first)->(@tracks);     # Girls & Boys
    say scalar pipeline($blur, keep_last)->(@tracks);      # Country House
    say scalar pipeline($blur, count_items)->(@tracks);    # 3
    say join ', ', pipeline($blur, keep(2))->(@tracks);    # Girls & Boys, Parklife

Asked for one value, in scalar context, a sink giving a list gives it
as an array reference; for how many, use C<count_items>:

    my $p = Ekorn::Pipeline->new(
        sub { $_->{title} },
        keep_all,
    );
    my @titles = $p->(@tracks);    # every title
    my $titles = $p->(@tracks);    # every title, as an array reference

An array reference is true even when it's empty, so test for no items
with C<@$titles>, or use C<count_items>.

C<from_fh> and C<from_file> remove C<$/> from each record, and C<to_fh> and
C<to_file> add it back, so a file read with one is written unchanged by
the other. With C<$/> undefined, or a reference to a record size, they
add nothing; with it empty, for paragraphs, a blank line:

    my $copied = Ekorn::Pipeline->new(to_file('copy.txt'))->iterator(from_file('original.txt'))->();

There's no sink for an array or a hash: C<keep_all> gives every item,
and C<< push @mine, @{ $p->(@values) } >> adds them to your array. A hash
is assigned from a list of keys and values, so to key values by
something of their own, give each one's key and value from a stage:

    my %by_title = Ekorn::Pipeline->new(sub { ($_->{title}, $_) })->(@tracks);

C<to_fh> croaks "Expected an open filehandle" given anything else.
C<to_file> opens its file, emptied, as the run starts, and croaks "Can't
write %s: %s" if it can't, as both do if they can't write, and
C<to_file> if it can't close the file. Each sink taking no arguments has
an empty prototype, so C<count_items + 0> reads as C<count_items() + 0>.

=head1 JSON: Ekorn::Pipeline::JSON

Four functions, one for each direction and format, each making a
different part by its options: given a C<file> or an C<fh>, a C<from_>
function makes a source and a C<to_> function a sink; given neither,
each makes a stage. Each part is made afresh for each run. Nothing is
exported by default.

    use Ekorn::Pipeline::JSON qw(from_json from_jsonl to_json to_jsonl);
    use Ekorn::Pipeline::Tooling qw(:json);    # the same

The C<json> functions read and write one JSON document; the C<jsonl>
functions JSON Lines, also called NDJSON. A stage passes on what a file
of its format would hold, so each C<to_> function's stage is undone by
its C<from_> function's:

    my @lines = Ekorn::Pipeline->new(
        sub { {title => $_->{title}, plays => $_->{plays}} },
        to_jsonl(json => {canonical => 1}),
    )->(@tracks[0, 1]);
    say for @lines;
    # {"plays":9100,"title":"Dancing Queen"}
    # {"plays":4200,"title":"Knowing Me, Knowing You"}

    my @titles = Ekorn::Pipeline->new(from_jsonl(), sub { $_->{title} })->(@lines);
    say join ', ', @titles;    # Dancing Queen, Knowing Me, Knowing You

C<from_json> reads its input whole, and croaks if it holds more than
one document, pointing to C<from_jsonl>. C<from_jsonl> keeps an array as
one value, and reads documents simply written one after another, on a
line or not, as it reads lines.

The encoder is JSON::MaybeXS's: Cpanel::JSON::XS where it's installed,
JSON::PP otherwise. Text is UTF-8 bytes, as C<encode_json> and
C<decode_json> have it, and files are opened C<:raw>.

=over 4

=item C<file>

the path of a file to read or write; opened as the run starts, emptied if it's written, and closed once the run ends, however it ended

=item C<fh>

an open filehandle, which is left open; C<:raw>, as the text is bytes

=item C<json>

a hash reference of options for C<< JSON::MaybeXS->new >>, over the defaults C<utf8> and C<allow_nonref>, such as C<< {canonical => 1} >>; or an encoder object of your own, used as it is

=back

An encoder that indents, such as with C<pretty>, has each value indented
in C<to_json>'s array; C<to_jsonl> croaks given one, as JSON Lines can't
be indented.

    my $count = Ekorn::Pipeline->new(
        sub { {title => $_->{title}} },
        to_json(file => 'titles.json'),
    )->(@tracks);    # 6, written as one array
    my @titles = Ekorn::Pipeline->new(sub { $_->{title} })->iterator(from_json(file => 'titles.json'))->all;

An encoder object reading a source, or decoding in C<from_jsonl>'s
stage, has its incremental parser reset for each run, so mustn't serve
two at once. JSON.pm exports a C<from_json> and a C<to_json> of its own
by default: a module using both imports one under another name, or
calls it by its full name.

=head1 CSV: Ekorn::Pipeline::CSV

Two functions, one for each direction, each making a different part by
its options, as JSON's do: given a C<file> or an C<fh>, C<from_csv> makes
a source and C<to_csv> a sink; given neither, each makes a stage. Each
part is made afresh for each run, so a source read twice reads its
header twice. Nothing is exported by default. Both are new in v0.3.10.

    use Ekorn::Pipeline::CSV qw(from_csv to_csv);
    use Ekorn::Pipeline::Tooling qw(:csv);    # the same

Rows are array references of their fields, or, with a C<header>, hash
references keyed by its names. A header read from a file gives the
run's context its C<columns>, as DBIx::Squirrel's statements do, and
C<to_csv>'s C<< header => 1 >> writes them back, in their order:

    my $written = Ekorn::Pipeline->new(
        to_csv(file => 'tracks.csv', header => [qw(title artist plays)]),
    )->(@tracks);    # 6

    my @blur = Ekorn::Pipeline->new(sub { $_->{artist} eq 'Blur' ? $_->{title} : () })
        ->iterator(from_csv(file => 'tracks.csv', header => 1))->all;
    say join ', ', @blur;    # Girls & Boys, Parklife, Country House

    my($copied) = Ekorn::Pipeline->new(
        take_if { $_->{plays} > 6000 },
        to_csv(file => 'hits.csv', header => 1),
    )->iterator(from_csv(file => 'tracks.csv', header => 1))->all;    # 3, under title,artist,plays

Given no file, C<to_csv>'s stage passes on each row's line, without its
end of line, and C<from_csv>'s parses each value, a text of any number
of rows, as a quoted field may hold a newline. Fields are quoted as
Text::CSV quotes them, those with a space among them:

    my @lines = Ekorn::Pipeline->new(to_csv(header => [qw(title plays)]))->(@tracks[0, 1]);
    say for @lines;
    # title,plays
    # "Dancing Queen",9100
    # "Knowing Me, Knowing You",4200

The parser is Text::CSV's: Text::CSV_XS where it's installed,
Text::CSV_PP otherwise. Ekorn only recommends Text::CSV, so the module
loads without it, and C<from_csv> and C<to_csv> croak when called if it
isn't installed. A file's text is UTF-8 unless C<encoding> says, so its
fields are characters; text that won't decode, a character the
encoding can't hold, and a row that won't parse each croak at its row,
saying where. A byte order mark that starts the input is dropped.

=over 4

=item C<file>

the path of a file to read or write; opened as the run starts, emptied if it's written, and closed once the run ends, however it ended

=item C<fh>

an open filehandle, read or written with its own layers, and left open

=item C<csv>

a hash reference of options for C<< Text::CSV->new >>, over the defaults C<binary> on and C<auto_diag> off, such as C<< {sep_char => "\t"} >> for TSV; or a parser object of your own, used as it is

=item C<header>

reading: false, every row data, as arrays; true, the first row names each row's fields, as hashes; C<'skip'>, the first row dropped, rows as arrays. Writing: false, no header, rows as arrays; an array reference of names, written first, ordering a hash's fields; true, the names from the run's context's C<columns>

=item C<munge>

reading, with a header: C<none>, the default, C<lc>, C<uc>, or C<db>, which makes C<Track Name> C<track_name>; a hash reference mapping names; or a code reference given each name, as C<$_> too, as Text::CSV's C<munge_column_names>

=item C<encoding>

a file's encoding, as Encode names it, C<UTF-8> by default, or C<raw>, for bytes as they are

=back

A header naming a column twice croaks, when rows are hashes, as one
field's value would be lost; C<munge> can name columns apart, and runs
first. A short row's missing fields are C<undef>, and a long row's extra
fields are dropped.

=head1 Operators: Ekorn::Pipeline::Operators

    use Ekorn::Pipeline::Operators;

It puts C<|>, C<|=> and C<@{}> in force for Ekorn's sources, stages,
gathers and chains, for the rest of the scope it's used in;
C<no Ekorn::Pipeline::Operators> takes them out again. Written where
they're not in force, they croak: "Expected use
Ekorn::Pipeline::Operators in scope". They're a shorthand for the
commonest shapes, not the whole of Ekorn: a pipeline made with C<new>
can have stages after a sink, give a list as a list, and, pulled with
C<iterator>, be a source that gives a sink's result, none of which a
chain can.

=over 4

=item C<$stage | $stage>

a chain of both stages: a pipeline, which C<|> can extend, and which goes wherever a pipeline does

=item C<$source | $stage>

a source: the source's values, through the stage

=item C<$source | ... | $sink>

the sink's result, at once, not a source; for a source of the result, use C<iterator>

=item C<$chain |= $stage>

a new chain with the stage added, put in the variable

=item C<@{ $source }>

every value the source gives, read through anew each time (see L<C<@{}>|/"@{} reads a source through">)

=back

B<A chain starts with one of the types,> a source or a stage made
with a word, or ready-made. What follows can be anything that goes
where a stage goes, a plain code reference or a package's own part.
Started with a plain code reference, C<sub { ... } | sub { ... }> is
Perl's bitwise OR of two addresses: a meaningless number, with no
error. So start a chain with C<stage { uc }>, never C<sub { uc }>. A
pipeline made with C<new> has no operators.

A package's own source class chains as Ekorn's do by overloading C<|>
with C<Ekorn::Pipeline::Operators::chain>, and C<@{}> with
C<Ekorn::Pipeline::Operators::drain> (see L<Delivering parts for
Ekorn|/"Delivering parts for Ekorn">).

C<|> binds more loosely than C<.> and C<+>, so put a chain inside a larger
expression in parentheses.

An operator gives one scalar, so a chain ending in a sink gives one
value: the result of a sink of one, such as C<count_items>, or the list
of a sink of many, such as C<keep_all>, as an array reference. Nothing
can be chained after a sink: a chain ending in one has already run,
and gives its result.

    my $n      = $source | count_items;          # a number
    my $titles = $source | keep_all;             # an array reference
    my @titles = @{ $source | keep_all };        # a list

As C<|> gives one value, a list assignment from a chain gets one
element: C<my @titles = $source | keep_all> is the array reference
alone. Dereference it, as above.

Keep a chain's result, even one run for what its sink does:
C<my $copied = $source | to_file($path)>. Written as a statement of its
own, the chain runs, but Perl warns "Useless use of numeric bitwise or
(|) in void context", as it compiles the line, which Ekorn can't stop.

=head2 C<@{}> reads a source through

C<@{ $source }> gives every value a source gives, with no sink. It looks
like a dereference, but a source holds no array. Perl lets a class say
what C<@{ $object }> means, with a function returning an array
reference, which Perl then dereferences. Ekorn's runs the source from
its start, collects every value into a new array, and returns a
reference to it. So:

=over 4

=item *

B<Each use is a run of its own,> reading the source to its end.
C<< $source->[0] >>, C<scalar @$source> and C<$#$source> read every value,
to give one value, a count or an index; two uses read it twice.

=item *

**C<for (@$source)> reads every value before the loop starts.** Pull
from an iterator to take each as it comes.

=item *

B<An iterator is one run,> so it's read through once, and croaks
the second time: "Expected a source with values still to give".

=item *

B<Only a source has it.> On a stage, or a chain of stages, Perl
says "Not an ARRAY reference"; a chain ending in a sink is already
its result, so C<@{ $source | count_items }> dereferences a number.

=item *

**C<@{ $source | keep_all }> is Perl's own dereference,** of the
array reference the sink gave.

=back

What to write, by what's wanted:

=over 4

=item every value, as a reference

B<Write:> C<my $all = $source | keep_all>

B<Rather than:> C<my @all = $source | keep_all>, one element

=item every value, as a list

B<Write:> C<my @all = @{ $source | keep_all }>, or C<@{$source}>

=item the first value

B<Write:> C<$source | keep_first>, reading one

B<Rather than:> C<< $source->[0] >>, reading them all

=item how many

B<Write:> C<$source | count_items>

B<Rather than:> C<scalar @$source>, keeping every value to count them

=item the first few

B<Write:> C<$source | take(5) | keep_all>

B<Rather than:> C<(@$source)[0 .. 4]>, reading them all

=item every value, added to your array

B<Write:> C<push @mine, @{ $source | keep_all }>

=item each, as it comes

B<Write:> C<< my $next = Ekorn::Pipeline->new->iterator($source) >>, then C<< while (my ($value) = $next->()) {...} >>

B<Rather than:> C<for (@$source) {...}>, reading them all first

=back

    my @all   = @{$source};               # every value
    my $first = $source | keep_first;     # the first, reading only one
    my $next  = Ekorn::Pipeline->new->iterator($source);
    while (my ($value) = $next->()) {     # each, as it comes
        say $value;
    }

=head1 Errors: Ekorn::Pipeline::Errors

=head2 When a stage dies

A stage, or a flush, that dies with a message is named by its
position, counting from 1 (C<#2.3> for one inside a pipeline given as a
stage). It's reported at the line that ran the pipeline: the call of
the pipeline, or of the iterator that asked for the result. The
message it died with follows, indented by four spaces:

    Pipeline stage #2 failed at app.pl line 12:
        No name for user 7 at app.pl line 9.

A stage within a named pipeline, or of the named pipeline run, is
named with it too: after its position, the innermost named pipeline
it's in, by its L<name|/"Named pipelines">, and its position there. The second
stage of the pipeline named C<clean>, given as the first stage, is:

    Pipeline stage #1.2 (main::clean#2) failed at app.pl line 12:

It's the name the pipeline has when the stage dies. An end that dies
is named the same way, as "Pipeline end of stage #1.2 (main::clean#2)
failed at ...". Before v0.3.0, a stage was named by its position
alone.

An exception object, such as a stop or an object of a class of your
own, is thrown again unchanged, so code that catches it can tell it by
its class.

Either way, the run has ended. Every end is called, told C<died>, and
then the error is thrown again. A pushed run returns nothing. An
iterator returns an empty list on every call after, without calling
its source or any flush again (see L<iterator|/"iterator">).

An end that dies is named the same way, as the end of C<the source> or
of a stage, in "Pipeline end of stage #2 failed at ...". In a run
already dying, it's a warning instead, and the run's own error is
thrown (see L<Flushes and ends|/"Flushes and ends">).

A mistake in making a pipeline, such as a stage that's neither a code
reference nor a pipeline, or in making a canned stage, such as
C<take(-1)>, is reported at the line that made it, before any value goes
through.

=head2 croakf

C<croakf> is for modules of stages outside Ekorn::Pipeline too. Called
from a function that makes a stage, it reports a mistake at the line
that called the function, where the mistake was made, with nothing
more to set up:

    package My::Stages::Text {
        use Ekorn::Pipeline::Errors qw(croakf);

        # Pass on each title cut to $length characters.
        sub shortened ($length) {
            croakf 'Expected a length of 1 or more, not %s', $length // 'undef'
                unless defined $length && $length =~ m( \A [1-9] \d* \z )xa;
            return sub ($title) { substr $title, 0, $length };
        }
    }

    say join ', ', Ekorn::Pipeline->new(sub { $_->{title} }, My::Stages::Text::shortened(8))->(@tracks[0 .. 2]);
    # Dancing , Knowing , Girls & 
    my $p = Ekorn::Pipeline->new(My::Stages::Text::shortened(0));
    # Expected a length of 1 or more, not 0 at app.pl line 14.

A C<%> in the message is written C<%%>. Write the format as a literal in
the code. Values go in as arguments,
through C<%s> and the like, never in the format. A format made from
data does whatever its C<%> directives say: C<%999999999s> makes a
string of a gigabyte.

=head2 @INTERNAL and @CARP_NOT

    our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

C<@Ekorn::Pipeline::Errors::INTERNAL> lists the packages of
Ekorn::Pipeline. Each of its modules that croaks uses the list as its
C<@CARP_NOT>, so Carp looks past all of them to the first line outside,
in the user's code.

A package that puts the list in its own C<@CARP_NOT> is looked past
too:

=over 4

=item *

B<A module of functions that take stages> runs its callers' stages.
With the list, their errors are reported at its callers' lines, not
at the module's own line that ran the pipeline. DBIx::Squirrel does
this.

=item *

B<A module of stages whose helpers are in another package> puts
that package in its C<@CARP_NOT>, and the helpers' package puts the
module's. Then C<croakf> in a helper reports at the line that called
the module. A helper in the same package needs nothing.

=back

=head1 Which result: Ekorn::Pipeline::Context

Each run counts the results it makes, and keeps the value each is
being made from, so a stage can ask which result it's making, and
from what. A I<result> is a value that leaves the last stage, or that
reaches a sink. C<result_number> is the run's results so far, plus one,
and C<result_original> the value the run's source gave, or that was
pushed, before any stage changed it:

    use Ekorn::Pipeline::Context qw(result_number result_original);
    use Ekorn::Pipeline::Tooling qw(:context);    # the same, from v0.3.15

    my @hits = Ekorn::Pipeline->new(
        sub { $_->{plays} > 6000 ? $_ : () },
        sub { result_number . ". $_->{title}" },
    )->(@tracks);    # 1. Dancing Queen, 2. Girls & Boys, 3. Sunshine of Your Love

    my @titles = Ekorn::Pipeline->new(
        sub { $_->{plays} },
        sub { $_ > 6000 ? result_original->{title} : () },
    )->(@tracks);    # Dancing Queen, Girls & Boys, Sunshine of Your Love

=over 4

=item *

B<A bare call is a term,> as a constant is: each takes no
arguments, and has an empty prototype, so C<result_number + 1> adds
one, and C<result_original // 'none'> gives C<'none'> where there's
none. In v0.3.11, C<result_number + 1> died with "Too many
arguments".

=item *

B<A value dropped makes no result,> so the number stays the same
while a stage drops values.

=item *

B<Each value a stage returns in place of one is a result of its
own,> numbered one after another, each with the original of the
value it was made from. So is each value a stop carries.

=item *

B<A flush's values have no original,> unless its stage holds values
back and says where each came from, as below. In a flush,
C<result_number> is the number of the first value it returns, and
C<result_original> is undef there and in the stages after it, for the
values it gives.

=item *

B<Each run counts its own,> from 1: a pipeline run inside a stage, a
tee's branch, and an iterator read as a source each count theirs,
and leave the count of the run around them as it was. For a run
reading an iterator, the original is the value the iterator handed
out, unless its source says otherwise, as below.

=item *

B<A source can give the original itself,> with an C<original> part,
a code reference returning the original of the value it gave last,
such as the row a statement fetched. C<result_original> then gives
what that says, calling it only when asked, and a run reading an
iterator of that source's run gets it too, so it reaches every
pipeline in a chain. A flush's values have none, whatever it says,
unless a stage that holds values back says where they came from.
The part answers for the value the source gave last, which is the
one the stages are working from, as values a stage returns several
of go through the stages before the next is pulled; but a source
whose step returns several values at once has it answer for the
last of them. A stage that holds values back asks it as each value
arrives, as below. New in v0.3.13.

=item *

B<They're for stages,> their flushes and sinks. Outside a run, and
in an end, both give undef. In a source's step, they give where the
run reading it has got to, which isn't promised.

=item *

B<Every run counts,> whether its stages ask or not. It costs a
value about 15 to 75 nanoseconds, measured on Perl 5.36 and 5.44
through one stage that does nothing: 1 to 3% for C<all>, 3 to 12% for
a pushed run, and 6 to 8% for an iterator's C<next>, which counts once
a call. Less through stages that do work. Roadmap 2026-0046's record
has the measurements.

=back

A batch is made from many values, so has no original, whether its step
or its flush gives it; C<take_last>'s value is the last it was given,
and has that value's:

    say join '; ', Ekorn::Pipeline->new(
        batch(4),
        sub { result_number . ': ' . @$_ . ' tracks, ' . (result_original // 'from many') },
    )->(@tracks);
    # 1: 4 tracks, from many; 2: 2 tracks, from many

    say Ekorn::Pipeline->new(
        sub { $_->{title} },
        take_last,
        sub { "$_, by " . result_original->{artist} },
    )->(@tracks);
    # Country House, by Blur

Until v0.5.0, a batch filled by a value had that value's original, and
C<take_last>'s value had none, as a flush's.

The run's context is asked with
L<C<run_context>|/"Stages that ask about their run">, and whether a
value came from a flush with L<C<ending>|/"ending">. DBIx::Squirrel has
the same functions under the same names, from its v3.6.1, its rows
carried through chains by its source's original, so a program
importing both Toolings gets one of each.

=head2 Stages that hold values back

A stage that maps gives what it made from the value it was just given,
so the run knows where each value came from. A stage that holds values
back, to give them later, as C<take_last>, C<batch> and a stage running
values in other processes do, gives values the run has gone past, so
only it knows which value each came from. It says so, and says which:

=over 4

=item *

**C<< holds => 1 >>** among its parts, by name (see L<Made for a
run|/"Made for a run">), says it holds values back.

=item *

**C<kept_origin>,** called in its step as it keeps a value, returns the
value's I<origin>: an opaque object holding what C<result_original>
answers for the value then, as later its source may answer for
another. The stage keeps the origin with the value.

=item *

**C<< $origin->gives(@values) >>** marks what it made from that value, as
it gives it, from its step, its flush or carried by its stop. The
stages after it get each value unmarked, with its own original.

=item *

B<A value it gives unmarked has none,> as made from many values, as
a batch is.

=back

    use Ekorn::Pipeline::Context qw(kept_origin result_original);

    # Each value, given only once the next has come: one behind.
    sub one_behind () {
        return gather {
            my @held;    # [value, origin]
            my $give = sub ($held) { $held->[1]->gives($held->[0]) };
            return {
                step => sub ($track) {
                    push @held, [$track, kept_origin];
                    return @held > 1 ? $give->(shift @held) : ();
                },
                flush => sub () { map { $give->($_) } splice @held },
                holds => 1,
            };
        };
    }

    say join ', ', Ekorn::Pipeline->new(
        sub { $_->{title} },
        one_behind(),
        sub { "$_ (" . result_original->{artist} . ')' },
    )->(@tracks[0 .. 2]);
    # Dancing Queen (ABBA), Knowing Me, Knowing You (ABBA), Girls & Boys (Blur)

=over 4

=item *

B<A value and where it came from go together,> in the one return,
so the two can't come apart, and a stage that keeps no origin, as
C<batch> doesn't, captures nothing.

=item *

B<The origin is captured as the value arrives,> in the step it was
given it in, so a source's original part, which answers for the
value it gave last, is asked for it then, and only by a stage that
holds values back: a pipeline of maps asks nothing.

=item *

B<Only what it gives is unmarked,> not a marked value inside a
structure it gives, which goes on as an
C<Ekorn::Pipeline::Origin::Given> object.

=item *

**C<kept_origin> works only in a run with a stage that holds values
back,** and croaks elsewhere, a run nested inside such a stage's
step included: "Expected kept_origin in the step of a stage that
holds values back". It doesn't tell one stage of the run from
another, so a stage that doesn't hold values back mustn't call it;
and in a flush, which has no value, it gives an origin of nothing.

=item *

B<A stage that holds values back but doesn't say so> is taken for
one that maps, as every stage was before v0.5.0: the stages after it
see the original of the value the run got to last, not of the value
theirs was made from.

=item *

B<It costs a run with such a stage> a check for what each stage
gave, and the capture of each value kept. Roadmap 2026-0060's record
has the measurements. A run without one takes the shorter way, or
pays a few checks a value. New in v0.5.0.

=back

=head1 Writing stages

Write a stage for others the way the canned stages are written, so it
works alongside them.

=over 4

=item *

B<Write a function that makes the stage.> A plain C<sub> is a stage,
but for one others will use, write a function that returns it, as
C<take(10)> does. The function can take options, and check them once,
when it's called, not on each value.

=item *

B<Report mistakes at the caller's line> with C<croakf> (see
L<croakf|/"croakf">), using a literal format and passing the values as
arguments. Start with "Expected" and say what was expected, as the
canned stages do: "Expected a count of 0 or more".

=item *

B<One argument in, a list out.> The stage gets one value, in C<$_>
and as its argument. It returns an empty list to drop it, one value
to pass it on, or several. A stage run for its side effects returns
the value.

=item *

B<Don't change the value you're given,> unless that's the stage's
documented job.

=item *

**Keep state in C<gather>,** even a count, so it starts afresh on each
run and two runs at once don't share it.

=item *

B<Give up held values in a flush.> It's called even when there were
no values, with no arguments and C<$_> undefined.

=item *

B<Say where held values came from.> A stage that holds values back
says C<< holds => 1 >>, keeps an origin for each value it keeps, and
gives what it made from it marked, so the stages after it get the
right original (see L<Stages that hold values
back|/"Stages that hold values back">).

=item *

B<Close what you open in an end,> which is told how the run ended,
however it ended, rather than in a flush, which isn't called when
the run stops before the stage, or dies.

=item *

B<Stop when no more values are wanted,> with C<Stop>, so an iterator
reads no more. Pass the last value on with the stop, as C<take> does,
so the source isn't asked for one more than is needed.

=item *

B<Throw stops again.> A stage that catches errors should throw a
stop again with C<die $e if $e isa 'Ekorn::Pipeline::Stop';>.

=item *

B<Document what the stage takes and gives:> what kind of value it
expects, what it passes on, whether it holds values or stops, and
what it croaks with.

=item *

B<Names.> A name says what the stage does to a value. A tap's name
says it passes values on, as C<peek> and C<count_into> do. Avoid names
that common modules export: Flow has C<drop>, not C<skip>, because
Test2::V0 and Test::More both export C<skip>. Test2::V0 also exports
names such as C<field>, C<item> and C<call>.

=item *

B<Exports.> Export the stages a module is mostly used for by
default, in C<@EXPORT>. Put the rest in C<@EXPORT_OK>, and all of them
in an C<:all> tag.

=item *

B<Where it goes.> Stages for any values go under
C<Ekorn::Pipeline::Stages::*>. Stages for one kind of value or one
source go under the namespace of the module that knows about it. For
example, DBIx::Squirrel's stages for rows are in
C<DBIx::Squirrel::Stages::Rows>.

=item *

B<Tests.> Calling a pipeline with values tests a stage with nothing
else to set up. Run it twice, to show it starts afresh. Run it with
no values, to show what its flush gives. And run it through an
iterator, counting the source's calls, to show that a stage that
stops reads no more than it should.

=back

    package My::Stages::Numbers {
        use Ekorn::Pipeline::Errors qw(croakf);
        use Ekorn::Pipeline::Gather qw(gather);
        use Ekorn::Pipeline::Stop qw();

        # Pass on values until their sum would pass $limit, then stop.
        sub sum_up_to ($limit) {
            croakf 'Expected a number for the limit, not %s', $limit // 'undef'
                unless defined $limit && $limit =~ m( \A -? \d+ (?: \.\d+ )? \z )xa;
            return gather {
                my $sum = 0;    # this run's
                return sub ($n) {
                    Ekorn::Pipeline::Stop->throw if $sum + $n > $limit;
                    $sum += $n;
                    return $n;
                };
            };
        }
    }

    say join ' ', Ekorn::Pipeline->new(My::Stages::Numbers::sum_up_to(10))->(4, 3, 2, 5, 1);    # 4 3 2

=head1 Writing functions that take stages

=over 4

=item *

B<Take the stages last,> after the function's own arguments, as in
C<sub lines_of ($file, @stages)>. A caller who wants nothing done
passes no stages.

=item *

B<Push what you have; pull what you make.> Call the pipeline with
values already in memory. For values made one at a time, give
C<iterator> a source and return the iterator. Then a stage that stops
saves the work of making the rest.

=item *

B<Let stages do the optional work.> A stage can already filter,
reshape or limit what's returned, so don't add options for it. Keep
the arguments only the function can act on, such as which file to
read.

=item *

B<Say what the first stage is given.> If the function puts stages
of its own before its caller's, say so: error messages count them in
the stages' positions.

=item *

B<Report errors at your callers' lines,> by putting
C<@Ekorn::Pipeline::Errors::INTERNAL> in the module's C<@CARP_NOT>.

=item *

**Find the stages with C<is_stage>,** if the function takes a list
of values of its own before them, so that callers can pass a
pipeline as a stage, as they can to C<new>. The values mustn't be
code references or pipelines themselves, or the last of them would
be taken for stages.

=item *

**Test C<is_stage> before C<is_hashref>,** if the function takes a
hash reference of options before its stages. A pipeline is a blessed
hash, so C<is_hashref> (or C<reftype($x) eq 'HASH'>) is true of it
too, and a pipeline would be taken for the options:
C<is_hashref($x) && !is_stage($x)>. Ref::Util's C<is_plain_hashref>,
false for any blessed hash, avoids it too.

=item *

B<Take a pipeline given last as the stages,> if the function's
values can be code references, so that C<is_stage> can't tell them
from stages. A pipeline is never taken for a value by this rule, and
the caller makes one with C<pipeline>. Without one, there are no
stages.

=item *

B<Give a sink's result where the caller's stages end in a sink,> if
the function would otherwise return an iterator. C<is_sink> says
whether a pipeline ends in one, and which kind, so the function can
read the run itself, and return what the sink gave.

=back

    use Ekorn::Pipeline v0.1.3 qw(is_stage);

    # The values given, up to the stages at the end, through those stages.
    sub only (@args) {
        my @stages;
        unshift @stages, pop @args while @args && is_stage($args[-1]);
        return Ekorn::Pipeline->new(@stages)->(@args);
    }

    my $hits = Ekorn::Pipeline->new(take_if { $_->{plays} > 6000 }, sub { $_->{title} });
    say join ', ', only(
        @tracks,
        $hits,
        take(2),
    );
    # Dancing Queen, Girls & Boys

C<is_stage> is false for a string, even the name of a pipeline, so a
value such as C<'clean'> is never taken for a stage.

    package My::Files {
        use Ekorn::Pipeline;
        our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

        # The lines of a file, without their newlines, through the caller's stages.
        sub lines_of ($file, @stages) {
            open my $fh, '<', $file or die "Can't read $file: $!\n";
            return Ekorn::Pipeline->new(sub { s( \n \z )()xr }, @stages)
                ->iterator(sub { scalar(<$fh>) // () });
        }
    }

    my $text = "one\ntwo\nthree\n";
    my $next = My::Files::lines_of(\$text, sub { uc }, take(2));
    my @lines;
    while (my($line) = $next->()) { push @lines, $line }
    say "@lines";    # ONE TWO

    use Ekorn::Pipeline::Factories qw(pipeline);

    # What each callback returns, through the stages given last, as a pipeline.
    sub call_all (@callbacks) {
        my $stages = @callbacks && $callbacks[-1] isa 'Ekorn::Pipeline' ? pop @callbacks : pipeline();
        return $stages->(map { $_->() } @callbacks);
    }

    say join ' ', call_all(sub {1}, sub {2}, sub {3}, pipeline(
        sub { $_ * 10 },
        take(2),
    ));
    # 10 20

    use Ekorn::Pipeline v0.3.0 qw(is_sink);

    # The tracks by an artist, through the caller's stages: an iterator, or,
    # if the stages end in a sink, what the sink gives.
    sub tracks_by ($artist, @stages) {
        my $p    = Ekorn::Pipeline->new(take_if { $_->{artist} eq $artist }, @stages);
        my $next = $p->iterator(from_array(@tracks));
        my $sink = is_sink($p) or return $next;
        return $sink eq 'one' ? $next->first : $next->all;
    }

    say join ', ', tracks_by('ABBA', sub { $_->{title} })->all;    # Dancing Queen, Knowing Me, Knowing You
    say scalar tracks_by('Blur', count_items);    # 3
    say join ', ', tracks_by('Blur', sub { $_->{title} }, keep(2));    # Girls & Boys, Parklife

=head1 Delivering parts for Ekorn

For the author of a package that hands out values, such as
DBIx::Squirrel, or a module reading CSV or JSON. Use Ekorn as it is:
deliver sources, sinks and stages that keep its protocols, and let your
users run them in Ekorn's pipelines, with Ekorn's parts and their own.
Don't subclass Ekorn's classes, or wrap them. L<Making each kind of
part|/"Making each kind of part"> has what each piece is called with
and returns, with a worked example of each kind of part.

=head2 The protocols

A part of yours says what it can be by its methods. Each is called at
the start of a run, and returns closures sharing that run's state:

=over 4

=item C<EKORN_SOURCE>

B<Makes it:> a source, given to C<iterator>

B<Returns:> its step, called with nothing for the next value, or an empty list at the end; optionally its end, told how the run ended; and optionally a context, anything its stages may want to know about this run

=item C<EKORN_STAGE>

B<Makes it:> a stage with state for the run

B<Returns:> its step, called with each value, returning a list; optionally its flush, called when its input runs out; and optionally its end

=item C<EKORN_SINK_ONE>, C<EKORN_SINK_MANY>

B<Makes it:> a sink, giving one value or a list

B<Returns:> its step, called with each value, its return ignored; its flush, giving the result; and optionally its end

=back

Each returns its parts as a list, in the order the table gives, or by
name, as a hash reference with the keys C<step>, C<flush>, C<end>,
C<context> and C<original>, as a set-up does (see
L<Made for a run|/"Made for a run">).

The methods are named for Ekorn, so an object of yours with a method
of its own such as C<as_list> is never taken for a part. One object can
offer C<EKORN_SOURCE> and one of the others, as a table can be read from
and written to; offering more than one of C<EKORN_STAGE>,
C<EKORN_SINK_ONE> and C<EKORN_SINK_MANY> croaks where it's given as a
stage. A plain code reference is a source or a stage, wherever it's
given, with no end. None of these needs your package to load Ekorn.

    package My::Rows;

    sub EKORN_SOURCE ($self) {
        my $sth = $self->{sth};
        $sth->execute;    # this run's
        return {
            step    => sub ()     { $sth->fetchrow_arrayref // () },
            end     => sub ($how) { $sth->finish },
            context => {columns => $sth->{NAME}},    # what stages may ask
        };
    }

=head2 Stages that ask about their run

A stage that needs to know about the values' source, such as the
names of the columns its rows have, asks C<run_context> for the
context its run's source gave, here C<My::Rows>'s, above. So a stage
can take a column by its name, wherever it is in the row:

    sub pluck ($name) {
        return sub ($row) {
            my $columns = Ekorn::Pipeline::run_context()->{columns};
            my($at) = grep { $columns->[$_] eq $name } 0 .. $#$columns;
            return $row->[$at];
        };
    }

    my $titles = Ekorn::Pipeline->new(pluck('title'))->iterator(bless {sth => $sth}, 'My::Rows');

Each run has its own context, and an iterator used as a source passes
on the context of the run inside it. A pushed run has none, and a feed
none of its own: its stages see the context of the code pushing into
it. Which result a stage is making, and from what, it asks
L<Ekorn::Pipeline::Context|/"Which result: Ekorn::Pipeline::Context">.

=head2 C<|> for your sources

To let your users start a chain with your source, overload C<|>, and
C<@{}>, with Ekorn's own functions. Load Operators with an empty import
list, which defines them without putting the operators in force in
your own scope; without loading it, C<|> dies with "Undefined
subroutine" until something else does:

    use Ekorn::Pipeline::Operators ();
    use overload
        '|'   => \&Ekorn::Pipeline::Operators::chain,
        '@{}' => \&Ekorn::Pipeline::Operators::drain;

=head2 Functions that take stages

A function of yours that runs its own values through its caller's
stages finds them with C<is_stage>, or takes a pipeline given last, and
runs them with C<new>, as any user of Ekorn does (see L<Writing
functions that take stages|/"Writing functions that take stages">):

    sub each_row ($rows, @stages) {
        return Ekorn::Pipeline->new(@stages)->iterator($rows);
    }

=head2 Ekorn's functions, for your users

You can export Ekorn's functions to your users, such as C<Stop> or
C<take>, as they are, with Exporter, so they needn't C<use> two
packages. They're the same functions, so your users can mix yours and
Ekorn's freely.

=head2 Your errors

Put C<@Ekorn::Pipeline::Errors::INTERNAL> in your modules' C<@CARP_NOT>,
so a mistake is reported at your users' lines.

=head1 Making each kind of part

This section is for developers making parts for others: what each
part of a run is called with, what it must return, and a worked
example of each kind, made with a word and as a class of your own.
Each example runs as it stands, given
C<use Ekorn::Pipeline; use Ekorn::Pipeline::Tooling qw(:all);>, and its
comments say what it prints.

=head2 What each piece is called with, and returns

A part made for a run, whether by a word or by a role method, is a
set of pieces. The set-up makes them at the start of each run, and the
run calls them:

=over 4

=item B<set-up> (a word's block, or a role method)

B<When it's called:> once, at the start of each run, before any value

B<What it's given:> nothing; a role method, its object

B<What it returns:> the part's pieces, as a list or by name

B<Can it stop the run?:> no: it croaks "Expected no stop in a set-up, as the run has nothing yet to stop"

=item a source's B<step>

B<When it's called:> each time the run wants more values

B<What it's given:> nothing

B<What it returns:> the next value, or several; an empty list when there are no more

B<Can it stop the run?:> yes: the values its stop carries are its last, and its end is told C<done>

=item a stage's B<step>

B<When it's called:> once for each value

B<What it's given:> the value, in C<$_> and as its only argument

B<What it returns:> a list: none drops the value, one passes it on, several go on one at a time

B<Can it stop the run?:> yes

=item a sink's B<step>

B<When it's called:> once for each value

B<What it's given:> the value, in C<$_> and as its only argument

B<What it returns:> nothing that's used: what it returns is ignored

B<Can it stop the run?:> yes: the sink still gives its result, and its end is told C<done>

=item a gather's B<flush>

B<When it's called:> once, when its input runs out: not if a stop at or after its stage cut its input short, or the run died

B<What it's given:> nothing, with C<$_> undefined

B<What it returns:> values to go on through the stages after it, as a step's do

B<Can it stop the run?:> yes

=item a sink's B<flush>

B<When it's called:> the same

B<What it's given:> nothing, with C<$_> undefined

B<What it returns:> the result: one value for a sink of one, a list for a sink of many

B<Can it stop the run?:> no need: its input has run out

=item an B<end>

B<When it's called:> once, when the run has ended, however it ended

B<What it's given:> how it ended, from where the part stands: C<done>, C<stopped> or C<died>

B<What it returns:> nothing that's used

B<Can it stop the run?:> no: it croaks "Expected no stop in an end, as the run has ended"

=item a source's B<context>

B<When it's called:> read by stages, while the run lasts

B<What it returns:> any value: stages ask for it with C<Ekorn::Pipeline::run_context()>

=item a source's B<original>

B<When it's called:> when a stage asks C<result_original>

B<What it's given:> nothing

B<What it returns:> the original of the value the source gave last

B<Can it stop the run?:> no

=back

What each part's set-up returns, as a list in this order, or as a
hash reference with these keys:

=over 4

=item a source

B<Made with:> C<source {...}>, or C<EKORN_SOURCE>

B<Its pieces, in order:> C<step>, C<end>, C<context>, C<original>

B<Required:> the step

=item a stage

B<Made with:> C<gather {...}>, or C<EKORN_STAGE>

B<Its pieces, in order:> C<step>, C<flush>, C<end>

B<Required:> the step

=item a sink

B<Made with:> C<sink_one {...}> or C<sink_many {...}>, or C<EKORN_SINK_ONE> or C<EKORN_SINK_MANY>

B<Its pieces, in order:> C<step>, C<flush>, C<end>

B<Required:> the step and the flush

=back

Six rules hold for every part:

=over 4

=item *

B<What a run needs goes in the set-up,> declared with C<my>, and
the pieces are closures sharing it. Never keep a run's state in the
object, or in the closure around the set-up: a part may be in two
runs at once, as when two iterators of one pipeline are read in turn.

=item *

B<By name, give only the pieces you have.> As a list, leave out
pieces from the end, and give C<undef> for one you leave out before
one you give: C<return ($step, undef, $end)>.

=item *

B<Ends run in order,> the source's first, then each stage's, first
stage first, and each is told how the run ended from where it
stands: the source and the stages up to the one that stopped the
run, itself included, are told C<stopped>, if they still had values
to come, and the stages after it, C<done>.

=item *

B<An end can't undo the run, but it can choose what to keep.> A
sink that writes somewhere commits in its end only when told C<done>,
and throws away what it wrote otherwise.

=item *

B<A piece that dies ends the run.> Every end is still called, told
C<died>, and then the error is thrown, naming the part, as in
"Pipeline stage #2 failed at ...". An end that dies in a run that
hadn't died ends it with its error; in a run already dying, it's a
warning.

=item *

**Only a C<gather> block may return a pipeline,** in place of its
step, so that its stages are made for the run. A role method returns
code references.

=back

=head2 A stage, with the word C<gather>

A stage that numbers each value, says how many there were once the
values run out, and notes in a log of your choosing how each run
ended:

    sub numbered ($log) {
        return gather {
            my $n = 0;    # this run's
            return {
                step  => sub ($value) { ++$n . ". $value" },
                flush => sub ()       { "($n in all)" },
                end   => sub ($how)   { push @$log, "numbered: $how" },
            };
        };
    }

    my @log;
    say for Ekorn::Pipeline->new(numbered(\@log))->(qw(a b));
    # 1. a
    # 2. b
    # (2 in all)

    say for Ekorn::Pipeline->new(
        numbered(\@log),
        take(1),
    )->(qw(a b));
    # 1. a

    say for Ekorn::Pipeline->new(
        take(1),
        numbered(\@log),
    )->(qw(a b));
    # 1. a
    # (1 in all)

    say "@log";    # numbered: done numbered: stopped numbered: done

In the second run, C<take(1)>, after the numbering stage, stopped the
run while C<b> was still to come, so the numbering stage's input was
cut short: its flush wasn't called, and its end was told C<stopped>. In
the third, C<take(1)> comes first, so the numbering stage got all the
values it was going to get: its flush was called, and its end was told
C<done>.

=head2 The same stage, as a class

A class of your own can be the same stage, with no word and nothing of
Ekorn's loaded, by offering C<EKORN_STAGE>. It's called at the start of
each run, with the object, and returns the pieces, as the set-up did:

    package My::Numbered {
        sub new ($class, %options) { bless {from => $options{from} // 1}, $class }

        sub EKORN_STAGE ($self) {
            my $n = $self->{from};    # this run's, starting where the object says
            return {step => sub ($value) { $n++ . ". $value" }};
        }
    }

    my $numbered = My::Numbered->new(from => 10);
    my $p        = Ekorn::Pipeline->new($numbered);
    say join ', ', $p->(qw(a b));    # 10. a, 11. b
    say join ', ', $p->(qw(c));      # 10. c

The object keeps its settings, such as where to count from, and each
run keeps its own count, as C<$n> is declared in the method.

=head2 A source, with the word C<source>

A source of the lines of a text, which closes what it opened however
the run ends, and tells its stages the text's name, as the run's
context:

    sub lines_in ($name, $text) {
        return source {
            open my $fh, '<', \$text or die "Can't read $name: $!\n";    # this run's
            return {
                step    => sub () { my $line = readline $fh; defined $line ? $line =~ s( \n \z )()xr : () },
                end     => sub ($how) { close $fh },
                context => {name => $name},
            };
        };
    }

    my $where = sub ($line) { Ekorn::Pipeline::run_context()->{name} . ": $line" };
    my $next  = Ekorn::Pipeline->new($where)->iterator(lines_in('verse', "one\ntwo\n"));
    say for $next->all;
    # verse: one
    # verse: two
    say $next->ended;    # done

Its step is called with nothing, and returns the next line, or an
empty list once there are none. Returning an empty list is the only
way a source says it has finished: C<undef>, 0 and the empty string are
values.

=head2 A sink of one and a sink of many, with the words

C<sink_one> makes a sink giving one value, and C<sink_many> one giving a
list. The step is given each value, and what it returns is ignored;
the flush gives the result:

    my $longest = sink_one {
        my $longest = '';
        return {
            step  => sub ($word) { $longest = $word if length $word > length $longest },
            flush => sub ()      { $longest },
        };
    };

    my $distinct = sink_many {
        my(%seen, @order);
        return {
            step  => sub ($word) { push @order, $word unless $seen{$word}++ },
            flush => sub ()      { @order },
        };
    };

    my @words = qw(the cat sat on the mat);
    say scalar Ekorn::Pipeline->new($longest)->(@words);     # the
    say join ' ', Ekorn::Pipeline->new($distinct)->(@words);    # the cat sat on mat
    my $list = Ekorn::Pipeline->new($distinct)->(@words);
    say scalar @$list;    # 5

Asked for one value, a pipeline ending in a sink of many gives its
list as an array reference, so it can never be mistaken for a count.
C<$longest> gives the first of the longest, as it keeps a word only if
it's longer than the one it has.

=head2 A class that's both a source and a sink

One object can offer C<EKORN_SOURCE> and a sink's method, as a shelf of
books can be read from and added to. This one adds what it's given
only if the whole run went through, so a run that dies, or is cut
short, leaves the shelf as it was:

    package My::Shelf {
        sub new ($class, @books) { bless {books => [@books]}, $class }

        sub books ($self) { @{ $self->{books} } }

        # Read: each book on the shelf, in order.
        sub EKORN_SOURCE ($self) {
            my $i = 0;    # this run's place
            return {step => sub () { $i < @{ $self->{books} } ? $self->{books}[$i++] : () }};
        }

        # Write: the books given, put on the shelf only once the run is done.
        sub EKORN_SINK_ONE ($self) {
            my @pending;
            return {
                step  => sub ($book) { push @pending, $book },
                flush => sub ()      { scalar @pending },
                end   => sub ($how)  { push @{ $self->{books} }, @pending if $how eq 'done' },
            };
        }
    }

    my $shelf = My::Shelf->new('Emma');
    say scalar Ekorn::Pipeline->new($shelf)->('Dune', 'Ulysses');    # 2
    say join ', ', $shelf->books;    # Emma, Dune, Ulysses

    eval {
        Ekorn::Pipeline->new(
            sub { die "Torn\n" if $_ eq 'Torn'; $_ },
            $shelf,
        )->('Ivanhoe', 'Torn');
    };
    say join ', ', $shelf->books;    # Emma, Dune, Ulysses

    say join ', ', Ekorn::Pipeline->new(sub { uc })->iterator($shelf)->all;
    # EMMA, DUNE, ULYSSES

The second run died at its second book, so the sink's end was told
C<died>, and C<Ivanhoe> was never put on the shelf.

=head2 Your source, chained with C<|>

To let your users start a chain with your source, overload C<|> and
C<@{}> with Operators' C<chain> and C<drain>. Load Operators with an empty
import list, so that it doesn't put the operators in force in your
package:

    package My::Chained::Shelf {
        our @ISA = ('My::Shelf');
        use Ekorn::Pipeline::Operators ();
        use overload
            '|'   => \&Ekorn::Pipeline::Operators::chain,
            '@{}' => \&Ekorn::Pipeline::Operators::drain;
    }

    use Ekorn::Pipeline::Operators;

    my $shelf  = My::Chained::Shelf->new('Emma', 'Dune', 'Ulysses');
    my $titles = $shelf
        | take_if { length > 4 }
        | stage { uc }
        | keep_all;
    say "@$titles";    # ULYSSES
    say scalar @{$shelf};    # 3

This uses C<My::Shelf>, from the example before. Your users need C<use
Ekorn::Pipeline::Operators> in their own scope, as for any chain.

=head1 Index

Every module, A to Z, and each of its functions and methods, A to Z,
with a synopsis of all its forms, what it does, and how it's exported.
Each ends with a link to the section that shows it in use.

=head2 Ekorn::Pipeline

Runs values through a list of stages: its class methods make a
pipeline, and its methods run one, or tell of it. Nothing is exported
by default; C<is_stage> and C<is_sink> are exported upon request.

=head3 ending

    my $flushing = Ekorn::Pipeline::ending();

True while a flush runs, and while the values it gave go through the
stages after it, rather than values from the source or the caller. A
pipeline run inside a stage has its own. Not exported: call it by its
full name.

See L<ending|/"ending">.

=head3 feed

    my $feed = $p->feed;

Returns a feed, an Ekorn::Pipeline::Feed: one run of the stages, given
values as they arrive, with its C<push>, and ended with its C<close>.
The run is made when C<feed> is called, so a C<gather>'s block is called
then. It takes no arguments.

See L<feed|/"feed">.

=head3 is_sink

    use Ekorn::Pipeline v0.3.0 qw(is_sink);

    my $kind = is_sink($thing);

Returns C<one> if C<$thing> is a sink of one, giving one value, and
C<many> if it's a sink of many, giving a list; for a pipeline, the kind
of sink it ends in, if any. Both are true. It's false for anything
else. A sink is anything offering C<EKORN_SINK_ONE> or
C<EKORN_SINK_MANY>. Exported upon request.

See L<Writing functions that take
stages|/"Writing functions that take stages">.

=head3 is_stage

    use Ekorn::Pipeline v0.1.3 qw(is_stage);

    my $ok = is_stage($thing);

True if C<$thing> can be used as a stage: a code reference; a pipeline
of Ekorn::Pipeline or a subclass; or an object offering one of
C<EKORN_STAGE>, C<EKORN_SINK_ONE> and C<EKORN_SINK_MANY>, such as a
gather or a sink. It's the test C<new> uses. It's false for a string,
even the name of a pipeline, and for a source.

New in v0.1.3: ask for that version on the C<use> line, as above, as
v0.1.2 compiles the line, and fails only when C<is_stage> is called.
Exported upon request.

See L<Writing functions that take
stages|/"Writing functions that take stages">.

=head3 iterator

    my $next = $p->iterator($source);
    while (my($result) = $next->()) {...}

Returns an iterator, an Ekorn::Pipeline::Iterator: one run of the
stages, handing out the results one per call, and pulling values from
C<$source> only as they're needed. C<$source> is a code reference,
called with nothing, returning the next value or values, or an empty
list when there are no more; or anything offering C<EKORN_SOURCE>, such
as a source made for each run, or another iterator. Anything else
croaks "Expected a code reference".

Read it in list context, as above, so that a result of C<undef>, 0 or
C<''> isn't taken for the end. Once the results run out, it returns an
empty list, on every call.

See L<iterator|/"iterator">.

=head3 name

    my $name = $p->name;

Returns the first name the pipeline was given with C<named>, qualified
by its package, as C<main::clean>, or C<undef> if it has none. Errors in
its stages name it.

See L<Named pipelines|/"Named pipelines">.

=head3 named

    my $p = Ekorn::Pipeline->named($name => @stages);
    my $p = Ekorn::Pipeline->new(@stages)->named($name);

Names a pipeline, keeping it under C<$name> in the caller's package,
or in the package a qualified name gives, and returns it. On the
class, it makes the pipeline first, of the class, from the stages
after the name, which may be names themselves, looked up as C<pipeline>
looks them up; on a pipeline, it names that one, and croaks if it's
given stages after the name.

A name is identifiers, as Perl's, joined by C<::>, such as C<clean> or
C<My::Module::clean>; anything else croaks "Expected a name, made of
words joined by ::". A name can't be defined twice, or removed:
defining it again croaks "A pipeline named main::clean is already
defined".

See L<Named pipelines|/"Named pipelines">.

=head3 new

    my $p       = Ekorn::Pipeline->new(@stages);
    my @results = $p->(@values);
    my $count   = $p->(@values);

Returns a pipeline that runs values through C<@stages>, in order. Each
stage is something C<is_stage> is true for: a code reference; a
pipeline, whose stages are spliced in where it stands; or a part
offering a stage's or a sink's role method, such as a gather or a
sink. Called with values, the pipeline runs each through the stages,
and returns the results, or, in scalar context, how many there are;
ending in a sink, it gives the sink's result.

Anything else given as a stage croaks, naming its position: "Expected
stage #2 to be a stage: a code reference, a pipeline, or an object
offering a stage's role method"; a source, "Expected stage #2 to be a
stage, not a source".

See L<Making and calling a pipeline|/"Making and calling a pipeline">.

=head3 pipeline_in

    my $p = Ekorn::Pipeline->pipeline_in($package, @stages);

Returns a new pipeline of its invocant's class, of C<@stages>, each a
code reference, a pipeline, or the name of one, looked up in
C<$package> unless it's qualified. Given one name alone, it returns the
pipeline named, itself, if it's of the invocant's class or a subclass.
It's the only method that reads names, and what the word C<pipeline>
calls, with its caller's package.

See L<pipeline_in|/"pipeline_in">.

=head3 run_context

    my $context = Ekorn::Pipeline::run_context();

Returns the context the run's source gave, if any: its C<context>, or
the third part its C<EKORN_SOURCE> returned as a list, such as a
statement's column names. A stage calls it as it runs.
Not exported: call it by its full name.

See L<Stages that ask about their
run|/"Stages that ask about their run">.

=head3 stages

    my @stages = $p->stages;
    my $count  = $p->stages;

Returns a copy of the pipeline's stages, in order, so changing it
changes nothing in the pipeline; in scalar context, how many there
are. A pipeline given as a stage appears as the stages it was made of,
and a code reference given to C<new> as an Ekorn::Pipeline::Stage of
it.

See L<stages|/"stages">.

=head2 Ekorn::Pipeline::Context

What a stage can ask about the result it's making, and, for a stage
that holds values back, where a value came from. Nothing is exported
by default; each is exported upon request, and is in Tooling's
C<:context>, from v0.3.15. New in v0.3.11.

=head3 kept_origin

    my $origin = kept_origin;
    my @marked = $origin->gives(@values);

For a stage that holds values back (C<< holds => 1 >>), in its step, as it
keeps a value: returns the value's origin, an opaque
C<Ekorn::Pipeline::Origin> holding what C<result_original> answers for
the value then. Its method C<gives> returns each of the values given
marked as made from that value; the stage gives them so, and the
stages after it get them unmarked, each with that value's original.
Croaks "Expected kept_origin in the step of a stage that holds values
back" in a run with no such stage, or outside a run. Exported upon
request. New in v0.5.0.

See L<Stages that hold values back|/"Stages that hold values back">.

=head3 result_number

    my $n = result_number;

Returns the number of the result being made, from 1: the run's
results so far, plus one, a result being a value that leaves the last
stage or reaches a sink. In a flush, the number of the first value it
returns. Each run counts its own. Undef outside a run, and in an end.
Exported upon request.

See L<Which result|/"Which result: Ekorn::Pipeline::Context">.

=head3 result_original

    my $original = result_original;

Returns the value the result is being made from, as the run's source
gave it, or as it was pushed, before any stage changed it: the value
itself, not a copy. Undef in a flush and the stages after it, for the
values it gives, outside a run, and in an end. If the run's source
gave an C<original> part, directly or through an iterator read as a
source, what that returns instead, called only now. After a stage that
holds values back, the original of the value it said each came from,
in a flush too, and undef for one it made from many. Exported upon
request.

See L<Which result|/"Which result: Ekorn::Pipeline::Context">.

=head2 Ekorn::Pipeline::CSV

Given a C<file> or an C<fh>, returns a sink writing each row, an array

context's C<columns>. Exported upon request.

See L<CSV: Ekorn::Pipeline::CSV|/"CSV: Ekorn::Pipeline::CSV">.

=head2 Ekorn::Pipeline::Factories

The words that make Ekorn's types from what you write. Nothing is

=head3 gather

The same C<gather> that Ekorn::Pipeline::Gather exports by default: a
stage made afresh for each run by its block. Exported upon request.

See L<gather|/"gather">.

=head3 generator

    my $source = generator { ...; yield @values; ... };

Returns a Source giving every value its block passes to C<yield>, in
order. Each run calls the block once, to its end, so the block mustn't
loop without end. An empty block, C<generator {}>, reads as an empty
hash: write C<generator { return }>. It croaks "Expected a code
reference" if it's given something other than a block or code
reference. Exported upon request.

See L<generator and yield|/"generator and yield">.

=head3 pipeline

    my $p = pipeline(@stages);
    my $p = pipeline($name);
    my $p = pipeline($name, @stages);

Returns a new pipeline of C<@stages>, each a code reference, a
pipeline, or the name of one, looked up now, in the caller's package
unless it's qualified, as C<My::Module::clean>; given one name alone,
the pipeline it names, itself. It's
C<< Ekorn::Pipeline->pipeline_in(scalar caller, @stages) >>.

A name not defined croaks "No pipeline named main::clean"; anything
else that isn't a stage, "Expected stage #2 to be a code reference, a
pipeline or the name of one". Exported upon request.

See L<Named pipelines|/"Named pipelines">.

=head3 sink_many

    my $sink = sink_many { ...; return ($step, $flush, $end) };
    my $sink = sink_many { ...; return ($step, $flush) };
    my $sink = sink_many { ...; return {step => $step, flush => $flush} };

Returns a sink of many, made for each run by its block, a set-up
returning its step, called with each value, its return ignored; its
flush, giving the result, a list; and, optionally, its end, told how
the run ended. Asked for one value, a pipeline ending in it gives its
list as an array reference. It croaks "Expected a code reference" if
it's given something other than a block or code reference. Exported
upon request.

See L<sink_one and sink_many|/"sink_one and sink_many">.

=head3 sink_one

    my $sink = sink_one { ...; return ($step, $flush, $end) };
    my $sink = sink_one { ...; return ($step, $flush) };
    my $sink = sink_one { ...; return {step => $step, flush => $flush} };

Returns a sink of one, made for each run by its block, a set-up
returning its step, called with each value, its return ignored; its
flush, giving the result, one value; and, optionally, its end, told
how the run ended. It croaks "Expected a code reference" if it's given
something other than a block or code reference. Exported upon request.

See L<sink_one and sink_many|/"sink_one and sink_many">.

=head3 source

    my $source = source { ...; return ($step, $end, $context) };
    my $source = source { ...; return ($step, $end) };
    my $source = source { ...; return $step };
    my $source = source { ...; return {step => $step, context => $context} };
    my $source = source { ...; return {step => $step, original => $original} };

Returns a Source, made for each run by its block, a set-up returning
its step, called with nothing, giving the next value or values, or an
empty list when there are no more; optionally, its end, told how the
run ended; optionally, a context, which its stages ask for with
C<run_context>; and, optionally, an original, returning the original of
the value it gave last, which C<result_original> gives (new in
v0.3.13). It croaks "Expected a code reference" if it's given
something other than a block or code reference. Exported upon request.

See L<source|/"source">.

=head3 stage

    my $stage = stage { ... };
    my $stage = stage sub ($value) { ... };
    my $stage = stage(\&code);

Returns a Stage of the block, called with each value, in C<$_> and as
its argument, as any stage is, but one of Ekorn's types from the
start. Give it a sub for a signature. It croaks "Expected a code
reference" if it's given something other than a block or code
reference. Exported upon request.

See L<stage|/"stage">.

=head3 yield

    yield @values;

In a generator's block, gives C<@values>, in order, as the generator's
next values. It croaks "Expected yield to be called inside a
generator" when it's called outside one. Exported upon request.

See L<generator and yield|/"generator and yield">.

=head2 Ekorn::Pipeline::Feed

One run, given values as they arrive; made by C<feed>, not by its
C<new>. Exports nothing.

=head3 close

    my @rest = $feed->close;
    my $rest = $feed->close;

Ends the input, as a source running out does: calls the flushes, in
order, and returns what they give, through the stages after them, and
a sink's result; in scalar context, as an array reference. Then it
calls the ends. On a feed whose run has ended, it croaks "Expected a
feed still open, but its run has ended".

See L<Feeds: Ekorn::Pipeline::Feed|/"Feeds: Ekorn::Pipeline::Feed">.

=head3 ended

    my $how = $feed->ended;

Returns nothing while the run is open; then C<done>, once it's closed,
C<stopped>, once a stop or C<finish> has ended it, and C<died>, if
anything in it died.

See L<Feeds: Ekorn::Pipeline::Feed|/"Feeds: Ekorn::Pipeline::Feed">.

=head3 finish

    $feed->finish;

Ends the run now, as from outside, if it hasn't ended: nothing waiting
goes on, no flush is called, and each end is told C<stopped>, if its
input hadn't run out. A feed let go before it's closed is finished so.

See L<Feeds: Ekorn::Pipeline::Feed|/"Feeds: Ekorn::Pipeline::Feed">.

=head3 push

    my @results = $feed->push(@values);
    my $results = $feed->push(@values);

Runs C<@values> through the stages, each through every stage before
the next, and returns what came out of them; in scalar context, as an
array reference. A value held back, as C<batch> holds values, comes out
of a later push, or of C<close>, as a sink's result does. On a feed
whose run has ended, it croaks "Expected a feed still open, but its
run has ended".

See L<Feeds: Ekorn::Pipeline::Feed|/"Feeds: Ekorn::Pipeline::Feed">.

=head2 Ekorn::Pipeline::Gather

A stage made afresh for each run, with a flush, called as its input
runs out, and an end. C<gather> is exported by default.

=head3 EKORN_STAGE

    my @parts = $gather->EKORN_STAGE;

Calls the block for a new run, and returns what it returns: the step,
and, optionally, the flush and the end. A run calls it as it starts;
you needn't.

See L<gather|/"gather">.

=head3 gather

    my $stage = gather { ...; return ($step, $flush, $end) };
    my $stage = gather { ...; return ($step, $flush) };
    my $stage = gather { ...; return ($step, undef, $end) };
    my $stage = gather { ...; return $step };
    my $stage = gather { ...; return {step => $step, flush => $flush, end => $end} };
    my $stage = gather { ...; return $pipeline };

Returns a stage, an Ekorn::Pipeline::Gather, that a pipeline makes
afresh as each run starts, by calling the block, so whatever the block
declares is that run's. The block returns the step, called with each
value, or a pipeline in its place; optionally, the flush, called with
nothing once its input runs out, what it returns going on through the
stages after it; and, optionally, the end, told how the run ended.

It croaks "Expected a code reference" if it's given something other
than a block or code reference. Exported by default.

See L<gather|/"gather">.

=head3 new

    my $stage = Ekorn::Pipeline::Gather->new($block);

Makes a gather of C<$block>, a code reference, as C<gather> does.

See L<gather|/"gather">.

=head2 Ekorn::Pipeline::Iterator

One run, handing out its values, a value each C<< $next->() >>; made by
C<iterator>, not by its C<new>, and a source too. Exports nothing.

=head3 all

    my @rest = $next->all;
    my $rest = $next->all;

Reads the run to its end, and returns every value still to come; in
scalar context, as an array reference. Values already waiting at the
end of the stages, such as a sink of many's result, it takes at once.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 all_arrayref

    my %report = (rows => $next->all_arrayref);

Returns every value still to come, as C<all> does, but always as an
array reference, whatever the context; an empty one, if there are
none.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 EKORN_SOURCE

    my $then = $p->iterator($next);    # a run calls $next->EKORN_SOURCE

Makes the iterator a source, for another pipeline's C<iterator>: its
values go through the second pipeline's stages, its run ends when the
second's does, and the second's stages see its context, and its
source's original, if it gave one. It's one run,
so it can be a source only once, before it has handed out everything
it will; after, it croaks "Expected a source with values still to
give: an iterator is one run, and this one is spent". A run calls it
as it starts; you needn't.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 ended

    my $how = $next->ended;

Returns nothing until the iterator has given all it will, been
finished, or died; then C<done>, if the source was read to its end,
C<stopped>, if a stop anywhere, such as C<take>'s, or C<finish>, cut the
reading short, or C<finish> dropped values still to be handed out, and
C<died>, if anything died.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 finish

    $next->finish;

Ends the run now, if it hasn't ended: nothing more is read, and
nothing waiting is handed out. Each end is told how from where it
stands: C<stopped>, if its input hadn't run out. Every call after
returns an empty list. An iterator let go before its values run out is
finished so.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 first

    my $value = $next->first;

Returns the next value, or C<undef> if there's none, and ends the run,
as C<finish> does, so nothing more is read.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 next

    while (my($value) = $next->next) { ... }

Returns the next value, as C<< $next->() >> does, in any context: one
value, or an empty list once the values run out.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

=head3 single

    my $value = $next->single;

Returns the next value, or C<undef> if there's none, as C<first> does,
but pulls one value more first, and warns "Expected only one item, but
there were more" if there's another. Then it ends the run.

See L<Iterators: Ekorn::Pipeline::Iterator|/"Iterators: Ekorn::Pipeline::Iterator">.

upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 keep

    keep($n)

A sink of many, giving the first C<$n> items, as C<take($n)> would pass
on, and stopping the pull once it has them. It croaks "Expected a
count of 0 or more" if C<$n> isn't a whole number. Exported upon
request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 keep_all

    keep_all

A sink of many, giving every item. Asked for one value, a pipeline
ending in it gives them as an array reference, which is true even when
it's empty. Exported upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 keep_first

    keep_first

A sink of one, giving the first item, or C<undef> if there's none, and
stopping the pull once it has it. Exported upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 keep_last

    keep_last

A sink of one, giving the last item, reading every one to find it, or
C<undef> if there's none. Exported upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 keep_single

    keep_single

A sink of one, giving the one item, or C<undef> if there's none. At a
second, it warns "Expected only one item, but there were more", and
stops the pull, giving the first: for when one item is meant, and a
limit was forgotten. Exported upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 to_fh

    to_fh($fh)

A sink of one, printing each item to C<$fh>, followed by C<$/>, and
giving how many it printed. It leaves C<$fh> open: you opened it, so
you close it. It croaks "Expected an open filehandle" if it's given
anything else, and "Can't write %s: %s" if it can't write. Exported
upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head3 to_file

    to_file($path)
    to_file($path, $layers)

A sink of one, writing each item to the file at C<$path>, followed by
C<$/>, through the I/O layers given, such as C<':encoding(UTF-8)'>, and
giving how many it wrote. It opens the file, emptied, as the run
starts, and closes it however the run ends. It croaks "Can't write %s:
%s" if it can't open, write or close it. Exported upon request.

See L<Sinks: Ekorn::Pipeline::Sinks|/"Sinks: Ekorn::Pipeline::Sinks">.

=head2 Ekorn::Pipeline::Source

A source made afresh for each run. Exports nothing.

=head3 EKORN_SOURCE

    my @parts = $source->EKORN_SOURCE;

Calls the set-up for a new run, and returns what it returns: the step,
and, optionally, the end, a context and an original. A run calls it as it starts;
you needn't.

See L<Sources: Ekorn::Pipeline::Source|/"Sources: Ekorn::Pipeline::Source">.

=head3 new

    my $source = Ekorn::Pipeline::Source->new($setup);

Returns a source made afresh for each run by C<$setup>, a code
reference returning its step, called with nothing, giving the next
value or values, or an empty list at the end; optionally, its end,
told how the run ended; and, optionally, a context, as a list or by
name. It croaks "Expected a code reference" if it's given anything
else. A source goes to C<iterator>: given to C<new> as a stage, or
called directly, it croaks.

See L<Sources: Ekorn::Pipeline::Source|/"Sources: Ekorn::Pipeline::Source">.

=head2 Ekorn::Pipeline::Sources

Ready-made sources, needing nothing beyond Perl. Nothing is exported
by default; each is exported upon request, and is in Tooling's
C<:sources>.

=head3 counter

    counter()
    counter($start)
    counter($start, $step)

A source of C<$start>, then on by C<$step>, without end, 1 and 1 by
default: give it a stage that stops, such as C<take>. It croaks
"Expected a number to start from, and one to step by" if it's given
anything else. Exported upon request.

See L<Sources: Ekorn::Pipeline::Sources|/"Sources: Ekorn::Pipeline::Sources">.

=head3 from_array

    from_array(@values)

A source of the values given, in order. Exported upon request.

See L<Sources: Ekorn::Pipeline::Sources|/"Sources: Ekorn::Pipeline::Sources">.

=head3 from_fh

    from_fh($fh)

A source of a filehandle's records, as C<$/> divides them at each read:
its lines, unless C<$/> is changed, each without the separator, as
C<chomp> removes it. It leaves C<$fh> open. It croaks "Expected an open
filehandle" if it's given anything else. Exported upon request.

See L<Sources: Ekorn::Pipeline::Sources|/"Sources: Ekorn::Pipeline::Sources">.

=head3 from_file

    from_file($path)
    from_file($path, $layers)

A source of a file's records, as C<$/> divides them at each read: its
lines, unless C<$/> is changed, each without the separator, read
through the I/O layers given, such as C<':raw'> or
C<':encoding(UTF-8)'>. It opens the file as the run starts, croaking
"Can't read %s: %s" if it can't, and closes it however the run ends.
Exported upon request.

See L<Sources: Ekorn::Pipeline::Sources|/"Sources: Ekorn::Pipeline::Sources">.

=head2 Ekorn::Pipeline::Stage

A code reference kept as a stage, one of Ekorn's types. Exports
nothing.

=head3 code

    my $code = $stage->code;

Returns what the stage was made of: a code reference, or an object
called as one.

See L<Stages and elements|/"Stages and elements">.

=head3 EKORN_STAGE

    my $step = $stage->EKORN_STAGE;

Returns the stage's step for a new run: its code, as a code reference.
A run calls it as it starts; you needn't.

See L<Stages and elements|/"Stages and elements">.

=head3 new

    my $stage = Ekorn::Pipeline::Stage->new($code);

Returns a stage of C<$code>, a code reference or an object called as
one, as C<new> keeps each code reference it's given. Called directly,
the stage calls its code with what it's given, but doesn't set C<$_>:
only a run does.

See L<Stages and elements|/"Stages and elements">.

=head2 Ekorn::Pipeline::Stages::Batch

Canned stages gathering values. Both are exported by default, and are
in Tooling's C<:batch>.

=head3 batch

    batch($size)

Passes values on in batches of C<$size>, each a new array reference,
holding no more than one batch at a time. Once the values run out, the
last batch goes on, which may be shorter; with no values, there's no
batch at all. A batch, made from many values, has no original; until
v0.5.0, one filled by a value had that value's. It croaks "Expected a
batch size of 1 or more" if C<$size> isn't a whole number above 0.
Exported by default.

See L<Batching and collecting:
Ekorn::Pipeline::Stages::Batch|/"Batching and collecting: Ekorn::Pipeline::Stages::Batch">.

=head3 collect

    collect
    collect { ... }
    collect(\&code)

Holds every value, and, once they run out, passes on an array
reference of them. Given a block, it calls the block once, with the
values as its arguments, and passes on what it returns: nothing, one
value or several, as a stage's. It gives a result even of no values:
an empty array, or what the block makes of none. It croaks "Expected a
code reference" if it's given something other than a block or code
reference. Exported by default.

See L<Batching and collecting:
Ekorn::Pipeline::Stages::Batch|/"Batching and collecting: Ekorn::Pipeline::Stages::Batch">.

=head2 Ekorn::Pipeline::Stages::Flow

Canned stages taking or dropping values. C<take> and C<drop> are
exported by default, the rest upon request; all are in Tooling's
C<:flow>.

=head3 drop

    drop($n)

Drops the first C<$n> values, and passes on the rest. It croaks
"Expected a count of 0 or more" if C<$n> isn't a whole number. Exported
by default.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 drop_if

    drop_if { ... }
    drop_if(\&code)

Drops each value the block is true of, and passes on the rest, testing
every one: C<take_if>'s opposite. The block gets each value in C<$_> and
as its argument. It croaks "Expected a code reference" if it isn't
given a block or code reference. Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 drop_while

    drop_while { ... }
    drop_while(\&code)

Drops values while the block is true of them, then passes on the rest,
starting with the first it's false of, without calling the block again
that run. The block gets each value in C<$_> and as its argument. It
croaks "Expected a code reference" if it isn't given a block or code
reference. Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take

    take($n)

Passes on the first C<$n> values, then stops the run, the last going
with the stop, so a source isn't asked for one more than is wanted. If
there are fewer, it passes them all on. C<take(0)> passes on none, but
sees one value first, as a stage isn't called until there is one. It
croaks "Expected a count of 0 or more" if C<$n> isn't a whole number.
Exported by default.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take_first

    take_first

Passes on the first value, then stops the run: C<take(1)>, named as the
stage of the sink C<keep_first>. Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take_if

    take_if { ... }
    take_if(\&code)

Passes on each value the block is true of, and drops the rest,
testing every one, as C<grep> does; it never stops the run. The block
gets each value in C<$_> and as its argument. It croaks "Expected a
code reference" if it isn't given a block or code reference.
Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take_last

    take_last

Passes on the last value, once there are no more, reading every one to
find it; nothing if there were none. If a stage before it stops the
run, it passes on the last value to reach it. Its value has its own
original, from v0.5.0; it had none, as a flush's values have. Exported
upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take_single

    take_single

Passes on the one value. At a second, it warns "Expected only one
item, but there were more", and stops the run, so only the first goes
on. Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head3 take_while

    take_while { ... }
    take_while(\&code)

Passes on values while the block is true of them. At the first it's
false of, it stops the run, and doesn't pass that value on, so it reads
no further. The block gets each value in C<$_> and as its argument. It
croaks "Expected a code reference" if it isn't given a block or code
reference. Exported upon request.

See L<Taking and dropping:
Ekorn::Pipeline::Stages::Flow|/"Taking and dropping: Ekorn::Pipeline::Stages::Flow">.

=head2 Ekorn::Pipeline::Stages::Taps

Canned stages run for what they do on the side, passing each value on
unchanged. C<peek> and C<count_into> are exported by default, C<dump_to>
and C<tee> upon request; all are in Tooling's C<:taps>.

=head3 count_into

    count_into(\$count)

Counts the values into C<$count>, setting it to 0 as each run starts,
so after a run it holds how many went by, even if none did. It croaks
"Expected a reference to a scalar" if it isn't given one. Exported by
default.

See L<Taps: Ekorn::Pipeline::Stages::Taps|/"Taps: Ekorn::Pipeline::Stages::Taps">.

=head3 dump_to

    dump_to
    dump_to($fh)

Writes each value to C<$fh>, or to STDERR, with Data::Dumper, and
passes it on. With Text::Redact::Secrets v1.x installed, each secret
it finds in a dump is written C<*REDACTED*>; set
C<$Ekorn::Pipeline::Stages::Taps::DumpSecrets> true, with C<local>, to
write them as they are. It croaks "Expected an open filehandle" if
C<$fh> isn't one. Exported upon request.

See L<dump_to|/"dump_to">.

=head3 peek

    peek { ... }
    peek(\&code)

Calls the block with each value, in C<$_> and as its argument, and
passes the value on, whatever the block returns. It croaks "Expected a
code reference" if it isn't given a block or code reference. Exported
by default.

See L<Taps: Ekorn::Pipeline::Stages::Taps|/"Taps: Ekorn::Pipeline::Stages::Taps">.

=head3 tee

    tee(@stages)

Runs each value through a branch of C<@stages>, one run of its own
beside the main run, for what they do on the side, and passes the
value on unchanged; what comes out of the branch is dropped. C<@stages>
are whatever C<new> takes, a sink last included, made into a pipeline
when C<tee> is called, so a mistake croaks then, at your line, with
C<new>'s message. With no stages, it does nothing. Exported upon
request.

See L<tee|/"tee">.

=head2 Ekorn::Pipeline::Stop

Ends a run early, and quietly. C<Stop> is exported by default.

=head3 Stop

    Stop();
    Stop(@values);

Throws a stop carrying C<@values>, the last values of the stage that
throws it, which go on through the stages after it. It's
C<< Ekorn::Pipeline::Stop->throw(@values) >>. Exported by default.

See L<What a stop does|/"What a stop does">.

=head3 throw

    Ekorn::Pipeline::Stop->throw(@values);
    My::Stop->throw(@values);

Throws a stop carrying C<@values>, blessed into the class it's called
on, so a subclass's stops are its own; a pipeline knows one with
C<isa>. A stop is an array reference, its first element its class, and
the rest its values.

See L<What a stop does|/"What a stop does">.

=head2 Ekorn::Pipeline::Sugar

Names pipelines as the program compiles, each with a function of its
name, by C<< use Ekorn::Pipeline::Sugar pipeline => {...} >> (see L<Named at
compile time|/"Named at compile time: Ekorn::Pipeline::Sugar">). Exports
nothing else.

=head3 import_into

    Ekorn::Pipeline::Sugar->import_into($package, pipeline => {...});
    Ekorn::Pipeline::Sugar->import_into($package, pipeline => [...]);

Does what C<use Ekorn::Pipeline::Sugar> does, for C<$package> in place
of its caller: names each pipeline in C<$package>, and gives it a
function of each name. It's for a module whose own C<use> line takes
pipelines, and hands them on to the package using it.

See L<Sugar of your own|/"Sugar of your own">.

=head2 Ekorn::Pipeline::Tooling

Exports what callers use to do work, from one place, by the names of
the other modules' functions, or by tags that hold them: C<:core>,
C<:flow>, C<:batch>, C<:taps>, C<:stages>, C<:context>, C<:sources>,
C<:sinks>, C<:json>, C<:csv>, C<:words> and C<:all> (see L<Importing|/"Importing: Ekorn::Pipeline::Tooling">).
Nothing is exported by default. It has no names of its own.
