# WWW::OpenBao — repo conventions

A deliberately small Perl HTTP client for OpenBao / HashiCorp Vault, extracted from
`HI::Daemon`. Domain knowledge about the API itself (paths, response shapes, status-code
semantics) is in skill `openbao-general` — this file is only about how *this
distribution* is built.

## Shape

One module, `lib/WWW/OpenBao.pm`, no sub-namespace. Moo, `namespace::clean`, POD in
`__END__` using the `[@Author::GETTY]` PodWeaver directives (`=attr`, `=method`).

```
endpoint   ro, required   base URL, no trailing slash — _request joins with '/'
token      rw             X-Vault-Token value; login_k8s writes to it
kv_mount   ro, default    KV v2 mount name, 'secret'
_http      lazy           HTTP::Tiny, timeout 10
```

`token` is `rw` on purpose: an auth call is a *mutation of the client*, not a factory for
a new one. Don't "fix" it to `ro`.

## The `_request` seam

**Every** HTTP call goes through `_request($method, $path, $body)`. It owns URL joining,
the token header, JSON encode/decode, the 404 rule and the croak. A new endpoint is a new
three-line method delegating to it — never a second call site for `HTTP::Tiny`, never a
bypass "just for this one case". If an endpoint genuinely cannot fit the seam (a custom
`Content-Type` for merge-patch, a status code that must reach the caller), widen
`_request` rather than routing around it.

`$path` is passed **without** a leading slash (`v1/sys/health`), because `_request`
inserts the separator. Path helpers `_kv_path` / `_kv_metadata_path` build the KV v2
forms and are covered by `t/10-paths.t` — private by name, public by test, so a change to
either breaks the suite deliberately.

## Error contract — this is the public API

Documented in the POD and relied on by callers:

- non-2xx → `croak "OpenBao $method $path: $status $content"`
- `404` → `undef`, never a croak. This is what makes "secret not found" a soft miss.

Two consequences worth stating out loud before changing anything nearby:

- **404 is overloaded.** An absent path and a soft-deleted KV v2 version both answer 404,
  so `undef` from `read_secret` means "no readable value", not "never existed".
- **A croak carries the response body**, which for a failed write includes what you sent.
  Never widen that message to include the token or the request body of a secret write.

## Known contract edges

These are properties of the current code, not accidents to silently repair — each one is
a decision a change has to knowingly keep or replace, and if you replace one, say so in
`Changes`:

- `secret_exists` maps only a **404** to false. It does a plain metadata `GET` and asks
  whether `_request` returned something defined, so a **403** (and any other non-2xx)
  propagates as a croak rather than being reported as "does not exist" — a policy-denied
  path is no longer mistaken for an absent one.
- `health` `eval`s and yields `undef` for every non-2xx, which for `/sys/health` means
  sealed (503), uninitialised (501) and standby (429) are indistinguishable from an
  unreachable host. See `openbao-general` for why those codes *are* the answer.
- `delete_secret` hits `metadata/`, i.e. the irreversible level-3 delete (key + every
  version), not the soft delete a reader might expect from the name.
- `list_secrets` uses the `LIST` HTTP verb. `HTTP::Tiny` passes it through fine; some
  proxies do not.
- `_read_sa_token` slurps the ServiceAccount file verbatim — no `chomp`.

## Dependencies — minimalism is the feature

`Moo`, `HTTP::Tiny`, `JSON::MaybeXS`, `namespace::clean`, `Carp`. Nothing else, and no
`IO::Socket::SSL` requirement forced on plain-HTTP users. The DESCRIPTION promises "no
caching, no lease renewal, no policy management"; adding one of those is a distribution
decision to raise with the maintainer, not a convenience to slip into a patch. A new
runtime dependency needs a reason bigger than "it would be tidier".

## Tests

`prove -lr t` — recursive; `t/` is flat today, keep `-r` so a future subdirectory is never
silently skipped.

**The suite never touches the network.** No live OpenBao, no k8s, not even localhost. The
existing tests cover construction and path building. To exercise request/response
behaviour, intercept at the `_http` attribute — it is `lazy`, so a test can pass a stub
object answering `request()` with a canned `{ status, success, content }` hashref, which
is also why the seam is worth keeping narrow. Never add a test that requires a running
server; if a behaviour cannot be tested offline, say so rather than shipping a test that
skips in CI and passes nowhere.

`t/author-pod-syntax.t` and friends are generated by `[@Author::GETTY]` at build time —
they live in the built dist, not in the repo. Don't commit them.
