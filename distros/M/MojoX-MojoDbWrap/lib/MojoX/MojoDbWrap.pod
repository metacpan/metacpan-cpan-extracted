=head1 SYNOPSIS

   use MojoX::MojoDbWrap;

   # anything good for the Mojo::Pg or Mojo::SQLite constructor
   my $wrap = MojoX::MojoDbWrap->new(
      db_url         => $db_url,  # e.g. 'postgresql://...' or a file
      migrations_for => {
         'Mojo::Pg'     => $pg_migrations,
         'Mojo::SQLite' => $sqlite_migrations,
      },
   );

   # run the migrations for the selected class, if any
   $wrap->init;

   say $wrap->mdb_class;  # "Mojo::Pg" or "Mojo::SQLite" or...
   say $wrap->mdb_module; # ditto, it's an alias

   # get the underlying Mojo::Pg or Mojo::SQLite or ... object
   my $mojodb = $wrap->mdb;

   # get the `db` for actual queries (same as `$wrap->mdb->db`)
   my $db = $wrap->db;

   # assuming an identifier column called `id`, get the identifier of
   # the record matching a condition (good for a `select` on `$db`)
   my $id_existing = $wrap->id_of($table, $condition);

   # if the identifier column has another name, pass it with the table
   # name like this (works for all methods taking a table)
   my $id_existing = $wrap->id_of([$table, $id_column], $condition);

   # either get the identifier of an existing record, or insert a new
   # record and get its identifier
   my $id_ensure = $wrap->id_or_insert($table, $condition, $default);

   # insert a new record, get its identifier back
   my $id_new = $wrap->insert($table, \%data);

   # insert a new record, or update the existing one with the same
   # value(s) in the "conflicting" column(s); get the identifier back
   my $id_up = $wrap->upsert($table, \%data, { conflicting => 'name' });
   my $id_up2 = $wrap->upsert($table, \%data, { conflicting => [qw< a b >] });

   # all of the above accept db in the final options, e.g. to work
   # inside a transaction started on that db
   my $db = $wrap->db;
   my $tx = $db->begin;
   my $id_tx = $wrap->insert($table, \%data, { db => $db });
   my $id_tx2 = $wrap->upsert($table, \%data, { conflicting => 'name', db => $db });
   $tx->commit;

   # extensibility
   my $wrap = MojoX::MojoDbWrap->new(
      db_url => $whatever,
      wrappers => [
         {
            class  => 'My::Class1',
            create => sub ($class, $db_url) { ... },
            insert => sub ($wrap, $tablish, $data, $opts) {
               my ($db, $db_opts) = $wrap->db_and_opts($opts, 'My::Class1');
               ...
            },
         },
         {  # without insert, default_inserter is used
            class  => 'My::Class2',
            create => sub ($class, $db_url) { ... },
         },
         ...
      ],
   );

=head1 DESCRIPTION

This module acts as a light wrapper around classes like L<Mojo::Pg> or
L<Mojo::SQLite>, which provide a largely overlapping interface, so that
the same code can work with either of them. On top of this, it provides
a few handy methods for common operations, like getting the identifier
of a record (L</id_of>), inserting a record and getting its identifier
back (L</insert>), doing both as needed (L</id_or_insert>), and
inserting or updating a record (L</upsert>).

Identifiers of inserted records are taken via C<RETURNING>, which is
supported by PostgreSQL and by SQLite 3.35.0 or later. This is correct
also when an insertion turns into an update due to C<on_conflict>,
which would not be the case with SQLite's C<last_insert_id>.

The wrapped object is created lazily, i.e. upon the first call to a
method needing it.

Methods taking a table also accept a I<tablish>, i.e. either a string
with the name of the table, or an array reference holding the name of
the table and the name of the identifier column. When only the name of
the table is provided (as a string, or as the only item of the array
reference), the identifier column is assumed to be C<id>.

All methods operating on records (L</id_of>, L</id_or_insert>,
L</insert> and L</upsert>) accept option C<db> in their final options
hash reference, to run their queries on a specific database handle.
This is how to work inside a transaction: start it with
C<< my $tx = $db->begin >> and pass the same C<$db>, keeping it in a
variable until the transaction ends (transaction objects only hold a
weak reference to their handle). It also pins a connection without any
transaction, e.g. for temporary tables, per-connection settings or an
in-memory SQLite database. Without C<db>, a handle is taken via L</db>.
This is important, because each call to L</db> can return a different
connection, outside of any transaction; with SQLite and an
in-memory database, a different connection is even a different (empty)
database! See L</db_and_opts>.

Errors are thrown as L<Ouch> exceptions. In particular, passing final
options that are neither C<undef> nor a hash reference to any of the
methods above (or to L</default_inserter>) throws an exception with
code 400, whose message starts with the name of the method. The same
happens for options holding key C<-asc> or C<-desc>, i.e. an old-style
sort specification that L<SQL::Abstract::Pg> would still accept in
place of options: put it inside option C<order_by> instead, e.g.
C<< { order_by => { -desc => 'id' } } >>.

Make sure to read L</SECURITY CONSIDERATIONS> too.

=head1 INTERFACE

=head2 db

   my $db = $wrap->db;

Same as C<< $wrap->mdb->db >>.

=head2 db_and_opts

   my ($db, $db_opts) = $wrap->db_and_opts($opts); # OR
   my ($db, $db_opts) = $wrap->db_and_opts($opts, $name);

Get the database handle to use for the operation, along with a copy of
the options in C<$opts> (a hash reference, or C<undef>) without key
C<db>. The handle is the value for key C<db> if present, or a fresh one
from L</db> otherwise.

An exception with code 400 is thrown, whose message is prefixed with
C<$name>, if C<$opts>:

=over

=item *

is neither C<undef> nor a hash reference;

=item *

holds key C<-asc> or C<-desc> (an old-style sort specification, see
L</DESCRIPTION>);

=item *

holds key C<db> with an undefined value (which would otherwise silently
lead to a fresh connection, outside of any transaction).

=back

By default, C<$name> is the name of the calling sub (or C<db_and_opts>
when called outside of any sub, including directly from an C<eval>
block), which can be C<__ANON__>; pass something meaningful when
calling from an anonymous sub, e.g. a custom inserter (see L</new>).

=head2 db_url

   my $url = $wrap->db_url;

The URL provided in L</new>.

=head2 default_inserter

   my $id = $wrap->default_inserter($tablish, $data, $opts);

Insert a new record based on hash reference C<$data>, returning the
value of the identifier column of the inserted (or updated) record,
using C<RETURNING>. This is the inserter used for L<Mojo::Pg>,
L<Mojo::SQLite> and any wrapper in C<wrappers> (see L</new>) that does
not provide its own C<insert>.

C<$opts> is an optional hash reference with options for the C<insert>
method of the C<db> object (e.g. C<on_conflict>), plus option C<db>
(see L</db_and_opts>); option C<returning> is always overridden.

Returns C<undef> if no record is returned, e.g. when C<on_conflict> is
C<undef> (i.e. C<DO NOTHING>) and there is a conflict.

It can also be called as a plain function from a custom C<insert> sub,
with the same arguments it receives:

   insert => sub ($wrap, $tablish, $data, $opts) {
      ...
      return MojoX::MojoDbWrap::default_inserter(@_);
   },

=head2 id_of

   my $id = $wrap->id_of($tablish, $cond);  # OR
   my $id = $wrap->id_of($tablish, $cond, $opts);

Get the identifier of a record matching condition C<$cond>, optionally
with options in hash reference C<$opts> (e.g. C<order_by>), both passed
to the C<select> method of the C<db> object. Option C<db>
selects the database handle, see L</db_and_opts>. Option C<limit> is
set to 1 when the wrapper supports it (see C<can_limit> in L</new>; it
is supported for L<Mojo::Pg> and L<Mojo::SQLite>), as only the first
matching record is used; use C<order_by> to choose which one. Otherwise,
the options are passed as they are, including any C<limit> provided by
the caller. Returns C<undef> if no record matches.

An undefined C<$cond> leads to an exception with code 400, as it would
match every record, i.e. return an arbitrary identifier. The same
happens for a C<$cond> that is not a reference: it would be bound as
C<WHERE ?>, so that e.g. C<"1"> would match every record too. With
L<Mojo::Pg> and L<Mojo::SQLite> (more precisely, when the wrapped
object has method C<abstract>), the same happens for any C<$cond>
generating no C<WHERE> clause, e.g. C<{}>, C<[]> or
C<< { -or => [] } >>. See L</SECURITY CONSIDERATIONS>.

C<$opts> must be an options hash: a sort specification on its own,
i.e. a string, an array reference or a hash reference with key C<-asc>
or C<-desc> (which the C<select> method of the C<db> object would
accept in place of options), leads to an exception with code 400. Pass
it as option C<order_by> instead:

   my $id = $wrap->id_of($table, $cond, { order_by => { -desc => 'id' } });

=head2 id_or_insert

   my $id = $wrap->id_or_insert($tablish, $cond, $default); # OR
   my $id = $wrap->id_or_insert($tablish, $cond, $default, $opts);

Retrieve the identifier of the record matching condition C<$cond>,
inserting a record with values in C<$default> in case it is missing.
C<$cond> is checked as in L</id_of>.

C<$opts> is an optional hash reference that can contain options
associated to keys C<select> (for searching the identifier using
L</id_of>) and C<insert> (for inserting a new record using
C<$default>), as well as C<db> (see L</db_and_opts>). The
same database handle is used for all queries in the call, overriding
any C<db> inside the C<select> and C<insert> options, which must be hash
references if present. Any other key in C<$opts> leads to an exception
with code 400 (as does a non-hash value for C<select> or C<insert>):
e.g. C<on_conflict> must go inside C<insert>, not at the top level.
The C<select> options follow the same rules as the options of
L</id_of>, so a sort specification goes inside C<order_by>.

Unless C<on_conflict> is set in the C<insert> options, the insertion
is done with C<on_conflict> set to C<undef> (i.e. C<DO NOTHING>). This
way, if another process inserts the same record between the search and
the insertion, no exception is thrown; the search is tried again
instead. After three unsuccessful rounds (i.e. three searches and three
insertions), an exception with code 409 is thrown. In practice this means that C<$default> conflicts (on some
unique key) with an existing record that does not match C<$cond>: make
sure C<$cond> covers the unique keys of C<$default>. The exception
carries no data, and the conflicting constraint is not known, because
C<DO NOTHING> does not report it.

=head2 init

   $wrap->init; # OR
   $wrap->init($name);

If available via L</migrations_for>, runs the migrations for the
specific class (see L</mdb_class>), using C<$name> as the name of the
migrations. C<$name> defaults to the string C<migrations>.

Returns the object itself.

=head2 insert

   my $id = $wrap->insert($tablish, $data); # OR
   my $id = $wrap->insert($tablish, $data, $opts);

Insert a new record based on hash reference C<$data>, returning the
identifier of that new record.

C<$opts> is an optional hash reference with options for the C<insert>
method of the C<db> object, e.g. C<on_conflict>, plus option C<db>
(see L</db_and_opts>). With the default
inserter (see L</default_inserter>), if C<on_conflict> leads to an
update of an existing record, the identifier of that record is
returned; if it leads to doing nothing, C<undef> is returned.

The insertion is done by the C<insert> sub of the selected wrapper,
see L</new>.

=head2 mdb

   my $mdb = $wrap->mdb;

Get the wrapped object (i.e. an instance of L<Mojo::Pg>,
L<Mojo::SQLite>, or whatever else was instantiated through any of the
C<wrappers> provided in L</new>).

=head2 mdb_class

   my $class = $wrap->mdb_class;

The class of the wrapped object, as set in the C<class> slot of the
selected wrapper (see L</new>). Technically, the wrapped object
I<might> be of another class.

The value of this method is used to select the relevant migrations when
calling L</init>.

=head2 mdb_module

   my $class = $wrap->mdb_module;

Alias for L</mdb_class>.

=head2 migrations_for

   my $hashref = $wrap->migrations_for;

Retrieve a hash reference with keys corresponding to classes of wrapped
objects (e.g. C<Mojo::Pg>, C<Mojo::SQLite>, see L</mdb_class>), and
values corresponding to the I<migrations> as strings (see e.g.
L<Mojo::Pg::Migrations/from_string>).

=head2 new

   my $wrap = MojoX::MojoDbWrap->new(%args); # OR
   my $wrap = MojoX::MojoDbWrap->new(\%args);

Create a new instance. Keys in C<%args> can be used to set L</db_url>
(required) and L</migrations_for>, as well as an array reference for
C<wrappers> as explained below.

Parameter C<db_url> is in general supposed to be a string that can be
used to instantiate a L<Mojo::Pg> object (if it starts with
C<postgres://> or C<postgresql://>, in any case) or a L<Mojo::SQLite>
object (any other string accepted by L<Mojo::SQLite/new>, e.g. a file
path or C<:memory:>). These are the two classes wrapped by default.

Parameter C<wrappers> allows providing a list of wrappers in case you
want to support further classes too. This list is given as an array
reference holding hash references with the following keys:

=over

=item C<can_limit>

a true value if the C<select> method of the C<db> object supports option
C<limit>, as with L<Mojo::Pg> and L<Mojo::SQLite> (which have it set).
When true, L</id_of> sets C<limit> to 1. Optional, defaults to false,
so a custom wrapper (even one for a subclass of L<Mojo::Pg> or
L<Mojo::SQLite>) has to set it explicitly to get C<LIMIT 1>.

=item C<class>

the name of the class, which in case of selection will also be used to
select the migrations (see L</init>). Required.

=item C<create>

a sub reference for creating a new instance, it will be called like
this:

   $sub->($class, $db_url)

with C<$class> the same as C<class> above and C<$db_url> the same as the
parameter C<db_url>.

The sub can return either a false value, in case it is not capable of
handling C<$db_url>, or an object that becomes the wrapped instance (as
returned by L</mdb>). Required.

The object must provide a C<db> method returning a database handle, as
L<Mojo::Pg> and L<Mojo::SQLite> do; it is called by L</db>, which is
used by all methods operating on records, including L</insert>.

=item C<insert>

a sub reference for inserting a new record. It will be called like this:

   $sub->($wrap, $tablish, $data, $opts)

where C<$wrap> is the MojoX::MojoDbWrap object, C<$tablish> is the name
of the table or an array reference with the name of the table and the
name of the identifier column (see L</DESCRIPTION>), C<$data> is the
data to insert and C<$opts> is a hash reference with insert options,
derived from the ones passed to L</insert>, L</upsert> (which turns
C<conflicting> into C<on_conflict>) or L</id_or_insert>.

When called by the methods of this module, C<$opts> always holds key
C<db> with the database handle to use, which must be honored to work
inside transactions and must not reach the C<insert> method of the
C<db> object: use L</db_and_opts> to get both the handle and the
remaining options. Also note that L</id_or_insert> sets
C<on_conflict> to C<undef> (i.e. C<DO NOTHING>) by default, which a
custom inserter for a backend not supporting it has to ignore or
translate.

The return value must be the identifier of the newly inserted (or
updated) record, or C<undef> if no record was inserted.

Optional, defaults to L</default_inserter>, which requires support for
C<RETURNING>.

=back

The hash references in C<wrappers> are copied, so they are not modified.
An exception with code 400 is thrown if C<wrappers> is not an array
reference, or any of its items is not a hash reference or lacks a
required key, or has a non-code value for C<create> or C<insert>.

When the wrapped object is needed, the C<create> subs of the items in
C<wrappers> are called in order, until one returns a true value, which
is taken as the wrapped object. L<Mojo::Pg> and L<Mojo::SQLite> are
always tried last, in this order; L<Mojo::SQLite> declines URLs it
cannot parse, e.g. C<mysql://...>.

If no item accepts C<db_url>, an exception with code 400 and message
C<unsupported DB URL> is thrown. The URL is neither part of the message
nor attached as exception data, as it might hold a password and
exceptions often end up in logs.

L<Mojo::Pg> and L<Mojo::SQLite> are not hard dependencies, and each is
loaded only when its turn comes. If the needed one is not installed, the
error from C<require> is thrown as is (not as an L<Ouch> exception).
As L<Mojo::SQLite> is the last resort, this means that without it any
C<db_url> not accepted by previous items leads to that error, even one
that would be unsupported anyway (e.g. C<mysql://...>).

=head2 upsert

   my $id = $wrap->upsert($tablish, $data, $opts);

Insert a new record, or update it if already present, returning its
identifier (see L</insert>). Option C<db> is supported as in
L</insert>.

The assumption is that a conflict in the insertion can arise on a
single column, or on a set of columns (e.g. a C<UNIQUE> constraint).
Pass its name, or an array reference with their names, as the value of
key C<conflicting> in C<$opts>, like this:

   $wrap->upsert($tablish, $data, { conflicting => 'name', ... });
   $wrap->upsert($tablish, $data, { conflicting => [qw< a b >], ... });

This generates an C<on_conflict> option for L</insert>, setting all
values in C<$data> I<except> the conflicting ones. If C<$data> only
holds the conflicting columns, the update sets the (first) conflicting
column to its own value, so that the identifier of the existing record
is still returned. Note that this is an update anyway, e.g. for
triggers.

All conflicting columns must have a defined value in C<$data>: as
C<NULL> values never conflict, a new record would be inserted every
time.

If you need a more nuanced I<upsert>, generate the C<on_conflict>
option yourself and pass it in C<$opts> without C<conflicting> (it's
still advisable to call this method instead of L</insert>, so that
you're explicit about your goal).

An exception with code 400 is thrown when:

=over

=item *

neither C<conflicting> nor C<on_conflict> is provided, as this would
be a plain L</insert>;

=item *

both C<conflicting> and C<on_conflict> are provided;

=item *

C<conflicting> is an empty array reference;

=item *

C<conflicting> is provided and C<$data> is not a hash reference (the
column names are needed);

=item *

any conflicting column is missing or C<undef> in C<$data>.

=back

=head1 SECURITY CONSIDERATIONS

First of all, read the L</COPYRIGHT AND LICENSE> section below very
carefully, then read on here.

With that as a basic foundation, this module tries to do its best to
avoid introducing any security issue, as well as trying to catch some
issues that might arise from the inputs it receives.

Some notes that you should keep in mind:

=over

=item *

You are supposed to validate all input parameters, especially those that
will be passed down to other modules that I<do what I mean>, like
L<SQL::Abstract> or its derivatives.

=item *

The condition parameter in L</id_of> and L</id_or_insert> should be used
to pinpoint at most one record. If it matches multiple ones, you are
probably doing something wrong; at the very least, you can't be sure to
receive a consistent response from your queries, unless you also set
option C<order_by> (in L</id_of>, or in the C<select> options of
L</id_or_insert>).

=item *

Again on the condition parameter, an undefined value or a value that is
not a reference leads to an exception with code 400: the latter would be
bound as C<WHERE ?>, so that e.g. C<"1"> would match every record.
Moreover, if the wrapped object supports method C<abstract> (as
L<Mojo::Pg> and L<Mojo::SQLite> do), the object it returns is assumed
to support L<SQL::Abstract>'s interface, including a C<where> method.
In this case, the module calls it to generate a WHERE clause and checks
whether it is empty, throwing an exception with code 400 if it is. This
still leaves you wide margins to shoot yourself in the foot, though,
like providing an always-true condition. Again, read the bullet
immediately before this.

=item *

Conditions, data and options are passed to L<SQL::Abstract::Pg> as they
are. Table and column names are quoted, and plain values are bound as
placeholders, so I<values> can safely come from users. The I<structure>
must not: nested hashes from untrusted inputs (e.g. from decoded JSON)
are read as operators like C<< { name => { -like => '%' } } >>, and
SQL::Abstract lets almost any operator text through to the query, i.e.
this is SQL injection. Build conditions and data in your code, from
scalar values, e.g. C<< { email => "$email" } >>, and never pass an
untrusted hash reference as it is.

=item *

Exceptions thrown by this module never hold the DB URL, which might
hold a password (see L</new>); connection errors from L<DBI> show the
database, host and user name, but not the password. The URL is still
available via L</db_url>, and the password via the wrapped object (e.g.
L<Mojo::Pg/password>): beware of dumping them, e.g. in logs. The
C<create> subs of custom wrappers receive the URL too: keep it out of
their exceptions.

=item *

Errors from the database are thrown as they are, and can hold values
from your data, e.g. PostgreSQL's C<Key (email)=(...) already exists>:
beware of exposing them, e.g. in HTTP responses or logs.

=item *

Parameters L</db_url>, L</migrations_for> and C<wrappers> (see L</new>)
must come from trusted sources, like your configuration or code:
migrations are run as SQL, wrappers are code, and both L<Mojo::Pg> and
L<Mojo::SQLite> turn the query string of the URL into options for
L<DBI>, e.g. C<?RaiseError=0>.

=back

=head1 BUGS AND LIMITATIONS

Minimum perl version 5.24.

Getting identifiers uses C<RETURNING>, so SQLite 3.35.0 or later is
needed. Please send requests/patches if you need support for something
older; most probably you will have to code a custom inserter anyway.

The test suite runs tests against PostgreSQL only if environment
variable C<TEST_PG> is set to a connection URL, e.g.:

   TEST_PG=postgresql://user@localhost:5432/test prove -l t

The tests create a schema with a unique name, and drop it at the end.

Please report any bug or feature request through the repository of the
project, available at L<https://codeberg.org/polettix/MojoX-MojoDbWrap>.
