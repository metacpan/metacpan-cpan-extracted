=head1 NAME

Fugu::OpenPGP - read an armored OpenPGP public key as bytes, and drive gpg(1) over a key

=head1 SYNOPSIS

    use Fugu::OpenPGP;

    my $pgp = Fugu::OpenPGP->new;
    die $pgp->error unless $pgp->is_available;

    $pgp->generate(
        email   => 'security@example.org',
        expires => time + 2 * 365 * 86_400,
        public  => '/etc/keys/example.asc',
        secret  => '/etc/keys/example.sec',
    ) or die $pgp->error;

    $pgp->sign(
        secret    => '/etc/keys/example.sec',
        file      => '/var/www/htdocs/KEYS',
        signature => '/var/www/htdocs/KEYS.asc',
    ) or die $pgp->error;

    my $key = $pgp->verify(
        keys      => ['/etc/keys/example.asc'],
        file      => '/var/www/htdocs/KEYS',
        signature => '/var/www/htdocs/KEYS.asc',
    ) or die $pgp->error;

    my $epoch = $pgp->expiry( public => '/etc/keys/example.asc' );
    die $pgp->error unless defined $epoch;

    # The byte reader needs no command.
    my $binary = $pgp->decode_armor($armored_text)
        or die $pgp->error;
    my $fingerprint = $pgp->fingerprint($binary)
        or die $pgp->error;

    my $hash = $pgp->wkd_hash('security');
    # .well-known/openpgpkey/hu/$hash

=head1 DESCRIPTION

Fugu::OpenPGP follows L<Fugu::Signer> over gpg(1). The parent holds
the constructor and the command resolution, the three verbs, the run
through L<Fugu::Process>, the key walk of a verification, and the
failure convention. This module holds the byte reader, the temporary
home, and the arguments of each gpg(1) command line.

The byte reader decodes the armor of RFC 4880. It computes the version
4 fingerprint of a public key packet. It also computes the Web Key
Directory hash of a local part. It runs no command, and it uses core
L<Digest::SHA> and core L<MIME::Base64>, so it adds no dependency. Each
reader is a method of the object, and a caller that reads bytes alone
needs no gpg(1).

The command part generates a key with an encryption subkey, it signs a
file, it verifies a detached signature, and it reads the expiry of a
key. Each half of a key enters as a path and leaves as a file, so no
key byte enters Perl.

The command part needs GnuPG 2.2 or later. It gives
C<--quick-generate-key>, C<--quick-add-key>, C<--pinentry-mode> and
C<--import-options show-only> to the command, and it stops the agent
with gpgconf(1). GnuPG 1.4 holds none of these, so a host that kept
C<gpg> for version 1 must carry version 2 as C<gpg2>.

Every recoverable failure returns C<undef>, and C<error> holds the
reason. No method answers the reason as a second return value. The
module never logs. The caller decides what to report.

A reader never dies for bad input: a key file comes from outside, so
bad bytes are data and not a programming error. A method dies for a
missing necessary argument alone, because that is a programming error.

=head2 The temporary home

Each run of gpg(1) takes a temporary home of its own, and the run
removes it. The module reads no home of the user, and no agent of the
user. A caller therefore signs with one key while the operator holds
another key in a keyring of their own.

The home can hold a secret half, so it holds no group mode and no
other mode. The generator names the destination of each half on the
command line, so gpg(1) writes both halves itself.

gpg 2 starts an agent under the home for a key operation, and an agent
that outlives its home leaks a process. Each run therefore stops that
agent with gpgconf(1) before it removes the home, per LIB-SIGNER-10.
gpgconf(1) ships beside gpg(1), so the module names it beside the
resolved command. An absent gpgconf(1) fails no call.

The home sits under C<TMPDIR> with a short name. The agent socket sits
in the home, and a unix socket path holds about 100 bytes.

=head2 new

C<new(command =E<gt> $command, timeout =E<gt> $seconds)> builds a
generator, a signer and a verifier. The method resolves the command
once, and it runs no process.

C<command> names the gpg command, as a name or as an absolute path.
Without the argument, the module walks C<$ENV{PATH}> over the search
list C<gpg2>, then C<gpg>.

C<timeout> is the bound of one run of the command, in seconds, and the
default is C<GPG_TIMEOUT>. A key generation needs entropy, so this
module raises the default of the parent.

C<new> must not die for an absent command. It sets C<error> instead,
and C<is_available> then returns 0.

=head2 is_available

C<is_available()> returns 1 when the object resolved an executable
command, and 0 otherwise. The method runs no process, and it never
dies. The byte reader needs no command, so the answer describes the
command part alone.

=head2 command

C<command()> returns the resolved command, or C<undef>. An operator
who installed the wrong C<gpg> needs this answer, and a caller can put
it in a diagnostic.

=head2 error

C<error()> returns the reason of the most recent failure. It returns
C<undef> after a success. Each method clears the reason before it
starts.

The reason of a failed run names the act and then the diagnostic of
gpg(1). The module takes the last line of that diagnostic, because
gpg(1) writes the reason last:

    cannot sign /var/www/htdocs/KEYS: no default secret key: No secret key

Each run takes C<LC_ALL=C>, so the diagnostic arrives in English under
any locale of the caller.

=head2 command_absent

C<command_absent()> returns 1 when the most recent failure means that
gpg(1) never ran. It covers a command that the search list did not
resolve, and a command that failed to execve(2). It returns 0
otherwise.

An absent command is an install problem, and a failed signature is an
integrity problem. The two answers let a caller tell them apart.

=head2 generate

C<generate(public =E<gt> $path, secret =E<gt> $path, email =E<gt>
$address, expires =E<gt> $epoch)> makes one Ed25519 key with one user
id, and one Curve25519 encryption subkey. It returns 1, or C<undef>
with the reason in C<error>.

C<public>, C<secret> and C<email> are necessary, and the method dies
without one. gpg(1) writes each half as armored text at its path.

The parent refuses a path that exists, so one call never overwrites a
key. It writes the private half in a private directory beside the
destination, it sets the owner-only mode there, and one rename then
moves the file into place. The export of the private half runs first,
so a failed call leaves no half behind.

The user id holds the email alone, in the form C<E<lt>addressE<gt>>. A
site publishes the public half, and a correspondent encrypts to the
subkey.

An angle bracket, a line ending or a NUL byte in C<email> would close
that user id and open a second one, so the key would carry an address
that the caller never named. The method refuses each of them, and an
empty address, before the command runs. Such a call makes no key.

C<expires> is optional, and it is seconds since the epoch, the unit
that C<expiry> answers. It must be a whole number after the current
time. The key and the subkey take the expiry that the caller named.
gpg(1) writes each expiry as a duration from a creation time, so the
subkey expiry can fall one second before the key expiry. With no
C<expires> neither holds one.

The key carries no passphrase, so the caller owns the storage of the
private half.

=head2 sign

C<sign(secret =E<gt> $path, file =E<gt> $path, signature =E<gt>
$path)> signs one file with a private half. It returns 1, or C<undef>
with the reason in C<error>. Each argument is necessary, and the
method dies without one.

gpg(1) reads the private half from the path, and it writes the armored
signature file itself, so no key byte enters Perl. A second call over
one C<signature> path replaces the file, because a rotation signs one
manifest again.

The parent refuses an input path that is no plain file, before the
command runs.

=head2 verify

C<verify(keys =E<gt> \@paths, file =E<gt> $path, signature =E<gt>
$path)> verifies one detached signature against a key set, in trust
order. Each argument is necessary, and the method dies without one. An
empty C<keys> list is a programming error, and the method dies for it
too.

The method returns the public key file that verified the signature. It
returns C<undef> on every failure. The walk pins one key in one run:
the temporary home takes that one public half, so a signature of
another key fails with C<Can't check signature: No public key>. A
signature over other bytes fails with C<BAD signature>. The keyring of
the operator holds no part in the answer.

For a signature that no key verified, C<error> names the file and then
each key with its own reason.

=head2 expiry

C<expiry(public =E<gt> $path)> returns the expiry of a public half, as
seconds since the epoch. It returns 0 for a key that holds no expiry,
and C<undef> with the reason in C<error> on a failure.

The three answers differ on purpose. A caller tells C<no expiry> from
C<cannot read> with one test, and a key with no expiry never reads as
a key that expired.

The read imports nothing: gpg(1) shows the key and drops it, so the
home keeps no keyring. A file that is no key is a failure, and the
reason comes from gpg(1).

=head2 decode_armor

C<decode_armor($text)> returns the binary form of an armored block, or
C<undef> with the reason in C<error>.

The method reads the two delimiter lines, it skips the armor headers,
it decodes the base64 body, and it compares the CRC-24 checksum line
against the decoded bytes.

The checksum comparison is not decoration. A decoder that skips it
accepts a truncated key, and a truncated key gives a fingerprint of
its own. A caller would then publish a fingerprint that no key
matches.

The padding of base64 ends the data, so it may sit at the end of the
last body line only. A line with interior padding decodes to a
truncated key, and a crafted checksum line would still agree with the
truncation. gpg(1) rejects such a block, and so does this method.

The method reads the first block of the text. A text with several
blocks therefore gives the first key, and the rest stay unread.
C<Fugu::KeyDir::keys_file> writes such a text, so a caller that wants
every key of a C<KEYS> file must split the text itself.

Armor is text, so the method reads either line ending. A block that
travelled through email holds CRLF, and it decodes to the same bytes.
The method also trims the whitespace of each body line, because a
mailer can pad one.

The method never changes the string of the caller.

Each of these is a failure:

=over 4

=item * a missing delimiter line

=item * two delimiter lines that name two block types

=item * an absent blank line after the armor headers

=item * an armor header with a value and no space after the colon

=item * a body line that is not base64

=item * a base64 body that is not a whole number of groups

=item * an absent checksum line, or more than one

=item * a body line after the checksum line

=item * a checksum mismatch

=back

The blank line after the armor headers is necessary. RFC 4880 states
it, and gpg(1) rejects a block without it. This method must not
accept a block that gpg(1) rejects, because a site would then publish
a key that no consumer can import.

The method trims the two ends of each body line, so a mailer that
padded a line changes nothing.

The rule runs one way only. The method never accepts a block that
gpg(1) rejects, so a key that this method validated always imports.
The method can reject a block that gpg(1) reads, and it does so for
each of these:

=over 4

=item * a body line with interior whitespace

=item * a second checksum line

=item * a body line after the checksum line

=item * two delimiter lines that name two block types

=item * a text above C<MAX_ARMOR_SIZE>

=back The bound C<MAX_ARMOR_SIZE> applies to the whole text, and not to one
block. A text above 1 MiB is a failure, whatever the size of its
first block.

=head2 fingerprint

C<fingerprint($binary)> returns the version 4 fingerprint of the first
packet, in upper-case hexadecimal with no separator, or C<undef> with
the reason in C<error>.

The fingerprint is the SHA-1 of the byte C<0x99>, the two-byte length
of the public key packet body, and that body, per RFC 4880 section
12.2. The method reads the length from the packet header and writes
the length again, so the same key gives the same answer in the old
packet format and in the new one.

The method reads both header formats. It reads every length form that
carries a whole packet. The old format has a one-byte, a two-byte and
a four-byte form, and the new format has a one-byte, a two-byte and a
five-byte form.

Two forms carry no whole packet, and the method rejects each one: the
indeterminate length of the old format, and a partial body length of
the new one. A public key packet never uses either.

The digest writes the body length in two octets. A body above
C<MAX_PACKET_BODY> therefore has no version 4 fingerprint, and it is
a failure. C<pack> would wrap the length with no warning, and the
method would then answer with a confident wrong fingerprint.

A first packet that is not a public key packet, a packet version other
than 4, and a truncated packet body are each a failure.

=head2 wkd_hash

C<wkd_hash($local)> returns the Web Key Directory hash of an email
local part, or C<undef> with the reason in C<error>.

The hash is the z-base-32 form of the SHA-1 of the local part in lower
case. C<gpg --locate-keys> asks for
C<.well-known/openpgpkey/hu/E<lt>hashE<gt>>, so the answer decides the
publication path.

The method folds the ASCII letters of the part itself, so the case of
an ASCII local part never changes the path. It leaves every byte above
127 alone, because gpg(1) does: a lowercase step that reads such a
byte as Latin-1 would rewrite the bytes of a UTF-8 local part.

An undef local part and an empty one are each a failure.

=head2 zbase32

C<zbase32($bytes)> encodes bytes in z-base-32. C<wkd_hash> calls it,
and a caller can call it for another purpose.

The alphabet is C<ybndrfg8ejkmcpqxot1uwisza345h769>, and it is not the
RFC 4648 alphabet. The order differs, so the same digest gives a
different string. A caller that swaps the alphabet publishes a key at
a URL that gpg(1) never asks for.

The encoding writes no padding, and it emits one character for each
five bits. A byte count that is not a multiple of five therefore ends
on a partial group, and the low bits of that group are zero. An undef
input and an empty one each give the empty string.

=head1 CONSTANTS

=over 4

=item C<MAX_PACKET_BODY>

The largest public key packet body that a version 4 fingerprint can
hold, 65535 bytes, per RFC 4880 section 12.2.

=item C<MAX_ARMOR_SIZE>

The size bound of the whole text, 1 MiB. A public key of a person
holds a few kilobytes. A caller that names a disk image by mistake
gets a clean failure, not a decode of 500 MB.

=item C<PACKET_PUBLIC_KEY>

The tag of a public key packet, 6, per RFC 4880 section 4.3.

=item C<ZBASE32_ALPHABET>

The z-base-32 alphabet of the Web Key Directory.

=item C<CRC24_INIT>, C<CRC24_POLY>

The initial value and the generator polynomial of the armor checksum,
per RFC 4880 section 6.1.

=item C<GPG_TIMEOUT>

The default time bound of one gpg(1) call, 60 seconds. A command that
a caller named can be the wrong program, and a key generation needs
entropy.

=item C<GPG_FLAGS>

The flags of every gpg(1) call. They hold the command away from a
terminal and away from a passphrase prompt.

=back

=head1 RETURN VALUES

Each method returns its answer, or C<undef> on a failure, and C<error>
holds the reason of that failure. No method answers the reason as a
second return value.

Each reader rejects a string that holds a code point above 255.
L<Digest::SHA> dies on such a string, and a byte unpack takes the low
byte of each character. A caller that holds text must encode it first.

=head1 CAVEATS

The byte reader reads the first packet of a block only. An armored key
holds a public key packet first, then the user id packets, the
signature packets and the subkey packets. A caller that needs a subkey
fingerprint needs a full packet walk, which this module does not hold.

A fingerprint proves which bytes the block holds. It proves nothing
about who made them. C<verify> answers the second question, over the
key set that the caller names.

The module makes no revocation certificate, and it edits no user id. A
retired key stays published, and a compromise takes a human decision.

The generator makes a key with no passphrase, because a daemon holds
no operator to type one. The caller owns the storage of the private
half.
