=head1 NAME

Acme::Parataxis::Sync - Base Class for Fiber Synchronization Primitives

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber];
    use Acme::Parataxis::Sync::Mutex;
    use Acme::Parataxis::Sync::WaitGroup;

    my $lock  = Acme::Parataxis::Sync::Mutex->new;
    my $group = Acme::Parataxis::Sync::WaitGroup->new;

    async {
        $group->add(4);

        for my $id ( 1 .. 4 ) {
            fiber {
                my $guard = $lock->guard;    # mutex held for scope of $guard
                perform_exclusive_operation($id);
                $group->done;
            };
        }

        $group->wait;    # parks until all 4 workers call done()
        say 'All workers completed safely!';
    };

=head1 DESCRIPTION

C<Acme::Parataxis::Sync> is the abstract base class powering the Parataxis synchronization primitive family:

=over

=item * L<Acme::Parataxis::Sync::Mutex> - Non-reentrant mutual exclusion locks with owner tracking and scope guards.

=item * L<Acme::Parataxis::Sync::RwLock> - Writer-preferring reader/writer locks with shared and exclusive guards.

=item * L<Acme::Parataxis::Sync::WaitGroup> - Concurrency counters that block until tasks decrement to zero.

=item * L<Acme::Parataxis::Sync::Barrier> - Fixed-party phase rendezvous gates.

=item * L<Acme::Parataxis::Sync::Once> - Thread-safe, single-execution initializers.

=back

All primitives share uniform operational guarantees:

=over

=item *

B<Scheduled cooperative parking>: Waiting fibers suspend cleanly in the scheduler; neither the OS thread nor the event
loop is ever blocked.

=item *

B<Context validation>: Methods that manage locks or waits resolve the calling fiber's ID immediately via C<_fid()>,
croaking with a descriptive error if called outside a scheduled fiber.

=item *

B<Safe wait unwinding>: Every wait is interruptible via L<with_timeout|Acme::Parataxis/with_timeout> and cancellation
tokens. When an interrupted wait unwinds, the primitive dequeues the fiber so stale wakeups never target reused fiber
IDs.

=back

=head1 SUBCLASS CONTRACT

The base class provides internal helpers for implementing custom synchronization objects:

=head2 C<_fid( $croak_message )>

Returns the numeric fiber ID of the currently executing fiber. If called from outside a scheduled fiber, croaks with
C<$croak_message>.

=head2 C<_park( $reason, [$dereg_coderef] )>

Parks the calling fiber in the scheduler with diagnostic label C<$reason>. If the park is interrupted by a timeout or
cancellation, C<$dereg_coderef> is executed immediately to clean up wait queues.

=head2 C<_wake( $fiber_id )>

Re-enqueues the fiber with ID C<$fiber_id> onto the scheduler run queue. If the fiber has already been destroyed or
reaped, the wake is safely dropped.

=head1 How Contended Waits Work

Contended acquisitions in Parataxis follow a strict four-stage cycle:

=over

=item 1.

B<Resolve the fiber ID>: Verify the calling fiber exists via C<_fid()>.

=item 2.

B<Evaluate immediate acquisition>: Uncontended locks, matching phases, or positive counts resolve immediately without
touching scheduler queues.

=item 3.

B<Queue and park>: The fiber ID and an unregister callback are added to the primitive's FIFO queue, and the fiber
parks. If interrupted, the callback cleans the queue.

=item 4.

B<Atomic hand-off>: When a releasing fiber calls C<unlock()> or C<done()>, ownership is assigned to the next waiter
B<before> the waiter is enqueued. This prevents third-party fibers from stealing the resource before the woken waiter
runs.

=back

=head1 Behavior Notes

=over

=item * Locks outlive fibers

If a fiber acquires a C<Mutex> or C<RwLock> and terminates without calling C<unlock()>, the lock remains held
permanently. Always use scoped guards (C<guard>, C<read_guard>, C<write_guard>) to guarantee release upon scope exit or
exception unwinding.

=item * Guards cannot cross fibers

Guards verify that the releasing fiber matches the acquiring fiber upon destruction. Passing a guard object to another
fiber will cause the guard's destructor to croak and strand the lock.

=item * Off-fiber arithmetic

C<WaitGroup->add> and C<WaitGroup->done> perform plain counter arithmetic and are safe to call outside a scheduled
fiber. All methods that actually park (such as C<wait>, C<lock>, and C<arrive_and_wait>) require an active fiber.

=back
