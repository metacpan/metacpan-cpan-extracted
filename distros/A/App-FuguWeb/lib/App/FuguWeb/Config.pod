=head1 NAME

App::FuguWeb::Config - the site description over Fugu::Config

=head1 SYNOPSIS

    use App::FuguWeb::Config;

    my $config = App::FuguWeb::Config->load(error => \my $reason)
        or die "$reason\n";

    say $config->site;
    say $_->{href} for $config->nav;
    say $_->{file} for $config->pages;

=head1 DESCRIPTION

The class reads F<.fuguwebrc>, applies the defaults, and validates the
result. The grammar, the quoting, and the yes/no spellings come from
L<Fugu::Config>; this class holds what is true of a site.

The description is UTF-8, per WEB-SITE-5. Each value that a reader
sees is characters: the site name, the name of a language, a title, a
label and a heading. Each other value names a file or an address, so it
stays bytes.

=head2 Languages

A C<language> block declares one language. The block name is its tag,
and the order of the blocks is the order of the languages. The first
one is the default, per D-05. A description with no C<language> block
has the one language C<en>.

    language en {
            name = English
    }

    language pt-BR {
            name   = Portugues
            site   = Exemplo
            footer = pt-br/footer.body.html
    }

A tag is a BCP 47 tag in its canonical case, per WEB-LANGUAGE-1. The
block takes a C<name>, and an optional C<dir> of C<ltr> or C<rtl>. It
can take a C<site> and a C<footer>, which take the place of those of
the description in that language. L<App::FuguWeb::Language> holds each
language.

The object is immutable once loaded, and the module keeps no package
state. Two sites in one process therefore share nothing.

=head2 Translations

A block of one argument is the default. A block of two is a
translation: the first argument is the tag of a declared language other
than the default, and the second names the default block that it
translates.

    page de "index.html" {
            title = Start
            body  = de/index.body.html
    }

A C<page>, a C<nav>, a C<manuals> and a C<modules> block can take a
translation. A translation of a C<page> takes C<title>, C<body> and
C<markdown>. A translation of a C<nav> takes C<label>. A translation of
a group takes C<heading> and C<dir>.

A page of a language takes each value of its translation, and the
value of the default block where the translation holds none. The
merged page obeys the rules of a default page. Thus a translation that
names C<markdown> for a page with a C<body> fails, because the page
then names two sources.

=head1 METHODS

=head2 load

    App::FuguWeb::Config->load(
        root  => $dir,          # default: discover
        error => \my $reason,
    )

Read and validate the description. The method returns the object, or
C<undef> with the reason in C<$reason>.

Without C<root>, the method walks up from the working directory to the
first directory that holds F<.fuguwebrc>, as C<fuguvm> finds
F<.fuguvmrc>.

The reason travels through a reference because the object that would
hold it does not exist when the load fails.

A load fails when the file is absent, when a line does not parse, or
when the description would make the build do something it must not.
Every message names the file, and the block when a block is at fault.

The description is rejected when:

=over 4

=item *

the description is not UTF-8, per WEB-SITE-5;

=item *

it names a block type or a setting that fuguweb(1) does not document,
per WEB-SITE-4. An old setting fails the same way;

=item *

there is no C<site> setting, or no C<url>. The C<url> is the absolute
URL of the site root: it starts with C<https://> or C<http://>, and it
ends in a solidus;

=item *

a C<language> block names no tag of WEB-LANGUAGE-1, a tag that a block
declares once more, no C<name>, or a C<dir> of another word;

=item *

a C<page> block names no source, or more than one. An C<index> page
can take a C<body> as well, which opens it;

=item *

two C<page> blocks name the same file, or two manuals, or a manual and a
C<page> block, would become the same page. Each test folds each name,
per WEB-OUTPUT-17;

=item *

a C<nav> block has no label;

=item *

a translation names a tag that no C<language> block declares, or the
tag of the default language;

=item *

a translation takes more than two arguments, names no default block
of its type, or comes twice for one name and one language;

=item *

a translation names a setting outside the set of its type;

=item *

a C<language>, a C<keys> or a C<key> block takes a translation;

=item *

a group block names no C<heading>, or its name is not one word of
lowercase letters, digits and hyphens, or two groups share one name;

=item *

a source of the C<dir> of a group translation has no namesake in the
default C<dir>;

=item *

a path setting steps out of the project with a C<..> component;

=item *

the C<source_dir> is the project root, per WEB-SITE-7. The record of
the translations sits there, per WEB-STATUS-1, and the build publishes
each plain file of the source directory;

=item *

a C<page> block name is absolute or steps out of the output directory:
the name becomes a file there, so it is a path and gets the same guard
the sources get;

=item *

a C<manuals> namespace holds a path separator: it prefixes a manual
name, and that name becomes both the staged file and the published
page;

=item *

a C<modules> directory is not below C<module_root>, which would leave
the module with no name to take but its whole path;

=item *

the path of a source from the project root holds ASCII white space or
a parenthesis, per WEB-SITE-6. A source is a page source, a manual or a
footer fragment, of any language;

=item *

a yes/no setting holds something that is neither;

=item *

the top level of the source directory holds a symlink, or the path of a
fragment that the build reads holds one. The rule holds for the file,
and for each directory between the source directory and the file.
Every file at the top level that the build does not render is copied
into the site. The fragments are the body fragment of each page in each
language, and the footer of each language. A symlink would publish
whatever it points at, from anywhere on the machine.

=back

A C<keys> block adds its own rules. The description is rejected when:

=over 4

=item *

two C<keys> blocks name one directory, or one C<org> word, or a C<key>
block stands with no C<keys> block;

=item *

the C<keys> block names no C<org>, or an C<org> that no key name can
hold;

=item *

the C<keys> name is not one segment below the source directory, names a
directory of the path, names the staging directory of the build, is the
path of the tree of a declared language, or names a file that the site
already holds. Each test of the name against another name, and the
test of two C<keys> blocks of one directory, folds the two, per
WEB-OUTPUT-17;

=item *

the C<keys> block names a C<contact> without an C<expires>, or the
other way round, or an C<expires> that RFC 3339 does not hold;

=item *

the C<keys> block names a C<url> that is not absolute;

=item *

the key directory holds no C<SHA256>, no C<SHA256.sig>, or a symlink;

=item *

a C<key> block names no file, more than one file, or a setting that no
block defines;

=item *

a C<key> block names a status outside C<current>, C<next> and
C<retired>, or a second block declares the same key;

=item *

a C<key> block names a setting that its type does not take: an
C<email> or a C<fingerprint> on a signify key, and an C<email> on a
certificate;

=item *

an C<email> is not a local part and a domain, or a C<fingerprint> does
not hold the width of its type. The fingerprint of an OpenPGP key
holds 40 hexadecimal characters, and the SHA-256 of the DER of a
certificate holds 64.

=back

L<App::FuguWeb::Keys> documents the blocks and the published tree.

=head2 root, path

The project root, and the F<.fuguwebrc> that this object read.

=head2 source_path

    my $dir  = $config->source_path;
    my $file = $config->source_path('footer.body.html');

The source directory, or one file in it.

=head2 site, url, out_dir, source_dir, entry, module_root, man_url, stylesheet

The settings. C<site> and C<url> are the ones a project must give.

    site            (required)  the site name of each language whose
                                block names none, as characters
    url             (required)  the absolute URL of the site root
    footer          (none)      the footer fragment of each language
                                whose block names none, below the
                                source directory
    out_dir         web/build   where the build writes
    source_dir      web         the fragments and the assets
    entry           index.html  the front page of each tree, and the
                                header link
    module_root     lib         the prefix a module name drops
                                (a trailing slash is dropped)
    man_url         https://man.openbsd.org/   where a remote .Xr goes
    stylesheet      (searched)  the base stylesheet

L<App::FuguWeb::Language/site> and L<App::FuguWeb::Language/footer>
answer the site name and the footer of each language.

C<stylesheet> overrides the search that L<Fugu::File/share_path> does.
The search finds the sheet that ships with the tool, so most projects
never set it. L<App::FuguWeb::Site/THE STYLESHEET> states the search.

=head2 url_path

The path of the C<url>: the part after the host, which starts and ends
with a solidus. A page of the top level carries it as its C<base>, per
WEB-TOP-3, and the check takes that C<base> as the one root-absolute
href, per WEB-LINKS-4.

=head2 nav

    my @nav = $config->nav('de');

The navigation of one language, in file order. Each entry is a hashref
with C<href>, C<label> and C<label_lang>. The tag defaults to that of
the default language, and an C<href> is the same in each language. The
C<label_lang> is the tag of the language of the label, per
WEB-LANGUAGE-8.

=head2 pages

    my @pages = $config->pages('de');

The pages of one language, in file order. The tag defaults to that of
the default language. Each entry is a hashref:

    file        the name of the page in each language tree
    title       the title, which defaults to the file name
    source      one of body, markdown or index
    value       what the source names; for index, the body
                that opens the page, or undef
    unlinked    true when no other page links to it
    lang        the language of the value: the tag of the
                page when its translation names the value,
                and the default tag otherwise
    title_lang  the language of the title, by the same rule

=head2 groups

The manual groups, in file order. Each entry is an
C<App::FuguWeb::Config::Group>, and the two block types interleave as
the description wrote them.

=head2 languages, default_language, language

    my @languages = $config->languages;
    my $default   = $config->default_language;
    my $chinese   = $config->language('zh-Hans');

Each L<App::FuguWeb::Language> of the site, in the order of the
declaration, the default first. Each one names a tree of the output,
below the path of its tag. C<language> answers the declared language of
a tag, or C<undef>.

=head2 page_names

The name of each page of one language tree: the pages of the
description, then one page for each manual of each group. Each tree
holds the same names.

=head2 top_pages

The pages of the top level: F<index.html>, which forwards to the entry
page of the default tree, and F<404.html> when the description holds
that page.

=head2 inventory

Every path that the output directory must hold after a build: each
page of each language tree, the pages of the top level, the
stylesheet, the assets, and each key directory. The build and the
checks read the same list, so the two can never disagree about what
the site holds.

A page of a tree is C<< <path>/<page> >>, for example
F<zh-hans/manuals.html>. The pages of the top level, the stylesheet and the
assets are file names. A key directory is one part below the root, so
its entries hold a solidus.

=head2 keys_dirs

The name of each key directory, in file order. The list is empty when
the description holds no C<keys> block, so it is the test for one.

A description can hold several C<keys> blocks, and each one names one
directory. Each directory holds its own root of trust, per D-02, and a
binding never crosses a directory. Two blocks must not name one
directory.

=head2 keys_org, keys_contact, keys_expires, keys_url

    my $org = $config->keys_org('keys');

The settings of one C<keys> block. Each accessor takes the name of the
directory, and each one answers C<undef> for a name that no block
holds.

    keys_org     (required)  the first field of every key name
    keys_contact             the Contact field of security.txt
    keys_expires             the Expires field of security.txt
    keys_url                 the published prefix of the directory,
                             with no trailing slash

RFC 9116 makes C<Contact> and C<Expires> both necessary, so C<contact>
and C<expires> stand or fall together. The C<Encryption> field needs
an absolute URL, so a block that names no C<url> writes no such field.

A site publishes one F<security.txt>, so one block alone names the
contact and the expiry. A second block that names either one fails the
load.

=head2 keys_path

    my $dir  = $config->keys_path('keys');
    my $file = $config->keys_path( 'keys', 'SHA256' );

One source key directory, or one file in it. The method answers
C<undef> for a name that no C<keys> block holds.

=head2 site_keys

    my @key = $config->site_keys('keys');

The C<key> blocks of one key directory, in file order. The directory
that holds the file owns the block, as the extension of that file owns
the type. A stem that two directories hold fails the load.

Each entry is a hashref:

    name         the key file in the directory
    stem         the block name, which is the name without the
                 extension
    type         signify, openpgp or x509, from the extension
    serial       the rotation count of the purpose
    purpose      what the key signs
    status       current, next or retired
    since        the date the key took its status, or undef
    until        the date it left it, or undef
    email        the address of an OpenPGP key, or undef
    wkd          the Web Key Directory hash of that address
    fingerprint  the declared fingerprint, in upper case, or undef

The list is named C<site_keys> and not C<keys>, because a method named
C<keys> in the package makes every call of the builtin ambiguous.

=head2 site_bindings

    my @binding = $config->site_bindings('keys');

The binding files of one key directory, in name order. A binding is
the signature of one key file by another key of the same directory.
Each entry is a hashref:

    name     the binding file in the directory
    target   the key file that the signature covers
    signer   the key file of the key that signed it
    type     the type of the signer

A binding carries no block: its name holds every field, and
L<Fugu::KeyDir> parses it. The list holds a binding whose target and
whose signer are both keys of that directory, and
L<App::FuguWeb::Keys> reports every other name as a stray file.

=head2 key_paths

Every path of every key directory in the output, relative to the
output directory, or the empty list when the description holds no
C<keys> block. L</inventory> holds the same paths.

The site holds one well-known tree, and each directory writes into it.
The list therefore holds one entry for the policy file, and one for an
address that two directories name.

=head2 sources

    my @paths = $config->sources;

The path of each source that a build reads, below the project root,
per WEB-OUTPUT-18. The files come first: each body, Markdown page,
manual, POD sidecar and footer of each language, and the C<stylesheet>
that the description names. The directories follow: the source
directory, each key directory, and the C<dir> of each group in each
language. L<App::FuguWeb::Site> refuses an output directory that holds
one, and names the first one that it meets.

=head1 GROUPS

A C<manuals> or C<modules> block becomes one group. A group never holds
a list of manuals: it reads its directory, so a manual that is added
reaches the site with no edit anywhere.

A group whose directory does not exist fails the load and names the
directory. A silent empty group hides a typo in a path, and a rename
that nothing catches is what this file exists to prevent.

=head2 kind, name, namespace, lang

C<kind> is C<manuals> or C<modules>. C<name> is the block name, which
becomes the C<id> of the C<< <h2> >>. Every language shares it. C<lang>
is the tag of the default language, and a manual of the default
C<dir> is of that language.

=head2 heading

    my $text = $group->heading('de');

The text of the C<< <h2> >> in one language, as characters: the
heading of the translation, or the default heading. The tag defaults
to that of the default language.

=head2 heading_lang

    my $tag = $group->heading_lang('de');

The language of that text: the tag when the translation names a
heading, and the default tag when the group takes the default heading,
per WEB-LANGUAGE-8. The tag defaults to that of the default language.
The index marks a heading of another language than the page, per
L<App::FuguWeb::Index/body>.

=head2 translate

    $group->translate( 'de', heading => $text, dir => $path );

Give the group the heading and the directory of one language. A
C<heading> of C<undef> keeps the default heading, and a C<dir> of
C<undef> keeps the default sources for that language. The description
calls it once for each translation of the block.

=head2 dirs

    my @dirs = $group->dirs;

The directory of the group in each language: the default C<dir>, then
the C<dir> of each translation that names one, in the order of the
tags.

=head2 manuals

    my @manuals = $group->manuals('de');

The manuals of the group in one language, in the order the index shows
them, as L<App::FuguWeb::Manual> objects. The tag defaults to that of
the default language. The method reads each directory once and keeps
the answer.

A translation C<dir> mirrors the default C<dir>. The namesake of a
source is the source of the same path below the other directory, and
the umbrella of a C<modules> group is the namesake of the umbrella. A
manual of a language comes from its namesake when the translation
C<dir> holds one, and from the default source otherwise. It keeps the
name and the page of the default source, so each language holds the
same pages.

A C<manuals> group reads its directory for F<*.1>, F<*.3p>, F<*.5>,
F<*.7> and F<*.8>, and takes a plain file only. It does not glob:
Perl's C<glob> splits its pattern on whitespace and reads
C<[ ] { } ? ~>, so a project whose path holds one of them would lose
its manuals or collect a sibling directory's. It sorts by section, in
the order 1, 3p, 5, 7, 8, and then by file name. The C<namespace>
setting prefixes the name and the staged file name, so
F<man/fugu/Daemon.3p> becomes C<Fugu::Daemon(3p)>.

A C<modules> group finds every F<.pod> file below its directory, and the
sidecar that names the directory itself: F<lib/App/FuguWeb.pod> is the
umbrella of F<lib/App/FuguWeb/>. It sorts by path, so F<Store.pod> stays
before F<Store/Memory.pod>.

Both sorts compare bytes and never read the locale of the builder. A
site must not depend on the machine that built it.

Never name a directory that holds more than one namespace. In this
repository F<lib/App> is such a directory, and one group there would
swallow three namespaces.

=head2 orphan

    my $path = $group->orphan('de');

The first source of the translation C<dir> of one language that has no
namesake in the default C<dir>, or C<undef>. The description refuses a
group with an orphan.
