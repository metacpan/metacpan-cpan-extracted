# 段落 reflow（`--reflow`）設計メモ

2026-11-01。検討のみ、未実装。方式は未決定で、三つの案を並べて比較する。別セッション（app-mdee-87）からの引き継ぎ（pandoc 前処理案）と、このセッションでの pandoc 3.13 の検証結果、設計メモの第三者確認の指摘をまとめた。

## 背景と目的

mdee は「書かれたとおりに見せる」方針で段落を reflow しない（CLAUDE.md の Concept）。そのため 70 桁などで段落内改行された原稿は nup のペイン幅と合わず、短い行と折り返し行が混ざって読みにくい。LLM が生成する文書にこの形が多い。

目的は、opt-in の `--reflow` オプションで段落・引用・リスト項目の行を 1 行につないでから mdee の通常の折り返しに渡すこと。既定の動作は変えない。

## どの案でも共通のこと

- オプションは `--reflow`（ブール、既定 off、`--no-reflow` 可）。config.sh に `default[reflow]`。`fold` と同じ `_` 番兵方式で「指定なし」を区別する。
- `--style` と `--no-theme` には直交させる。`--no-theme` は色とマーカーの話で、`--reflow` は入力の変換。POD の「`--no-theme` gives back the original file」に「unless `--reflow`」を添える。
- Concept（CLAUDE.md と POD）の「paragraphs are not reflowed」を「not reflowed unless `--reflow`」に改める。どこまで変わるかは案で違うので、文言は案が決まってから。
- hard break（行末 2 スペース、行末 `\`）は改行として残す。
- 詩・住所・歌詞のように hard break 無しで改行に意味を持たせた素のテキストは、どの案でも Markdown の規則どおりつながる。`--reflow` は opt-in なので、そうした文書では使わない、というのが答え。
- nup を使わないスタイルのうち pager と cat では、md モジュールが折るのはリスト項目と定義だけで、普通の段落は nup が折っている。reflow で 1 行になった段落を `mdee -p --reflow` や `-s cat --reflow` で誰が折るかを決める必要がある。fold が無効のとき（filter、raw、`--no-fold`）は無加工で見せる場面なので、つないだ段落は 1 行のまま出してよく、禁則や単語境界を気にする必要はない（ユーザーの判断、2026-11-01）。つまり決めるのは「fold が有効で nup が無いとき」だけ。端末任せ（less や端末の文字単位の折り返し、単語境界も禁則も効かない）で良しとするか、`--reflow` のときは md の `--fold-by` の対象に「つないだ段落」を加えて折るか。後者なら B と C では「つないだ行」をそのまま対象にできる。A では pandoc 出力に対する段落パターンを別に作る。
- 和文の結合規則は三つ: 全角句読点の後ろの改行は詰める、両側が CJK の改行は詰める、それ以外は空白 1 個にする。ansifold の `fill_up` と同じ。英文と和文の境目には空白が入る。
- pandoc を使う案（A、B）では pandoc は任意依存。cpanfile には書かず、README と POD に「`--reflow` には pandoc が要る」と書く。`--reflow` 指定時に pandoc が無いか古ければ mdee 自身が明確なエラーで止める（greple の `--if` の中で pandoc が失敗すると空出力や greple のエラーになって分かりにくい）。CI で pandoc を入れて実出力まで検証するか、無ければ skip して `-n` の照合だけにするかも決める。
- 所要時間: README.md（約 1000 行）で pandoc は約 0.17 秒。

## 案 A: pandoc で書き直す（引き継ぎの案）

pandoc に gfm として読ませ、`--wrap=none` で gfm として書き出させる。段落の境界判定を丸ごと任せられ、mdee 側のコードは最少。入力は `gfm` に限る（`commonmark` は表が壊れ、`markdown` は表が simple table になる）。

### コマンド（検証済み）

```
pandoc -p \
  -f gfm+east_asian_line_breaks+definition_lists-tex_math_dollars-tex_math_gfm \
  -t gfm+definition_lists-tex_math_dollars-tex_math_gfm \
  --wrap=none --columns=WIDTH --lua-filter=share/pandoc/reflow.lua FILE
```

- `-p`（`--preserve-tabs`）: 無いとコードブロック内のタブが空白になる。
- `east_asian_line_breaks`: 両側が和文の改行を空白なしでつなぐ。無いと「日本語の段落も 途中で改行されて いる。」のように空白が入る。
- `definition_lists` を reader と writer の両方に: 無いと `Term\n: Def` が `Term : Def` の 1 段落になり、md モジュールの DEFINITION パターンに合わなくなる。
- `tex_math_dollars` と `tex_math_gfm` を reader と writer の両方で無効に: 既定では `$x^2$` が `` $`x^2`$ `` になり、`$5-$10` が `\$5-\$10` になる。reader だけ無効にしても writer が `$` をエスケープする。対象文書では金額の `$` の方が数式より多いと考えた。`tex_math_gfm` は pandoc 3.1.9（2023-10）から。それより古い版では未知の拡張として異常終了するので、下限を 3.1.9 にするか、`--list-extensions` で有無を見て付け外しするかを決める。
- `--wrap=none`: 段落を 1 行にする。
- `--columns=WIDTH`: 水平線 `***` が `-` の並びになる。既定の 72 桁でペイン幅より長いと折り返されるので、mdee の fold 幅を渡す。
- Lua フィルタ（必須）: info string の無いフェンス（```` ``` ```` だけの行、`~~~` も）は gfm writer がインデントコードブロックにしてしまう。md モジュールはインデントコードを保護も着色もしないので、中の `*x*` が強調され背景色も付かない。属性の無い CodeBlock を `pandoc.RawBlock('markdown', "```\n…\n```")` にして返すと gfm writer はそのまま通し、フェンスが残る（3.13 で検証済み。下限を下げるなら古い版で再検証）。`share/pandoc/reflow.lua` に置き、テーマと同じく `$share_dir` から探す。

### 組み込み

greple の `--if` 入力フィルタ（`--` の後ろ）に pandoc のコマンドラインを渡す。greple がファイルごとにフィルタを適用するので、複数ファイルのファイル名ラベル（`--filestyle=once`）、`\f` 区切り、`-V` の並列表示、stdin 入力がそのまま動く（検証済み）。`-n` には `--if '…'` がそのまま出るのでテストはそれを照合する。新しい stage を足す案は、run_greple がファイルを引数で受けている構造と合わないので採らない。

### 出力の変化（検証結果）

残るもの: 段落・引用（`>` 付き）・リスト項目・`<details>` 内の段落が 1 行になる。hard break は行末 `\` に統一されて残る。パイプ表（`x\|y` も）、コードブロックの中身（`-p` とフィルタ併用時）、GFM alert、タスクリスト、絵文字ショートコード、自動リンク、インライン HTML、HTML ブロック、順序付きリストの開始番号。

変わるもの: フェンスの info string の前に空白（```` ```perl ```` → ```` ``` perl ````、表示は変わらない）。箇条書き記号が `-` に統一され、記号の違う隣接リストの間に `<!-- -->` が入る（コメントとして着色される）。順序付きリストのマーカーの後ろが 2 スペース。リスト項目の下のインデント段落のインデントが 4 から 2 に。setext 見出しが ATX に。見出しの閉じハッシュが取れる（`hashed` テーマが h3-h6 には付け直す）。`__bold__` が `**bold**` に。参照リンクがインラインリンクになり `[ref]: url` が消える（mdee は参照リンク未対応なので改善でもある）。脚注の定義が文末に移る。エスケープが足される（line block の `| ` は gfm 未対応で `\|` に。md モジュールはエスケープ未処理なのでそのまま見える。docs/plans/2026-10-26-backslash-escape-design.md の優先度が上がる）。水平線が `-` の並びに。

失われるもの: YAML front matter（gfm reader がメタデータとして取り込む。`-s` を付けても `title:` だけが再出力され `date:` は消えた）。ファイル末尾の改行の有無などの細部。

### 評価

利点は実装量の少なさと境界判定の確かさ。欠点は、利用者が「自分のファイルと違うもの」を見ることになり、reflow 以外の変化がすべて副作用になること。三案のうち Concept に最も深く触る。

## 案 B: pandoc を段落の位置を教える役だけに使う

pandoc に `sourcepos` 拡張付きで gfm を解析させ、JSON から Para ブロックの行範囲を取り、md モジュールがその範囲の行だけを元のテキスト上でつなぐ。pandoc の出力は使わない。reflow 以外は一文字も変わらない。

### 仕組み（検証済み）

```
pandoc -f gfm+sourcepos+definition_lists -t json FILE
```

JSON では各ブロックが `data-pos` 属性付きの Div に包まれて出る。Para の位置は `file@3:1-6:1` のように行範囲で、リスト項目や引用の中では `7:3-8:1;8:3-10:1` のように、pandoc がマーカー（`- ` や `> `）を消費した所で区切った区間になる。区間の開始桁は本文の開始桁だが、区切りは行ごとではなく、`8:3-10:1` のように lazy continuation の行（9 行目、1 桁目から始まる）は前の行の区間に含まれて開始桁が出ない。桁は文字（コードポイント）単位で、タブはタブ幅 4 で展開した桁。終端の `6:1` は 6 行目の先頭、つまり 3〜5 行目が対象。この形式（`;` 区切り、タブ幅、Div で包む形）は 3.13 で確かめたもので、2.17 で見出しの属性の付け方が変わった記録があるので、対応する最古の版で再確認が要る。

`definition_lists` が無いと `Term\n: Def` が 1 つの Para になり、`Term : Def` につながってしまう（別セッションのレビューで判明）。付けると DefinitionList になり、定義の本文だけが Plain として出る。gfm reader が知らない構文は Para になるので、md が特別扱いする構文は確かめる: Pandoc の自動番号リスト `#.`/`#)` は `fancy_lists` を付けても Para のままなので、結合時に md のリストマーカーで始まる行の前では改行を残す。また `Text\n***` の Para の範囲は水平線の行まで含んで報告されるので、Para の終わりは「次に始まるブロックの直前の行」で切る。md モジュールの `begin()` で colorize の前に `reflow()` を呼ぶ。`reflow()` は pandoc を子プロセスで走らせて JSON を受け取り（JSON::PP はコア）、Para の行範囲ごとに 2 行目以降の接頭辞（インデントと、そのブロックの引用の深さまでの `>`）を自分で取り除いてつなぐ。区間の開始桁は確認に使えるが、lazy continuation の行には無いので頼れない。1 行目の接頭辞はそのまま残す。行末が 2 スペース以上か `\` の行の後ろは改行を残す。結合は上の和文規則。表・コード・見出し・HTML ブロック・front matter・setext は Para ではないので触らない。

つないだ行は `--fold-by` の対象にして md 側で折る（nup 無しのスタイルの問題がここで解ける）。対象のパターンは「reflow が印を付けた行」にするのが簡単で、たとえば reflow 時に行末へ置く不可視の印か、`begin()` が記録した行番号を関数パターンで返す。

### 要件と注意

- `sourcepos` 拡張は pandoc 2.11.3（2020-12）で追加された。出力形式を確かめたのは 3.13 だけなので、下限は対応したい最古の版で確かめてから決める。他の拡張は使わないので版依存は A より少ない。
- ファイルごとに pandoc を 1 回走らせる。greple の `--if` ではなく md モジュール内から呼ぶので、`-n` にはその様子が出ない。`-dd` の debug 出力か md の config で見せる。
- `begin()` が受け取るテキストは greple が読んだ後なので、pandoc には一時ファイルか標準入力で渡す。
- Para 内の inline にも `data-pos` が付くが、Para のものだけ読む。
- pandoc の Para の範囲は gfm の解釈なので、mdee の表（先頭 `|` 必須）より広く表を認識する。先頭 `|` の無い GFM 表は Table ブロックになり触られない（安全側）。

### 評価

A の境界判定の確かさと、C の「reflow 以外は変えない」を両取りできる。Concept の文言は「`--reflow` のときだけ段落の行をつなぐ」で済む。欠点は pandoc 依存が残ることと、Perl のコードが 100 行前後要ること（位置の対応付け、タブ、hard break、和文結合、fold 対象の印）。

## 案 C: 自前の行分類器

md モジュールの `begin()` で、行ごとの状態を持つ分類器が「つないでよい行の組」を決め、B と同じ結合規則でつなぐ。依存なし。判断に迷う行はつながない方針にして、失敗を「つながらなかった」側に倒す。

### 規則の案

- 対象は 1 桁目から始まる素の行の連続。次の行頭の形があれば境界: `#`、`>`、`-`/`*`/`+` + 空白、数字 + `.`/`)` + 空白、`|`、`<`、`[x]:`、`[^x]:`、`: `、`$$`、`:::`、空白（インデント行）、`=` か `-` だけの行（setext）、`-`/`=`/`+`/`|`/空白だけの行（水平線、Pandoc 表の罫線）。
- 状態で扱うもの: フェンス内、HTML コメント内、先頭の front matter（`---` で始まり `---` か `...` で終わる）、HTML ブロック（`<div>` などから空行まで）、`$$` の内外、Pandoc の simple/grid 表（罫線行で始まり罫線行で終わる）。
- 前の行が hard break なら境界。どちらかの行に `|` があれば境界（先頭 `|` 無しの GFM 表の見出し行を守る）。
- リスト項目: マーカー行に、同じ内容オフセットで始まるインデント行と、マーカー無し・インデント無しの直後行（lazy continuation）をつなぐ。空行を挟んだインデント段落は、直前のリスト項目の内容オフセットと同じインデントのときだけ段落として扱い、オフセット + 4 以上はコードとして触らない。
- 引用: 同じ `>` 接頭辞の連続行を、接頭辞を外してつなぎ、1 行目の接頭辞を残す。
- 定義: `: ` 行に続くインデント行をつなぐ。

### 評価

依存がなく、Concept への影響も B と同じく最小。欠点は CommonMark のブロック構造の簡易版を自前で持つことで、コード量と端ケースのバグは三案で最大。規則の漏れは「つながらない」として現れるので文書は壊れないが、どこまで対応するかの線引きが続く。

## A と B を両方持つ案

A と B は排他ではない。md モジュールの `begin()` に `reflow` を置き、モードで切り替える形にすれば、pandoc の起動・版の確認・エラー処理・テストの skip 判定・「つないだ行を fold 対象にする印」を共有できる。B は `pandoc -t json` の位置で元テキストをつなぐ。A は `pandoc -t gfm` の出力でバッファを置き換えたあと、その出力に対して B と同じ位置取得を行えば、どの行が段落かが分かり、fold 対象の印も同じ仕組みで付く（pandoc は 2 回走るが 1 ファイル 0.2 秒ほど）。A を greple の `--if` で bash 側に置く形より、この方が実装が一本化される。代わりに `-n` には pandoc の呼び出しが出ない。

オプションは `--reflow` に値を持たせる形が考えられる。たとえば `--reflow`（既定 = B、元のテキストを保つ）と `--reflow=pandoc`（A、pandoc の書き直しを見せる）。A は B より副作用が多い分、参照リンクの解決や脚注の整理のような「整った表示」が得られるので、使い分ける価値はある。追加の実装量は、B を作った上に A の pandoc コマンドと Lua フィルタと置き換え処理を足す程度で、B 単独より 2〜3 割増しの見込み。

## 比較

| 観点 | A: pandoc 書き直し | B: pandoc を位置取得に | C: 自前分類器 |
|---|---|---|---|
| 境界判定 | pandoc 任せで確実 | pandoc 任せで確実 | 自前、保守的 |
| reflow 以外の変化 | 多い（上記） | なし | なし |
| 依存 | pandoc >= 3.1.9（または拡張を版で切替） | pandoc >= 2.11.3 | なし |
| mdee 側の実装量 | 少（bash + Lua） | 中（Perl 100 行前後） | 大 |
| nup 無しスタイルの折り返し | 段落パターンを別途 | つないだ行を対象に | つないだ行を対象に |
| front matter | 消える | 残る | 残る |
| 失敗の出方 | 想定外の書き換え | つながらない | つながらない |

## 要決定（ユーザー）

決定（2026-11-01）: 1 は B を「現状の拡張」として実装。A は本格的なプレビューアを別に考えるときの土台とし、その場合は gfm 往復ではなく pandoc の AST を描画する設計にする（gfm writer は `\*` や `\|` を残し、AST を消費する出力なら解決する）。2 は md 側で折る（結合後の行を `--fold-by` の対象に加える）。fold 無効時（filter、raw、`--no-fold`）は 1 行のまま。4 は `--reflow`。以下は決定前の記述。

1. 方式: A、B、C のどれか、または A と B の両方（上記）。B は使い捨ての試作（JSON を読んで元テキストをつなぐだけ）で 1 時間ほどで手応えを確かめられる。
2. fold が有効で nup が無いとき（pager、cat）に、つないだ段落を md 側で折るか、端末任せにするか（fold 無効時は 1 行のままでよい）。
3. A の場合: front matter の消失を受け入れるか、mdee 側で先頭の `---` ブロックを切り出して戻すか。`$` を素通しにする案でよいか。pandoc の下限版。
4. オプション名は `--reflow` でよいか。

## 検討した経緯

最初に C（greple の関数パターン `-E '&paragraph_regions'` と tee の `--crmode` を使う形）を検討し、引き継ぎで A が提示され、A の副作用を検証する中で B が成立することを確かめた。推奨は B（書いた者の意見）。pandoc 依存を避けたいなら C、依存も副作用も受け入れて最短で済ませるなら A。

## 追って検討すること（このタスクの範囲外）

- リスト項目の下のインデント段落は、reflow 後は長い 1 行になり、nup がインデントを保たずに折り返す（継続行が 1 桁目に戻る、検証済み）。既存の挙動だが reflow で目立つ。md の fold 対象に `^\h+.*\n` を加えてインデント付きで折る改善。CLAUDE.md の「Indented Line Folding (TODO)」が挙げる障害のうち、B と C では「つないだ行」だけを対象にすれば回避でき、A では pandoc 出力に Pandoc 非パイプ表も意図的な継続行も無いので回避できる。
- バックスラッシュエスケープの処理（A で特に目立つ）。
- インデントコードブロックの保護（md モジュールの弱点として残る）。
