# Proc::ShellSubset::Large: the large parser, its specification and its measurements

Written with Claude by the parser session (file prefix `large-subset-`), 2026-11-01 and 2026-11-02. The module was
called `ShellSubsetLarge` until the distribution moved every module under `Proc::` (2026-11-02). The current
documents below use the new names; the historical ones keep the names of their day.

| File | What |
|---|---|
| [`large-subset-spec.md`](large-subset-spec.md) | **The specification** (current): what the large grammar accepts beyond `Proc::ShellSubset`, the rules where dash and bash differ (A3), the tree additions, the rules for the executor at run time (A4: status 248, A5: as dash), tests and measurements. |
| [`large-subset-state.md`](large-subset-state.md) | **The state of the union** (current): the rules and which beats which, the yardsticks decided by the shells alone, the parse results, the work list, subtle and open verdicts, blatant differences; section 7: **the behaviour**, every accepted sample run in dash, bash and ours (the run of post-0.12, 2026-11-17; ours at exit, the modes of K5; the runs of post-0.09 and, with the programs inside Perl, of 0.10, IP1; W5, the event loop, checked over the library on Linux and what ran under Wine; ours through Run; the atomic calls). |
| [`large-subset-logical.md`](large-subset-logical.md) | **Rule E** (current): where dash and bash differ, the plainly logical behaviour, by category, item by item; the earlier decisions checked against it. |
| [`large-subset-environment.md`](large-subset-environment.md) | **The samples and the run's environment** (known issue [X27](../pspawn-known-issues.md#my-x27), current): for every accepted corpus sample, whether the run-time comparison could come out otherwise in another environment (strict, almost strict, undecided), the codes, how to remake it; section 9: the six kinds of workaround and the runs with the environment varied (other cases of `POSIXLY_CORRECT`, the locale, SIGPIPE, `/proc`; fresh or private places; stand-ins for programs; fixed file times), footnotes to the totals of section 1 (EV1). |
| [`large-subset-provenance.tsv`](large-subset-provenance.tsv) | Its record: one line per accepted corpus sample, by snippet ID, with a short code; the header says how to read it. |
| [`tools/large-subset-env-variants.tsv`](tools/large-subset-env-variants.tsv) | Every sample whose result changed when the run's environment was varied ([section 9 of `large-subset-environment.md`](large-subset-environment.md#my-section-9)), by variant. |
| [`tools/large-subset-match.tsv`](tools/large-subset-match.tsv) | The match across environments ([section 11 of `large-subset-environment.md`](large-subset-environment.md#my-section-11), post-0.11): for every snippet where the shells or ours differ somewhere, whether dash and bash agree, with whom ours sides, how it is legalized (the rulings found), the class in each environment, and whether builtin-vs-coreutils holds; messages count nowhere. |
| [`tools/large-subset-match-calls.jsonl`](tools/large-subset-match-calls.jsonl) | Its commands: every `echo`, `printf`, `test`, `[`, `kill`, `pwd` ours ran in those snippets, run alone by coreutils, dash's builtin, bash's builtin and ours (status, output, messages). |
| [`large-subset-match-raw.md`](large-subset-match-raw.md) | The same match with messages compared as before post-0.11 (a message on standard output or in a file counted as a difference); not part of the analysis. |
| [`tools/large-subset-env-setups.tsv`](tools/large-subset-env-setups.tsv) | Step 2 ([section 10 of `large-subset-environment.md`](large-subset-environment.md#my-section-10)): the 2,902 samples it tried (undecided before step 3, every dependence named exactly: files, variables, standard input, arguments, `cd`, `HOME`), each with its class in two base runs and every example setup, its dependences and what each setup did. |
| [`tools/large-subset-programs.txt`](tools/large-subset-programs.txt) | The program names the runs see (A23 (b), post-0.12): the runner makes a recorder for each name here, installed or not, and for no other name. |
| [`tools/large-subset-match-known.tsv`](tools/large-subset-match-known.tsv) | Why ours differs from a shell where the match report cannot tell by itself: a decision or rule by name, or chance ([section 11 of `large-subset-environment.md`](large-subset-environment.md#my-section-11); `large-subset-runreport.pl -known`). |
| [`tools/large-subset-endmodes.tsv`](tools/large-subset-endmodes.tsv) | Ours at exit (K5): the samples with a background job, each mode of `PROC_SHELLSPAWN_END` 5 times, side by side ([`large-subset-state.md`](large-subset-state.md#my-section-7), section 7). |
| [`tools/large-subset-step3.tsv`](tools/large-subset-step3.tsv) | Step 3 ([section 12 of `large-subset-environment.md`](large-subset-environment.md#my-section-12)): every sample undecided by its codes alone, with where its values from the environment land (classes pass, split, control, affects-shell, AI-…). |
| [`tools/large-subset-env-control.tsv`](tools/large-subset-env-control.tsv), [`tools/large-subset-env-affects-shell.tsv`](tools/large-subset-env-affects-shell.tsv) | The samples of step 3's classes control and affects-shell, run in example setups, every run in a root of its own; their commands run alone: [`tools/large-subset-env-control-calls.jsonl`](tools/large-subset-env-control-calls.jsonl), [`tools/large-subset-env-affects-shell-calls.jsonl`](tools/large-subset-env-affects-shell-calls.jsonl). |
| [`tools/large-subset-env-races.tsv`](tools/large-subset-env-races.tsv) | The races, run many times in the same environment (`make corpus-races`, `large-subset-repeat.pl`): whether a difference of ours is a race or ours' own result. |
| [`tools/large-subset-ai-classes.tsv`](tools/large-subset-ai-classes.tsv) | The undecided samples step 3's setups left out (93), classified by Claude reading them (AI- categories; `large-subset-blocks.pl -ai`). |
| [`tools/large-subset-run-differences.tsv`](tools/large-subset-run-differences.tsv) | The samples of the behaviour run where ours differs from both shells, or the shells differ and ours agrees with neither, or the messages are worded as neither's. |
| [`large-subset-dialect-features.md`](large-subset-dialect-features.md) | **dash vs bash, feature by feature** (current): every probed feature, blatant or subtle, with who decided it; the per-test record. |
