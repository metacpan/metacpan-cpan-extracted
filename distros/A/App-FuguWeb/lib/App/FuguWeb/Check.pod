=head1 NAME

App::FuguWeb::Check - what a built site must be true of

=head1 SYNOPSIS

    use App::FuguWeb::Check;

    my $check = App::FuguWeb::Check->new(
        config => $config,
        out    => 'web/build',
    );

    my @problems = $check->run;
    warn "$_\n" for @problems;
    note("external link: $_") for $check->external;

=head1 DESCRIPTION

The checks are generic, so every project that uses the tool gets them.
A project keeps only the assertions that are about its own content.

The class never fetches a link. It collects the external ones and
reports them, because the build and its checks touch no network.

=head1 METHODS

=head2 new

    App::FuguWeb::Check->new(
        config => $config,      # required
        out    => $dir,         # required: the built site
    )

=head2 pages, generated_pages

C<pages> names each page of each language tree, as
C<< <code>/<page> >>: for each language, the pages of the description,
then one page for each manual of each group. C<generated_pages> names
the human page of each key directory, which the build writes itself
and which no block names. The pages of the top level sit outside every
tree as well, and L<App::FuguWeb::Config/top_pages> names them.

A generated page takes the checks of a page. It takes no reachability
check: a site links the key directory when it chooses to. The pages of
the top level take none either.

The full expectation, assets and the pages of the top level included,
comes from L<App::FuguWeb::Config/inventory>, so the build and the
checks can never disagree about what the site is.

=head2 run

Check the site and return the problems, each one a sentence that names
the page. An empty list means the site is good.

The checks are:

=over 4

=item *

every expected page and asset exists and is not empty;

=item *

on every page but the top-level F<index.html>, the check finds a
title, the header link and every navigation link;

=item *

each of those links takes the form of the kind of its page:
C<< <page> >> on a tree page, C<< ../en/<page> >> on the key page, and
C<< en/<page> >> on the top-level copy of F<404.html>. An absolute URL
and a fragment stay as they stand;

=item *

every page of a language tree carries the code of its tree as
C<lang>;

=item *

the chrome of a tree page links the same page in each other language,
as C<< <a href="../<code>/<page>" hreflang="<code>"><code></a> >>. The
chrome of any other page, and of a site of one language, holds no
C<hreflang>. The chrome ends where the C<< <main> >> element starts, so
a link of the body is the writer's own;

=item *

no reference starts with C</>, because the host may serve the site from
a path below the root. The C<< <base href="/"> >> of the top-level
copy of F<404.html> is the one exception, and that page must carry it;

=item *

the top-level F<index.html> holds a meta refresh to the entry page of
the default tree. Its one reference is a link to that page, so it
loads nothing, and it carries no navigation;

=item *

no reference uses a C<file:> URL;

=item *

every relative reference resolves to a file in the output, a manual
cross-reference included;

=item *

a reference of a page resolves against the directory of that page: a
language tree, a key directory, or the top level;

=item *

every fragment resolves to an C<id> on the target page;

=item *

no relative href reads as a URL scheme, so every local link keeps its
C<./>;

=item *

every page of a language tree is reachable from the entry page of that
tree, except a page that the description marks C<unlinked>. The walk
stays inside the tree;

=item *

the output holds the site and nothing else, at any depth: no staging
directory, no editor backup, no stray source, and no empty
directory.

=back

A description with a C<keys> block adds the checks of
L<App::FuguWeb::Keys/THE CHECKS>. They read the source key directory
and not the output. A stray key file and a stale digest are therefore
found whether or not a build has run.

=head2 external

The external links that the last C<run> collected, sorted.
