=head1 NAME

Acme::Parataxis::Driver::IOAsync - IO::Async Event Loop Driver for Parataxis

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[await_read await_sleep fiber];
    use IO::Async::Loop;

    # Wrap an IO::Async loop and make it the active driver:
    Acme::Parataxis->attach_loop( IO::Async::Loop->new );

    Acme::Parataxis::run( sub {
        my $sender = fiber {
            await_sleep(30);
            syswrite( $socket, "ping\n" );
        };

        # I/O readiness driven by IO::Async (epoll/select):
        await_read( $socket, 2000 );
    } );

    Acme::Parataxis->detach_loop;    # reverts to built-in native thread pool

=head1 DESCRIPTION

C<Acme::Parataxis::Driver::IOAsync> connects Parataxis to an L<IO::Async::Loop>. When attached, calls to C<await_read>,
C<await_write>, and C<await_sleep> register filehandle watchers and timers directly with the C<IO::Async> loop rather
than delegating to the native C thread pool.

Key operational characteristics:

=over

=item *

B<Loop abstraction>: C<< IO::Async::Loop->new >> detects and instantiates the best backend available for your platform
(such as C<IO::Async::Loop::Epoll> on Linux or C<IO::Async::Loop::Select> on Windows). The driver interacts strictly
via the documented C<watch_io>, C<unwatch_io>, and C<watch_time> methods.

=item *

B<Truly non-blocking polling>: C<poll_ready()> maps directly to C<< $loop->loop_once(0) >>, returning instantly while
still firing due timers. This prevents polling stalls when coordinating with background workers.

=item *

B<Automatic non-blocking handles>: C<IO::Async> configures C<O_NONBLOCK> automatically when a handle is first monitored
with C<watch_io>.

=back

=head1 CONSTRUCTOR

=head2 C<new( loop =E<gt> $loop )>

    my $driver = Acme::Parataxis::Driver::IOAsync->new( loop => $loop );

Constructs a new driver instance. C<$loop> is required and must be an instance of (or inherit from) C<IO::Async::Loop>.

=head1 METHODS

=head2 C<watch_read( $fh, $cb )> / C<watch_write( $fh, $cb )>

Registers a read or write callback on C<$fh> and returns C<$fh>. If both directions are registered on the same handle,
they share a single underlying C<watch_io> registration. Croaks if C<$fh> is closed.

=head2 C<unwatch( $fh )>

Removes all read and write watchers for C<$fh> on the loop. Returns true if the handle was monitored; false otherwise.

=head2 C<timer( $ms, $cb )>

Arms a timer to invoke C<< $cb->() >> after C<$ms> milliseconds. Returns an opaque timer ID.

=head2 C<cancel_timer( $id )>

Cancels an active timer. Returns true if successfully cancelled; false if unknown or already expired.

=head2 C<drive( )>

Executes C<< $loop->loop_once(undef) >>, blocking in the kernel until an event fires. Invoked by the scheduler when all
fibers are parked.

=head2 C<poll_ready( )>

Executes C<< $loop->loop_once(0) >>. Performs an immediate non-blocking poll pass, firing due timers without delaying
the caller.

=head1 Behavior Notes

=over

=item * Idle drive blocks

Calling C<drive()> manually when no watchers or timers are active will block indefinitely inside C<loop_once(undef)>.
The Parataxis scheduler prevents this by only calling C<drive()> while C<< $driver->pending >> is positive.

=item * Dual-direction write preference

When a filehandle is monitored for both read and write readiness, an event loop pass on a connected socket often
reports the writable branch first. The scheduler handles this naturally on subsequent passes.

=back
