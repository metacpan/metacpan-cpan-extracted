# CRD Support Design

Status: decided 2026-09-03 (design interview, Getty + Claude). Supersedes nothing;
extends `2026-08-10-exact-gvk-and-compatibility-design.md`, whose resolution
contract stays in force and is extended in "Resolution order" below.

Scope: three distributions that share one author -- `IO::K8s` (this repo),
`Kubernetes::REST` (`~/dev/kubernetes-rest`) and, as a consumer,
`kubernetes-ocp`. Every decision below names the distribution it lands in.

## Goal

CRD support "in every direction":

- **Author** a CRD in Perl (a class) and sync it to the cluster.
- **Consume** CRDs a cluster already serves, as typed classes, without writing
  Perl for each one.
- **Bundle** typed classes for the ecosystem CRDs the maintainers run
  themselves, at the same depth and quality as the core Kubernetes classes.

Two personas are primary: the manifest author (builds YAML / `.pk8s` offline,
wants builder ergonomics and validation before `kubectl apply`) and the
`Kubernetes::REST` user on a live cluster (wants the cluster's CRDs usable
without writing classes). Writing a Perl operator/controller is out of scope;
nothing here prevents it later.

## Verified facts the decisions rest on

Measured on master at 1.108, 2026-09-03:

- 62 of the 70 bundled provider classes declare `spec => { Str => 1 }` -- an
  opaque hash. Only the 8 AgentSandbox classes model `spec`/`status`
  (inline structs, top-level fields only). A bundled provider therefore
  contributes GVK identity, `resource_plural`, scope, the builder roles and
  `SpecBuilder` -- no field typing. `maint/crd-drift-check.pl` reports all
  16 Traefik + cert-manager classes as "OPAQUE SPEC".
- `SpecBuilder` assumes `spec` is a plain hashref. On a modeled spec
  (`AgentSandbox` `Sandbox`) `spec_set` replaces the `_Spec` object with `{}`
  and the write lands in an orphaned hash: `to_json` emits `spec: {}`
  afterwards; `spec_get` returns undef. **k90.** All builder roles
  (`CertManaged`, `HelmManaged`, `MiddlewareBuilder`, `Loadbalanced`,
  `Routable` non-core branches, `NetworkPolicy` cilium branch) share the
  hash-only assumption.
- Unknown fields are silently dropped on **every** class, both on `inflate`
  and `new_object` (`Pod` with `spec.bogusField` loses it on `to_json`). The
  README AgentSandbox example passes `spec.replicas`, which the class does
  not model and upstream v1.0.0 does not have. **k91.**
- `IO::K8s::AutoGen` consumes swagger-v2 `definitions` with `#/definitions/`
  refs (the cluster's `/openapi/v2`). It does not accept a CRD manifest
  (`openAPIV3Schema`). There is no untyped fallback object: an unknown Kind
  dies (`Cannot resolve Kubernetes GVK` / `Can't locate IO/K8s/Widget.pm`).
- `Kubernetes::REST` (default `resource_map_from_cluster => 1`) downloads
  `/openapi/v2`, maps every CRD group to `IO::K8s::Api::<Group>::...` (for
  `cilium.io` a class that does not exist; for `cert-manager.io` an invalid
  package name), does not pass the spec on as `openapi_spec`, and has no
  `with`. `kubernetes-ocp` works around this with
  `$api->k8s->add(@providers)`, and its comment describes exactly this hole.
  It does not fetch `/apis` discovery at all.
- Full-depth field counts of the served `spec` schemas at the pinned upstream
  versions (K3s is schemaless upstream and excluded):

  | Provider     | top-level | all depths | nested structs | max depth |
  |--------------|----------:|-----------:|---------------:|----------:|
  | Cilium       |        99 |       1000 |            313 |         7 |
  | Traefik      |        75 |        695 |            133 |         5 |
  | cert-manager |        60 |       1413 |            441 |        13 |
  | Gateway API  |        43 |        646 |            188 |         7 |
  | AgentSandbox |        21 |       2304 |            629 |         9 |
  | **Total**    |   **298** |   **6058** |       **1704** |           |

  A large share are embedded core types (AgentSandbox's `podTemplate` is a
  full `PodTemplateSpec`); those are referenced, not re-modeled.
- Industry comparison (Go, Rust, Python, Java, TS, .NET, Ruby, Terraform,
  Helm): every ecosystem ships an untyped escape hatch (`Unstructured`,
  `DynamicObject`, `GenericKubernetesResource`, dicts). Typed CRD classes are
  user-owned -- written by the CRD author or generated by the consumer from
  the CRD YAML and checked in (kopium, cdk8s import, crd2pulumi, fabric8
  java-generator). Only fabric8 and `kube-custom-resources-rs` bundle
  ecosystem CRDs, and both generate. Multi-version is uniformly "one
  class per served version, caller picks"; tools that silently pick one are
  the known rough edges.

## Decisions

### Core object model (`IO::K8s`)

**D1 -- Unknown fields are preserved, `strict` dies.** Every class composing
`IO::K8s::Role::Resource` keeps constructor arguments it has no attribute for
in an `_unknown_fields` bag and re-emits them from `TO_JSON` (declared
attributes win on collision). This is the forward-compatibility floor: a
class pinned at Cilium 1.20 keeps round-tripping a 1.21 field. A dynamic
`$IO::K8s::Resource::STRICT` flag, set by an `IO::K8s` instance constructed
with `strict => 1` for the duration of `inflate` / `new_object` /
`json_to_object` / `struct_to_object` / `load` / `load_yaml`, makes an unknown
field die naming the class and the field instead. Default is preserve.
Rejected: global fail-closed (breaks against newer clusters, makes D5 a
trap); status quo (silent data loss, the k56 line). Precedent: fabric8
`additionalProperties`.

**D2 -- `SpecBuilder` and the builder roles become object-aware.** `spec_get`
/ `spec_set` / `spec_push` / `spec_merge` / `spec_delete` walk typed objects
through their accessors (JSON key mapped to attribute via the registry),
vivify missing intermediates as the registry's class / array / hash, inflate
hashrefs handed to typed slots, and put a key an object does not declare into
its `_unknown_fields` bag (D1). Negative array indices address from the end
and vivify one element on an empty array. The builder roles are rewritten on
top of `SpecBuilder` so they work on hash and object specs alike; the `core`
branches of `NetworkPolicy` / `Routable` (typed core classes) are unchanged.
Fixes k90; k91 part 2 is D1. Rejected: dropping `SpecBuilder` from modeled
classes (README promises it); hash-like inline structs.

**D3 -- Per-field option hash in the `k8s` DSL.** `k8s replicas => Int,
{ default => 1, minimum => 0 }`. Version 1 carries `required` (exists),
`default`, `enum`, `minimum`, `maximum`, `pattern`, `description`,
`nullable`, `preserve_unknown`. All of them are emitted into the CRD schema
(D9). `enum`, `minimum`, `maximum` and `pattern` are additionally enforced
client-side as Type::Tiny constraints at construction, the same way
`{ Quantity => 1 }` validates its values. `default` is **not** applied
client-side -- defaulting is the API server's job and a client default would
change the wire output. `description` is emitted only; feeding it from POD
is deferred.

**D4 -- `IO::K8s::Unstructured`, opt-in.** A class with `apiVersion`, `kind`
and `metadata` as real attributes and everything else preserved (D1), used
for a Kind nothing else resolves. Opt-in on the `IO::K8s` constructor
(`unknown_kinds => 'unstructured'`); bare `IO::K8s` keeps failing closed by
default. `Kubernetes::REST` turns it on for discovery-confirmed Kinds (D16).

### Bundled providers

**D5 -- Full depth, one file per structure, hand-built.** Provider classes
model `spec` and `status` to the full depth of the upstream schema, the way
the core API classes do: every nested structure is its own `IO::K8s::Resource`
class in its own file with POD. Embedded core types (`PodTemplateSpec`,
`ObjectMeta`, `LabelSelector`, ...) are referenced, never re-modeled. Nothing
in `lib/` is generated code: the emitter (D10) proposes source, an agent
curates and documents it, and the result is checked in. Mass work is
delegated to Sonnet-class subagents, one per provider. Rejected: top-level
only (drift-check blind below the first level); anonymous inline structs
(no POD, no shared types).

**D6 -- Nested classes carry the upstream Go type names.** The CRD manifest
only knows field paths and inlines shared types; the Go types are the
upstream's own names (`Rule`, `EndpointSelector`, `RateLimit`), match the
upstream docs, and make a shared type one class (Cilium's `Rule` is shared by
`CiliumNetworkPolicy` and `CiliumClusterwideNetworkPolicy`). All six current
providers publish their Go types; K3s can only be modeled that way because
its CRDs are schemaless. Naming: `IO::K8s::<Provider>::<Version>::<GoType>`;
a collision across groups inside one provider is disambiguated by the
version directory first, then by prefixing the owning Kind.

**D7 -- Superset rule for every provider, tracks kept indefinitely.** Every
upstream-**served** version of a Kind gets a class (Gateway API gains its
served v1beta1 / v1alpha2 / v1alpha3 tracks and the eight
`ignore_missing_kinds` exceptions go away). A track upstream **removed**
stays as a back-compat superset, reachable through its domain-qualified
resource_map key, for as long as it can serve an older cluster -- no time
limit. Only a class that can serve no cluster at all moves to the
`IO::K8s::Deprecated` distribution. The short name maps to the storage
version of the pinned upstream (D17 refines this with a cluster).

**D8 -- Provider selection: what the maintainers run, in one dist.** The
providers stay inside `IO::K8s`; splitting into per-provider CPAN dists is
deferred until a provider bumps more often than the core releases. Added to
the bundle: **Prometheus Operator** (`monitoring.coreos.com`),
**VolumeSnapshot** (`snapshot.storage.k8s.io`), **external-secrets**
(`external-secrets.io`). Candidates deliberately not taken now: MetalLB
(overlaps Cilium LB-IPAM), Flux/ArgoCD (large, fast-moving), Longhorn (~20
Kinds), CloudNativePG, KEDA -- each waits for a project of ours that needs it.
The builder roles stay hand-maintained on top of the modeled classes; no
automation regenerates them (an upstream bump shows the agent which builder
methods need touching).

### Class-to-CRD and CRD-to-class (`IO::K8s::CRD`)

**D9 -- `to_crd`.** A CRD class (`use IO::K8s::APIObject api_version => ...,
resource_plural => ...`) can emit its `CustomResourceDefinition` object:
schema from the attribute registry (scalars, arrays, maps, inline structs,
referenced classes by recursion, `required`, D3 options), opaque
`{ Str => 1 }` as `type: object` + `x-kubernetes-preserve-unknown-fields:
true`, scope from `IO::K8s::Role::Namespaced`, `names.plural` from
`resource_plural`, `names.kind` from `kind`. `Class->to_crd` yields a
single-version CRD; `IO::K8s::CRD->new(classes => [...], storage => 'v1')`
assembles a multi-version CRD from one class per version. Rejected: a
`storage => 1` import parameter with sibling discovery through the registry.

**D10 -- `add_crd` and the source emitter.** `$k8s->add_crd($crd)` accepts a
`CustomResourceDefinition` object, a hashref, YAML/JSON text or a path,
builds one class per served version in the instance's AutoGen namespace (the
same schema-to-DSL mapping `IO::K8s::AutoGen` already has, extended for
`openAPIV3Schema`), registers domain-qualified keys for every version and the
short name for the storage version. The same machinery emits Perl source: a
`.pm` per class with the DSL block and a POD skeleton, for users who want
checked-in, documented classes (the kopium / `cdk8s import` path) and for
the maintainers' own D5 work. `maint/crd-drift-check.pl --suggest` prints
those blocks for the gaps it reports; it never writes into `lib/`.

### `Kubernetes::REST`

**D11 -- Aggregated discovery replaces `/openapi/v2` for the cluster map.**
`GET /apis` with the aggregated-discovery `Accept` header (v2, Kubernetes
>= 1.27; per-group fallback below that) yields every group, version,
resource plural, Kind, scope and the group's preferred version in one small
response. The cluster resource map is built from it, cached per instance,
and invalidated by `ensure_crd` (D14). `/openapi/v2` becomes lazy: fetched
only when AutoGen needs a schema.

**D12 -- `with` and `openapi_spec` pass through.** `Kubernetes::REST->new(
with => [...])` mirrors `IO::K8s`. The lazily fetched spec is handed to the
inner `IO::K8s` as `openapi_spec`. The cluster map no longer invents
`IO::K8s::Api::<Group>` names for groups the distribution does not ship;
those Kinds resolve through AutoGen or `Unstructured`. `kubernetes-ocp`
replaces `register_resource_providers` with `with`.

**D13 -- Resolution order** (extends the 2026-08-10 contract):
1. explicit `+Full::Class` in `resource_map`
2. provider classes (`with`)
3. AutoGen from `openapi_spec` when the spec is loaded
4. `IO::K8s::Unstructured` when discovery confirms the GVK (D16)
5. the existing fail-closed error

**D14 -- `ensure_crd(@classes)`.** `ensure` (create-or-update) of each
class's `to_crd`, then wait with timeout for the `Established` condition,
then invalidate the discovery cache so the new Kind resolves. Rejected:
ensure-only (the next call is almost always creating a CR, which 404s until
Established).

**D15 -- `kube_crd2class`.** The CLI for the D10 emitter lives in
`Kubernetes::REST` next to `kube_watch` / `kube_create`, with `-f file.yaml`
and `--from-cluster <name>` inputs. `IO::K8s` ships the library API only (no
`bin/` today).

**D16 -- Unstructured by default for discovery-confirmed Kinds.** In
`Kubernetes::REST`, a GVK the cluster reports through discovery but no class
resolves becomes `IO::K8s::Unstructured` (plural and scope from discovery)
without opt-in. Bare `IO::K8s` stays opt-in (D4).

**D17 -- Short name resolves to the cluster's preferred version.** With
discovery available, a bare Kind resolves to the version the cluster marks
preferred for that group; without a cluster, to the storage version of the
pinned upstream (D7). The rule is documented in one place and tested per
provider.

### Testing

**D18 -- Live tests.** Finish the minikube runner (`kubernetes-rest` ticket
22: `bin/kube_test_minikube`, isolated kubeconfig, sets
`TEST_IO_K8S_KUBECONFIG` / `TEST_KUBERNETES_REST_KUBECONFIG`), run the
cross-dist suite against it with CRD fixtures applied, then against the new
cluster provisioned via `kubernetes-ocp` once its control-plane node is up.
No writing tests against clusters we did not provision.

## Non-goals and deferred items

- A Perl operator/controller framework.
- `strict` checking inside `spec_set` and friends after construction (the
  dynamic flag is only set during an `IO::K8s` instance's own entry points).
- Filling `description` from POD.
- Relaxing AutoGen's unresolved-`$ref` refusal (k56) now that unknown data
  would be preserved -- revisit after D1 has shipped.
- Splitting providers into their own CPAN distributions.
- Release cadence: steps land on master one at a time with a green suite;
  releasing remains a separate, explicit decision (co-maintained dist).
