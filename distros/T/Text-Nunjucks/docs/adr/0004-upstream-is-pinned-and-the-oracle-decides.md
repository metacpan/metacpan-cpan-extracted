# ADR 0004 — Upstream is pinned to one tag, and the oracle decides behaviour

- Status: accepted
- Date: 2026-09-22
- Tags: testing, process

## Context

"1:1 port" is only checkable against one exact upstream. Nunjucks' docs and its
Jinja2 heritage both disagree with its actual behaviour in places, and a port
written from memory of either drifts without anyone noticing.

## Decision

The port targets the tag named in `maint/fetch-upstream` (`v3.2.4`), checked out
to the gitignored `upstream/`. `maint/oracle.js` runs cases through that
checkout; its output defines correct behaviour. Expected values in `t/corpus/`
are generated by the oracle and committed, so the shipped test suite needs no
node; `xt/oracle-live.t` guards them against staleness.

## Consequences

- A behaviour question is settled by running a case, not by argument.
- Bumping the tag is a deliberate change: regenerate the corpus, review the
  diff, re-read the changed upstream files.
- Anything the oracle cannot express as JSON (coderefs in the context, custom
  loaders) is covered by ported upstream tests or Perl-side tests instead.
- Known upstream bugs are ported, not fixed — unless an ADR says otherwise.
