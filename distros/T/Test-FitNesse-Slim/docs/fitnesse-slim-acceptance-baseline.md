## PageDriver behavior implemented

The installed Java class has an implicit no-argument constructor. The acceptance scenarios use `createPageWithContent(String,String)`, `makeATestPage(String)`, `makeASuitePage(String)`, `requestPage(String)`, `content()`, `contentContains(String)`, `contentMatches(String)`, and `lineNumberContaining(String)`. The class metadata in the installed jar confirms this method surface; the upstream implementation is available in the [FitNesse source repository](https://github.com/unclebob/fitnesse/blob/master/src/fitnesse/fixtures/PageDriver.java).

The Perl fixture keeps this test-harness behavior under `t/lib/Fitnesse/Fixtures/`, outside `lib/Test/FitNesse/Slim/`. It creates a page with `POST /<page>` using `responder=saveData`, `editTime=9999999999999`, `ticketId=321`, and `pageContent`; marks it as a test page with `responder=saveProperties` and `PageType=Test`; and requests the supplied URI with HTTP GET. This supports page views and the `?test`, `?test&debug`, `?suite`, and `?executionLog` responders used by the scenario library. The Java `requestPage` method returns the response status, and the Perl implementation retains that status and body on the PageDriver instance. `content`, `content_contains`, `content_matches`, and `line_number_containing` inspect that retained response. HTTP error statuses remain available with their response body; transport failures are raised as fixture exceptions and retained in the shared `ResponseContext` for later fixture inspection.

The response context is process-local. The external Perl server forks one worker per SLiM connection, so a nested FitNesse request can open its own connection while the outer PageDriver call waits; each connection keeps its own fixture state.

`RUN_PAGE_DRIVER_INTEGRATION=1 perl t/page-driver-integration.t` passed against the live FitNesse server and Perl SLiM listener. It created and marked a generated test page, FitNesse executed that page over a second Perl SLiM connection, and the original outer connection then successfully executed another fixture statement. The upstream `ScenarioLibraryTestSuite.ScenarioLibraryShouldIncludeVariables` page also passed separately (6 right, 0 wrong, 0 ignored, 0 exceptions) through the Perl server; it is not one of the 50 Test=true inventory pages. Focused HTTP request, status, encoding, response-retention, and error tests are in `t/page-driver.t` (25 assertions).

The acceptance inventory now removes the generated `MySuite` subtree before each Test=true page request by POSTing `confirmed=yes` to `/MySuite?deletePage`. This is required because FitNesse retains pages created by PageDriver across HTTP test requests. The StopTestInSuiteSetUp page creates `MySuite.SuiteSetUp`; leaving it in the wiki makes later stop pages inherit its stop-test behavior. The reset is limited to generated test data and does not change the upstream wiki sources.

The Perl ResponseExaminer now reads the current `ResponseContext` created by PageDriver. It implements response status and body access, raw and escaped content selectors, rendered response HTML, line access, multiline/dotall regex matching, match counts, and configured capture extraction. The acceptance scenario also calls `extractMatch(pattern, type, group)`, which selects a source and capture in one operation. Unknown source types, invalid patterns, and a missing response raise fixture errors; a valid pattern without a match returns null, matching upstream `found` behavior. The focused cases include nested failure, ignored markup, and exception-detail extraction.

## Automatic SlimHelperLibrary actor stack implemented

The installed `fitnesse.slim.SlimHelperLibrary` exposes `getFixture()`, `pushFixture()`, and `popFixture()` using the executor instance named `scriptTableActor`. The Perl `StatementExecutor` creates one helper for each executor and registers it as the oldest library. Actor methods still take precedence, and user libraries remain newer. The helper stores the fixture references directly on its own stack; nested pushes restore in LIFO order, and each executor has an independent stack. A missing actor reports `NO_INSTANCE`, and popping an empty stack reports `EmptyStackException`.

The upstream `TestSlim.toString()` output is needed when `getFixture()` returns an actor to a FitNesse cell. The Perl TestSlim fixture now stringifies as `TestSlim: <constructorArg>, <stringArg>` and explicitly preserves identity equality, so serializing a helper result does not change symbol or fixture identity behavior. This behavior is scoped to the fixture rather than adding arbitrary object stringification to protocol serialization. See the upstream [SlimHelperLibrary.java](https://www.javatips.net/api/fitnesse-master/src/fitnesse/slim/SlimHelperLibrary.java) and [TestSlim.java](https://www.javatips.net/api/fitnesse-master/src/fitnesse/slim/test/TestSlim.java).

## SplitFixture and DuplicateRows behavior implemented

The installed FitNesse v20251025 classes expose a one-string constructor and `query()` method. `SplitFixture` uses its constructor text as row data: semicolons separate rows, commas separate cells, and query results are nested lists of column/value pairs (column keys are the strings `1`, `2`, and so on). `DuplicateRows` returns one-column `x` rows in the phase A or B order shown by the upstream acceptance tables. It deliberately retains repeated `SuiteSetUp` and `SuiteTearDown` values because duplicate multiplicity is what the ordered and subset query cases exercise. The Perl fixtures live in `t/lib/Fitnesse/Fixtures/`, outside the SLiM executor.

`QueryTableSuite.SetContextValue` uses the SLiM `assign` instruction to transfer query cells into symbols. The pinned FitNesse v20251025 session uses protocol V0.5; the server stores the supplied value and returns `OK`, while null remains an undefined symbol value. The class metadata in the installed FitNesse JAR confirms `SplitFixture(String)`, `DuplicateRows(String)`, and `query()`; the unchanged acceptance pages validate the row structures, ordering, duplicate handling, matching, and symbol assignment end to end.

## Stop and exception behavior implemented

The installed FitNesse v20251025 implementations of `ConstructorThrows`, `DecisionTableExecuteThrows`, and the SLiM exception path were used as the behavioral reference. The Perl `ConstructorThrows` fixture raises ordinary, StopTest, and StopSuite constructor exceptions. `DecisionTableExecuteThrows` reproduces the upstream state, method errors, and table hooks. `TestSlim` now exposes the exception methods used by the acceptance page. The statement executor formats ordinary and Java-style exception payloads, and returns the `ABORT_SLIM_TEST` or `ABORT_SLIM_SUITE` marker for stopping exceptions. The list executor stops the remainder of the current instruction batch and resets the stop request before the next batch. FitNesse then applies its own page/suite rules, including running the appropriate teardown.

`StopTestInSuiteSetUp` and `TestExceptionIsDisplayed` pass their outer checks. In an isolated wiki, StopSuite and StopTest also pass: their nested output includes the expected teardown results, while the stop markers still skip the intended tests. The order-sensitive discrepancy came from reusing FitNesse's generated `MySuite` pages across separate inventory requests, not from stop-state handling in the Perl executor. `IgnoredTestsShouldColorGray` verifies the nested stop exception and that later script statements are not run. Two of its outer checks remain incompatible with the installed renderer: they expect `class="ignore">Not Executed...`, while FitNesse v20251025 emits `class="slimRowColor3"><td>Not Executed... <span class="ignore">Test not run</span>`.

## Hash/map result conversion implemented

The installed FitNesse v20251025 `HashFixture.hash()` returns a sorted `TreeMap`. `MethodExecutionResult` converts that map with `MapConverter` before `SlimSerializer` serializes the SLiM response. The converter emits `table.hash_table` rows with `hash_key` and `hash_value` cells, escapes ordinary text, and retains valid HTML cell content.

The Perl engine previously returned a plain hash reference from `StatementExecutor::call`. Since `Test::FitNesse::Slim::List` serializes arrays recursively but does not encode hashes, the reference reached the wire as `HASH(0x...)`. `Test::FitNesse::Slim::MapResult` now converts only plain hash-reference method results into the upstream table form before response serialization. It sorts keys, handles nulls and nested map/list values, and uses explicit object string methods inside maps; other executor references and list behavior remain unchanged. The regression first failed with `HASH(0x6401465af600)` and now checks the full output and identity preservation in `t/hash-results.t`.

### StopTest and StopSuite order dependence

The exact wrong assertions in a contaminated wiki are `StopTest`'s checks that the nested response contains a passing per-test teardown row for `MySuite.TestPageA` and `MySuite.TestPageB`, and `StopSuite`'s check for the passing teardown row for `MySuite.TestPageA`. In each case the stale setup makes FitNesse mark the per-test teardown row as ignored. That is why the prior isolated reruns reported StopTest at 4 right / 2 wrong and StopSuite at 5 right / 1 wrong.

`StopTestInSuiteSetUp` creates `MySuite.SuiteSetUp` with a StopTest constructor and does not delete it. When that page runs first, subsequent StopTest and StopSuite requests reuse the same generated wiki subtree and inherit the setup, reproducing exactly those counts. The earlier 50-page inventory ran StopSuite and StopTest before StopTestInSuiteSetUp; its 6/0 results were correct for that order, but the inventory procedure did not reset shared wiki state, so those results were not reproducible by later isolated requests. The same contaminated behavior reproduced on source snapshot `dc7561e`; the Perl SLiM stop implementation was not the cause. No engine code change was needed.

The opt-in regression `RUN_STOP_PAGE_INTEGRATION=1 prove -v t/stop-page-order.t` exercises both states: it first confirms the contaminated 4/2 and 5/1 results, then deletes generated `MySuite` data between requests and verifies StopSuite 6/0, StopTest 6/0 on two consecutive runs, StopTestInSuiteSetUp 7/0, and the reverse StopSuite-then-StopTest order at 6/0 each. The complete 50-page inventory uses the same cleanup before every page.

The original 14 fixture-gap pages grouped into AddUpChange (2 pages), library setup and reused library IDs (2), EchoFixture/HashFixture (hash HTML and include pages, 2), Sleep (2), and five one-page fixture families: EchoScript, TestSlim concatenation, LoginDialogDriver, DetailedDiff, and TableTableIncFirstCol. AddUpChange ranked first because one shared fixture removed a large cascade of failed setup calls; the other two-page groups followed by coverage. The standalone fixtures each covered one page. TableTable required a separate but bounded StatementExecutorConsumer engine increment; it and its fixture now pass. TestSlimWithConverter and the required type conversion support are now implemented.

The fixture-managed-symbol executor path mirrors upstream `StatementExecutorConsumer`: fixtures receive the current executor, can register a method-name regex for symbol handling, and restore normal replacement when finished. The TableTable page uses the existing `TestSlim.echoInt` method; it does not need a separate TestQuery fixture.
