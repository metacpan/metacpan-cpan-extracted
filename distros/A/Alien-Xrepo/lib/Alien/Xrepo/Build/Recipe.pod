=head1 NAME

Alien::Xrepo::Build::Recipe - Load and validate an xrepo.json recipe

=head1 SYNOPSIS

    my $recipe = Alien::Xrepo::Build::Recipe->new( dir => 'dist-root' );
    my $recipe = Alien::Xrepo::Build::Recipe->new( file => 'xrepo.json' );
    my $recipe = Alien::Xrepo::Build::Recipe->new(
        packages => [
            'zstd',
            { name => 'libsdl3', version => '3.4.12', kind => 'shared', configs => { wayland => 1 } }
        ],
        defaults => { mode => 'release' }
    );

=head1 DESCRIPTION

C<xrepo.json> is a small JSON recipe consumed by L<Alien::Xrepo::Build>. This class loads it (from a file/directory or
inline data), validates it, and normalizes the package entries. The allowed per-package keys are the installer flags
taken by L<Alien::Xrepo> (C<plat>, C<arch>, C<mode>, C<kind>, C<toolchain>, C<vs*>, C<ndk>, C<sdk>, C<mingw>, C<jobs>,
C<force>, ..., plus C<name>, C<version>, and the nested recipe options under C<configs>).

=head1 RECIPE FORMAT

    {
       "name" : "Alien-Zstandard",
       "packages" : [
          { "name" : "zstd", "kind" : "shared" }
       ],
       "defaults" : { "mode" : "release", "configs" : { "legacy" : 1 } },
       "pkg_roots" : { "ZSTD" : "$ZSTD" },
       "local_repos" : [ "vendor/recipes" ],
       "hooks" : [ "Alien::Zstandard::Hooks" ]
    }

C<packages> is required and must not be empty; order matters (the first entry is the primary package). C<local_repos>
are registered with xrepo during the configure stage. C<pkg_roots> maps a package name to an advanced-user environment
variable (mirroring Alien::Build's C<pkg_roots>): when the variable names an existing directory, C<Alien::Xrepo::Build>
treats the package as system-provided there and never touches xrepo for it. C<hooks> names recipe hook modules; each is
loaded once at the configure stage and invited to register its own stage hooks (see L<Alien::Xrepo::Build>).

=head1 METHODS

=over

=item C<name()>

The recipe's C<name>, or C<undef> when the recipe does not set one.

=item C<packages()>

The normalized package names in declaration order (the first entry is the primary package).

=item C<package_defs()>

A hashref of the normalized per-package definitions, keyed by package name.

=item C<defaults()>

The ambient options applied under every package: the same key set a package def accepts (C<plat>, C<arch>, C<mode>,
C<kind>, C<jobs>, ...), plus the nested C<configs> hashref.

=item C<pkg_roots()>

A hashref mapping a package name to an advanced-user environment variable name, mirroring L<Alien::Build>'s
C<pkg_roots>. When the variable names an existing directory, L<Alien::Xrepo::Build> treats the package as
system-provided there (see L<Alien::Xrepo::Build>).

=item C<local_repos()>

An arrayref of directory paths to local xmake-repo trees (each containing a C<packages/> subdirectory).
L<Alien::Xrepo::Build> registers each of them with xrepo during the configure stage, so packages that are not in the
central xmake-repo can be installed.

=item C<hooks()>

An arrayref of recipe hook module names. L<Alien::Xrepo::Build> loads each module once during the configure stage and
invokes its class method C<register_hooks($build)> so it can attach its own stage hooks (see L<Alien::Xrepo::Build>).

=item C<version_for( $name )>

The per-package version constraint, or C<undef> when the recipe does not pin one.

=item C<opts_for( $name, %ambient )>

Ambient options with the package's per-package def merged over them (flag keys override; C<configs> merge per-key).

=back
