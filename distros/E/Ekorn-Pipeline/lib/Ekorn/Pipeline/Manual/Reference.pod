=head1 NAME

Ekorn::Pipeline::Manual::Reference - Ekorn::Pipeline reference

=head1 DESCRIPTION

Stages for any function: let the caller finish the job.

A function that hands out values takes a list of I<stages> from its
caller, as its last arguments, and runs each value through them. A
stage can change a value, drop it, or turn it into several, and can
stop the pipeline early, so that the function makes no more values
than its caller wants.

This reference describes every module, function and method, and how a
pipeline behaves, with examples; L<the how-to|Ekorn::Pipeline::Manual::HowTo> shows how to do
common tasks with them, one recipe at a time. Notes marked B<For stage
authors> are for those writing stages for others, and
L<Writing stages|/"Writing stages"> brings them together. Each module's
own POD says the same things more briefly, and is the authority where
the two differ.

Ekorn::Pipeline needs Perl 5.36 or later. Its version is 0.x, so the
interface may still change before 1.0, but the version says when it
can: a release that only fixes or adds moves the last number, as
v0.1.1, and one that changes how stages behave, or drops or renames a
name, moves the middle one, as v0.2.0. L<Changes|https://metacpan.org/dist/Ekorn-Pipeline/changes> says what
each release changed.

=head1 At a glance

    use v5.36;
    use Ekorn::Pipeline;
    use Ekorn::Pipeline::Stop;                                       # Stop
    use Ekorn::Pipeline::Gather;                                     # gather
    use Ekorn::Pipeline::Stages::Flow qw(:all);                      # take, drop, take_while, drop_while
    use Ekorn::Pipeline::Stages::Batch;                              # batch, collect
    use Ekorn::Pipeline::Stages::Taps qw(:all);                      # peek, count_into, dump_to

    # A pipeline: a list of stages, each a code reference given one value,
    # in $_ and as its argument, returning nothing, one value or several.
    my $p = Ekorn::Pipeline->new(
        sub { $_ % 3 ? $_ : () },    # filter: drop multiples of 3
        sub { $_ * 10 },             # map: ten times each
        sub { ($_, -$_) },           # flatMap: each, and its negative
    );

    # Pushed: called with values, it returns what comes out.
    say join ' ', $p->(1 .. 4);    # 10 -10 20 -20 40 -40

    # Pulled: given a source, it hands out the results one per call.
    my $n    = 0;
    my $next = Ekorn::Pipeline->new(sub { $_ * $_ }, take(3))->iterator(sub { ++$n });
    my @squares;
    while (my($square) = $next->()) { push @squares, $square }
    say "@squares";    # 1 4 9

    # A function of your own, taking stages from its caller.
    sub numbers (@stages) { Ekorn::Pipeline->new(@stages)->(1 .. 10) }
    say join ' ', numbers(drop(2), take(3));    # 3 4 5

=head1 Terms

=over 4

=item *

B<Value:> anything a pipeline is given, or a stage returns. C<undef>,
0 and the empty string are values.

=item *

B<Stage:> a code reference, called with one value, returning a list
of values: none, one or several.

=item *

B<Pipeline:> a list of stages, made with C<< Ekorn::Pipeline->new >>.

=item *

B<Run:> one call of a pipeline with values, or one iterator made
from it. Stages made with C<gather> start afresh on each run.

=item *

B<Source:> a code reference an iterator calls for values, returning
the next value or values, or an empty list when there are no more.

=item *

B<Result:> a value that comes out of the last stage.

=item *

B<Stop:> the exception a stage throws to end its run early, with
C<Stop> or C<< Ekorn::Pipeline::Stop->throw >>.

=item *

B<End function:> a function a C<gather> stage can have, called once
the values run out, whose values go on through the stages after it.

=back

=head1 Pipelines: Ekorn::Pipeline

    use Ekorn::Pipeline;

It exports nothing.

=head2 new

    my $p = Ekorn::Pipeline->new(@stages);

Returns a pipeline running values through C<@stages>, in order. It
croaks if a stage isn't a code reference, naming it by its place:
"Expected stage #2 to be a code reference". A stage can be any code
reference: an anonymous C<sub>, a reference to a named one, such as
C<\&trim>, a stage made by a function, such as C<take(10)>, or one made
with C<gather>.

With no stages, a pipeline returns its values as they are.

A pipeline is not itself a stage: given to C<new>, it's refused, as it's
an object that can be called like a code reference, not a code
reference. To use one inside another, splice its stages in, with
L<stages|/"stages">, or call it from a stage, as
L<Pipelines inside stages|/"Pipelines inside stages"> says.

=head2 Calling a pipeline

    my @results = $p->(@values);
    my $count   = $p->(@values);

A pipeline is an object that can be called as a code reference. Called
with values, it runs each of them through the stages, in order, and
returns what comes out of the last: in list context, the results; in
scalar context, how many there are.

    my $evens = Ekorn::Pipeline->new(sub { $_ % 2 ? () : $_ });
    my @evens = $evens->(1 .. 6);
    my $count = $evens->(1 .. 6);
    say "@evens, $count of them";    # 2 4 6, 3 of them

Each call is a run. A pipeline can be called as often as you like, and
from inside one of its own stages.

=head2 iterator

    my $next = $p->iterator($source);
    while (my($result) = $next->()) { ... }

Returns a closure handing out, one per call, the values that come out
of the stages, pulling values from C<$source> as they're needed.
C<$source> is a code reference, called with no arguments, returning the
next value, several values, or an empty list when there are no more. It
croaks "Expected a code reference" if C<$source> isn't one.

=over 4

=item *

The source is called only when a result is wanted, and only once the
values from its last call have all gone through the stages, so a
source reading a file, a socket or a database reads no more than its
caller asks for.

=item *

The closure returns one result per call, and an empty list once the
results run out, on every call after that. Read it in list context,
as C<< my($x) = $next->() >>, so that a result of C<undef>, 0 or C<''> isn't
taken for the end.

=item *

Once the source has returned an empty list, or a stage has stopped
the pipeline, the source isn't called again.

=item *

The end functions of C<gather> stages are called once the source
runs out, or after a stop, before the closure returns an empty list.

=item *

If a stage or an end function dies, the call dies with it, and the
iterator has ended: every call after returns an empty list, nothing
waiting goes on, no end function is called, and the source isn't
called again, as when a pushed run dies. So an end such as
C<collect>'s never reports on a run that lost values. To skip a bad
value and carry on, catch the error inside the stage, as the how-to's
"Catch errors in a stage, but not a stop" does.

=back

Each iterator is a run of its own, so two iterators from one pipeline
can be read in turn, and each has its own C<gather> stages:

    my $numbered = Ekorn::Pipeline->new(gather { my $n = 0; sub { ++$n . $_ } });
    my @a = qw(a b);
    my @b = qw(x y);
    my $first  = $numbered->iterator(sub { @a ? shift @a : () });
    my $second = $numbered->iterator(sub { @b ? shift @b : () });
    say join ' ', $first->(), $second->(), $first->(), $second->();    # 1a 1x 2b 2y

A source that returns C<shift @queue // ()> ends at the first C<undef> in
the queue; C<@queue ? shift @queue : ()> doesn't. A filehandle is read
in scalar context, C<< sub { scalar(<$fh>) // () } >>, so that each call
reads one line.

=head2 stages

    my @stages = $p->stages;

Returns the pipeline's stages, in order, as they were given to C<new>:
a copy of the list, so changing it changes nothing in the pipeline. In
scalar context, it returns how many there are.

A pipeline isn't a stage, but its stages can be spliced into another
pipeline, or given to any function that takes stages, so a pipeline
made once can be used wherever stages go:

    my $clean = Ekorn::Pipeline->new(sub { s( \A \s+ | \s+ \z )()xgr }, sub { length ? $_ : () });
    say join '|', Ekorn::Pipeline->new($clean->stages, take(2))->(' a ', '  ', 'b ', 'c');    # a|b

Spliced in, the stages run in the other pipeline's run, as if they'd
been listed there, so it behaves just as listing them would:

=over 4

=item *

A stop in one of them ends the whole run, and the source is called no
more.

=item *

A C<gather> stage is made afresh for each run of the pipeline it's
in, so its state isn't shared between pipelines, or between its uses
when given twice. A plain closure is the same code reference
wherever it goes, so whatever it keeps is shared: keep state in
C<gather>.

=item *

A stage that dies is named by its place in the pipeline it was
spliced into.

=back

That differs from calling a pipeline from a stage, where each call is a
run of its own, as L<Pipelines inside stages|/"Pipelines inside stages">
says.

=head2 ending

    Ekorn::Pipeline::ending()

True while the values going through the stages come from an end
function, rather than from the source or the values a pipeline was
called with. It isn't exported.

It's for code that tells its stages about the value they're given,
such as the value it came from, which a value an end function makes
doesn't have. DBIx::Squirrel, for instance, tells its stages the row a
value was made from, and has none to tell while C<ending> is true.

    my @seen = Ekorn::Pipeline->new(
        collect { scalar @_ },
        sub { Ekorn::Pipeline::ending() ? "count $_" : $_ },
    )->(qw(a b c));
    say "@seen";    # count 3

A pipeline run inside a stage has its own: in a pipeline called from a
stage while C<ending> is true, C<ending> is false until one of its own
end functions is called.

=head1 How values go through stages

=head2 One value at a time

Each value goes through every stage before the next one starts, as it
would in a C<for> loop. So the results come out in order, each stage
sees the values in order, and nothing is held between stages, except by
a stage that holds values itself, such as C<batch> or C<collect>.

When a stage returns several values, the first goes on through the
rest of the stages, then the second, and so on, before the next value
from the source or the caller:

    my @trace;
    Ekorn::Pipeline->new(
        sub { push @trace, "1:$_"; ("$_.1", "$_.2") },
        sub { push @trace, "2:$_"; $_ },
    )->(qw(a b));
    say "@trace";    # 1:a 2:a.1 2:a.2 1:b 2:b.1 2:b.2

=head2 What a stage is given

A stage is called with one value, both as its only argument and in
C<$_>, so it can name the value with a signature, C<sub ($track) { ... }>,
or leave the signature out and use C<$_>, C<sub { ... }>.

=over 4

=item *

C<$_> is local to each call, so the caller's C<$_> is left as it was,
and a stage can call code that uses C<$_> itself.

=item *

The values a pipeline is called with are copied, so assigning to C<$_>
or C<$_[0]> changes the pipeline's copy, not the caller's variable.

=item *

A reference is copied as a reference: a stage that changes the hash
or array it's given changes the caller's.

=back

=over 4

B<For stage authors:> a stage is always called with exactly one
argument, so a signature of one is safe. Don't change the value
you're given, unless that's what your stage is for and its
documentation says so: return a new value instead.

=back

=head2 What a stage returns

A stage returns a list, and what it returns is all that goes on:

=over 4

=item an empty list

B<Its kind:> a filter

B<What goes on:> nothing: the value is dropped, and the stages after it don't see it

=item one value

B<Its kind:> a map

B<What goes on:> that value, in place of the one it was given

=item several values

B<Its kind:> a flatMap

B<What goes on:> each of them, in order, through the rest of the stages

=back

C<undef>, 0 and C<''> are values, so C<return undef> passes on C<undef>,
and a stage ending in a test, such as C<< sub { $_ > 2 } >>, passes on what
the test returns, not the value. To drop a value, return an empty list:
C<return;> or C<()>.

=over 4

B<For stage authors:> a stage run for its side effects, such as
logging, returns the value it was given, as C<peek> does, or it drops
it.

=back

=head2 Runs

Each call of a pipeline with values is a run, and so is each iterator
made from it. At the start of each run, the block of every C<gather>
stage is called, so what those stages keep starts afresh. An iterator's
run starts when it's made, not when it's first read.

A stage that isn't made with C<gather> is the same code reference on
every run, so whatever it keeps in a closure stays there from one run
to the next:

    my $count = 0;
    my $plain = Ekorn::Pipeline->new(sub { ++$count });
    my @first  = $plain->(qw(a b));
    my @second = $plain->(qw(a b));
    say "@first / @second";    # 1 2 / 3 4

=over 4

B<For stage authors:> anything a stage keeps, even a count, goes in
a C<gather> block. A stage made once may be given to several
pipelines, run more than once, or run by two iterators at the same
time.

=back

=head2 Pipelines inside stages

A stage can run a pipeline of its own, so stages can be built from
stages:

    my $trim = Ekorn::Pipeline->new(sub { s( \A \s+ | \s+ \z )()xgr }, sub { length ? $_ : () });
    say join '|', Ekorn::Pipeline->new(sub { $trim->($_) })->(' a ', '  ', 'b ');    # a|b

Each call of the inner pipeline is a run of its own: its C<gather>
stages start afresh on each value the outer stage is given, its end
functions are called at the end of each call, and a stop in it ends
only that call, not the outer pipeline. To have its stages run in the
outer pipeline's run instead, as if listed there, splice them in with
L<stages|/"stages">.

=head1 Stopping a pipeline: Ekorn::Pipeline::Stop

    use Ekorn::Pipeline::Stop;       # Stop
    use Ekorn::Pipeline::Stop ();    # nothing: call Ekorn::Pipeline::Stop->throw

A stop is the exception that ends a run early and quietly.

=head2 Stop

    Stop();
    Stop(@values);

Throws a stop carrying C<@values>, the last values of the stage that
throws it. It's the same as C<< Ekorn::Pipeline::Stop->throw(@values) >>,
and is exported by default.

=head2 throw

    Ekorn::Pipeline::Stop->throw(@values);
    My::Stop->throw(@values);

Throws a stop carrying C<@values>, blessed into the class it's called
on, so a subclass of Ekorn::Pipeline::Stop throws one of its own.

=head2 What a stop does

When a stage throws a stop:

=over 4

=item *

The rest of the stage that threw it doesn't run.

=item *

The results already out are kept: returned, in a pushed run, or
already handed out, by an iterator.

=item *

The values the stop carries go on through the stages after the one
that threw it, as that stage's last values.

=item *

Nothing else is processed. The values waiting to go through the
stages are dropped: the rest of the values a pipeline was called
with, the rest of what a source returned in one call, and the rest of
what a stage returned as a flatMap. The source isn't called again.

=item *

The end functions of C<gather> stages after the one that stopped are
called, in order, so they get the values that went by before the
stop, and the values it carries. Those of the stage that stopped, and
of the stages before it, aren't.

=back

    my @seen;
    my @out = Ekorn::Pipeline->new(
        sub { push @seen, $_; $_ == 3 ? Stop('three') : $_ },
        sub { uc },
    )->(1 .. 5);
    say "@out; saw @seen";    # 1 2 THREE; saw 1 2 3

An end function can stop the pipeline too. The values its stop carries
go on through the stages after it, and the ends after it are still
called.

=head2 The stop object

A stop is an array reference, blessed into its class. Its first
element is that class, and the rest are the values it was thrown with:

    eval { Ekorn::Pipeline::Stop->throw(1, 2) };
    say ref $@, ' ', "@{$@}[1 .. $#{$@}]";    # Ekorn::Pipeline::Stop 1 2

As a string, a stop is "Stop used outside a pipeline", with a newline,
which is what a user sees if one is thrown with no pipeline to catch
it.

A stop that isn't an array, made without C<throw>, as by blessing a
hash into the class, still stops the pipeline, but carries nothing.

=head2 Subclasses

A pipeline recognises a stop with C<isa>, so a stop of a subclass of
Ekorn::Pipeline::Stop stops it too, and behaves in the same way.

=head2 Catching errors in a stage

A stop is an exception, so a stage that catches errors itself, with
C<eval> or C<try>, catches stops too, including those of the stages it
runs, such as C<take>'s. It must throw them on:

    use experimental qw(try);

    my @out = Ekorn::Pipeline->new(sub ($x) {
        try {
            Stop() if $x > 2;
            return 10 / $x;
        }
        catch ($e) {
            die $e if $e isa 'Ekorn::Pipeline::Stop';
            return 'n/a';
        }
    })->(0, 1, 2, 3);
    say "@out";    # n/a 10 5

Test with C<isa 'Ekorn::Pipeline::Stop'>, not with C<ref>, so that a stop
of a subclass is thrown on too.

=head1 Gathering: Ekorn::Pipeline::Gather

    use Ekorn::Pipeline::Gather;       # gather
    use Ekorn::Pipeline::Gather ();    # nothing: call Ekorn::Pipeline::Gather::gather

A plain stage can't tell when the last value has gone by, and whatever
it keeps stays from one run to the next. A stage that gathers values,
to give them in batches or all together, needs both: state of its own
on each run, and a call at the end. C<gather> makes such a stage.

=head2 gather

    my $stage = gather { ...; return ($stage, $end) };
    my $stage = gather { ...; return $stage };

Returns a stage that a pipeline makes afresh at the start of each run,
by calling the block, so whatever the block declares is fresh on each
run. The block returns:

=over 4

=item *

the stage, called with each value, as any stage is;

=item *

optionally, an end function, called once the values run out.

=back

C<gather> croaks "Expected a code reference" if it's given something
other than a block or code reference. The block is called when the run
starts, not when C<gather> is: when the pipeline is called with values,
or an iterator is made from it. So a block that returns something
other than one or two code references is reported then, as "Expected
stage #%d, made with gather, to return one or two code references".

What C<gather> returns is a code reference, blessed into
Ekorn::Pipeline::Gather, so it can be given wherever a stage can.

    sub running_total () {
        return gather {
            my $total = 0;    # this run's
            return sub ($n) { $total += $n };
        };
    }

    my $p = Ekorn::Pipeline->new(running_total());
    say join ' ', $p->(1, 2, 3);    # 1 3 6
    say join ' ', $p->(1, 2, 3);    # 1 3 6

=head2 End functions

An end function is called with no arguments, and with C<$_> undefined,
once the values run out: in a pushed run, after the last value has gone
through; with an iterator, once the source returns an empty list, or
after a stop. What it returns goes on through the stages after its
own, as what a stage returns does: nothing, one value, or several.

=over 4

=item *

It's called even when no values went by, so an end can give an empty
result, such as C<[]>, or nothing at all.

=item *

The ends are called in order, first stage first. What one returns
goes through the stages after it, and those stages' ends see it,
before the next end is called. So a C<collect> after a C<batch> gets
C<batch>'s last, short batch.

=item *

After a stop, only the ends of the stages after the one that stopped
are called, as L<What a stop does|/"What a stop does"> says.

=item *

While the values an end returns go through the stages,
L<C<ending>|/"ending"> is true.

=item *

An end that dies is reported as its stage would be, by the stage's
place.

=back

    sub average () {
        return gather {
            my($sum, $n) = (0, 0);
            my $stage = sub ($x) { $sum += $x; $n++; return };
            my $end   = sub ()   { $n ? $sum / $n : () };
            return ($stage, $end);
        };
    }

    say Ekorn::Pipeline->new(average())->(2, 4, 9);    # 5
    say scalar Ekorn::Pipeline->new(average())->();    # 0

The second line prints 0, the number of results: with no values, the
end returns nothing.

=over 4

B<For stage authors:> a stage that holds values gives them up in
its end, as C<batch> and C<collect> do, so none are lost when the
values run out. Give the end a signature of none, C<sub ()>.

=back

=head1 pipe and tap: Ekorn::Pipeline::Pipes

    package My::Client;
    use parent 'Ekorn::Pipeline::Pipes';

A parent class giving its children two methods, C<pipe> and C<tap>,
which run the object they're called on through a pipeline of stages.
The first stage is given the object, in C<$_> and as its argument.
DBIx::Squirrel's database and statement handles have the same two
methods.

=head2 pipe

    my @results = $object->pipe(@stages);
    my $first   = $object->pipe(@stages);

Runs the object through a pipeline of C<@stages>, and returns what
comes out of the last one. In scalar context, it returns the first of
the results, or C<undef> if there are none, where a pipeline called in
scalar context returns how many there are. With no stages, it returns
the object.

=head2 tap

    $object = $object->tap(@stages);

Runs the object through a pipeline of C<@stages> for their side effects,
and returns the object, whatever comes out of the stages, so a chain
of method calls can carry on after it.

    package Counter {
        use parent 'Ekorn::Pipeline::Pipes';
        sub new ($class) { bless {n => 0}, $class }
        sub up ($self) { $self->{n}++; $self }
        sub n ($self) { $self->{n} }
    }

    say Counter->new->up->tap(sub { $_->up })->up->n;    # 3
    say scalar Counter->new->pipe(sub { $_->n + 10 });   # 10

=head1 Canned stages

Stages for any values, whatever they are and wherever they come from,
in three modules. Each is a function that returns a stage, and checks
what it's given when it's called, not on each value, croaking at the
caller's line if it's wrong. Those that keep state or hold values are
made with C<gather>, so they start afresh on each run.

=over 4

=item C<take($count)>

B<Module:> Flow

B<Passes on:> the first C<$count> values, then stops

B<Exported:> by default

=item C<drop($count)>

B<Module:> Flow

B<Passes on:> all but the first C<$count> values

B<Exported:> by default

=item C<take_while { ... }>

B<Module:> Flow

B<Passes on:> values until the block is false of one, then stops

B<Exported:> on request

=item C<drop_while { ... }>

B<Module:> Flow

B<Passes on:> values from the first the block is false of

B<Exported:> on request

=item C<batch($size)>

B<Module:> Batch

B<Passes on:> array references of C<$size> values, the last shorter

B<Exported:> by default

=item C<collect>

B<Module:> Batch

B<Passes on:> at the end, an array reference of every value

B<Exported:> by default

=item C<collect { ... }>

B<Module:> Batch

B<Passes on:> at the end, what the block makes of every value

B<Exported:> by default

=item C<peek { ... }>

B<Module:> Taps

B<Passes on:> every value, after calling the block with it

B<Exported:> by default

=item C<count_into(\$n)>

B<Module:> Taps

B<Passes on:> every value, counting them into C<$n>

B<Exported:> by default

=item C<dump_to($fh)>

B<Module:> Taps

B<Passes on:> every value, after writing it to C<$fh> or STDERR

B<Exported:> on request

=back

Each module exports its defaults with a plain C<use>, and every stage it
has with C<:all>. To have the defaults and one more, name C<:DEFAULT>
too:

    use Ekorn::Pipeline::Stages::Flow qw(:DEFAULT take_while);

=head2 Ekorn::Pipeline::Stages::Flow

Stages that decide which values go on, by their place or by a test.

=head3 take

    take($count)

Passes on the first C<$count> values, then stops the pipeline, so an
iterator calls its source no more. The last value it passes on goes
with the stop, so the source isn't asked for one more than is wanted.
With fewer values, it passes them all on. C<take(0)> passes on none,
but sees one value first, as a stage isn't called until there is one:
with an iterator, the source is called once.

It croaks "Expected a count of 0 or more" if C<$count> isn't a whole
number.

=head3 drop

    drop($count)

Drops the first C<$count> values, and passes on the rest. With C<take>,
it gives a page: C<drop(20), take(10)> passes on the 21st to the 30th.
It croaks "Expected a count of 0 or more" if C<$count> isn't a whole
number.

=head3 take_while

    take_while { ... }

Passes on values while the block is true of them, then stops the
pipeline at the first it's false of, which isn't passed on. The block
is given each value in C<$_> and as its argument. It croaks "Expected a
code reference" if it isn't given a block or code reference.

=head3 drop_while

    drop_while { ... }

Drops values while the block is true of them, and passes on the rest,
from the first it's false of. Once it's false, the block isn't called
again on that run. The block is given each value in C<$_> and as its
argument. It croaks "Expected a code reference" if it isn't given a
block or code reference.

    say join ' ', Ekorn::Pipeline->new(drop_while { $_ < 3 }, take_while { $_ < 6 })->(1 .. 9);
    # 3 4 5

=head2 Ekorn::Pipeline::Stages::Batch

Stages that gather values, and pass them on together. Both hold values,
and pass on what they still hold once the values run out.

=head3 batch

    batch($size)

Passes values on in batches of C<$size>, each a new array reference.
Once the values run out, the last batch, which may be shorter, goes
on. There's no empty batch: without values, there's no batch at all.
It holds no more than one batch at a time. It croaks "Expected a batch
size of 1 or more" if C<$size> isn't a whole number above 0.

=head3 collect

    collect
    collect { ... }

Holds every value, and once they run out, passes on an array reference
of them, or, given a block, what the block returns, called once with
the values as its arguments. What the block returns goes through the
stages after it, as what a stage returns does: nothing, one value, or
several. It's called even without values, so C<collect> still gives a
result: an empty array, or what the block makes of none. It croaks
"Expected a code reference" if it's given something other than a
block or code reference.

C<collect> holds every value until the end, so the whole result is in
memory at once.

    say join ' ', map { "[@$_]" } Ekorn::Pipeline->new(batch(2))->(1 .. 5);    # [1 2] [3 4] [5]
    say Ekorn::Pipeline->new(collect { join '+', @_ })->(1 .. 3);               # 1+2+3

=head2 Ekorn::Pipeline::Stages::Taps

Stages that look at each value as it goes by, and pass it on as it is,
for logging, counting or debugging.

=head3 peek

    peek { ... }

Calls the block with each value, in C<$_> and as its argument, and
passes the value on, whatever the block returns. It croaks "Expected a
code reference" if it isn't given a block or code reference.

=head3 count_into

    count_into(\$count)

Counts the values into C<$count>, setting it to 0 at the start of each
run, so after a run it holds how many values went by, even when that's
none. It croaks "Expected a reference to a scalar" if it isn't given
one.

=head3 dump_to

    dump_to($fh)
    dump_to

Writes each value to C<$fh>, or to STDERR, with Data::Dumper, its keys
in order and indented by two, and passes it on. It croaks "Expected an
open filehandle" if C<$fh> isn't one.

It's for debugging. It writes each value in full, secrets and all, and
doesn't escape control characters in strings, so a value from outside
can send escape sequences to a terminal.

=head1 Errors: Ekorn::Pipeline::Errors

=head2 When a stage dies

A stage, or an end function, that dies with a message is reported by
its place in the pipeline, counting from 1, at the line that ran the
pipeline: the call of the pipeline, or of the iterator that asked for
the result. The message it died with follows, indented by four spaces:

    Pipeline stage #2 failed at app.pl line 12:
        No name for user 7 at app.pl line 9.

An exception object, such as a stop or an object of a class of your
own, is thrown on as it is, so code that catches it can tell it by its
class.

Either way, the run has ended. A pushed run returns nothing, and an
iterator returns an empty list on every call after, without calling
its source or any end function again, as L<iterator|/"iterator"> says.

A mistake in making a pipeline, such as a stage that isn't a code
reference, or in making a canned stage, such as C<take(-1)>, is
reported at the line that made it, before any value goes through.

=head2 croakf

    use Ekorn::Pipeline::Errors qw(croakf);

    croakf 'Expected a length of 0 or more, not %s', $length;

Croaks with a message made by C<sprintf> from a format and its
arguments, reporting it at the same line as Carp's C<croak> would: the
line that called the function calling C<croakf>. It's exported only on
request.

It's for modules of stages outside Ekorn::Pipeline too. Called from a
function that makes a stage, in a package of its own, it reports a
mistake at the line that called the function, with no more set up. A
C<%> in the message is written C<%%>.

The format is a literal, written in the code: values go in as
arguments, through C<%s> and the like, never as the format. A format
made from data does whatever its C<%> directives say, such as
C<%999999999s>, which makes a string of a gigabyte.

=head2 @INTERNAL and @CARP_NOT

    our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

C<@Ekorn::Pipeline::Errors::INTERNAL> lists the packages of
Ekorn::Pipeline. Each of its modules that croaks takes the list as its
C<@CARP_NOT>, so that Carp looks past all of them to the first line
outside, where the user's code is.

A package that puts the list in its own C<@CARP_NOT> is looked past
too:

=over 4

=item *

B<A module of functions taking stages,> which runs its callers'
stages, has their errors reported at its callers' lines, rather than
at its own line that ran the pipeline. DBIx::Squirrel does this.

=item *

B<A module of stages whose helpers are in another package> puts
that package in its C<@CARP_NOT>, and the helper's package puts the
module's, so that C<croakf> in the helper reports at the line that
called the module. A helper in the same package needs nothing.

=back

=head1 Writing stages

A stage for others to use is written as the canned stages are, so that
it works alongside them.

=over 4

=item *

B<A function that makes a stage.> A plain C<sub> is a stage. For a
stage others will use, write a function that returns one, as
C<take(10)> does. It can take options, and check them once, when it's
called, not on each value.

=item *

B<Report mistakes at the caller's line,> with C<croakf>, from a
package of your own, as L<croakf|/"croakf"> says, with a literal
format and the values as its arguments. Put "Expected" first,
and say what was expected, as the canned stages do: "Expected a count
of 0 or more".

=item *

B<One argument in; a list out.> The stage is given one value, in C<$_>
and as its argument. It returns an empty list to drop it, one value to
pass it on, or several. Return the value from a stage run for its side
effects.

=item *

B<Don't change the value you're given,> unless that's the stage's
job and its documentation says so.

=item *

**State goes in C<gather>,** even a count, so that it starts afresh on
each run, and two runs at once don't share it.

=item *

B<Values held go out in an end function,> called even when there
were no values, with no arguments and C<$_> undefined.

=item *

B<Stop when no more values are wanted,> with C<Stop>, so an iterator
reads no more. Pass the last value on with the stop, as C<take> does,
so the source isn't asked for one more than is needed.

=item *

B<Throw stops on.> A stage that catches errors throws a stop on with
C<die $e if $e isa 'Ekorn::Pipeline::Stop';>.

=item *

B<Say what the stage takes and gives,> in its documentation: what
kind of value it's given, what it passes on, whether it holds values
or stops, and what it croaks with.

=item *

B<Names.> A name says what the stage does to a value, and a tap's
says it passes values on, as C<peek> and C<count_into> do. Avoid names
that common modules export: Flow has C<drop>, not C<skip>, which
Test2::V0 and Test::More both export, and Test2::V0 also exports
names such as C<field>, C<item> and C<call>.

=item *

B<Exports.> Export the stages a module is usually used for by
default, in C<@EXPORT>, the rest in C<@EXPORT_OK>, and all of them with
an C<:all> tag.

=item *

B<Where it goes.> Stages for any values go under
C<Ekorn::Pipeline::Stages::*>. Stages for one kind of value or one
source go under the namespace of the module that knows about it, as
DBIx::Squirrel's stages for rows are C<DBIx::Squirrel::Stages::Rows>.

=item *

B<Tests.> A pipeline called with values tests a stage with nothing
else to set up. Run it twice, to show it starts afresh, with no
values, to show what its end gives, and through an iterator, counting
the calls of the source, to show a stage that stops reads no more
than it should.

=back

    package My::Stages::Numbers {
        use Ekorn::Pipeline::Errors qw(croakf);
        use Ekorn::Pipeline::Gather qw(gather);
        use Ekorn::Pipeline::Stop qw();

        # Pass on values until their sum would pass $limit, then stop.
        sub sum_up_to ($limit) {
            croakf 'Expected a number for the limit, not %s', $limit // 'undef'
                unless defined $limit && $limit =~ m( \A -? \d+ (?: \.\d+ )? \z )xa;
            return gather {
                my $sum = 0;    # this run's
                return sub ($n) {
                    Ekorn::Pipeline::Stop->throw if $sum + $n > $limit;
                    $sum += $n;
                    return $n;
                };
            };
        }
    }

    say join ' ', Ekorn::Pipeline->new(My::Stages::Numbers::sum_up_to(10))->(4, 3, 2, 5, 1);    # 4 3 2

=head1 Writing functions that take stages

=over 4

=item *

B<Take the stages last,> after whatever arguments the function
needs, as C<sub lines_of ($file, @stages)>. A caller who wants nothing
done passes none.

=item *

B<Push what you have; pull what you make.> Call the pipeline with
values already in memory. For values made one at a time, give
C<iterator> a source and return the iterator, so a stage that stops
saves the work of making the rest.

=item *

B<Let stages do the optional work.> An option that filters,
reshapes or limits what's returned is one a stage does already. Keep
the arguments only the function can act on, such as which file to
read.

=item *

B<Say what the first stage is given,> and number your own stages
into it, if the function puts stages of its own before its caller's.

=item *

B<Report errors at your callers' lines,> by putting
C<@Ekorn::Pipeline::Errors::INTERNAL> in the module's C<@CARP_NOT>.

=back

    package My::Files {
        use Ekorn::Pipeline;
        our @CARP_NOT = @Ekorn::Pipeline::Errors::INTERNAL;

        # The lines of a file, without their newlines, through the caller's stages.
        sub lines_of ($file, @stages) {
            open my $fh, '<', $file or die "Can't read $file: $!\n";
            return Ekorn::Pipeline->new(sub { s( \n \z )()xr }, @stages)
                ->iterator(sub { scalar(<$fh>) // () });
        }
    }

    my $text = "one\ntwo\nthree\n";
    my $next = My::Files::lines_of(\$text, sub { uc }, take(2));
    my @lines;
    while (my($line) = $next->()) { push @lines, $line }
    say "@lines";    # ONE TWO

=head1 Diagnostics

Every message Ekorn::Pipeline writes, by module. Each is reported at
the line of the caller's code that caused it.

=head2 Ekorn::Pipeline

=over 4

=item *

B<Expected stage #%d to be a code reference:> a stage given to
C<new> wasn't a code reference. A pipeline, which is an object, isn't
one either.

=item *

B<Expected a code reference:> the source given to C<iterator> wasn't
a code reference.

=item *

B<Expected stage #%d, made with gather, to return one or two code
references:> the block given to C<gather> for that stage returned
something other than a stage, or a stage and an end function.
Reported when the run starts.

=item *

B<Pipeline stage #%d failed at %s line %d:> a stage, or its end
function, died with a message, which follows, indented. An exception
object is thrown on as it is.

=back

=head2 Ekorn::Pipeline::Stop

=over 4

=item *

B<Stop used outside a pipeline:> a stop was thrown with no pipeline
running to catch it.

=back

=head2 Ekorn::Pipeline::Gather

=over 4

=item *

B<Expected a code reference:> C<gather> was given something other
than a block or code reference.

=back

=head2 Canned stages

=over 4

=item *

B<Expected a count of 0 or more:> C<take> or C<drop> was given
something other than a whole number.

=item *

B<Expected a batch size of 1 or more:> C<batch> was given something
other than a whole number above 0.

=item *

B<Expected a code reference:> C<take_while>, C<drop_while>, C<collect>
or C<peek> was given something other than a block or code reference.

=item *

B<Expected a reference to a scalar:> C<count_into> was given
something other than a reference to a scalar.

=item *

B<Expected an open filehandle:> C<dump_to> was given something other
than an open filehandle.

=back

=head1 The modules

=over 4

=item C<Ekorn::Pipeline>

Runs values through a list of stages: C<new>, C<iterator>, C<stages> and C<ending>.

=item C<Ekorn::Pipeline::Stop>

Ends a pipeline early: C<Stop> and C<throw>.

=item C<Ekorn::Pipeline::Gather>

Makes a stage afresh for each run, with a function called at the end: C<gather>.

=item C<Ekorn::Pipeline::Pipes>

A parent class giving C<pipe> and C<tap> methods.

=item C<Ekorn::Pipeline::Errors>

Reports errors at the caller's line: C<croakf> and C<@INTERNAL>.

=item C<Ekorn::Pipeline::Stages::Flow>

Canned stages taking or dropping values: C<take>, C<drop>, C<take_while>, C<drop_while>.

=item C<Ekorn::Pipeline::Stages::Batch>

Canned stages gathering values: C<batch>, C<collect>.

=item C<Ekorn::Pipeline::Stages::Taps>

Canned stages run for their side effects: C<peek>, C<count_into>, C<dump_to>.

=back
