=encoding utf8

=head1 NAME

Acme::Parataxis::TVar - Software Transactional Memory (STM) with Versioned Cells

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber await_sleep atomically retry];
    use Acme::Parataxis::TVar;

    my $account = Acme::Parataxis::TVar->new( value => 5 );

    async {
        # Consumer: waits for sufficient balance using retry
        my $taker = fiber {
            atomically {
                my $have = $account->get;
                retry if $have < 10;    # balance insufficient: park until modified
                $account->set( $have - 10 );
                return 'withdrew 10';
            };
        };

        await_sleep(10);
        say "Taker parked; waiters: " . $account->waiters;    # 1

        # Producer: deposit funds to satisfy the condition
        atomically {
            $account->set( $account->get + 20 );
        };

        say $taker->await . ", balance: " . $account->value;  # withdrew 10, balance: 15
    };

=head1 DESCRIPTION

A C<TVar> (Transactional Variable) is a mutable cell paired with a version counter. Rather than reading and writing
cells directly, operations are wrapped in an C<atomically> block and accessed through C<get> and C<set>. Writes remain
staged and isolated until the outermost transaction commits; at commit time, all writes land atomically as a single
unit, or none do.

This provides lock-free composability:

=over

=item *

B<Zero interleaving>: Two fibers performing multi-variable transfers cannot observe half-completed states. Either the
entire transaction commits, or it conflicts and restarts.

=item *

B<Automatic conflict resolution>: If another fiber commits changes to any TVar read by your transaction before your
transaction commits, your staged writes are discarded and your block is automatically re-run from the top.

=item *

B<Conditional waiting without polling>: Calling C<retry> aborts the current transaction and parks the calling fiber
until at least one of the TVars in its read set is committed by another fiber, whereupon the block re-runs
automatically.

=back

B<Critical Side-Effect Rule>: Because an C<atomically> block can be re-run multiple times due to commit conflicts or
C<retry> calls, the block must be free of irreversible side effects. Do not perform network I/O, file writes, channel
sends, or logging inside an C<atomically> block. Perform pure calculations inside the transaction, and execute side
effects afterward from the committed state.

=head1 METHODS

=head2 C<new( value =E<gt> $initial )>

    my $count = Acme::Parataxis::TVar->new( value => 0 );
    my $text  = Acme::Parataxis::TVar->new( value => 'initial' );

Constructs a new TVar cell holding C<$initial>. The C<value> parameter is required. A newly created cell starts at
version C<0>.

=head2 C<get( )>

    atomically {
        my $current = $cell->get;
    };

Reads the current value and journals the read in the active transaction log.

=over

=item *

B<Read-your-writes>: If C<set()> was called earlier in the same transaction, C<get()> returns that staged value.

=item *

B<Journaling>: Records the cell's version at the time of the read. If that version has changed by commit time, the
transaction aborts and restarts.

=back

Must be called from within an C<atomically> block (croaks otherwise).

=head2 C<set( $value )>

    atomically {
        $cell->set($new_value);
    };

Stages C<$value> as the cell's pending value for this transaction and returns that value. Staged writes are completely
invisible to other fibers and to L</"value( )"> until the transaction commits successfully. Falsy values (C<0>, C<''>,
and C<undef>) are supported.

Must be called from within an C<atomically> block (croaks otherwise).

=head2 C<value( )>

    my $val = $cell->value;

Returns the committed value of the cell directly. Can be called from anywhere (no fiber or transaction required).

B<Warning>: C<value()> is an unjournaled read intended strictly for tests, logging, and diagnostics. Reading a cell via
C<value()> inside a transaction bypasses conflict detection and can lead to lost updates (see L</"Behavior Notes">).

=head2 C<version( )>

Returns the cell's commit counter (incremented every time a transaction successfully writes to this cell). Can be read
from outside a transaction.

=head2 C<waiters( )>

Returns the number of fibers currently parked in a C<retry> call whose read set includes this TVar.

=head1 TRANSACTIONS

C<atomically> and C<retry> are exported by L<Acme::Parataxis>.

=head2 C<atomically( sub { ... } )>

    atomically {
        my $a_val = $a->get;
        my $b_val = $b->get;
        $a->set( $a_val - 10 );
        $b->set( $b_val + 10 );
    };

Executes the code block as an atomic transaction on the current fiber. Nested C<atomically> blocks join the enclosing
transaction; staged writes from inner blocks commit only when the outermost transaction completes. Returns the block's
return value in the caller's context.

=head2 C<retry( )>

    atomically {
        my $val = $cell->get;
        retry if $val <= 0;
        $cell->set( $val - 1 );
    };

Aborts the transaction, discards staged writes, and parks the fiber until one or more TVars in its read set change.
Once modified, the fiber is woken and the transaction re-executes from the beginning. Must be called inside
C<atomically> and after reading at least one TVar (croaks if called with an empty read set).

=head1 Recipes

=head2 Deadlock-free account transfers

    sub transfer ($from, $to, $amount) {
        atomically {
            my $bal_from = $from->get;
            retry if $bal_from < $amount;    # wait for funds
            my $bal_to = $to->get;
            $from->set( $bal_from - $amount );
            $to->set( $bal_to + $amount );
        };
    }

No locks are held during computation. If two fibers concurrently transfer between the same accounts in opposite
directions, one commits and the other restarts cleanly without deadlocking.

=head1 Behavior Notes

=over

=item * Semicolons after C<atomically { ... }>

Because C<atomically> has a C<(&)> prototype, omitting the trailing semicolon on an C<atomically { ... };> block
statement causes Perl to parse subsequent lines as additional arguments, producing confusing C<Too many arguments>
compile errors.

=item * C<value()> vs C<get()>

Calling C<< $cell->value >> inside an C<atomically> block reads the raw committed memory without logging it in the
transaction's read set. If another fiber modifies the cell before you commit, your transaction will not detect the
conflict, silently overwriting the other fiber's work. Always use C<< $cell->get >> inside transactions.

=item * Nested C<retry> unwinds the outer block

Calling C<retry> inside a nested C<atomically> block aborts the entire outermost transaction, not just the inner block.
Execution restarts from the top of the outermost block.

=back
