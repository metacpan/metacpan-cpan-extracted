# The record of known issues (ShellSpawn, Proc::Spawner, the parsers, the measurement tools)

This is the one list of the distribution's known problems, and of the bugs its authors ("we" below) found in others' code. It covers the shell layer [`lib/Proc/ShellSpawn.pm`](../lib/Proc/ShellSpawn.pm) (`Proc::ShellSpawn`, *ShellSpawn* below), the spawner [`lib/Proc/Spawner.pm`](../lib/Proc/Spawner.pm) (`Proc::Spawner`) with its Windows part, the parsers (`Proc::ShellSubset` and its `::Small` and `::Large`), and the tools with which we measure how close ShellSpawn comes to dash and bash. An item keeps its ID when it is fixed, and moves to the table "Fixed". Older records, whose items are summarized here: the Changes of the module Run, entries 0.05 and 0.06 ([Run 0.07's `Changes`](https://metacpan.org/release/ILYAZ/Run-0.07/changes); Run's items R1–R5, the last row of "Fixed"), [`pspawn-run-shortcomings.md` (0.03)](https://metacpan.org/release/ILYAZ/Proc-Spawner-0.03/view/doc/pspawn-run-shortcomings.md) (in Proc-Spawner 0.03; a summary of Run's shortcomings), [`pspawn-upstream-reports.md` (0.03)](https://metacpan.org/release/ILYAZ/Proc-Spawner-0.03/view/doc/pspawn-upstream-reports.md) (in Proc-Spawner 0.03; P1).

Module names: since 2026-11-02, 07:30, every module is under `Proc::` (`ShellSpawn` is `Proc::ShellSpawn`; the binding `PosixSpawn` became part of `Proc::Spawner`). Rows written before then keep the old names. The modules: the table at the top of [`pspawn-spawner.md`](pspawn-spawner.md).

## <a id="my-how-to-read-the-tables"></a>How to read the tables

- The column *Where* names the part with the problem. *Executor*: ShellSpawn, which runs the parsers' trees. *Parser*: the parsers. *Spawner*: Proc::Spawner; *binding*: its C part, [`Spawner.xs`](../Spawner.xs). *Measurement*: our tools that run the corpus snippets (below), in `doc/large-subset/tools/`. *Tests*: the test suite. *Upstream*: someone else's program, named in parentheses. *Run*: the module Run (on CPAN, by the same author), which Proc::Spawner uses where there is no posix_spawn and no fork. *Windows*, after a comma or alone: only on Windows. *(TODO)*: the open work is in [`TODO`](../TODO.md). *The distribution*: all of it.
- **❰BUG❱** marks a bug. A bug in others' code names their program right after the mark (**❰BUG❱ bash 5.2.21**); every other one is ours, in this distribution; most rows say so, "(ours; …)", with when and how it was found (some older ones, such as X14, do not). Not every problem of ours is marked; the mark is for wrong behaviour, not for limits.
- *Corpus snippets*: the shell snippets of six public collections, with which [README.md](../README.md#my-how-close) measures how close ShellSpawn comes to the shells, each named by its collection and number: `TL:` the tldr pages, `NB:` NL2Bash, `SC:` ShellCheck's tests, `BC:` the bash Cookbook, `PS:` pure-sh-bible, `PB:` pure-bash-bible; for example NB:9731. `LS:N` and `OWN:N` name tests of the parsers' own test files. *The corpus run*: every corpus snippet the large parser accepts (40,410) run by dash, `bash --posix` and ShellSpawn, and the results compared ([section 7 of `large-subset-state.md`](large-subset/large-subset-state.md#my-section-7)).
- *Batteries*: the files of hand-written shell snippets, one per line, in `t/batteries/`, that [`t/dash.t`](../t/dash.t) runs in dash and in ShellSpawn and compares ([README.md](../README.md#my-the-test-files)).
- *The spawn primitive*: the call that starts a child. *posix_spawn* is the C library's (on Windows our own, [`win_spawn.h`](../win_spawn.h)); *system1* is Perl's own `system 1, LIST`, through the module Run, which applies the redirections around it. *M2*: the user's decision for a system without posix_spawn: fork and exec, and where there is no fork either, system1. *M1*: settings that the primitive cannot make, made in C around the call. A setting made *around the call* is made in Perl's own process just before the primitive's call, and undone after, because the primitive cannot make it ([README.md](../README.md#my-the-approaches)).
- *The user*: the distribution's author, who makes its decisions. Names such as K3, NV1, A4 or rule E name the user's decisions, recorded where they apply. The same letter and number may name items of different lists (a decision page, a checklist, a session's findings); a row then says which, as X23 does for B2. Met often below: A5, where dash and bash differ at run time ShellSpawn may answer as dash; A4, a form outside the subset found only at run time gives a message and status 248; rule E, where dash and bash differ ShellSpawn takes the behaviour that rule E's categories (error, posix, harm, …) call better (the rules: [section 1 of `large-subset-state.md`](large-subset/large-subset-state.md#my-section-1); rule E's choices: [`large-subset-logical.md`](large-subset/large-subset-logical.md)). "[`TODO` A13](../TODO.md#my-a13)" is item A13 of `TODO`.
- Version labels: `post-0.11` is the work after release 0.11, before the next release; `post2-0.04`, `post3-0.04`, … are later stages after the same release ([the labels](README.md#my-version-labels-of-the-results)). [`Changes`](../Changes) has each. A fix labelled post-0.11 is in every release after 0.11.
