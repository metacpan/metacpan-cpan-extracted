# Sweep: whole repo (2026-10-22)

What this code does: a Mojolicious plugin. A template helper (`component`) emits a script tag; a route serves the component's JavaScript file with a rendered template spliced in. Load assumed: many concurrent web users, possibly several server worker processes, with the request URL (query string) under the control of anyone who can send a link. Mojolicious 9.42, Perl 5.42 for the runs below.
Read: `lib/Mojolicious/Plugin/WebComponent.pm`, all of `t/`, `Build.PL`, `META.json`, `cpanfile`, `minil.toml`, CI workflow, `Changes`, `README.md` and the POD. Not read: `.git` history (no `--hot` run), the installed Mojolicious source beyond behaviour seen when running.

Every finding below marked "reproduced" was run against a scratch Lite app (outside the repo) built on the plugin.

## Findings

### Must
1. **Any file on disk can be read through the script route** (`WebComponent.pm:77-81`)
   - **What this is:** The route takes the `*component` part of the URL and joins it onto `/assets/js/components/` to find a script.
   - **Problem:** The part is not checked for `..`. `GET /component/x/..%2f..%2f..%2f..%2fouter.js` returned the contents of a file outside `public/` (reproduced: 200 with the file body). Nothing limits the file to `.js` or to the component folder.
   - **Fix:** Reject a component name that has a `/` segment equal to `..`, or whose resolved path is not under the component folder; accept only `.js` names.
   - **If we skip it:** A visitor can read application source, config or any file the server user can read and that `static->file` resolves.

2. **A crafted link runs script in the visitor's browser (cross-site scripting)** (`WebComponent.pm:61-73`, `:133-139`)
   - **What this is:** The page's query string is copied into the script URL. The plugin pastes the template's HTML into a JavaScript backtick string.
   - **Problem:** Two ways in (both reproduced). (a) `?template=%60;alert(1);%60` on any page that uses `component` makes the "template not found" text contain a backtick, closing the string and running `alert(1)`. No template needs to echo anything. (b) Any template that prints a param, as the POD example does with `<%= $params->{system} %>`, lets `${alert(1)}` through, because HTML escaping does not touch `${`, backticks or backslashes.
   - **Browser check:** both payloads set `window.__pwned` in headless Chromium (Playwright 1.49 in a podman pod with the app) (reproduced). The same cause also breaks ordinary templates: a template containing a backtick or a backslash (`` `tick` back\slash ``) makes the component script a syntax error ("Unexpected identifier 'tick'"), and the element is never defined (reproduced).
   - **Fix:** Build the JavaScript with `Mojo::JSON::encode_json` or `to_json` on the HTML string (one string literal, correctly escaped) instead of hand-wrapping backticks. Leave the 404 message out of the JavaScript or escape it the same way.
   - **If we skip it:** One link sent to a user runs the attacker's code with the app's cookies and page access.

3. **Script route does not exist until a page has rendered the helper, in that process** (`WebComponent.pm:9-13`, `:107`)
   - **What this is:** The `route` attribute is lazy. The route is added the first time `component` is called, not in `register`.
   - **Problem:** `GET /component/x/a-b.js` before any page render returned 404 (reproduced). Under a multi-process server (hypnotoad, prefork), a script request that reaches a worker that has not rendered a page yet 404s; in a podman container (`perl:5.42-slim-threaded`, Mojolicious `prefork -w 2`), 8 script requests before any page render all returned 404, and after one page render only some returned 200 (`200 404 404 404 404 404 200 200`), so only the worker that rendered the page had the route (reproduced). The route is also added after every route the app defined, so a user's catch-all route can shadow it.
   - **Fix:** Touch `$self->route` in `register`.
   - **If we skip it:** Random missing components in production after restarts or on cold workers.

4. **A missing script file returns 500** (`WebComponent.pm:78-81`)
   - **What this is:** `static->file` returns `undef` for an unknown name.
   - **Problem:** `->handle` is called on it anyway; `GET /component/x/nope.js` returned 500 (reproduced). Any user can trigger it, and it logs an exception each time.
   - **Fix:** `return $c->reply->not_found unless $asset;`
   - **If we skip it:** Crawlers and typos produce a stream of server errors and log noise.

### Should
5. Should | `WebComponent.pm:137` | `delete $params->{cb}` does nothing, so the route's callback leaks into every script URL | `cb=CODE%280xb951672d0%29` appeared in the generated tag (reproduced), exposing a memory address and making every URL unique. Fix: delete `cb` from the hash before building `Mojo::Parameters` (or skip `cb` and other route-internal captures).
6. Should | `WebComponent.pm:113-116` | the `template` option of one `component` call leaks into later calls on the same request | `component 'a-b'`, then `{template => 'notes'}`, then `component 'a-b'`: the third URL carried `template=notes` (reproduced) because the option is merged into the request params. Fix: put the option on that call's own parameter copy.
7. Should | `WebComponent.pm:49` | unanchored `/(false|f|no|0)/i` skips templating for any name that contains `f`, `no` or `0` | `?template=notes` produced no template (reproduced); a name like `footer` or `10-grid` also matches. The `|| !defined($template)` part can never be true after the match. Fix: `/^(?:false|f|no|0)$/i`, test `defined` first.
8. Should | `WebComponent.pm:83-99` | script file is read as bytes and the rendered template is characters, then both go out through `render(text =>)` | a `.js` file with `é` and `€` came back double-encoded (reproduced), and in Chromium the value read `cafÃ© â¬` (reproduced); non-ASCII inside the template itself was fine. Fix: open the file with `:encoding(UTF-8)` or use `$asset->slurp` decoded.
9. Should | `WebComponent.pm:99` | response is sent as `text/html` | reproduced (`text/html;charset=UTF-8`). A server with `X-Content-Type-Options: nosniff` will not run it as a script. Fix: `$c->render(text => $content, format => 'js')`.
10. Should | `WebComponent.pm:120`, route `:12` | the request id in the URL changes on every page view, so the script URL is never the same twice | the browser cannot cache the script and the server renders the template again on each fetch. 11. Should | `WebComponent.pm:464`, `:21` | the POD documents a `helper` option; code ignores it | `register` hardcodes `'component'`. Fix: read `$config->{helper} // 'component'`, or delete the POD item.
12. Should | `t/register.t` | the tests cover the happy path only | no test fails for findings 1 to 9 (see TR table).

## Architecture notes

- `WebComponent.pm`: one module serves as plugin, helper and controller; `_serve` mixes name resolution, template choice, file read and string splicing in one 70-line function, so every fix above lands in the same function. The deletion test does not apply (one module, no seams). Worth `/deepen-it` only if the module grows; splitting out a `render script` function would let TR-1 to TR-7 test it without HTTP.

Compliance: `guard-it` scanner clean (11 rules, whole history); no `.compliance-rules/`, `SECURITY_POLICY.md` or `.dependency-audit.json` exist.

Verdict: fix 1 and 2 first (file read and script injection), then 3 and 4.
Lean: -3 lines (findings 14, 15), no dependency removable.
Browser run (Chromium, 14 checks): 8 pass, 6 fail, all six traced to findings 2 and 8. Passing: elements define, template lands in the shadow root, attribute setter updates the DOM, request param reaches the template, non-ASCII in a template, `template => undef`.
Not checked: the Musts by a separate validator agent; Perl versions other than 5.42; `META.json` beyond the `perl` line; installed Mojolicious versions other than 9.42; `--hot` history.
