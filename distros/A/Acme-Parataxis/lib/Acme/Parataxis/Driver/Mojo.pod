=head1 NAME

Acme::Parataxis::Driver::Mojo - Mojo::IOLoop and Mojo::Reactor Driver for Parataxis

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[await_read await_sleep fiber];
    use Mojo::IOLoop;

    # Attach Mojo's loop:
    Acme::Parataxis->attach_loop( Mojo::IOLoop->new );

    Acme::Parataxis::run( sub {
        my $ponger = fiber {
            await_sleep(30);
            syswrite( $socket, "ping\n" );
        };

        await_read( $socket, 2000 );
    } );

    Acme::Parataxis->detach_loop;

    # Or drive a bare Mojo::Reactor directly:
    Acme::Parataxis->attach_loop( $ioloop->reactor );

=head1 DESCRIPTION

C<Acme::Parataxis::Driver::Mojo> connects Parataxis to Mojolicious event loops. It allows fibers executing
C<await_read>, C<await_write>, and C<await_sleep> to be driven directly by a C<Mojo::IOLoop> or C<Mojo::Reactor>.

Key implementation details:

=over

=item *

B<Single I/O watcher constraint>: Mojo reactors support exactly one C<io()> watcher callback per filehandle.
Directional interest is updated via C<< $reactor->watch($fh, $read, $write) >>. The driver manages this automatically,
allowing fibers to watch reading and writing concurrently on a single descriptor while sharing a single reactor slot.

=item *

B<Handle non-blocking persistence>: The driver sets filehandles non-blocking via C<< $fh->blocking(0) >> when first
registered and leaves them non-blocking. Code sharing handles with this driver must expect non-blocking behavior.

=item *

B<Reactor duck-typing>: Accepts a full C<Mojo::IOLoop> or any object implementing the C<Mojo::Reactor> interface (such
as an embedded worker reactor).

=back

=head1 CONSTRUCTOR

=head2 C<new( loop =E<gt> $loop_or_reactor )>

    my $driver = Acme::Parataxis::Driver::Mojo->new( loop => $loop );

Constructs a new driver instance. Accepts a C<Mojo::IOLoop> or any reactor providing a C<one_tick()> method.

=head1 METHODS

=head2 C<watch_read( $fh, $cb )> / C<watch_write( $fh, $cb )>

Registers interest in read or write readiness on C<$fh>, installing the reactor C<io()> callback if not already present
and updating the interest mask. Returns C<$fh>. Croaks if C<$fh> is closed.

=head2 C<unwatch( $fh )>

Removes all I/O registrations for C<$fh> from the reactor. Returns true if the handle was monitored; false otherwise.

=head2 C<timer( $ms, $cb )>

Arms a reactor timer for C<$ms> milliseconds. Returns an opaque timer ID.

=head2 C<cancel_timer( $id )>

Cancels an active timer via C<< $reactor->remove($id) >>. Returns true if cancelled; false if already fired or unknown.

=head2 C<drive( )>

Executes C<< $reactor->one_tick >>. Runs one iteration of the reactor (waiting for I/O or the earliest timer).

=head2 C<poll_ready( )>

Also executes C<< $reactor->one_tick >>. See L</"Behavior Notes"> regarding Mojo polling characteristics.

=head1 Behavior Notes

=over

=item * C<one_tick> always waits for the earliest timer

Mojo's C<one_tick()> method does not take a timeout argument; it always waits until an event occurs or the earliest
registered timer fires. Because of this, C<poll_ready()> and C<drive()> execute the identical call. If long timers are
armed, polling passes will wait out that duration before returning.

=item * Reactor shutdown on idle tick

Calling C<one_tick> on a reactor with no active I/O watchers and no timers stops the reactor. Parataxis only calls
C<drive()> while C<< $driver->pending >> is positive, avoiding this condition.

=back
