=head1 NAME

Acme::Parataxis::Future - Single-Assignment Values for Fiber Coordination

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber];
    use Acme::Parataxis::Future;

    my $future = Acme::Parataxis::Future->new;

    async {
        # Consumer: parks until the future resolves
        fiber {
            say 'Waiting for answer...';
            my $val = $future->await;
            say "Got result: $val";
        };

        # Producer: sets the result from another fiber
        fiber {
            $future->set_result(42);
        };
    };

=head1 DESCRIPTION

An C<Acme::Parataxis::Future> represents a value that will become available at a later time. It acts as a
single-assignment coordination point between fibers: producers fulfill the future with a result or error, and consumers
park on it until it is ready.

Key characteristics:

=over

=item *

B<Zero polling>: Calling C<< $future->await >> suspends the calling fiber in the scheduler. When C<set_result> or
C<set_error> is called, all waiting fibers are re-enqueued onto the run queue in a single pass.

=item *

B<Single resolution>: A future can be fulfilled exactly once. Attempting to call C<set_result> or C<set_error> on an
already-ready future dies immediately.

=item *

B<Cancellable waits>: Fibers parked in C<await()> can be interrupted by L<with_timeout|Acme::Parataxis/with_timeout> or
L<Acme::Parataxis::CancellationToken>. If interrupted, the fiber is safely unregistered from the future's waiter list,
preventing stale wakeups.

=item *

B<Composable>: Futures compose with L<< Acme::Parataxis->wait_all >> and L<< Acme::Parataxis->wait_any >>.
C<Acme::Parataxis> fiber objects themselves implement this same Future interface.

=back

=head1 METHODS

=head2 C<new( )>

    my $fut = Acme::Parataxis::Future->new;

Constructs a new, unfulfilled future.

=head2 C<await( )>

    my $val = $fut->await;

Suspends the current fiber until the future is ready.

=over

=item * If the future is already ready, returns the result immediately without yielding.

=item * If the future resolves via C<set_result($val)>, returns C<$val>.

=item * If the future fails via C<set_error($err)>, dies with C<$err> in the awaiting fiber.

=back

Must be called from inside a scheduled fiber (croaks otherwise).

=head2 C<result( )>

    my $val = $fut->result;

Returns the resolved value immediately. Croaks with C<"Future not ready"> if the future is unfulfilled, or croaks with
the stored error if the future failed. Unlike C<await()>, C<result()> does not park—use this when C<is_ready()> is
already known to be true or inside an C<on_ready> callback.

=head2 C<set_result( $value )>

    $fut->set_result( { status => 'ok' } );

Fulfills the future with C<$value>. Transitions C<is_ready> to true, fires all callbacks registered via C<on_ready()>,
and wakes every fiber currently parked in C<await()>. Dies if the future is already ready.

=head2 C<set_error( $error )>

    $fut->set_error("Connection refused");

Fails the future with C<$error>. Transitions C<is_ready> to true, fires all callbacks registered via C<on_ready()>, and
wakes every fiber parked in C<await()>, where the error is rethrown. Dies if the future is already ready.

=head2 C<is_ready( )>

    if ( $fut->is_ready ) { ... }

Returns true if the future has been fulfilled (either by a result or an error).

=head2 C<error( )>

    my $err = $fut->error;

Returns the error passed to C<set_error>, or C<undef> if the future succeeded or is not yet ready.

=head2 C<on_ready( sub ($future) { ... } )>

    $fut->on_ready( sub ($f) {
        say "Finished with: " . ( $f->error // $f->result );
    } );

Registers a callback to execute when the future resolves. The callback receives the future object as its sole argument.
If the future is I<already> ready, the callback executes immediately inline.

=head2 C<clear_result( )>

    $fut->clear_result;

Resets the future back to an unfulfilled state, clearing stored results, errors, callbacks, and waiters.

=head2 C<remove_waiter( $fid )>

    $fut->remove_waiter($fid);

Unregisters a fiber ID from the future's wake queue. Used by the scheduler when a wait is interrupted via a timeout or
cancellation token.

=head1 Recipes

=head2 Bridging asynchronous callbacks to fibers

To integrate standard callback-based code with fibers, allocate a future and resolve it inside the callback:

    sub fetch_async ($url) {
        my $future = Acme::Parataxis::Future->new;

        legacy_http_client()->get( $url, sub ( $status, $body ) {
            if ($status == 200) { $future->set_result($body) }
            else                { $future->set_error("HTTP $status") }
        } );

        return $future;
    }

    async {
        my $data = fetch_async('https://cpan.org')->await;
        say "Downloaded: ${\length($data)} bytes";
    };

=head2 Fan-out broadcast

Multiple fibers can await the same future; when fulfilled, all waiting fibers are resumed:

    my $barrier = Acme::Parataxis::Future->new;

    for my $id ( 1 .. 3 ) {
        fiber {
            $barrier->await;
            say "Worker $id unblocked!";
        };
    }

    fiber {
        await_sleep(100);
        $barrier->set_result(1);    # wakes all 3 fibers
    };

=head1 Behavior Notes

=over

=item * Exception preservation

Exceptions passed to C<set_error> can be plain strings or structured exception objects. They survive intact across the
C<await> boundary and rethrow in the awaiting fiber with their original class and properties preserved.

=item * Futures vs. Fibers

Every fiber spawned via C<fiber { ... }> or C<spawn { ... }> implements the Future interface. You can pass a fiber
directly to C<wait_all>, C<wait_any>, C<await>, or inspect its C<< ->result >> once complete.

=back
