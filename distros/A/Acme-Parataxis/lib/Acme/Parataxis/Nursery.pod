=head1 NAME

Acme::Parataxis::Nursery - Structured Concurrency Container for Scoped Fiber Lifecycles

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async nursery];

    async {
        my ( $user, $preferences );

        my $ok = eval {
            nursery( sub ($n) {
                $n->spawn( sub { $user        = fetch_user(123) } );
                $n->spawn( sub { $preferences = fetch_prefs(123) } );
            } );
            1;
        };
        die $@ unless $ok;

        # Both children are guaranteed to have completed:
        say "User: " . $user->name;
    };

=head1 DESCRIPTION

C<Acme::Parataxis::Nursery> implements structured concurrency (popularized by Trio and Go errgroups). When concurrent
tasks are executed inside a nursery, the lifetimes of all child fibers are bounded by the enclosing block:

=over

=item *

B<Guaranteed join>: C<nursery( sub ($n) { ... } )> does not return until every child spawned via C<< $n->spawn >> has
completely terminated.

=item *

B<Prompt sibling cancellation>: If any child fiber dies with an unhandled exception, the nursery immediately cancels
all surviving siblings via an internal cancellation token. The nursery drains all in-flight work before rethrowing the
culprit failure.

=item *

B<No orphaned fibers>: Even if the parent fiber is interrupted (e.g. by an outer C<with_timeout>), all children in the
nursery are cancelled and drained before the parent unwinds.

=back

Fibers spawned independently via the top-level C<fiber { ... }> or C<spawn()> inside the block are B<not> enrolled in
the nursery and do not delay its join.

=head1 METHODS

=head2 C<spawn( sub { ... } )>

    my $child = $n->spawn( sub {
        do_concurrent_work();
    } );

Spawns a child fiber enrolled in this nursery. Returns the C<Acme::Parataxis> fiber object.

Children park once at birth rather than executing synchronously inline. This guarantees that an immediate failure on
the child's first statement routes through the scheduler's aggregation machinery rather than throwing unexpectedly into
the parent's setup block.

Croaks if called outside a scheduled fiber or without a code reference.

=head2 C<token( )>

    my $token = $n->token;

Returns the nursery's internal L<Acme::Parataxis::CancellationToken>. Cancelling this token manually cancels all
enrolled children and drains the group. Passing this token into a nested C<with_timeout> binds the group to an external
deadline.

=head1 ERROR HANDLING

=head2 Acme::Parataxis::Error::Nursery

When one or more child fibers die, the nursery drains all remaining siblings and throws an
L<Acme::Parataxis::Error::Nursery> exception:

=over

=item * C<< $err->primary >>: Returns the first I<natural> failure (the real bug or exception that caused the nursery
to fail, ignoring subsequent C<Cancelled> errors thrown by siblings as they were unwound).

=item * C<< $err->failures >>: Returns the list of every exception thrown by any child in the nursery, in spawn order.

=back

    use v5.40;
    use Acme::Parataxis qw[async nursery await_sleep];

    async {
        eval {
            nursery( sub ($n) {
                $n->spawn( sub { die "Database connection lost\n" } );
                $n->spawn( sub { await_sleep(10_000) } );
            } );
        };

        if ( my $err = $@ ) {
            if ( ref $err && $err->isa('Acme::Parataxis::Error::Nursery') ) {
                say "Root cause: " . $err->primary;    # "Database connection lost"
                say "Total child errors: " . scalar( $err->failures ); # 2 (database error + cancelled sleep)
            }
        }
    };

=head1 Recipes

=head2 Concurrent scatter-gather

To collect data from children, write into variables in the parent's lexical scope:

    my ( $orders, $inventory, $shipping );

    nursery( sub ($n) {
        $n->spawn( sub { $orders    = load_orders($id) } );
        $n->spawn( sub { $inventory = check_stock($id) } );
        $n->spawn( sub { $shipping  = calc_rates($id)  } );
    } );

    # All three lookups are complete and successful here.

=head2 Setting a deadline on the entire nursery

Pass the nursery's token to L<with_timeout|Acme::Parataxis/with_timeout>:

    use Acme::Parataxis qw[async nursery with_timeout await_sleep];

    async {
        eval {
            nursery( sub ($n) {
                $n->spawn( sub { await_sleep(5000) } );
                $n->spawn( sub { await_sleep(5000) } );

                # If 500ms elapses, the token cancels and aborts both children:
                with_timeout( 500, $n->token, sub { await_sleep(10_000) } );
            } );
        };
        warn "Nursery timed out: $@" if $@;
    };

=head1 Behavior Notes

=over

=item * Block returns do not short-circuit children

The block passed to C<nursery()> cannot return early to bypass pending children. The nursery joins I<every> child
spawned via C<< $n->spawn >> before returning. The nursery's return value is the return value of the enclosed block,
delivered only when all children have succeeded.

=item * Fail-fast vs. best-effort

A nursery enforces all-or-nothing execution. The moment one child fails, all surviving siblings are cancelled. If you
need independent background tasks where failures do not cascade, use unmanaged C<fiber { ... }> instances combined with
L<Acme::Parataxis::Monitor> instead.

=item * Parent exceptions take priority

If the parent block itself throws an exception before spawning finishes, all currently enrolled children are
immediately cancelled and drained, and the parent's own exception is rethrown verbatim (not wrapped in an
C<Error::Nursery>).

=item * Nested nurseries are isolated

Nesting a C<nursery> inside another forms an independent hierarchy. A failure in an inner nursery cancels only its own
children; if the inner nursery's error is caught with an C<eval>, the outer nursery continues uninterrupted.

=back
