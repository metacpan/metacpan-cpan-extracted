=pod

=encoding utf8

=head1 NAME

Acme::Parataxis::Sync::WaitGroup - Coordinate Completion of Multiple Concurrent Fibers

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber await_sleep];
    use Acme::Parataxis::Sync::WaitGroup;

    my $wg = Acme::Parataxis::Sync::WaitGroup->new;

    async {
        # Register 3 tasks before spawning:
        $wg->add(3);

        for my $id ( 1 .. 3 ) {
            fiber {
                say "Task $id running...";
                await_sleep(50);
                $wg->done;    # decrement counter
            };
        }

        say "Waiting for all tasks to finish...";
        $wg->wait;            # parks until counter hits 0
        say "All tasks complete!";
    };

=head1 DESCRIPTION

An C<Acme::Parataxis::Sync::WaitGroup> coordinates the completion of multiple asynchronous tasks, providing the fan-in
half of a fan-out/fan-in concurrency pattern.

The group maintains an integer counter:

=over

=item * C<add($n)> increments the counter by C<$n>.

=item * C<done()> decrements the counter by C<1>.

=item * C<wait()> parks the calling fiber until the counter drops to C<0>.

=back

WaitGroups do not track fibers or job handles; they track a numeric tally. This keeps the primitive lightweight and
fast, but requires callers to ensure that every C<add> is matched by exactly one C<done>.

=head1 METHODS

=head2 C<new( [ count =E<gt> $n = 0 ] )>

    my $wg = Acme::Parataxis::Sync::WaitGroup->new;
    my $primed = Acme::Parataxis::Sync::WaitGroup->new( count => 5 );

Constructs a new WaitGroup with an initial counter of C<$n> (default C<0>).

=head2 C<add( $n )>

    $wg->add(4);

Adds C<$n> to the counter and returns true. C<$n> must be an integer string or number (matches C</\A-?\d+\z/>).
Negative numbers are supported.

=over

=item * Croaks with C<WaitGroup add() requires an integer> if C<$n> is invalid or non-numeric.

=item * Croaks with C<WaitGroup counter would become negative> if adding C<$n> drives the counter below zero.

=item * If the counter transitions to C<0>, all fibers currently parked in C<wait()> are unblocked immediately.

=back

Safe to call outside a scheduled fiber.

=head2 C<done( )>

    $wg->done;

Decrements the counter by 1. Equivalent to C<< $wg->add(-1) >>. Safe to call outside a scheduled fiber.

=head2 C<wait( )>

    $wg->wait;

Parks the calling fiber until the counter reaches C<0>. If the counter is already C<0>, returns true immediately
without parking.

Must be called from within a scheduled fiber (croaks otherwise). Bounded waits are supported via
L<with_timeout|Acme::Parataxis/with_timeout>.

=head2 C<count( )> / C<remaining( )>

Returns the current value of the counter. C<remaining> is an alias. Both work outside of scheduled fibers.

=head2 C<waiters( )>

Returns the number of fibers currently parked in C<wait()>.

=head1 Recipes

=head2 Safe fan-out with guaranteed completion

To prevent jobs from stranding the group if an exception occurs, wrap the task in an C<eval> or C<defer>:

    use v5.40;
    use experimental 'defer';
    use Acme::Parataxis qw[async fiber];
    use Acme::Parataxis::Sync::WaitGroup;

    async {
        my $wg = Acme::Parataxis::Sync::WaitGroup->new;
        $wg->add( scalar @items );

        for my $item (@items) {
            fiber {
                defer { $wg->done };    # always decrements, even if process_item dies!
                process_item($item);
            };
        }

        $wg->wait;
    };

=head2 Dynamic task registration

A running task can increment the WaitGroup to enroll sub-tasks dynamically:

    sub worker ($wg, $task) {
        if ( my @subtasks = split_work($task) ) {
            $wg->add( scalar @subtasks );    # add subtasks before spawning
            for my $st (@subtasks) {
                fiber { worker($wg, $st) };
            }
        }
        $wg->done;
    }

=head1 Behavior Notes

=over

=item * Add before spawn

Always call C<< $wg->add() >> B<before> spawning the child fiber. If you call C<add> inside the spawned fiber, the
calling fiber might reach C<wait()> while the counter is still C<0>, causing C<wait()> to return immediately before the
children have even begun.

=item * Counter underflows

Calling C<done()> more times than C<add()> throws an exception. Crucially, C<add()> decrements the counter I<before>
checking the bounds, so a croaked C<done()> leaves the counter negative. A negative counter causes future C<wait()>
calls to return immediately without waiting. Avoid this by matching counts carefully.

=item * Re-checking on wake

C<wait()> re-checks C<count> in a loop upon waking. If a waking fiber is unblocked when C<count == 0>, but a concurrent
fiber immediately calls C<< $wg->add(2) >> before the waiter resumes, the waiter detects the positive count and
re-parks automatically until zero is reached again.

=back
