=head1 NAME

Term::Fabulous::Cookbook::TableRows - Recipes: sort, filter, group, nest and page table rows

=head1 DESCRIPTION

This page is part of L<Term::Fabulous::Cookbook>. Previous page: L<Term::Fabulous::Cookbook::Tables>. Next page: L<Term::Fabulous::Cookbook::TableStyles>.

The recipes on this page decide which rows a
L<Term::Fabulous::Widget::Table> shows and in which order: they sort
the rows, let the user filter them, filter them from Perl, put them into
groups the user can open and close, show nested rows as a tree, and split
many rows into pages. Each recipe is a complete program, shipped in
F<examples/cookbook/>, with a screenshot and notes on every feature it
uses. Besides the table, the recipes use
L<Term::Fabulous::Widget::Table::Filter> (conditions on rows) and
L<Term::Fabulous::Widget::Table::Mutator> (number and date formats).

L<Term::Fabulous::Manual::TableRows> explains the concepts behind these
recipes: sorting, filtering, groups, trees and pages.
L<Term::Fabulous::Manual::Tables> explains rows, columns and display
text, and L<Term::Fabulous::Manual::TableStyles> the lines and colors.
The reference of every parameter, method, key and event is on
L<Term::Fabulous::Widget::Table>. For a first table, start with
L<Term::Fabulous::Cookbook::Tables>.

All recipes on this page give the table the look of the recipe
L<A table with colored rows and titles|Term::Fabulous::Cookbook::TableStyles/A table with colored rows and titles (block frame, no grid lines)>:
C<< border => 'Outer' >>, C<< column_lines => 'none' >>,
C<< header_line => 'none' >> and a C<stripe_color>. Leave these four
parameters out for the default look: a rounded frame with thin lines
between the columns and below the titles.

The recipes on this page:

=over

=item *

L</Sort rows, also with your own comparison>

=item *

L</Let the user filter rows (filter row and search box)>

=item *

L</Filter rows from Perl (numbers, dates, text, raw or shown values)>

=item *

L</Group rows by a column (collapsible group headers)>

=item *

L</Show nested data as a tree (expand and collapse rows)>

=item *

L</Split many rows into pages (pager and page sizes)>

=back

=head1 Sort rows, also with your own comparison

Goal: sort a table by two columns at the start, sort version numbers
and ticket names in natural order, order priorities with a function of
your own, and report every sort the user chooses.

This program is shipped as F<examples/cookbook/table-sort.pl>.

=for code-from examples/cookbook/table-sort.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Table;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	my @tickets = (
		{ ticket => 'T-9',   title => 'Crash on empty config',    priority => 'high',   version => '2.10.1', opened => '2026-05-12', note => 'add a test' },
		{ ticket => 'T-10',  title => 'Typo in the help text',    priority => 'low',    version => '2.9',    opened => '2026-05-20', note => '' },
		{ ticket => 'T-2',   title => 'Slow start, 1000 rows',    priority => 'normal', version => '2.10',   opened => '2026-04-02', note => 'profile' },
		{ ticket => 'T-11',  title => 'Dark theme for the pager', priority => 'normal', version => '2.9.3',  opened => '2026-05-28', note => '' },
		{ ticket => 'T-101', title => 'Wrong date in reports',    priority => 'high',   version => '2.9.12', opened => '2026-05-30', note => 'customer' },
		{ ticket => 'T-7',   title => 'Mouse wheel too fast',     priority => 'low',    version => '2.10',   opened => '2026-03-15', note => '' },
	);

	# The order of the priorities: a custom comparison gets two raw values
	# (and copies of the two rows) and returns a number like <=> does.
	my %RANK = ( high => 1, normal => 2, low => 3 );

	sub by_priority ( $left, $right, $left_row, $right_row ) {
		return ( $RANK{ $left // '' } // 9 ) <=> ( $RANK{ $right // '' } // 9 );
	}

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);

	my $table = Term::Fabulous::Widget::Table->new(
		id     => 'tickets',
		row_id => 'ticket',
		sort   => [ 'priority', [ opened => 'desc' ] ],    # highest priority first, newest first within each
			# The look: a block frame, and colors instead of grid lines.
		border       => 'Outer',
		column_lines => 'none',
		header_line  => 'none',
		stripe_color => '#1c2029',
		columns      => [
			{ key => 'ticket',   title => 'Ticket', compare => 'natural' },    # T-2 before T-10
			{ key => 'title',    title => 'Title' },
			{ key => 'priority', title => 'Priority', compare  => \&by_priority },
			{ key => 'version',  title => 'Version',  compare  => 'natural' },    # 2.9.3 before 2.10
			{ key => 'opened',   title => 'Opened',   type     => 'date' },
			{ key => 'note',     title => 'Note',     sortable => 0 },
		],
		rows => \@tickets,
	);

	sub describe_sort ($spec) {
		return 'Not sorted: the rows are in data order.' unless @$spec;
		return 'Sorted by ' . join ', then ', map { "$_->[0] ($_->[1])" } @$spec;
	}

	my $help   = Term::Fabulous::Widget::Text->new( text => 'Click a title to sort, Ctrl+click adds it. Keys: Up into the titles, then Enter or Space.', text_color => [ 150, 160, 180, 255 ] );
	my $status = Term::Fabulous::Widget::Text->new( text => describe_sort( $table->sort_spec ),                                                          text_color => [ 229, 192, 123, 255 ] );
	$root->add_child( $help, $table, $status );

	$table->on(
		SortChange => sub ($event) {
			$status->text( describe_sort( $event->sort ) );
			return;
		}
	);

	my $ui = Term::Fabulous->new( root => $root, width => 96, height => 20 );
	$ui->interaction->set_focused_widget($table);
	$ui->run;

=end html

The picture shows the table after the keys C<Up>, C<Right> three
times, C<Enter> (sort by Version alone), C<Left> and C<Space> (add
Priority to the sort).

=over

=item *

C<< sort => [ 'priority', [ opened => 'desc' ] ] >> sorts by priority
first; rows with the same priority are ordered by the opening date,
newest first. A plain key sorts ascending, C<[ $key, 'desc' ]>
descending. Rows that are equal in every sort column keep their data
order. See L<Term::Fabulous::Manual::TableRows/Sorting from Perl> and
L<Term::Fabulous::Manual::TableRows/Sorting by several columns>.

=item *

C<< compare => 'natural' >> compares runs of digits as numbers:
C<T-2> comes before C<T-10>, and version C<2.9.12> before C<2.10>.
The default for text columns, C<'string'>, would put C<T-10> before
C<T-2>. See L<Term::Fabulous::Manual::TableRows/How values are compared>.

=item *

C<compare> also takes a code reference. It gets the two raw values and
copies of the two rows, and returns a negative number, 0 or a positive
number for B<ascending> order, like C<< <=> >> and C<cmp>. The table
reverses the result for descending order. The named comparisons put
blank values, and values they cannot read, last in both directions; a
function gets every value, blank ones (C<undef>) included, so it must
handle them itself, as C<by_priority> does with C<//>. See
L<Term::Fabulous::Manual::TableRows/Custom sort functions>.

=item *

C<< sortable => 0 >> keeps the user from sorting by the C<Note>
column: clicks and keys on its title do nothing. Your program can still
sort by it with
L<sort_by|Term::Fabulous::Widget::Table/sort_by>.

=item *

The user sorts by one column with a click on its title, which cycles
through ascending, descending and unsorted. C<Ctrl>+click (or
C<Shift>+click or C<Alt>+click) adds a column to the sort. With the
keyboard, C<Up> on the first row moves into the titles, C<Left> and
C<Right> choose one, C<Enter> sorts by it alone and C<Space> adds it to
the sort. The markers C<▴1> and C<▾2> show the direction and the place
of each column in the sort. See
L<Term::Fabulous::Manual::TableRows/Sorting by the user> and
L<Term::Fabulous::Widget::Table/In the header>.

=item *

C<SortChange> fires for every sort the user chooses.
C<< $event->sort >> is the new sort as a list of
C<[ $key, $direction ]> pairs, the same form
L<sort_spec|Term::Fabulous::Widget::Table/sort_spec> returns. The
C<sort> parameter fires no event, so the program writes the first
status line itself from C<< $table->sort_spec >>.

=back

=head1 Let the user filter rows (filter row and search box)

Goal: let the user filter a table by typing expressions such as
C<< >=80000 >> or C<2019..2021> under the column titles, search all
columns from a text field above the table, and show how many rows
pass.

This program is shipped as F<examples/cookbook/table-filter.pl>.

=for code-from examples/cookbook/table-filter.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Table;
	use Term::Fabulous::Widget::Table::Mutator qw(date number);
	use Term::Fabulous::Widget::Text;
	use Term::Fabulous::Widget::TextField;
	use Clay::XS qw(sizing_grow sizing_fixed CLAY_TOP_TO_BOTTOM);

	my @staff = (
		{ id => 1,  name => 'Ada Lovelace',      team => 'Core',     started => '2019-03-04', salary => 81000 },
		{ id => 2,  name => 'Grace Hopper',      team => 'Web',      started => '2021-11-15', salary => 92500 },
		{ id => 3,  name => 'Linus Torvalds',    team => 'Core',     started => '2017-06-01', salary => 90000 },
		{ id => 4,  name => 'Margaret Hamilton', team => 'Platform', started => '2016-02-22', salary => 99000 },
		{ id => 5,  name => 'Ken Thompson',      team => 'Core',     started => '2023-01-09', salary => 70000 },
		{ id => 6,  name => 'Barbara Liskov',    team => 'Platform', started => '2018-09-17', salary => 95500 },
		{ id => 7,  name => 'Dennis Ritchie',    team => 'Core',     started => '2020-05-11', salary => 78000 },
		{ id => 8,  name => 'Radia Perlman',     team => 'Network',  started => '2022-08-29', salary => 76000 },
		{ id => 9,  name => 'Tim Berners-Lee',   team => 'Web',      started => '2020-10-05', salary => 74500 },
		{ id => 10, name => 'Frances Allen',     team => 'Platform', started => '2024-02-12', salary => 68000 },
		{ id => 11, name => 'Hedy Lamarr',       team => 'Network',  started => '2019-12-02', salary => 88000 },
		{ id => 12, name => 'Katherine Johnson', team => 'Research', started => '2021-03-08', salary => 83000 },
	);

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);

	my $search = Term::Fabulous::Widget::TextField->new(
		id          => 'search',
		placeholder => 'Search all columns',
		layout      => { sizing => { width => sizing_fixed(30) } },
	);

	my $table = Term::Fabulous::Widget::Table->new(
		id         => 'staff',
		row_id     => 'id',
		filter_row => 1,
		sort       => ['name'],
		layout     => { sizing => { width => sizing_grow() } },

		# The look: a block frame, and colors instead of grid lines.
		border       => 'Outer',
		column_lines => 'none',
		header_line  => 'none',
		stripe_color => '#1c2029',
		columns      => [
			{ key => 'name',    title => 'Name',    width => 'grow' },
			{ key => 'team',    title => 'Team',    width => 'fixed(14)' },
			{ key => 'started', title => 'Started', width => 'fixed(16)', type => 'date',   mutator => date('%d %b %Y') },
			{ key => 'salary',  title => 'Salary',  width => 'fixed(14)', type => 'number', mutator => number( decimals => 0 ) },
		],
		rows => \@staff,
	);

	my $status = Term::Fabulous::Widget::Text->new( text => '',                                                                  text_color => [ 229, 192, 123, 255 ] );
	my $help   = Term::Fabulous::Widget::Text->new( text => 'Tab: next field. Try "core", ">=80000", ">=2020" or "2019..2021".', text_color => [ 150, 160, 180, 255 ] );
	$root->add_child( $search, $table, $status, $help );

	# The count of the rows that pass, or why a filter field is not used.
	sub show_count () {
		foreach my $key ( $table->column_keys ) {
			my $error = $table->filter_error($key) // next;
			$status->text( sprintf '%s: %s', $table->column($key)->title, $error );
			return;
		}
		$status->text( sprintf '%d of %d rows', scalar $table->filtered_row_ids, $table->row_count );
		return;
	}

	$search->on(
		Change => sub ($event) {
			$table->search( $event->value );
			show_count();
			return;
		}
	);

	$table->on(
		FilterChange => sub ($event) {
			show_count();
			return;
		}
	);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );
	show_count();
	$ui->interaction->set_focused_widget($search);
	$ui->run;

=over

=item *

C<< filter_row => 1 >> puts a text field under every column title.
The table filters while the user types, and shows only the rows that
match all fields. See L<Term::Fabulous::Manual::TableRows/The filter row>.

=item *

What a field accepts depends on the column's C<type>. In text columns,
C<core> keeps the rows whose cell contains "core" (upper and lower
case do not matter), C<^Ada> those whose cell starts with "Ada", and
C<!Web> those whose cell does not contain "Web". In number columns, C<< >=80000 >>,
C<< <70000 >> and C<70000..90000> compare numbers. In date columns,
C<< >=2019 >>, C<2021-03> and C<2019..2021> compare dates, and a date
stands for the whole year, month or day it names. In every column,
C<=> alone keeps the rows whose cell is empty and C<!=> alone those
whose cell is not empty. L<The filter row section of the manual|Term::Fabulous::Manual::TableRows/The filter row> lists the
full notation.

=item *

Number and date fields compare the I<raw value>, not the display
text: type C<80000>, not C<80,000>, and C<2019-03-04>, not
C<04 Mar 2019>. Text fields compare the display text. A column's
C<filter_on> changes this; see
L<Term::Fabulous::Manual::TableRows/Raw value or display text>.

=item *

The columns have fixed or growing widths so that the filter fields are
wide enough to type in. A filter field is as wide as its column.

=item *

C<Tab> and C<Shift+Tab> move between the search field, the table and
the filter fields. In a filter field, C<Enter> or C<Down> go to the
rows and C<Escape> empties the field.

=item *

The search field is a plain L<Term::Fabulous::Widget::TextField>. Its
C<Change> listener passes the text to
L<search|Term::Fabulous::Widget::Table/search>, which keeps the rows
where the display text of at least one visible cell contains the text.
The search and the filter fields work together: a row must pass both.
See L<Term::Fabulous::Manual::TableRows/Searching all columns>.

=item *

C<FilterChange> fires after every change the user makes in a filter
field. When a field holds an expression its column cannot read, such as
C<< >abc >> in the Salary field, its text turns red, the column is not
filtered, and L<filter_error|Term::Fabulous::Widget::Table/filter_error>
returns the reason, which C<show_count> shows. Otherwise it shows the
number of rows that pass, from
L<filtered_row_ids|Term::Fabulous::Widget::Table/filtered_row_ids>,
and of all rows. Calling C<search> from Perl fires no event, so the
C<Change> listener of the search field calls C<show_count> itself.

=item *

When no row passes, the table shows C<No rows match>. See
L<Term::Fabulous::Manual::TableRows/What a filtered table shows>.

=back

=head1 Filter rows from Perl (numbers, dates, text, raw or shown values)

Goal: give the user a choice of ready-made filters, such as "placed in
May" or "not paid", built from conditions on numbers, dates and text,
combined with and, or and not.

This program is shipped as F<examples/cookbook/table-filter-perl.pl>.

=for code-from examples/cookbook/table-filter-perl.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Table;
	use Term::Fabulous::Widget::Table::Filter;
	use Term::Fabulous::Widget::Table::Mutator qw(date lookup number);
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	my $F = 'Term::Fabulous::Widget::Table::Filter';

	my @invoices = (
		{ invoice => 'A-1001', customer => 'Babbage Ltd',      placed => '2026-04-14', status => 'p', total => 1250.00, paid => 1250.00 },
		{ invoice => 'A-1002', customer => 'Analytical Works', placed => '2026-04-29', status => 'd', total => 480.50,  paid => 0 },
		{ invoice => 'A-1003', customer => 'Byron & Sons',     placed => '2026-05-03', status => 'o', total => 2300.00, paid => 1000.00 },
		{ invoice => 'A-1004', customer => 'Hollerith Ltd',    placed => '2026-05-11', status => 'o', total => 99.90,   paid => 0 },
		{ invoice => 'A-1005', customer => 'Countess Supply',  placed => '2026-05-20', status => 'p', total => 640.00,  paid => 640.00 },
		{ invoice => 'A-1006', customer => 'Boole Partners',   placed => '2026-05-27', status => 'd', total => 1720.00, paid => 200.00 },
		{ invoice => 'A-1007', customer => 'Jacquard Looms',   placed => '2026-06-01', status => 'o', total => 315.25,  paid => 0 },
	);

	# Key 1 to 5 sets one of these filters under the name 'chosen'; key 0
	# removes it.
	my @choices = (
		[ 'Totals of 1,000 or more' => $F->new( column => 'total',  op => '>=', value => 1000 ) ],
		[ 'Placed in May 2026'      => $F->new( column => 'placed', op => '=',  value => '2026-05' ) ],
		[
			'Open or overdue, totals from 100 to 2,000' => $F->all(
				$F->new( column => 'status', op => 'in', value => [ 'open', 'overdue' ], on => 'display' ),
				$F->new( column => 'total',  op => 'between', value => [ 100, 2000 ] ),
			)
		],
		[
			'Starts with B or is a Ltd, and is not paid' => $F->all(
				$F->any(
					$F->new( column => 'customer', op => 'starts_with', value => 'B' ),
					$F->new( column => 'customer', op => 'matches',     value => qr/\bLtd\z/ ),
				),
				$F->not( $F->new( column => 'status', op => 'equals', value => 'p' ) ),
			)
		],
		[ 'More than 500 still owed' => sub ($row) { $row->{total} - $row->{paid} > 500 } ],
	);

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);

	my $table = Term::Fabulous::Widget::Table->new(
		id     => 'invoices',
		row_id => 'invoice',

		# The look: a block frame, and colors instead of grid lines.
		border       => 'Outer',
		column_lines => 'none',
		header_line  => 'none',
		stripe_color => '#1c2029',
		columns      => [
			{ key => 'invoice',  title => 'Invoice' },
			{ key => 'customer', title => 'Customer' },
			{ key => 'placed',   title => 'Placed', type    => 'date', mutator => date('%d %b %Y') },
			{ key => 'status',   title => 'Status', mutator => lookup( { o => 'open', p => 'paid', d => 'overdue' } ) },
			{ key => 'total',    title => 'Total',  type    => 'number', mutator => number( decimals => 2 ) },
			{ key => 'paid',     title => 'Paid',   type    => 'number', mutator => number( decimals => 2 ) },
		],
		rows => \@invoices,
	);

	my $help   = Term::Fabulous::Widget::Text->new( text => 'Keys 1 to 5 choose a filter, 0 shows all rows. Ctrl+C quits.', text_color => [ 150, 160, 180, 255 ] );
	my $status = Term::Fabulous::Widget::Text->new( text => '',                                                             text_color => [ 229, 192, 123, 255 ] );
	$root->add_child( $help, $table, $status );

	sub choose_filter ($number) {
		if ( $number == 0 ) {
			$table->remove_filter('chosen');
			$status->text( sprintf '0: all rows (%d)', $table->row_count );
			return;
		}
		my ( $label, $filter ) = $choices[ $number - 1 ]->@*;
		$table->filter( chosen => $filter );
		$status->text( sprintf '%d: %s (%d of %d rows)', $number, $label, scalar $table->filtered_row_ids, $table->row_count );
		return;
	}

	# The table does not use the digit keys, so they bubble up to the root.
	$root->on(
		KeyPress => sub ($event) {
			my $key = $event->key_name // return;
			return unless $key =~ /\A[0-5]\z/;
			choose_filter($key);
			return;
		}
	);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );
	choose_filter(0);
	$ui->interaction->set_focused_widget($table);
	$ui->run;

=over

=item *

A condition is a L<Term::Fabulous::Widget::Table::Filter> with a
C<column>, an C<op> and a C<value>. The comparison ops (C<=>, C<!=>,
C<< < >>, C<< <= >>, C<< > >>, C<< >= >>, C<between>, C<in>) compare as
the column's C<type> says: numbers as numbers, dates as dates. The text
ops (C<contains>, C<not_contains>, C<equals>, C<not_equals>,
C<starts_with>, C<ends_with> and C<matches>) compare text and ignore
case unless the condition says C<< case_sensitive => 1 >>. C<empty> and
C<not_empty> need no C<value>: they keep the rows whose cell is blank,
or not blank. See
L<Term::Fabulous::Manual::TableRows/Filters from Perl> and
L<Term::Fabulous::Widget::Table::Filter/new>.

=item *

A date in a filter stands for the span of time it names: C<2026-05> is
all of May 2026, so C<< op => '=', value => '2026-05' >> keeps every
row placed in May. C<between> includes both ends; its value is an array
reference of two.

=item *

C<matches> takes a C<qr//> pattern, which is used with its own flags,
or a string with a regular expression.

=item *

C<< $F->all(...) >> matches rows that match every filter given,
C<< $F->any(...) >> rows that match at least one, and
C<< $F->not(...) >> rows that do not match. They nest, as filter 4
shows. See L<Term::Fabulous::Widget::Table::Filter/all>.

=item *

A code reference is a filter, too: it gets a copy of the row's data and
returns true for the rows to keep. Filter 5 compares two entries of the
row, which no single condition can do.

=item *

Conditions compare the I<raw value> unless they say
C<< on => 'display' >>. The C<status> column holds the codes C<o>,
C<p> and C<d>, shown as C<open>, C<paid> and C<overdue> by its mutator.
Filter 3 compares the shown words (C<< on => 'display' >>), filter 4 the
raw code C<p>. See
L<Term::Fabulous::Manual::TableRows/Raw value or display text>.

=item *

L<filter|Term::Fabulous::Widget::Table/filter> sets a filter under a
name; setting another filter under the same name replaces it, and
L<remove_filter|Term::Fabulous::Widget::Table/remove_filter> removes
it. A table shows the rows that match all its named filters, its filter
row and its search. A filter that names an unknown column, or compares
with a value its column cannot read, dies in C<filter>.

=item *

Filters set from Perl fire no event; C<choose_filter> writes the
status line itself after setting one.

=item *

The C<KeyPress> listener sits on the root. The table, which has the
focus, uses keys such as C<Up> and C<Space> itself and stops them; the
digits it does not use bubble up to the root. A listener on the table
itself would get every key the table gets. See
L<Term::Fabulous::Widget::Table/EVENTS>.

=back

Goal: show the rows of a table in groups, one per value of a column,

=over

=item *

C<< group_by => 'team' >> puts the rows into one group per value of the
C<team> column. Each group starts with a group header, a line across
the whole table. The groups are ordered by their value; the C<sort>
orders the rows within each group, here by salary, highest first. See
L<Term::Fabulous::Manual::TableRows/GROUPING>.

=item *

The C<team> column is hidden with C<< visible => 0 >>, since the group
headers show the team. A hidden column still groups, sorts and filters.
See L<Term::Fabulous::Manual::Tables/Choosing the visible columns>.

=item *

Without C<group_label>, a header shows the column title, the value and
the number of rows, such as C<Team: Core (4)>. C<group_label> replaces
that text: it gets a hash reference about the group and returns a
string (or a widget). C<team_label> uses C<display>, C<count> and
C<ids>, the ids of the group's rows, and reads each salary with
C<< $group->{table}->value >>. See
L<Term::Fabulous::Manual::TableRows/Group headers>.

=item *

A mutator is a plain code reference, so C<team_label> uses C<$money>,
the mutator of the Salary column, to format the sum.

=item *

C<group_style> sets the colors of all group headers, and can also draw
lines around them (C<< border_bottom => 'Solid' >>). See
L<Term::Fabulous::Manual::TableStyles/Style keys>.

=item *

The user opens and closes a group with a click on its header, or with
the cursor on the header: C<Enter> or C<Space> toggle it, C<Right> or
C<+> open it, C<Left> or C<-> close it. A closed header shows C<▸>, an
open one C<▾>. See
L<Term::Fabulous::Manual::TableRows/Opening and closing groups>.

=item *

Opening and closing fire C<Expand> and C<Collapse>.
C<< $event->group_path >> is the group's path: an array reference with
the group's raw value (with several group columns, the values of the
groups around it come first). It is C<undef> when a tree row opened or closed instead (see
L</Show nested data as a tree (expand and collapse rows)>).

=item *

From Perl, C<< $table->collapse_group('Network') >>,
C<expand_group>, C<collapse_all_groups> and C<expand_all_groups> do the
same without events.

=item *

C<< group_by => [ 'team', 'role' ] >> makes groups within groups. Their
paths then have two values, such as C<[ 'Core', 'Engineer' ]>, and
C<< $table->collapse_group( 'Core', 'Engineer' ) >> closes one.

=back

=head1 Show nested data as a tree (expand and collapse rows)

Goal: show a folder tree in a table, with sizes and dates, folders that
open and close, and one folder whose entries are read only when the
user opens it.

This program is shipped as F<examples/cookbook/table-tree.pl>.

=for code-from examples/cookbook/table-tree.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Table;
	use Term::Fabulous::Widget::Table::Mutator qw(bytes datetime);
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	sub file ( $path, $size, $modified ) {
		my ($name) = $path =~ m{([^/]+)\z};
		return { path => $path, name => $name, size => $size, modified => $modified };
	}

	sub folder ( $path, $modified, @children ) {
		my ($name) = $path =~ m{([^/]+)\z};
		return { path => $path, name => "$name/", modified => $modified, children => \@children };
	}

	# A folder whose entries are read only when the user opens it: its one
	# child is a placeholder, which the Expand listener below replaces.
	sub folder_to_load ( $path, $modified ) {
		return folder( $path, $modified, { path => "$path/...", name => 'loading...' } );
	}

	# What a real program would read from the disk with opendir and stat.
	my %ON_DISK = (
		'/project/releases' => [
			file( '/project/releases/app-1.0.tar.gz', 48_211,  1767225600 ),
			file( '/project/releases/app-1.1.tar.gz', 51_876,  1772323200 ),
			file( '/project/releases/app-2.0.tar.gz', 204_413, 1779753600 ),
		],
	);

	my $table = Term::Fabulous::Widget::Table->new(
		id           => 'files',
		row_id       => 'path',
		children_key => 'children',
		tree_column  => 'name',

		# The look: a block frame, and colors instead of grid lines.
		border       => 'Outer',
		column_lines => 'none',
		header_line  => 'none',
		stripe_color => '#1c2029',
		columns      => [
			{ key => 'name',     title => 'Name' },
			{ key => 'size',     title => 'Size',     type => 'number', mutator => bytes() },
			{ key => 'modified', title => 'Modified', type => 'date',   mutator => datetime( '%Y-%m-%d %H:%M', utc => 1 ) },
		],
		rows => [
			folder(
				'/project', 1780310460,
				folder(
					'/project/src', 1780307100,
					file( '/project/src/main.pl', 2_841, 1780307100 ),
					folder(
						'/project/src/lib', 1780220400,
						file( '/project/src/lib/App.pm',  18_506, 1780220400 ),
						file( '/project/src/lib/Util.pm', 4_402,  1779874800 ),
					),
				),
				folder( '/project/t', 1780138200, file( '/project/t/basic.t', 1_377, 1780138200 ), file( '/project/t/util.t', 2_019, 1779960000 ) ),
				folder_to_load( '/project/releases', 1779753600 ),
				file( '/project/README.md',   6_310, 1780048800 ),
				file( '/project/Makefile.PL', 912,   1777996800 ),
			),
		],
	);
	$table->expand( '/project', '/project/src' );

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);
	my $help   = Term::Fabulous::Widget::Text->new( text => 'Right opens a folder, Left closes it. Click a marker to toggle.', text_color => [ 150, 160, 180, 255 ] );
	my $status = Term::Fabulous::Widget::Text->new( text => 'Open releases/ to load its files.',                               text_color => [ 229, 192, 123, 255 ] );
	$root->add_child( $help, $table, $status );

	$table->on(
		Expand => sub ($event) {
			my $path = $event->row_id // return;
			if ( $table->has_row("$path/...") ) {
				$table->remove_row("$path/...");
				$table->add_rows( $ON_DISK{$path} // [], parent => $path );
			}
			$status->text( sprintf 'Opened %s: %d entries', $path, scalar $table->children_of($path) );
			return;
		}
	);
	$table->on(
		Collapse => sub ($event) {
			my $path = $event->row_id // return;
			$status->text("Closed $path");
			return;
		}
	);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );
	$ui->interaction->set_focused_widget($table);
	$ui->run;

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.05/screenshots/cookbook-table-tree.svg" alt="A file tree in a table: folders with open and closed markers, indented files, sizes and dates"></p>

=end html

The picture shows the tree after the user moved the cursor to
F<releases/> and pressed C<Right>, which loaded its three files.

=over

=item *

C<< children_key => 'children' >> makes the table a tree: a row's
C<children> entry holds its child rows, which can have children of
their own. Every row at every level is a row of the table with its own
id, so C<row_id> must be unique in the whole tree; a full path is a
good id. See L<Term::Fabulous::Manual::TableRows/TREES>.

=item *

C<tree_column> names the column that shows the tree: it indents each
row by two columns per level and shows C<▸> in front of closed rows
with children and C<▾> in front of open ones. Without C<tree_column>,
the tree column is the first visible column, which here is C<name>
as well.

=item *

Rows with children start closed. C<< $table->expand(...) >> opens rows
from Perl and fires no event; C<< tree_expanded => 1 >> would start
them all open. See
L<Term::Fabulous::Manual::TableRows/Opening and closing tree rows>.

=item *

The user opens a row with C<Right> or C<+> and closes it with C<Left>
or C<->, or clicks its marker. C<Right> on an open row moves the cursor
to its first child; C<Left> on a closed row, or on a row without
children, moves it to the parent row.

=item *

C<Expand> and C<Collapse> fire when the user opens or closes a row.
C<< $event->row_id >> is the row's id (it is C<undef> when a group
opened or closed instead).
L<children_of|Term::Fabulous::Widget::Table/children_of> returns the
ids of a row's child rows.

=item *

A row needs at least one child row to get a marker. C<folder_to_load>
gives F<releases/> a placeholder child, C<loading...>. When the user
opens the folder, the C<Expand> listener removes the placeholder and
adds the real entries with C<< add_rows( ..., parent => $path ) >>. The
C<has_row> check makes this happen only on the first opening. Here
C<%ON_DISK> stands for reading the directory; a real program would use
C<opendir> and C<stat>. See
L<Term::Fabulous::Manual::TableRows/Loading child rows when a row opens>
and L<Term::Fabulous::Manual::TableRows/Changing a tree>.

=item *

Folders have no C<size> entry, so their size cells stay empty: the
C<bytes> mutator shows a blank value as nothing.

=back

=head1 Split many rows into pages (pager and page sizes)

Goal: show 300 orders ten at a time, with a pager below the table, a
choice of page sizes, and a status line that follows the page.

This program is shipped as F<examples/cookbook/table-pages.pl>.

=for code-from examples/cookbook/table-pages.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Table;
	use Term::Fabulous::Widget::Table::Mutator qw(datetime number);
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	# 300 orders, made up from fixed lists, so every run shows the same data.
	my @customers = ( 'Acme Corp', 'Globex', 'Initech', 'Umbrella', 'Hooli', 'Stark Industries', 'Wayne Enterprises' );
	my @states    = qw(open paid shipped);
	my $first_day = 1767225600;    # 2026-01-01 00:00 UTC

	my @orders = map {
		{
			number   => 10_000 + $_,
			placed   => $first_day + $_ * 41_113,
			customer => $customers[ $_ * 5 % @customers ],
			state    => $states[ $_ * 7 % @states ],
			total    => ( $_ * 7_919 % 90_000 ) / 100 + 10,
		}
	} 1 .. 300;

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);

	my $table = Term::Fabulous::Widget::Table->new(
		id         => 'orders',
		row_id     => 'number',
		page_size  => 10,
		page_sizes => [ 10, 20, 50 ],

		# The look: a block frame, and colors instead of grid lines.
		border       => 'Outer',
		column_lines => 'none',
		header_line  => 'none',
		stripe_color => '#1c2029',
		columns      => [
			{ key => 'number',   title => 'Order',  type => 'number' },
			{ key => 'placed',   title => 'Placed', type => 'date', mutator => datetime( '%d %b %Y %H:%M', utc => 1 ) },
			{ key => 'customer', title => 'Customer' },
			{ key => 'state',    title => 'State' },
			{ key => 'total',    title => 'Total', type => 'number', mutator => number( decimals => 2, prefix => '$' ) },
		],
		rows => \@orders,
	);

	my $status = Term::Fabulous::Widget::Text->new( text => '', text_color => [ 150, 160, 180, 255 ] );
	$root->add_child( $table, $status );

	sub show_page ( $page, $page_size ) {
		my @shown = $table->page_row_ids;
		$status->text( sprintf 'Page %d of %d, %d per page: orders %d to %d', $page, $table->page_count, $page_size, $shown[0], $shown[-1] );
		return;
	}

	# The pager, Ctrl+PageDown and Ctrl+PageUp fire PageChange, and so does a
	# new size from the pager's list of page sizes.
	$table->on( PageChange => sub ($event) { show_page( $event->page, $event->page_size ); return } );

	show_page( $table->page, $table->page_size );
	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );
	$ui->interaction->set_focused_widget($table);
	$ui->run;

=over

=item *

C<< page_size => 10 >> cuts the view into pages of ten lines and shows
the pager below the table: buttons for the first, previous, next and
last page, the page number, a list of page sizes and the range of lines
shown. See L<Term::Fabulous::Manual::TableRows/PAGES>.

=item *

C<page_sizes> is the choice in the pager's list. A C<page_size> that is
not in the list is added to it. C<Tab> moves the focus from the table
to the list; C<Up> and C<Down> choose another size there. After a new
size, the table shows the page that holds the cursor's line.

=item *

The user turns pages with the pager's buttons and with
C<Ctrl+PageDown> and C<Ctrl+PageUp>; C<Ctrl+Home> and C<Ctrl+End> go to
the first and last line of all pages. C<PageUp>, C<PageDown>, C<Home>
and C<End> stay within the page.

=item *

Every page turn and every new page size from the user fires
C<PageChange>. Its C<page> and C<page_size> are the new values;
C<page_count> and C<page_row_ids> ask the table for the rest.

=item *

Your program turns pages with C<page>, C<next_page> and
C<previous_page>, and changes the size with C<page_size>. These fire no
event, so the program shows the first status line itself.

=item *

Pages count I<lines>, not rows: in a grouped table, every group header
is a line of its own.

=item *

Use pages for tables with more than a few hundred rows. Only the cells
of the current page are widgets, so a table of 10,000 rows with pages of
50 lines still answers a key at once, while the same table without
pages builds widgets for every row and, with the default
C<max_element_count>, dies once it has more than about 750 rows of 5
columns. See L<Term::Fabulous::Widget::Table/PERFORMANCE>.

=item *

C<< datetime( '%d %b %Y %H:%M', utc => 1 ) >> shows the epoch seconds
of C<placed> in UTC; without C<utc>, the dates are in local time.
