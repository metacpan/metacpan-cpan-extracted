=head1 NAME

MojoX::Authentication::Model::Db


=head1 SYNOPSIS

   use MojoX::Authentication::Model::Db;


=head1 DESCRIPTION

This class is not supposed to be used directly but through
L<MojoX::Authentication::Model> instead.

This class composes role L<MojoX::Authentication::Model::Role::Local>
and inherits its methods.

This class needs L<MojoX::MojoDbWrap> version 0.100 or later.

=head1 INTERFACE

=head2 B<< create >>

   my $instance = MojoX::Authentication::Model::Db->create($config, %args);

Constructor. 

Can receive the configuration either from a more "generic" C<$config>
hash as well as direct named arguments.

First a name is determined, either from C<$args{name}> or C<dby> by
default. Then C<$config> is looked at for a corresponding value, which
is either expected to be missing/C<undef> or be a hash reference. In
case a hash reference is found, its pairs override those on C<%args>,
with the only exception of the key C<name> which is preserved if already
present or set to the default otherwise.

Argument C<wmdb> is mandatory (an exception is thrown otherwise), see
L</wmdb>.

Also accepts parameters for the following accessors: L</name> (only from
C<%args>, see above), L</table>, C<crypt_passphrase>, C<key_for_secret>
and C<protected_keys> (inherited from role
L<MojoX::Authentication::Model::Role::Local>), L</remaps>, and
L</username_column>.


=head2 B<< load_user >>

   my $user = $provider->load_user($ignored, $uid);

Load the user by its userid, compatibly with
L<Mojolicious::Plugin::Authentication>'s interface for loading users.
The first parameter (which is supposed to be a controller instance) is
ignored.

This class has no distinction between user identifiers and usernames:
the record is looked for in L</table>, using column
L</username_column>. The record is then passed through L</remaps>.
Returns nothing if the record is not present.

=head2 B<< load_user_by_username >>

   my $user = $provider->load_user_by_username($ignored, $username);

Alias for L</load_user>, as this class has no distinction between user
identifiers and usernames.

=head2 B<< name >>

   my $name = $provider->name;
   $provider->name($new_name);

Name assigned to the provider (e.g. if you want to use different
databases at the same time and hence want to instantiate this class
multiple times). It is read-write: L<MojoX::Authentication::Model> sets
it to the name it registers the provider under (see
L<MojoX::Authentication::Model/Provider names>).

=head2 B<< remaps >>

   my $aref = $provider->remaps;

Accessor for the list of remaps, handled by
L<MojoX::Authentication::Model::Role::Remap>.

Remaps never see the column holding the secret, nor the other
protected keys (see L<MojoX::Authentication::Model::Role::Remap>): if
the hash is not in a column named C<secret>, set C<key_for_secret> to
the column's name (e.g. C<< key_for_secret => 'userpass' >>) instead of
remapping it.

=head2 B<< save_user >>

   $provider->save_user($user);    # OR
   $provider->save_user($user, $is_secret_cleartext);

Save a user.

The input C<$user> is supposed to be a hash reference with I<at least>
key C<username> (for the username/userid) and, for an account that
logs in with a password, the key for the secret (C<secret> by default,
see C<key_for_secret>), after L</remaps> are applied backwards. It I<MAY> contain other
key/value pairs, which will be copied.

The record is inserted, or updated if a record with the same value in
column L</username_column> is already present; for this reason, the
column B<MUST> have a C<UNIQUE> constraint (or be the primary key).

The secret is supposed to be already hashed. It is possible to set
the optional additional parameter C<$is_secret_cleartext> to a true
value to indicate that the hashing should be done by the function before
saving the user.

=head2 B<< table >>

   my $string = $provider->table;

Returns the name of the table where user accounts are kept. Defaults to
C<account>.

See also L</username_column> and L</remaps>.

=head2 B<< username_column >>

   my $string = $provider->username_column;

Returns the name of the column where the username is kept. Defaults to
C<username>.

See also L</table>.

=head2 B<< wmdb >>

   my $wmdb = $provider->wmdb;

Accessor to the L<MojoX::MojoDbWrap> object wrapping the relevant
database access object (most probably an object of either
L<Mojo::SQLite> or L<Mojo::Pg> class).

At construction it can be a L<MojoX::MojoDbWrap> object, an object with
a C<wmdb> method returning one, a sub reference returning one, or the
arguments for creating one (e.g. C<< { db_url => 'sqlite:accounts.db' } >>).
