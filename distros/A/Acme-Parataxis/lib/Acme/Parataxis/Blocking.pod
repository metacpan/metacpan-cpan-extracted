=head1 NAME

Acme::Parataxis::Blocking - Run CPU-Bound Perl Closures on Background Interpreters or Forked Children

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber await_sleep];
    use Acme::Parataxis::Blocking qw[spawn_blocking spawn_blocking_fork kill_blocking_fork];

    async {
        # Offload CPU-heavy computation to a background thread interpreter:
        my $future = spawn_blocking( sub ($data) {
            return heavy_cpu_digest($data);
        }, $payload );

        # Other fibers continue running smoothly while the background thread computes
        fiber {
            await_sleep(10);
            say 'Cooperative fibers are still running!';
        };

        my $result = $future->await;
        say "Digest: $result";
    };

=head1 DESCRIPTION

The C<Acme::Parataxis> native C worker pool handles blocking I/O and sleeps, but it cannot run arbitrary Perl code
without blocking the main interpreter. C<Acme::Parataxis::Blocking> offloads heavy, CPU-bound Perl closures to separate
execution contexts so your cooperative fibers never drop frames or stall.

Two backends are provided:

=over

=item *

B<C<spawn_blocking>>: Runs the closure on an isolated background Perl interpreter using native threads
(C<threads-E<gt>create>). Requires a Perl built with ithreads (C<useithreads>). Thread dependencies (C<threads>,
C<threads::shared>, C<Thread::Queue>) are loaded lazily on the first invocation.

=item *

B<C<spawn_blocking_fork>>: Runs the closure in a forked child process, marshaling arguments and results over a pipe
using L<Storable>. Works on non-threaded Perls (POSIX platforms where C<d_fork> is defined).

=back

Both functions return an L<Acme::Parataxis::Future> that can be awaited, combined with C<wait_all>/C<wait_any>, or
bounded with C<with_timeout>.

=head1 FUNCTIONS

=head2 C<spawn_blocking( $code, [@args] )>

    my $future = spawn_blocking( sub ($x, $y) {
        return $x ** $y;
    }, 2, 64 );

Executes C<$code> on an isolated background Perl interpreter. C<@args> are passed to the closure.

=over

=item * B<Copy-in / Copy-out>: The closure receives a snapshot of its arguments and captured lexicals. Memory is not
shared with the parent interpreter; in-place mutations in the worker do not affect the caller.

=item * B<Return values>: The result (or exception) is serialized back via C<threads::shared::shared_clone>. Plain
scalars, arrayrefs, and hashrefs cross safely. Non-serializable structures (such as CODE refs or open handles) cause
the future to fail with an error.

=item * B<No scheduler access>: The worker closure runs in an isolated interpreter and must not invoke
C<Acme::Parataxis> scheduling primitives.

=back

Concurrence is capped by C<max_blocking_threads()>. Calls exceeding capacity park the calling fiber until a slot frees.
Must be called within a scheduled fiber and under a real-time scheduler (croaks under C<virtual =E<gt> 1>).

=head2 C<set_max_blocking_threads( $count )>

    set_max_blocking_threads(8);

Sets the maximum number of concurrent background interpreter threads (default 4, or overridden by the
C<PARATAXIS_SB_THREADS> environment variable). Must be called before the first C<spawn_blocking> invocation.

=head2 C<max_blocking_threads( )>

Returns the current thread concurrency limit.

=head2 C<spawn_blocking_fork( $code, [@args] )>

    my $future = spawn_blocking_fork( sub ($n) {
        return compute_pi_digits($n);
    }, 10_000 );

Forks a child process to run C<$code>. Arguments and results are marshaled over an internal pipe using L<Storable>.

Unlike thread workers, forked workers can be cancelled and terminated midway through execution via
C<kill_blocking_fork()>.

Not available on Windows (where Perl's C<fork()> is an emulation over threads) or platforms without C<fork(2)>. Croaks
under C<run( virtual =E<gt> 1 )>.

=head2 C<kill_blocking_fork( $future, [$signal = 'TERM'] )>

    kill_blocking_fork( $future, 'KILL' );

Delivers C<$signal> to the child process associated with C<$future>. Returns true if the signal was delivered, or false
if the child was already reaped. The future resolves with an error indicating termination.

=head2 C<set_max_blocking_forks( $count )>

    set_max_blocking_forks(8);

Sets the maximum number of concurrent forked child processes (default 4, or overridden by C<PARATAXIS_SBF_FORKS>). Must
be called before the first C<spawn_blocking_fork> invocation.

=head2 C<max_blocking_forks( )>

Returns the current fork concurrency limit.

=head1 Recipes

=head2 Offloading long-running calculations

    use Acme::Parataxis qw[async await];
    use Acme::Parataxis::Blocking qw[spawn_blocking];

    async {
        my $task = spawn_blocking( sub {
            my $sum = 0;
            $sum += $_ for 1 .. 100_000_000;
            return $sum;
        } );

        say 'Calculating in background...';
        my $total = await($task);
        say "Total: $total";
    };

=head2 Cancelling runaway background work

Native threads cannot be forcibly killed, but forked processes can:

    use Acme::Parataxis qw[async fiber await_sleep];
    use Acme::Parataxis::Blocking qw[spawn_blocking_fork kill_blocking_fork];

    async {
        my $f = spawn_blocking_fork( sub { 1 while 1 } );

        fiber {
            await_sleep(500);
            say 'Work took too long; killing child...';
            kill_blocking_fork($f);
        };

        my $err = eval { $f->await } ? undef : $@;
        say "Stopped with error: $err";
    };

=head1 PLATFORM WARNING

=over

=item * Strawberry Perl / Win32 ithreads crashes

On certain Perl 5.42.x builds on Windows, calling C<threads-E<gt>create> triggers a C<perl_clone> segmentation fault if
classes with a C<method DESTROY> inside a C<feature 'class'> block have been compiled. In addition, loading specific
namespaces (including C<Acme::Parataxis::Sync> or C<Acme::Parataxis::TVar>) can trigger this crash. If targeting
Windows with C<spawn_blocking>, run compute tasks before loading sync modules, or use non-class fallback guards.

=item * Windows socket cloning stall

Under Windows, while any fiber is parked in C<await_read> or C<await_write> on a socket, invoking
C<threads-E<gt>create> stalls until the socket wait returns. This occurs because Windows holds descriptor duplication
during outstanding socket operations. Schedule C<spawn_blocking> calls before initiating socket loops to avoid latency
spikes.

=back

C<spawn_blocking_fork> does not use C<threads-E<gt>create> and is unaffected by these issues (though it is not
available on Windows).
