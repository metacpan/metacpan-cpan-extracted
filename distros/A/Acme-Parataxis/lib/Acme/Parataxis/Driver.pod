=head1 NAME

Acme::Parataxis::Driver - Base Class for Event-Loop Adapters Driving Parataxis

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[await_read await_sleep fiber];
    use Mojo::IOLoop;

    # Attach an event loop. Parataxis wraps it in the matching reference driver:
    Acme::Parataxis->attach_loop( Mojo::IOLoop->new );

    Acme::Parataxis::run( sub {
        my $reader = fiber { await_read( $socket, 2000 ) };    # an I/O watch on the loop
        my $napper = fiber { await_sleep(50) };                # a timer on the loop
        ...
    } );

    Acme::Parataxis->detach_loop;    # unwinds all watches/timers; reverts to C thread pool

=head1 DESCRIPTION

A driver is the adapter between Parataxis and an existing CPAN event loop. Attaching a loop via L<<
Acme::Parataxis->attach_loop|Acme::Parataxis/attach_loop >> switches C<await_read>, C<await_write>, and C<await_sleep>
away from submitting jobs to the background OS worker pool. Instead, readiness and timers are registered directly with
the attached loop.

The immediate benefit is multiplexing via C<epoll>, C<kqueue>, or reactor notification rather than dedicating a C
thread parked in C<select()> per filehandle. This also lifts the traditional C<FD_SETSIZE> ceiling on platforms where
the event loop supports modern poll interfaces.

The division of labor is strictly isolated:

=over

=item *

The B<driver> manages loop registrations: it tells the event loop which handles to watch and which timers to arm, and
hands control to the loop when all fibers are parked.

=item *

The B<scheduler> retains complete ownership of fibers, parks, and resumes. Loop callbacks B<only enqueue fibers> back
onto the run queue; they never execute user code directly. This prevents re-entrancy into the scheduler from inside
third-party event loop ticks.

=item *

Parataxis and the event loop never invoke each other's user callbacks—they cooperate exclusively through readiness
triggers.

=back

From the perspective of a running fiber, the API contract is unchanged: C<await_read> and C<await_write> return C<1> on
readiness, C<-1> on timeout or unwatchable descriptor, and enclosing C<with_timeout> or nursery scopes abort cleanly.

Two reference drivers ship with the distribution: L<Acme::Parataxis::Driver::Mojo> (for C<Mojo::IOLoop> and
C<Mojo::Reactor>) and L<Acme::Parataxis::Driver::IOAsync> (for C<IO::Async::Loop>). L<<
Acme::Parataxis::Driver::wrap|/"Acme::Parataxis::Driver::wrap( $loop )" >> selects between them automatically.

=head1 METHODS

=head2 C<pending( )>

    my $driver = Acme::Parataxis->loop;    # undef unless attached
    say $driver->pending;                  # watch_count + timer_count

Returns the total number of watches and timers currently managed by this driver. The scheduler idle branch only yields
control to the loop when C<pending> is greater than zero; if nothing is pending, the scheduler proceeds to deadlock
detection rather than stalling indefinitely inside the loop.

=head2 C<reset( )>

    $driver->reset;

Unwinds and cancels every watch and timer registered with the loop, clearing internal tracking tables. Automatically
invoked when C<run()> terminates and during C<detach_loop()>. This guarantees that leftover listeners or orphaned
timers from an exited run cannot stall subsequent scheduler runs. Returns true.

=head2 C<has_watch( $fh )>

    if ( $driver->has_watch($fh) ) { ... }

Returns true if C<$fh> is currently being watched for read or write readiness. Both directions share a single watch
slot per handle.

Slots are keyed by descriptor number but validated by handle identity (via C<builtin::refaddr>). Because operating
systems eagerly recycle descriptor numbers when handles close, matching on filehandle identity prevents a newly opened
handle from accidentally inheriting stale callbacks associated with a retired descriptor number.

=head2 C<watch_count( )>

Returns the number of filehandles currently registered for readiness monitoring.

=head2 C<timer_count( )>

Returns the number of timers currently armed on the loop.

=head1 Writing a Custom Driver

Subclasses implement the loop-specific interactions. The base class manages the bookkeeping table (which handles and
timer IDs are active) relied on by C<pending()> and C<reset()>.

Custom drivers should inherit from C<Acme::Parataxis::Driver> and use the internal tracking helpers: C<_track_watch>,
C<_untrack_watch>, C<_track_timer>, and C<_untrack_timer>.

    package My::Driver {
        use v5.40;
        use feature 'class';
        no warnings 'experimental::class';

        class My::Driver : isa(Acme::Parataxis::Driver) {
            field $loop : param;

            method watch_read ($fh, $cb) {
                my $fd = fileno($fh) // die 'Cannot watch a closed handle';
                $loop->add_reader( $fh, sub { $cb->() } );
                $self->_track_watch($fh);
            }
            method watch_write  ($fh, $cb) { ... }
            method unwatch      ($fh)      { ... }    # loop remove + _untrack_watch
            method timer        ($ms, $cb) { ... }    # loop timer  + _track_timer
            method cancel_timer ($id)      { ... }    # loop cancel + _untrack_timer
            method drive        ()         { ... }    # run one blocking loop tick
            method poll_ready   ()         { ... }    # run one non-blocking tick
        }
    };

Subclasses must implement:

=over

=item * C<watch_read( $fh, $cb )> - Fire C<< $cb->() >> when C<$fh> is readable. Croaks if closed.

=item * C<watch_write( $fh, $cb )> - Fire C<< $cb->() >> when C<$fh> is writable. Croaks if closed.

=item * C<unwatch( $fh )> - Stop watching both directions on C<$fh>. Return false if unmonitored.

=item * C<timer( $ms, $cb )> - Arm a timer to invoke C<< $cb->() >> after C<$ms> milliseconds. Returns an opaque ID.

=item * C<cancel_timer( $id )> - Cancel an active timer. Returns false if already expired or unknown.

=item * C<drive( )> - Execute the loop until at least one event fires (may block).

=item * C<poll_ready( )> - Perform a single non-blocking readiness pass and return immediately.

=back

=head1 FUNCTIONS

=head2 C<Acme::Parataxis::Driver::wrap( $loop )>

    my $driver = Acme::Parataxis::Driver::wrap( $loop );

Wraps an event-loop instance in the appropriate reference driver. Returns the driver object as-is if already blessed
into an C<Acme::Parataxis::Driver> subclass.

=over

=item * C<Mojo::IOLoop> or C<Mojo::Reactor> instances wrap as L<Acme::Parataxis::Driver::Mojo>.

=item * C<IO::Async::Loop> instances wrap as L<Acme::Parataxis::Driver::IOAsync>.

=back

Croaks if passed an unblessed value or an unsupported loop class.

=head1 Recipes

=head2 Attaching for a single scoped run

Keep driver attachments scoped: attach before running, and detach when finished:

    my $old_driver = Acme::Parataxis->attach_loop( Mojo::IOLoop->new );
    Acme::Parataxis::run( sub {
        # driven via epoll/kqueue through Mojo
    } );
    Acme::Parataxis->detach_loop;    # reverts cleanly to native worker pool

Attaching or detaching while a scheduler run is active croaks to prevent corrupting in-flight watches.

=head2 Driving an existing embedded Mojo::Reactor

You do not need a full C<Mojo::IOLoop>; any object implementing the C<Mojo::Reactor> interface works:

    my $reactor = $ioloop->reactor;
    Acme::Parataxis->attach_loop($reactor);

    Acme::Parataxis::run( sub {
        await_sleep(50);
    } );

=head1 Behavior Notes

=head2 Platform descriptor ceilings

When a loop relies on C<select()>, descriptor limits are bound by the platform C library's C<FD_SETSIZE>:

=over

=item * Linux, macOS, FreeBSD: 1024 (128-byte bitmask)

=item * NetBSD: 256 (32-byte bitmask)

=item * Windows: 64-entry socket array

=back

Because C<FD_SETSIZE> bounds the numeric value of the descriptor rather than the total count of active handles, twenty
descriptors opened early and three hundred opened late occupy different watch ranges.

Parataxis inspects descriptors before registration. Descriptors at or exceeding C<FD_SETSIZE> are rejected immediately
with C<-1> (simulating a timeout) rather than writing past the end of a C library bitmask.

=head2 C<poll_ready( )> semantics vary by backend

The scheduler calls C<poll_ready()> when background C pool tasks remain in flight and runnable fibers are temporarily
exhausted.

=over

=item * L<Acme::Parataxis::Driver::IOAsync> executes C<< $loop->loop_once(0) >>, returning instantly while still
firing due timers.

=item * L<Acme::Parataxis::Driver::Mojo> uses C<< $reactor->one_tick >>, which ignores duration arguments and always
waits for the earliest pending timer. A long timer combined with an active C worker task can cause C<poll_ready()> to
wait for that timer before servicing the worker completion.

=back
