=head1 NAME

Acme::Parataxis::Sync::Barrier - Phase-Boundary Rendezvous Synchronization for Fibers

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber];
    use Acme::Parataxis::Sync::Barrier;

    my $barrier = Acme::Parataxis::Sync::Barrier->new( parties => 3 );
    my @log;

    async {
        my @workers = map {
            my $id = $_;
            fiber {
                for my $phase ( 1 .. 2 ) {
                    $barrier->arrive_and_wait;    # blocks until all 3 fibers arrive
                    push @log, "worker_$id/phase_$phase";
                }
            };
        } 1 .. 3;

        $_->await for @workers;
        say "Crossed: " . join(' ', @log);
    };

=head1 DESCRIPTION

An C<Acme::Parataxis::Sync::Barrier> provides a synchronized rendezvous point for a fixed number of fibers. Fibers
arrive at the barrier by calling C<arrive_and_wait()>. The first C<parties - 1> fibers park; the final arrival
immediately unblocks all waiting fibers simultaneously and re-arms the barrier for the next phase.

Barriers are ideal for lockstep algorithms, phased pipelines, and parallel computations where intermediate data from a
given stage must be completely produced before any worker is permitted to begin the next stage.

=over

=item *

B<Cyclic re-arming>: A barrier automatically resets its arrival counter to C<parties> as soon as a phase is released,
allowing a single barrier instance to coordinate multiple consecutive rounds.

=item *

B<Zero-wait final arrival>: The fiber that registers the final arrival does not park; it enqueues the waiting fibers
and returns immediately.

=back

=head1 METHODS

=head2 C<new( parties =E<gt> $n )>

    my $barrier = Acme::Parataxis::Sync::Barrier->new( parties => 4 );

Constructs a barrier requiring C<$n> arrivals per phase. C<parties> is required and must be an integer C<E<gt>= 1>.
Croaks if C<parties> is less than 1.

=head2 C<arrive_and_wait( )>

    $barrier->arrive_and_wait;

Registers the current fiber's arrival in the current phase.

=over

=item *

If fewer than C<parties> have arrived, the calling fiber parks until the remaining parties arrive.

=item *

If this call represents the final arrival (C<remaining == 1>), it bumps the generation counter, resets C<remaining> to
C<parties>, wakes all parked parties, and returns true immediately without yielding.

=back

Must be called from within a scheduled fiber (croaks otherwise).

=head2 C<parties( )>

Returns the total number of participating fibers required to open a phase.

=head2 C<remaining( )>

Returns the number of arrivals still required to complete the current phase.

=head2 C<waiters( )>

Returns the number of fibers currently parked waiting for the phase to complete.

=head1 Recipes

=head2 Multiphase lockstep iteration

    my $barrier = Acme::Parataxis::Sync::Barrier->new( parties => 2 );

    async {
        my $f1 = fiber {
            for my $round ( 1 .. 3 ) {
                compute_part_a($round);
                $barrier->arrive_and_wait;
            }
        };

        my $f2 = fiber {
            for my $round ( 1 .. 3 ) {
                compute_part_b($round);
                $barrier->arrive_and_wait;
            }
        };

        $f1->await;
        $f2->await;
    };

=head1 Behavior Notes

=over

=item * Interrupted arrivals consume quota

When a fiber calls C<arrive_and_wait()>, C<remaining> is decremented immediately. If that fiber's wait is interrupted
by a timeout or cancellation token, the fiber unregisters from the queue, but the slot it claimed is not refunded. The
barrier remains one arrival short until a replacement arrival occurs.

=item * Deadlock risk if workers fail to arrive

A barrier never opens on its own; it requires exactly C<parties> arrivals. If a participant dies before arriving,
surviving waiters will park permanently, triggering a scheduler deadlock error unless protected by C<with_timeout>.

=back
