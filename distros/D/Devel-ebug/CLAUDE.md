## What this is

Devel::ebug is a Perl debugger distributed as a CPAN module (`Devel::ebug`), managed with
[Dist::Zilla](https://dzil.org) (see `dist.ini`, using the `@Author::Plicease` bundle). There is no
checked-in `Makefile.PL`/`cpanfile`/`Build.PL` — those are generated by `dzil build`. `dist.ini` and
`author.yml` are the sources of truth for distribution metadata, prereqs, and POD spellcheck config.

## Common commands

Tests run directly against `lib/` without a build step (test files `use lib 'lib'`):

```
prove -l t                 # run the full test suite
prove -l t/basic.t         # run a single test file
prove -lv t/basic.t        # verbose output for one test file
```

Author/release-only checks live in `xt/` (currently `xt/author/critic.t`, a Perl::Critic pass using
`perlcriticrc`, which applies Perl::Critic::Freenode/Community policies at severity 1):

```
prove -l xt/author/critic.t
```

Dist::Zilla workflow (requires a full author toolchain):

```
dzil test           # build + run full test suite, including release tests
dzil build           # build a distribution tarball
```

Do not run `dzil release` or anything that publishes/uploads — that's a release action, not a dev task.

CI (`.github/workflows/linux.yml`) runs the test suite across a matrix of Perl versions from 5.8 to
5.45 using `uperl/cip`; `.github/workflows/static.yml` runs the static/author checks (e.g. perlcritic).
Devel::ebug does not support Perl versions prior to 5.10.1 at runtime (see README CAVEATS), but CI still
tests older Perls for back-compat awareness.

## Architecture

Devel::ebug has a **frontend/backend split over a TCP socket**, not a single in-process debugger:

- **Frontend** — `Devel::ebug` (`lib/Devel/ebug.pm`). The object the caller interacts with (`->new`,
  `->program`, `->load`, `->step`, etc.). `load()` spawns the target program as a child process running
  under `perl -d:ebug::Backend` (via `Proc::Background`), then connects to it as a TCP client.
- **Backend** — `Devel::ebug::Backend` (`lib/Devel/ebug/Backend.pm`). Installed as the `DB` package that
  Perl's core debugger hooks (`-d`) call into (`DB::DB`, `DB::sub`, `DB::postponed`, etc). On startup it
  opens a TCP server socket and waits for the frontend to connect.
- **Wire protocol**: requests/responses are Perl data structures serialized with `YAML::Dump`/`Load`,
  then hex-packed (`unpack("h*", ...)`) and sent as a single newline-terminated line over the socket
  (see `talk()` in `ebug.pm` and `put()`/`get()` in `Backend.pm`).
- **Handshake/security**: a random "secret" word (encoded via `String::Koremutake`) is generated by the
  frontend, passed to the child process through `%ENV`, and checked during the initial `ping` command.
  The TCP port is chosen pseudo-randomly in the range 3141–4165 so multiple debug sessions can run
  concurrently on one host.

**Plugin system** (both sides use `Module::Pluggable`, loaded automatically, not manually registered):

- Frontend plugins: `Devel::ebug::Plugin::*` (`lib/Devel/ebug/Plugin/`). Each exports methods (e.g.
  `basic`, `run`, `eval`) that call `$self->talk({ command => ... })` to issue a request to the backend.
- Backend plugins: `Devel::ebug::Backend::Plugin::*` (`lib/Devel/ebug/Backend/Plugin/`). Each registers
  command handlers via `register_commands()`, returning a map of `command name => { sub => \&handler }`
  (optionally `record => 1` to make the command replayable for `undo`).
- Frontend and backend plugins are paired by feature (e.g. `Plugin::Basic` <-> `Backend::Plugin::Basic`,
  `Plugin::Eval` <-> `Backend::Plugin::Eval`), matched by the `command` name sent over the wire. When
  adding a debugger feature, you generally add both halves together.
- `undo` works by replaying recorded state-changing commands (`break_point`, `break_point_delete`,
  `break_point_subroutine`, `eval`, `next`, `step`, `return`, `run`, `watch_point`) against a freshly
  restarted backend process — it is not true rollback.

**Command-line tools** (`bin/`):

- `ebug` — interactive console frontend, built on `Devel::ebug::Console` (`lib/Devel/ebug/Console.pm`),
  which itself drives a `Devel::ebug` instance.
- `ebug_server` / `ebug_client` — split the frontend/backend across separate processes/hosts for remote
  debugging (`ebug_server` execs the debuggee and prints the secret/port; `ebug_client` attaches to it by
  overriding `Devel::ebug::load` to call `attach` directly instead of spawning a new process).
- `ebug_backend_perl` — helper backend entry point.

**Test corpus**: `corpus/` holds small standalone Perl scripts (`calc.pl`, `signal.pl`,
`infinite_loop.pl`, etc.) that tests in `t/` load and step through via `Devel::ebug` to exercise real
debugger behavior end-to-end, rather than mocking the backend protocol.

## Changes file

`Changes` follows the standard CPAN::Changes format, templated by Dist::Zilla (`{{$NEXT}}` is expanded to
the version/date at release time). When adding an entry under `{{$NEXT}}`, reference the relevant GitHub
issue(s) and PR(s) — including the PR currently being worked on — in the same style as existing entries:
a trailing `(gh#xx, gh#yy)` on the bullet, e.g.:

```
  - Fix ^C (SIGINT) while running killing the console instead of
    dropping back into the debugger (gh#27, gh#55)
```
