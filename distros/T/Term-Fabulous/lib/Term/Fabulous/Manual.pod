=head1 NAME

Term::Fabulous::Manual - The Term::Fabulous user guide

=head1 HOW TO READ THIS MANUAL

This manual explains how Term::Fabulous works and how you use it. This
page is its starting point: it introduces the library, shows a first
program and ends with the L</FEATURE INDEX>, which maps tasks to the
sections, recipes and class pages that describe them. The topics
themselves are on pages of their own, listed under L</CONTENTS>.

=over

=item To learn Term::Fabulous

Read L</INTRODUCTION> and L</YOUR FIRST PROGRAM> on this page, then the
topic pages in the order of L</CONTENTS>. Every topic page links to the
previous and the next page at its top and bottom, so you can read the
whole manual from start to end.

=item To find something

Look the task up in the L</FEATURE INDEX>. Every topic has its own
heading, so you can also search a page: with C</> in C<perldoc>, or with
the table of contents on MetaCPAN. Terms the manual uses are defined in
L<Term::Fabulous::Manual::Glossary>.

=back

The manual is one of four kinds of documentation:

=over

=item The manual (this page and its topic pages)

Explains the concepts: layout, text and colors, events, the keyboard,
the mouse and the focus, forms, tables, charts, KDL layout files, the
event loop, testing and writing widgets of your own.

=item L<Term::Fabulous::Cookbook>

Recipes: complete, runnable programs for common tasks, each with a
picture and notes on the lines that matter. Its index page lists every
recipe; the recipes themselves are on fifteen topic pages, from
L<Term::Fabulous::Cookbook::GettingStarted> to
L<Term::Fabulous::Cookbook::Extending>.

=item L<Term::Fabulous::Examples>

The example programs of the distribution, each with a picture: demo
programs, one program per widget, and the programs of the cookbook.

=item The class pages

One reference page per class, such as L<Term::Fabulous> (the
application object), L<Term::Fabulous::Widget::Box> or
L<Term::Fabulous::Widget::TextField>. A class page lists every
constructor parameter, method, event, key, mouse action and KDL
property of the class. The
L<list of modules|Term::Fabulous/MODULES> on the main page names all of
them, grouped by purpose.

=back

=head2 Conventions

Every example uses subroutine signatures. A complete program starts
with this header, which works on every Perl that Term::Fabulous
supports (5.32.1 and later):

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

Shorter snippets leave the header out. A snippet may use variables from
an earlier snippet of the same section, and usually C<$root> (the root
widget) and C<$ui> (the L<Term::Fabulous> object).

Code in these documents is indented. When you copy an example that
contains a here-document (C<<< <<'KDL' >>>), remove the indentation from
the line that ends it (C<KDL>): Perl recognizes the terminator only at
the start of a line.

=head1 INTRODUCTION

Term::Fabulous builds terminal user interfaces in Perl: forms,
dashboards, log viewers, data browsers, editors, games. You describe
the screen as a tree of I<widgets>: boxes, text, buttons, input fields,
tables, charts, scrollable areas and canvases. Term::Fabulous sizes and
positions the widgets, draws them, and turns key presses, mouse clicks
and terminal resizes into I<events> that your code reacts to.

A program usually takes over the whole terminal while it runs and gives
it back unchanged when it ends. It can also draw into a few rows below
the shell's output instead, like a prompt (see
L<Term::Fabulous/INLINE MODE>), or print a widget tree once as text,
without any interaction (see
L<Term::Fabulous::Manual::Programs/RENDERING WITHOUT A TERMINAL>).

The parts of a program are always the same:

=over

=item The widget tree

The widgets, built in Perl with C<new> and C<add_child>, or read from a
KDL layout file. The top of the tree is the I<root widget>. See
L<Term::Fabulous::Manual::Layout>.

=item Listeners

Code references registered with C<< $widget->on( EventName => sub {...} ) >>
that run when an event happens: a key press, a click, a changed value.
See L<Term::Fabulous::Manual::Events>.

=item The application object

A L<Term::Fabulous> object that holds the tree. Its C<run> method opens
the terminal, runs the event loop and returns when the program should
end.

=back

Three libraries do the heavy lifting:

=over

=item Clay

A layout engine (used through L<Clay::XS> and L<Clay::UI>). It decides
the position and size of every widget from rules such as "fill the
remaining width" or "be as tall as the content". Term::Fabulous
measures in terminal cells, so for Clay one unit is one cell.

=item termbox2

A small C library, compiled into L<Term::Fabulous::Termbox>, that
switches the terminal into full-screen mode, reads keys and mouse
input, and writes characters with 24-bit colors.

=item IO::Async

The event loop (L<IO::Async::Loop>). It waits for input, draws the
screen when something changed, and runs your timers, sockets and child
processes in the same loop.

=back

You do not need to know these libraries in detail. The manual explains
everything you need from them and links to their documentation for the
rest.

=head2 How a frame is drawn

A I<frame> is one complete layout and drawing of the screen. While L<run|Term::Fabulous/run> is active, Term::Fabulous checks 30 times per
second whether anything changed since the last frame: a widget was
changed through one of its methods, input arrived, the terminal was
resized, or the program asked for a frame with
L<invalidate|Term::Fabulous/invalidate>. When nothing changed, nothing is drawn.
When something changed, a frame is drawn in three steps:

=over

=item 1.

Clay lays out the widget tree for the current terminal size.

=item 2.

Term::Fabulous draws every widget into termbox2's screen buffer:
backgrounds, borders, text and canvases.

=item 3.

termbox2 compares the buffer with what the terminal already shows and
sends only the cells that changed.

=back

Because the whole screen is laid out again in every frame, there is no
"redraw" method to call. Change a widget (its text, color, size or
children), and the change is visible in the next frame, at most 1/30
second later. The widget methods tell Term::Fabulous that a frame is
needed; only a widget of your own that draws from state it keeps itself
has to say so (see
L<telling Term::Fabulous that something changed|Term::Fabulous::Manual::CustomWidgets/Telling Term::Fabulous that something changed>).

Pointer movement is the one exception to "drawn at the next check":
when frames take long to draw, a frame that only shows the pointer at a
new position is drawn at most at every other check, so that moving the
mouse cannot keep the program busy with nothing but redrawing.

=head1 REQUIREMENTS

=over

=item *

Perl 5.32.1 or later.

=item *

A C compiler. termbox2 ships with the distribution and is compiled into
L<Term::Fabulous::Termbox> when Term::Fabulous is installed, with
truecolor and grapheme cluster support always on; there is no separate
library to install or find.

=item *

A terminal that understands 24-bit ("truecolor") colors. Most modern
terminals do (xterm, GNOME Terminal, Konsole, kitty, iTerm2, Windows
Terminal), and so does tmux with truecolor enabled (see
L<Term::Fabulous::Manual::Troubleshooting/Colors are wrong or look washed out>).
In a terminal without truecolor support, the colors come out wrong.

=item *

A UTF-8 locale, for example C<LANG=C.UTF-8> or C<LANG=en_US.UTF-8>
(C<locale -a> lists the installed ones). Without it, wide characters
such as CJK text and emoji cannot be placed correctly, and L<run|Term::Fabulous/run> warns about
it when it starts.

=item *

For mouse support, a terminal that reports mouse events. Nearly all do;
see L<Term::Fabulous::Manual::Events/MOUSE> for what is reported.

=item *

Optional: L<Imager>, for pictures in L<Term::Fabulous::Widget::Image>,
with the image libraries (libpng, libjpeg, ...) of the formats you
want to show. Installing Term::Fabulous does not require it; without
it, an image widget shows a notice in its place.

=item *

Optional: L<Imager::File::SIXEL> with L<Imager>, for pictures in sixel
graphics in L<Term::Fabulous::Widget::Sixel>, and a terminal that shows
sixel graphics and reports the size of its cells. Without them, a sixel
widget shows a notice in its place.

=back

=head1 YOUR FIRST PROGRAM

This program shows a dark blue screen with a framed greeting in the
middle and ends when you press C<q>, C<Escape> or C<Ctrl+C>. It is
shipped as F<examples/cookbook/first-program.pl>; run it with
C<perl examples/cookbook/first-program.pl> (see
L<Term::Fabulous::Examples/RUNNING THE EXAMPLES>).

=for code-from examples/cookbook/first-program.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Clay::XS qw(sizing_grow CLAY_ALIGN_X_CENTER CLAY_ALIGN_Y_CENTER);
	use Term::Fabulous;
	use Term::Fabulous::Enum::BorderStyle;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Text;

	# The root widget fills the whole terminal and centers its child.
	my $root = Term::Fabulous::Widget::Box->new(
		background_color => [ 20, 25, 45, 255 ],
		layout           => {
			sizing          => { width => sizing_grow(),       height => sizing_grow() },
			child_alignment => { x     => CLAY_ALIGN_X_CENTER, y      => CLAY_ALIGN_Y_CENTER },
		},
	);

	# A box with a rounded border, one cell of space left and right of the text.
	my $frame = Term::Fabulous::Widget::Box->new(
		bordered     => 1,
		border_style => Term::Fabulous::Enum::BorderStyle->Round,
		border_color => [ 120, 170, 255, 255 ],
		layout       => { padding => { left => 1, right => 1 } },
	);
	$frame->add_child(
		Term::Fabulous::Widget::Text->new(
			text       => 'Hello, terminal! Press q to quit.',
			text_color => [ 255, 255, 255, 255 ],
		)
	);
	$root->add_child($frame);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );

	# Nothing has the keyboard focus, so key presses go to the root widget.
	$root->on(
		KeyPress => sub ($event) {
			my $name = $event->key_name // '';
			$ui->loop->stop if $name eq 'q' || $name eq 'Escape';
			return;
		}
	);

	$ui->run;    # returns when the loop stops
	say 'Bye!';

=end html

What happens here:

=over

=item *

L<Term::Fabulous::Widget::Box> is the general container. It can have a
background color, a border and any number of children.

=item *

The C<layout> hash tells Clay how to size and arrange the box and its
children (see L<Term::Fabulous::Manual::Layout/LAYOUT>).
C<sizing_grow()> means "take all the room the parent offers"; a box
without C<sizing> is as big as its content. C<child_alignment> centers
the children (see
L<Term::Fabulous::Manual::Layout/Aligning and centering children>).

=item *

L<Term::Fabulous::Widget::Text> shows one piece of text. Colors are
C<[red, green, blue, alpha]> arrays with values from 0 to 255; color
strings such as C<'#78aaff'> work too (see
L<Term::Fabulous::Manual::Looks/COLORS>). The border style comes from
L<Term::Fabulous::Enum::BorderStyle> (see
L<Term::Fabulous::Manual::Looks/BORDERS>).

=item *

C<< Term::Fabulous->new >> takes the root widget and an initial size.
C<width> and C<height> are required, but C<run> replaces them with the
real terminal size.

=item *

C<< $root->on( KeyPress => sub { ... } ) >> registers a I<listener>:
code that runs when the event happens (see
L<Term::Fabulous::Manual::Events/EVENTS>). Key presses go to the widget
that has the keyboard focus, or to the root widget when no widget has
it, as here. C<key_name> returns a readable name of the key, such as
C<q>, C<Escape> or C<Ctrl+Left> (see
L<Term::Fabulous::Manual::Events/KEYBOARD>).

=item *

C<< $ui->run >> opens the terminal, handles input and draws frames until
the loop stops: when a listener calls C<< $ui->loop->stop >>, when the
user presses C<Ctrl+C>, or when the process receives C<SIGINT>,
C<SIGTERM> or C<SIGHUP>. Then it restores the terminal and returns, and
the program prints C<Bye!> on the normal screen.

=item *

Quitting on C<Escape> does not catch C<Alt> plus a letter: terminals
send that as C<Escape> followed by the letter, in one write, and
Term::Fabulous names it C<Alt+x> (see
L<Term::Fabulous::Manual::Events/Key names>).

=back
