# ShellSpawn and its parser: the record of known issues

This is the single list of currently known problems of the posix_spawn executor (`claude/pspawn-ShellSpawn.pm`, `claude/pspawn-tree.tar.gz-base64.txt`) and of the bugs it found elsewhere. Each item keeps its ID when it is fixed; fixed items move to the end. Older records, now summarized here: [`Run's Changes, 0.05 and 0.06`](https://metacpan.org/release/ILYAZ/Run-0.07/changes) (Run R1–R5), [`pspawn-run-shortcomings.md` (0.03)](https://metacpan.org/release/ILYAZ/Proc-Spawner-0.03/view/doc/pspawn-run-shortcomings.md) (in Proc-Spawner 0.03) (Run, summary), [`pspawn-upstream-reports.md` (0.03)](https://metacpan.org/release/ILYAZ/Proc-Spawner-0.03/view/doc/pspawn-upstream-reports.md) (in Proc-Spawner 0.03) (P1).

Updated 2026-11-02, 07:50 Pacific. Module names: since 07:30 every module is under `Proc::` (`ShellSpawn` is `Proc::ShellSpawn`, the binding `PosixSpawn` is part of `Proc::Spawner`); rows written before keep the old names. Table: [`pspawn-spawner.md`](pspawn-spawner.md), top.

| X1 | executor | Background jobs still running when `run()` returns went on only in later `run()` calls (until 0.04): `run('sleep 1 && echo b &')`, then 3 s of other work, ran `echo b` at second 3, not 1. Since post-0.04 (K3, the user's choice B, 2026-11-03) they go on between calls too, with a documented cost: the program's own `sleep` and `select` return early when a child ends ([`pspawn-design.md`](pspawn-design.md), section 6). ## Corpus testing (X12), proposed (closed 2026-11-07: done by the run-time comparison, [`large-subset-state.md`](large-subset/large-subset-state.md), section 7)

Run every one-liner of the corpora under dash and under the executor, with every program replaced by a **reporter**: a PATH directory holding one small program under every command name that occurs, which appends to a log what it was started with, then behaves like a filter.

- What it records: argv; cwd; the environment (minus a fixed baseline); each open fd with its kind, access mode and close-on-exec flag; SigIgn, SigBlk and SigCgt; process group and session; umask.
- What it does: copies standard input to standard output (so pipelines carry data), adds one line of its own, and exits with a status chosen by its name (`false`-like names 1, others 0), so that `&&` and `||` take both paths.
- Comparison: the set of reports (concurrent pipeline elements may come in any order, so sorted), the final output, the messages and the status.
- In a fixed fixture directory, so that globbing gives the same names.
- Known difference to filter out: dash runs `echo`, `printf`, `test`, `[`, `kill`, `true`, `false` and `pwd` as builtins, which no reporter sees, while the executor runs them as programs (spec B2). Commands given with a `/` cannot be replaced; they are skipped.
- Cost: the corpora must first be restored ([`parsers/shell-subset-test-provenance.md`](parsers/shell-subset-test-provenance.md), `claude/corpus-run.tar.gz-base64.txt`); about 40,000 one-liners, two shells each.
