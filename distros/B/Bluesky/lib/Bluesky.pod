=head1 NAME

Bluesky - Bluesky Client Library in Perl

=head1 SYNOPSIS

    use Bluesky;
    my $bsky = Bluesky->new( );

    # Recommended: log in once and reuse the saved session on later runs
    $bsky->ensure_auth( handle => 'user.bsky.social' );

    # Or drive the interactive OAuth flow directly:
    $bsky->oauth_helper(
        handle     => 'user.bsky.social',
        listen     => 1, # Automatically catch the redirect
        on_success => sub { say 'Logged in!' }
    );

    # Or use an app password (not recommended)
    $bsky->login( 'sanko', '1111-2222-3333-4444' );

    # Posting
    $bsky->createPost( text => 'Hello from Perl!' );

    # Streaming
    my $fh = $bsky->firehose(sub ( $header, $body, $err ) {
        return warn $err if $err;
        say 'New event: ' . $header->{t};
    });
    $fh->start();

=head1 DESCRIPTION

You shouldn't need to know the AT protocol in order to get things done so I'm including this sugary wrapper so that
L<At> can remain mostly technical.

=head1 Constructor and Session Management

Bluesky.pm is my attempt to make use of Perl's class syntax so this is obviously OO.

=head2 C<new( [...] )>

    my $bsky = Bluesky->new( );

Create a new Bluesky client object.

Expected parameters include:

=over

=item C<service> - optional

Bluesky PDS host. Defaults to C<https://bsky.social>.

=item C<chat_service> - optional

Chat (DM) service host. Defaults to C<https://api.bsky.chat>.

=item C<at> - optional

Underlying L<At> object. If not provided, it defaults to C<At-E<gt>new( host =E<gt> $service )>.

=back

=head2 C<ensure_auth( %args )>

    $bsky->ensure_auth( handle => 'you.bsky.social' );

Convenience wrapper for applications that want to stay logged in across runs. When C<file> exists it loads and resumes
the saved session (re-saving it if the underlying tokens were rotated); otherwise it runs an interactive OAuth flow via
C<oauth_helper> and saves the resulting session.

Expected parameters include:

=over

=item C<file>

Path to the session file. Defaults to C<session.json>.

=item C<handle>

The user's handle or DID. Required when no saved session exists.

=item C<scope>

Requested OAuth scopes. Defaults to C<atproto>.

=item C<listen>

Passed through to C<oauth_helper>. Defaults to C<1>.

=item C<client_id>, C<redirect>

Optional OAuth overrides, passed through to C<oauth_helper>.

=item C<on_success>

Optional callback invoked after a successful first-time login. Receives the C<$bsky> object.

=back

=head2 C<oauth_helper( %args )>

A high-level helper to manage the entire OAuth flow. This is the recommended way to authenticate for interactive
applications.

    $bsky->oauth_helper(
        handle     => 'user.bsky.social',
        listen     => 1,
        on_success => sub ($self) {
            say 'Authenticated as ' . $self->did;
        }
    );

Expected parameters include:

=over

=item C<handle> - required

The user's handle or DID.

=item C<listen>

Boolean. If true, attempts to start a local HTTP server (using L<Mojolicious>) to automatically capture the C<code> and
C<state> from the redirect.

=item C<redirect>

The redirect URI. Defaults to C<http://127.0.0.1:8888/callback>.

=item C<scope>

The requested OAuth scopes. Defaults to C<atproto>.

See L<https://atproto.com/guides/scope-builder> to build your own scope strings.

=item C<on_success>

A callback subroutine invoked after a successful login. Receives the C<$bsky> object as an argument.

=back

=head2 C<oauth_start( $handle, $client_id, $redirect_uri, [ $scope ] )>

Initiates the OAuth 2.0 Authorization Code flow. Returns the authorization URL.

C<$scope> defaults to C<atproto> if omitted.

    my $url = $bsky->oauth_start(
        'user.bsky.social',
        'http://localhost',
        'http://127.0.0.1:8888/callback'
    );

The C<$scope> here defaults to simply 'C<atproto>'. See L<https://atproto.com/guides/scope-builder> to build your own
scope strings.

=head2 C<oauth_callback( $code, $state )>

Exchanges the authorization code for tokens and completes the OAuth flow.

    $bsky->oauth_callback( $code, $state );

=head2 C<login( $identifier, $password )>

Expected parameters include:

=over

=item C<password> - required

This is the app password not the account's password. App passwords are generated at
L<https://bsky.app/settings/app-passwords>.

=back

=head2 C<resume( $accessJwt, $refreshJwt, [ $token_type, ... ] )>

=head2 C<save_session( [ $file ] )>

    $bsky->save_session();    # writes session.json

Serializes the current session to C<$file> (default C<session.json>) so it can be restored later with C<load_session>

=head2 C<load_session( [ $file ] )>

    $bsky->load_session();

Reads a previously saved session from C<$file> (default C<session.json>) and resumes it. Returns false when the file
does not exist or cannot be parsed.

=head2 C<createPost( ... )>

    $bsky->createPost( text => 'Test. Test. Test.' );

Create a new post.

Expected parameters include:

=over

=item C<text> - required

The primary post content. May be an empty string, if there are embeds.

The lexicon limits text to 300 graphemes (3000 bytes).

Annotations of text (mentions, URLs, hashtags, etc) are automatically parsed. These include:

=over

=item mentions

Facet feature for mention of another account. The text is usually a handle, including a '@' prefix, but the facet
reference is a DID.

    This is an example. Here, I am mentioning @atproto.bsky.social and it links to their profile.

=item links

Facet feature for a URL. The text URL may have been simplified or truncated, but the facet reference should be a
complete URL.

    This is an example that would link to Google here: https://google.com/.

=item tags

Facet feature for a hashtag. The text usually includes a '#' prefix, but the facet reference should not (except in the
case of 'double hash tags').

    This is an example that would link to a few hashtags. #perl #atproto

=back

=item C<timestamp>

Client-declared timestamp (ISO 8601 in UTC) when this post was originally created.

A timezone is required and a trailing C<Z> is preferred over C<+00:00>, per
L<https://atproto.com/specs/lexicon#string-formats>. Clients may supply any value (useful for imports and migration),
but far-future values sort first everywhere.

Defaults to the current time.

=item C<lang>

Indicates human language of post primary text content. Up to 3 language codes.

    $bsky->createPost(
        lang     => [ 'en', 'ja' ],
        reply_to => 'at://did:plc:pwqewimhd3rxc4hg6ztwrcyj/app.bsky.feed.post/3lbvllq2kul27',
        text     => 'こんにちは, World!'
    );

This is expected to be a comma separated string of language codes (e.g. C<en-US,en;q=0.9,fr>).

Bluesky recommends sending the C<Accept-Language> header to get posts in the user's preferred language. See
L<https://www.w3.org/International/questions/qa-lang-priorities.en> and
L<https://www.iana.org/assignments/language-subtag-registry/language-subtag-registry>.

=item C<reply_to>

AT-URL of a post to reply to.

    $bsky->createPost( reply_to => 'at://did:plc:pwqewimhd3rxc4hg6ztwrcyj/app.bsky.feed.post/3lbvllq2kul27', text => 'Exactly!' );

=item C<reply_gate>

Arrayref of rules to restrict who can reply to this post (thread gate). At most 5 rules.

An empty arrayref means nobody can reply; omitting C<reply_gate> means anybody can reply.

Supported rules:

=over

=item C<mention> - Only users mentioned in the post can reply.

=item C<follower> - Only users following the author can reply.

=item C<following> - Only users the author follows can reply.

=item C<list> - Only users in a specific moderation list can reply (requires C<reply_gate_list>).

=back

Example:

    $bsky->createPost( text => 'Private post', reply_gate => ['following'] );

=item C<reply_gate_list>

The AT-URI of a moderation list to use with the C<list> rule in C<reply_gate>.

=item C<post_gate>

Arrayref of rules to restrict embedding or quoting of this post.

Currently supports:

=over

=item C<disable> - Disable all quotes and embeds of this post.

=back

Example:

    $bsky->createPost( text => 'No quoting allowed', post_gate => ['disable'] );

=item C<embed>

Bluesky allows for posts to contain embedded data.

Known embed types:

=over

=item C<images>

Up to 4 images (path name or raw data), each limited to 1,000,000 bytes.

Set alt text by passing a hash.

    $bsky->createPost(
        embed    => { images => ['path/to/my.jpg'] },
        lang     => 'en',
        reply_to => 'at://did:plc:pwqewimhd3rxc4hg6ztwrcyj/app.bsky.feed.post/3lbvllq2kul27',
        text     => 'I found this image on https://google.com/'
    );

    $bsky->createPost(
        embed    => { images => [{ alt => 'Might be a picture of a frog.', image => 'path/to/my.jpg' }] },
        lang     => 'en',
        reply_to => 'at://did:plc:pwqewimhd3rxc4hg6ztwrcyj/app.bsky.feed.post/3lbvllq2kul27',
        text     => 'I found this image on https://google.com/'
    );

Each image may also carry an C<aspectRatio> (C<< { width =E<gt> 4, height =E<gt> 3 } >>).

    $bsky->createPost(
        embed => { images => [ { image => 'path/to/my.jpg', alt => 'A frog.', aspectRatio => { width => 4, height => 3 } } ] },
        text  => 'Look at this!'
    );

=item C<gallery>

A gallery embed (C<app.bsky.embed.gallery>). The schema allows up to 20 items, though clients currently soft-limit
authoring UIs to 10. Each item is a hash with C<image> and C<alt>, plus an optional C<aspectRatio>.

    $bsky->createPost(
        embed => { gallery => [
            { image => 'one.jpg', alt => 'First',  aspectRatio => { width => 4, height => 3 } },
            { image => 'two.jpg', alt => 'Second', aspectRatio => { width => 1, height => 1 } },
        ] },
        text => 'A little gallery.'
    );

=item C<url>

A card (including the URL, the page title, and a description) will be presented in a GUI.

    $bsky->createPost( embed => { url => 'https://en.wikipedia.org/wiki/Main_Page' }, text => <<'END');
    This is the link to wikipedia, @atproto.bsky.social. You should check it out.
    END

=item C<ref>

An AT-URL to link from this post.

=item C<video>

A video to be embedded in a Bluesky record (eg, a post).

    $bsky->createPost( embed => { video => 'path/to/cat.mpeg' }, text => 'Loot at this little guy!' );

This might be a single path, raw data, or a hash reference (if you're really into what and how the video is presented).

If passed a hash, the following are expected:

=over

=item C<video> - required

The path name.

=item C<alt>

Alt text description of the video, for accessibility.

=item C<mime>

Mime type.

We try to figure this out internally if undefined.

=item C<aspectRatio>

Represents an aspect ratio.

It may be approximate, and may not correspond to absolute dimensions in any given unit.

    ...
    aspectRatio =>{ width => 100, height => 120 },
    ...

=item C<captions>

This is a hash reference of up to 20 L<WebVTT|https://en.wikipedia.org/wiki/WebVTT> files organized by language.

    ...
    captions => {
        en => 'english.vtt',
        ja => 'japanese.vtt'
    },
    ...

=item C<presentation>

A hint to clients about how to present the video. Known values are C<default> and C<gif>.

    ...
    presentation => 'gif',
    ...

=back

=back

You may also pass your own valid embed: any hashref carrying a C<$type> key is used verbatim. This is how the video
service flow is embedded, using L</"videoEmbed( $blob, %opts )"> to wrap the processed blob returned by
L</"getVideoJobStatus( $jobId )">.

=item C<labels>

Self-label values for this post. Effectively content warnings. Up to 10 values.

=item C<tags>

Additional hashtags, in addition to any included in post text and facets. Up to 8 tags.

These are not visible in the current Bluesky interface but do cause posts to return as results to to search (such as
L<https://bsky.app/hashtag/perl>.

=back

Note that a post may only contain one of the following embeds: C<images>, C<gallery>, C<video>, C<embed_url>, or
C<embed_ref>.

=head1 Video Services

Methods in this section deal with the video upload service.

=head2 C<getVideoUploadLimits( )>

    $bsky->getVideoUploadLimits();

Get video upload limits for the authenticated user (whether uploads are allowed, remaining daily bytes/videos).

=head2 C<getVideoJobStatus( $jobId )>

    $bsky->getVideoJobStatus( $jobId );

Get status details for a video processing job. Returns the C<jobStatus>.

=head2 C<uploadVideoJob( $bytes_or_path, [ $mime_type, %opts ] )>

    $bsky->uploadVideoJob( 'path/to/clip.mp4', 'video/mp4', did => $bsky->did, name => 'clip.mp4' );

Upload a video to the video service (C<app.bsky.video.uploadVideo>) for processing. Returns the C<jobStatus>; poll
L</"getVideoJobStatus( $jobId )"> until C<blob> is present, then use that blob in a post.

Optional C<%opts>:

=over

=item C<did> and C<name> - Identifying query params accepted by the video service. C<did> defaults to the authenticated user.

=item C<host> - Service host. Defaults to C<https://video.bsky.app>.

=item C<token> - Pre-minted service token to send as a C<Bearer> token. By default one is fetched from the PDS with
C<com.atproto.server.getServiceAuth>.

=item C<aud> and C<exp> - Override the audience (defaults to the user's PDS DID) and expiry of the minted service token.

=back

The video service cannot be reached through the PDS: C<uploadVideo> posts the bytes to
C<https://video.bsky.app/xrpc/app.bsky.video.uploadVideo> with an C<Authorization: Bearer> service token (I<not> the
session's DPoP token). The token is minted by the user's PDS via C<com.atproto.server.getServiceAuth> with the PDS DID
as the audience and C<com.atproto.repo.uploadBlob> as the lexicon, because the service deposits the processed blob into
your PDS on your behalf. L</"getVideoUploadLimits( )"> and L</"getVideoJobStatus( $jobId )"> use the video service host
too.

Unlike L</"uploadVideo( $video )">, which uploads a finished blob for embedding, this starts a server-side processing
job. The recommended flow from L<https://bsky.network/docs/about-bluesky-content/video> is: create a service token for
C<com.atproto.repo.uploadBlob>, upload to the video service, poll the job for its C<blob>, then post. The
C<uploadVideo> reply is the job status: if it already carries a C<blob> use it directly, otherwise poll
L</"getVideoJobStatus( $jobId )"> until C<blob> is present. If the video was already processed the service reports an
C<already_exists> error (HTTP C<409>), and the returned job may need to be polled to obtain its C<blob>. Note that
Bluesky-hosted accounts must verify their email before uploading video, and daily video limits apply (see
L</"getVideoUploadLimits( )">).

=head2 C<parse_mentions( $text )>

=head2 C<parse_facets( $text )>

Resolves mentions, URLs, and tags in C<$text> into an array of C<app.bsky.richtext.facet> structures.

Facet indexes are byte offsets into the UTF-8 encoding (inclusive start, exclusive end), not character offsets; this
module enables L<bytes> internally so the offsets come out correctly. Facets must not overlap. See

=head2 C<uploadImages( @images )>

Uploads up to 4 images (paths, raw bytes, Path::Tiny objects, or C<{ image =E<gt> ..., alt =E<gt> ..., mime =E<gt> ...,

Uploads gallery items (same accepted forms as L</"uploadImages( @images )">) and returns an C<app.bsky.embed.gallery>

=head2 C<uploadVideoCaption( $lang, $caption )>

Uploads a WebVTT caption file and returns an C<app.bsky.embed.video#caption> structure.

=head2 C<uploadVideo( $video )>

Uploads a video blob (path, raw bytes, Path::Tiny object, or hashref with C<video>, C<alt>, C<mime>, C<aspectRatio>,
C<presentation>, and C<captions>) and returns an C<app.bsky.embed.video> structure.

This uploads a finished video blob straight to the PDS. To run the video service's server-side processing job instead,
use L</"uploadVideoJob( $bytes_or_path, [ $mime_type, %opts ] )"> and then L</"videoEmbed( $blob, %opts )">.

=head2 C<videoEmbed( $blob, %opts )>

Builds an C<app.bsky.embed.video> structure from an already-uploaded blob, typically the processed blob returned by
L</"getVideoJobStatus( $jobId )"> after L</"uploadVideoJob( $bytes_or_path, [ $mime_type, %opts ] )">. Recognized
C<%opts> are C<alt>, C<aspectRatio>, C<presentation> (C<default> or C<gif>), and C<captions> (either C<< { lang =E<gt>
file } >> or C<< [ { lang =E<gt> ..., file =E<gt> ... } ] >>). Caption files are uploaded for you.

    my $job    = $bsky->uploadVideoJob( 'clip.mp4', 'video/mp4', did => $bsky->did, name => 'clip.mp4' );
    my $status = $bsky->getVideoJobStatus( $job->{jobId} );
    my $embed  = $bsky->videoEmbed( $status->{blob},
        alt          => 'A cat playing a piano',
        aspectRatio  => { width => 1280, height => 720 },
        presentation => 'default',
        captions     => { en => 'captions.en.vtt' },
    );
    $bsky->createPost( text => 'Music!', embed => $embed );
