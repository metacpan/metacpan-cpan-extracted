=encoding utf-8

=head1 NAME

OpenTelemetry::Instrumentation::Mango - OpenTelemetry instrumentation for Mango

=head1 SYNOPSIS

  use OpenTelemetry::Instrumentation 'Mango';

  my $mango = Mango->new('mongodb://localhost:27017');
  $mango->db('test')->collection('foo')->insert({ bar => 'baz' });
  # ... a client span is created for the operation

=head1 DESCRIPTION

L<OpenTelemetry::Instrumentation::Mango> adds OpenTelemetry tracing to the
L<Mango> MongoDB driver. It follows the same model as
L<OpenTelemetry::Instrumentation::DBI>: installing this instrumentation wraps
selected methods so that every MongoDB operation runs inside a CLIENT span.

Yes, Mango uses an obsolete wire protocol, and yes, it has not been updated since 2014,
but it still works with older versions of MongoDB and this module will emit telemetry
for this stack if you need it.

The instrumentation wraps the semantic funnels of L<Mango>, which means every
wire operation is covered:

=over 2

=item *

L<Mango::Database/"command">: every database command (which includes all
collection CRUD operations, as they are implemented as commands: C<insert>,
C<update>, C<delete>, C<findAndModify>, C<count>, C<distinct>,
C<aggregate>, and friends).

=item *

L<Mango::Cursor::Query> C<_start>: the initial C<find> query.

=item *

L<Mango/"get_more"> and L<Mango/"kill_cursors">: cursor pagination and
cleanup.

=back

=head2 Spans

Each operation produces a span named C<< "<operation> <db.collection>" >>
(for example C<insert test.foo>), or C<< "<operation> <db>" >> for
database-level commands without a collection target. The name is truncated to
100 characters. Because L<Mango/"kill_cursors"> receives a cursor id rather
than a namespace, the id is kept in the span name instead of any database
attributes.

=head2 Attributes

Spans generated by this instrumentation will record the following
attributes:

=over 2

=item C<db.system.name>

Always C<mongodb>.

=item C<db.name>

Name of the database the operation ran against.

=item C<db.collection.name>

Name of the targeted collection, when the operation targets one.

=item C<db.operation.name>

The operation: the command name for database commands (C<insert>, C<count>,
C<findAndModify>, ...), or C<find>, C<get_more>, C<kill_cursors>.

=item C<db.statement>

The command or query document encoded as JSON, truncated to 512 characters.
Omitted if it cannot be encoded.

=item C<server.address> and C<server.port>

Taken from the first entry of C<< $mango->hosts >>, with a default value
of 27017.

=back

=head2 Blocking and non-blocking operations

Both blocking and non-blocking (callback-style) operations are supported.
For blocking operations, the span is ended once the call returns (or dies,
in which case the exception is recorded and the span status is set to
error). For non-blocking operations, the span is ended when Mango invokes
the callback: the status is set to error if Mango passed an error as the
first callback argument after the invokant, and to success otherwise. The
callback runs with the captured context restored, so spans created inside it
nest under the operation span.
Please not that if Mango never invokes the callback, the span for the non-blocking
operation will not be ended.

This instrumentation never starts or stops any event loop, so it is safe to
use under L<Mojolicious> applications: blocking operations continue to use
the L<Mango> object's own C<ioloop>, and non-blocking operations continue to
be driven by whatever loop is running the application.

=head2 Testing with Test::Mock::Mango

If L<Test::Mock::Mango> is loaded B<before> this instrumentation is
installed, the same wrappers are installed on the mocked classes
(L<Test::Mock::Mango::DB>, L<Test::Mock::Mango::Collection>, and
L<Test::Mock::Mango::Cursor>), which lets you test instrumented code without
a MongoDB server. In production, L<Test::Mock::Mango> is not loaded, so
this has no effect. Note that mocked cursors carry no collection reference,
so spans produced through them only carry the operation name. Additionally,
spans produced through mocked collection methods do not carry a
C<db.statement> attribute.

=head2 Running the integration tests

The test suite is fully offline by default: C<t/OpenTelemetry/Instrumentation/Mango.t>
runs against L<Test::Mock::Mango> stubs and never opens a network connection.
Additionally, C<t/online.t> runs the same instrumentation against a real
MongoDB server, but only when the C<TEST_ONLINE> environment variable holds a
connection string; without it, that test skips.

Note that as mentioned above L<Mango> speaks MongoDB's legacy wire protocol, which was
deprecated in MongoDB 5.0 and removed in MongoDB 5.1, so use a server of version 5.0 or
earlier. For example, with Docker:

  docker run --rm -d --name otel-mango-test \
    -p 127.0.0.1:28017:27017 mongo:4.4

  TEST_ONLINE=mongodb://127.0.0.1:28017 prove -lv t/online.t

  docker stop otel-mango-test

The test uses its own database (C<otel_mango_online_test>) and drops it when
it finishes, and the container above is removed as soon as it stops, so no
data is left behind.
