=head1 NAME

App::FuguWeb::Index - the body of the manual index

=head1 SYNOPSIS

    use App::FuguWeb::Index;

    my $index = App::FuguWeb::Index->new(
        config   => $config,
        language => $config->language('de'));

    my $html = $index->body('Handbuch', $opening, body_lang => 'en');

=head1 DESCRIPTION

The index lists every manual of the site, grouped and described. The
groups follow the source directories, which is already how a tree is
organized, so the index cannot drift when a manual is added: no list
here names one.

The index does not retype a description either. It asks each
L<App::FuguWeb::Manual>, and that reads the source.

The index writes no prose of its own. The title, the opening and each
heading come from the description, and each description comes from a
source.

=head1 METHODS

=head2 new

    App::FuguWeb::Index->new(config => $config, language => $language)

C<config> is an L<App::FuguWeb::Config> and is required. C<language>
is the L<App::FuguWeb::Language> of the page, and it defaults to the
default language of the site.

=head2 body

    $index->body($title, $opening,
        title_lang => 'en',
        body_lang  => 'en')

The body fragment, as characters. L<App::FuguWeb::Page> wraps it,
exactly as it wraps a body fragment that a project wrote by hand.

The fragment opens with the title as its C<< <h1> >>, and then the
opening as it stands. The caller passes the title and the C<body> of
the index page for the language of the page, so the heading and the
browser tab always agree. A page with no C<body> passes C<undef>, and
the groups then follow the heading.

Each group then emits an C<< <h2> >>, one C<< <dl> >>, and one blank
line. The C<id> of the heading is the group name, and its text is the
heading of the language. A group with no manual emits nothing, so an
empty group leaves no heading behind.

Each manual of the language emits a term and a definition. The
description comes from the source of that language.

    <dt><a href="./Fugu::Daemon.3p.html">Fugu::Daemon(3p)</a></dt>
    <dd>daemonize a process the OpenBSD way</dd>

The C<./> is mandatory. A browser reads a relative URL whose first
segment holds a colon as a scheme, so a bare F<Fugu::Daemon.3p.html>
would be read as the C<fugu:> protocol.

The parts of the page come from the sources of more than one language:
the title, the opening, each heading and each description. A part from
a source of another language than the page carries the marks of that
language on its own element, per WEB-LANGUAGE-11: the tag as C<lang>,
and its direction as C<dir> when the two directions differ. That
element is the C<< <h1> >> of the title, one C<< <div> >> around the
opening, the C<< <h2> >> of a heading, or the C<< <dd> >> of a
description. A part of the language of the page carries no mark,
because the C<< <html> >> element carries that language.

C<title_lang> and C<body_lang> are the tags of the languages of the
title and of the opening. The caller passes the C<title_lang> and the C<lang> of the
page, as L<App::FuguWeb::Config/pages> names them. Each one defaults to
the language of the page. The group gives the language of each
heading, and the manual the language of each description.
