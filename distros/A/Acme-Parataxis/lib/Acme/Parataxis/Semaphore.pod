=head1 NAME

Acme::Parataxis::Semaphore - Counting Semaphore for Fiber Synchronization and Resource Pools

=head1 SYNOPSIS

    use v5.40;
    use Acme::Parataxis qw[async fiber await_sleep];
    use Acme::Parataxis::Semaphore;

    async {
        # Limit concurrency to 3 simultaneous fibers:
        my $pool = Acme::Parataxis::Semaphore->new( count => 3 );

        my @workers = map {
            my $id = $_;
            fiber {
                $pool->down;    # acquire permit (parks if count == 0)
                say "Worker $id acquired permit";
                await_sleep(50);
                $pool->up;      # release permit back to pool
            };
        } 1 .. 6;

        $_->await for @workers;
    };

=head1 DESCRIPTION

A counting semaphore manages a pool of abstract permits. Fibers request permits via C<down> (parking if none are
available) and return permits via C<up>.

Semaphores have no concept of thread or fiber ownership: one fiber can call C<down> while an entirely different fiber
calls C<up>, and permits can be added before any fiber requests them.

Waiters park cooperatively in FIFO order without polling. Parked waits integrate with Parataxis structured concurrency:
they can be interrupted cleanly via L<with_timeout|Acme::Parataxis/with_timeout> or cancellation tokens, and
interrupted fibers automatically unregister from the wait queue without consuming leaked permits.

C<Acme::Parataxis::Semaphore> is a foundational building block for the rest of the distribution: channels use two
internal semaphores for read and write queues, rate limiters use one as a token bucket, and mutexes wrap a semaphore
with strict owner tracking.

=head1 METHODS

=head2 C<new( [ count =E<gt> $n = 1 ] )>

    my $sem = Acme::Parataxis::Semaphore->new;             # default 1 permit
    my $sem = Acme::Parataxis::Semaphore->new( count => 5 );

Constructs a new semaphore with C<$n> initial permits. Keyword-only.

=head2 C<down( [$reason = 'Semaphore down'] )>

    $sem->down;

Decrements the permit count by 1. If the permit count is zero or negative, the calling fiber parks until a permit is
returned via C<up()> or C<adjust()>. Returns true.

Must be called from within a scheduled fiber if the call needs to park.

=head2 C<up( )>

    $sem->up;

Increments the permit count by 1 and wakes the longest-waiting parked fiber, if any. Returns true.

=head2 C<try( )>

    if ( $sem->try ) {
        # permit acquired without parking
    } else {
        # no permits available
    }

Attempts to acquire a permit without parking. If C<count> is greater than zero, decrements the count and returns true.
Otherwise, returns false immediately. Safe to call outside of a scheduled fiber.

=head2 C<adjust( $diff )>

    $sem->adjust(5);     # add 5 permits and wake up to 5 waiters
    $sem->adjust(-2);    # subtract 2 permits (does not wake waiters)

Modifies the permit count by C<$diff> (which may be positive or negative). If the count becomes positive, wakes up to
C<min(count, waiters)> parked fibers. Used during bulk releases, capacity resizes, or shutdown teardowns.

=head2 C<guard( )>

    {
        my $guard = $sem->guard;    # acquires permit via down()
        do_protected_work();
    }
    # permit returned automatically via up() when $guard goes out of scope

Acquires a permit via C<down()> and returns an L<Acme::Parataxis::Semaphore::Guard> object. When the guard is destroyed
(via lexical scope exit or an unhandled exception), it calls C<up()> automatically.

=head2 C<wait( )>

    $sem->wait;

Blocks until C<count> is greater than zero B<without decrementing the permit count>. This is a non-consuming readiness
check, not an acquisition.

=head2 C<count( )>

Returns the number of permits currently available.

=head2 C<waiters( )>

    my $count = $sem->waiters;
    my @fids  = $sem->waiters;

In scalar context, returns the number of fibers currently parked on this semaphore. In list context, returns their
numeric fiber IDs in FIFO queue order.

=head2 C<remove_waiter( $fid )>

    my $removed = $sem->remove_waiter($fid);

Removes a specific fiber ID from the wait queue without waking it. Returns the number of entries removed (0 or 1). Used
internally for cancellation cleanup.

=head1 Recipes

=head2 One-way gating (coordinating simultaneous start)

Initialize the semaphore to 0 to block all incoming fibers until a trigger opens the gate:

    async {
        my $gate = Acme::Parataxis::Semaphore->new( count => 0 );

        for my $i ( 1 .. 4 ) {
            fiber {
                $gate->down;
                say "Runner $i started!";
            };
        }

        await_sleep(50);
        say "Releasing all runners at once:";
        $gate->adjust(4);    # wakes all 4 waiting fibers simultaneously
    };

=head2 Scoped permit management

    sub process_transaction ($sem, $data) {
        my $guard = $sem->guard;    # acquires permit
        execute_remote_call($data); # if this dies, $guard->DESTROY safely calls ->up()
    }

=head1 Behavior Notes

=over

=item * C<wait()> does not acquire

C<wait()> blocks until a permit exists, but does not decrement the counter. Calling C<< while ($sem->wait) { ... } >>
against a non-empty semaphore produces an infinite, non-yielding busy loop. Use C<down()> to consume permits.

=item * Automatic deregistration on cancellation

If a fiber parked in C<down()> is interrupted by a timeout or cancellation token, it unregisters from the semaphore's
wait list. When a permit is subsequently returned via C<up()>, it bypasses the cancelled fiber and goes to the next
active waiter.

=item * Negative counts

Calling C<adjust()> with a negative number can cause C<count> to drop below zero. A negative count requires an
equivalent number of C<up()> calls before any future C<down()> operations will be allowed through.

=back
