Changes

The two most recent releases in full, then the version history. The distribution's Changes file is the authoritative record.

0.52 — 22 November 2026

Almost every change in this release came from fuzzing real distributions with t/all-fuzz.t: schemas that read the documentation more fully, types that are no longer guessed from incidental syntax, and harnesses that expect only what a routine actually promises.

Enhancements

  • A sample_max schema key. When a documented range is far wider than its default (10_000 to 100_000_000 (default 200_000)), the default is recorded as sample_max: valid values are generated only up to it, while max stays the bound a value is checked against. A work factor such as a PBKDF2 round count is fuzzed at its default instead of at a value that takes minutes per call. The harness, CoverageGuidedFuzzer and BenchmarkGenerator all honour it; an ordinary bounded option such as a port is still generated across its whole range.
  • Positional arguments followed by named options. A routine declared as my ($password, %opts) = @_ is called in that shape: the leading arguments keep their position, the rest are marked named: 1 and passed after them.
  • Class methods. An Input section that documents a $class invocant sets the new invocant: class key, and the harness calls Module->routine(...) instead of shifting every argument by one.
  • More classes can be built. A constructor that takes a directory is given a temporary one, and a constructor that takes a documented list of objects is given a stand-in built from the POD, so their instance methods are fuzzed rather than skipped.
  • Byte strings. A parameter documented as a file's contents gets the new bytes semantic and is fuzzed with octets rather than text.
  • bin/run-all-fuzz runs every t/all-fuzz.t in the surrounding workspace against the working tree and keeps the logs of any suite that fails.

Bug fixes

  • More of the POD is read. Input sections written as a table (name : type, $name SCALAR, \@list => ...), as the Perl hash they describe, with several parameters on one row, or with quoted types are all understood, as is POD that sits in a later block headed with the routine's name. Ranges written with words or .., "one or more", "a readable file", "an existing directory" and documented element shapes ("arrayref of {col, op, val} hashrefs") become constraints. Output shapes such as "Always an arrayref of hashrefs" are read as the container.
  • Types are not guessed from incidental syntax. A / or % in a regex, a hyphen in a string, a sprintf format, //, -> and -e are no longer read as arithmetic, and an operator in the body no longer overrides a documented type. return \%hash is a hashref, a return of sprintf or join is a string, localtime is a nine-element list, and a guarded return undef is the error return rather than the success type. An argument the body only calls methods on is an object.
  • Patterns. A regex held in a variable, or built from the routine's own lexicals, is no longer emitted as a matches constraint (the harness did not compile). Every pattern a parameter is accepted by is joined into one domain, and only a regex that spells out a date is taken for ISO 8601.
  • The harness expects only what is promised. A wrong-typed number must die only when the routine's own validator checks it. A routine that reports bad input by returning undef passes a must-die case; a blessed exception counts as an error; a documented boolean is a truth value, not literally 0 or 1; an environment variable set to undef is unset; and an argument the routine refuses when empty gets an expect-to-die empty-string case. Semantic cases were all being generated as though every semantic type were a Unix timestamp.
  • Untestable routines are skipped as a family. A constructor that needs an object it calls methods on, a live database server, or a hashref of a specific documented shape is reported as skipped, and its instance methods with it. A constructor that stores one field is no longer mistaken for an accessor.
  • File descriptors. The leak check is turned off only for a call documented to hold a database handle on purpose, not for any routine that mentions the cache.
  • Comments are not code. A signature-like example in a comment (# my ($password, %opts) = @_;) is no longer read as the routine's parameters.
  • BenchmarkGenerator passes a parameter with no position as a name => value pair after the positional ones, instead of dropping it.

0.51 — 18 November 2026

Enhancements

  • Mutants that do not compile are reported. They are still not run or scored, but test-generator-mutate prints Skipped (compile): N and its --json report has a compile_skipped count per file. test-generator-index shows the count in the mutation summary, as (+N not compiled) in each file's Skipped cell, and on the file's mutation page. A file whose mutants all failed to compile now gets a row instead of being left out.

Bug fixes

  • Mutants compile against the project's own lib/. They were checked against whatever copies of the project's modules were installed, so a module that used a newer or uninstalled sibling had every mutant silently skipped and scored a vacuous 100% with Total: 0.

Upgrading

cpanm App::Test::Generator

Schemas are compatible across releases: a schema that works with 0.52 has worked since the transform syntax settled. Generated harnesses are regenerated by tooling, so a stale one is replaced rather than migrated. If you keep generated .t files in version control, regenerate them after upgrading — an older harness may not know about a type or a config key that the new version accepts.
