# SLiM protocol conformance audit

## Scope and evidence

This audit compares the Perl service with the [FitNesse SLiM protocol specification](https://fitnesse.org/FitNesse.UserGuide.WritingAcceptanceTests.SliM.SlimProtocol.html), the official [exception-handling](https://fitnesse.org/FitNesse.UserGuide.WritingAcceptanceTests.SliM.ExceptionHandling.html) and [data-type](https://fitnesse.org/FitNesse.UserGuide.WritingAcceptanceTests.SliM.DataTypes.html) documentation, and the installed FitNesse v20251025 implementation. The installed `/opt/fitnesse/fitnesse.jar` declares `Implementation-Version: 20251025` and has SHA-256 `824596f90381a9637abd4d5b2aa0f4f03f2ef5e5716399c41b2ae8889d470d11`; inspected classes include `SlimVersion`, `SlimStreamReader`, `SlimSerializer`, `SlimDeserializer`, `SlimServer`, `ListExecutor`, `StatementExecutor`, `SlimExecutionContext`, `VariableStore`, `SlimSymbol`, `ConverterRegistry`, `VoidConverter`, and the standard converters. Source locations are under [`fitnesse/slim`](https://github.com/unclebob/fitnesse/tree/master/src/fitnesse/slim) and [`fitnesse/slim/protocol`](https://github.com/unclebob/fitnesse/tree/master/src/fitnesse/slim/protocol).

The test column below describes direct regression coverage in this repository, not just acceptance-page outcomes. The current [acceptance inventory](fitnesse-slim-acceptance-baseline.md) executes 50 upstream pages against the external Perl service; 45 conform, with five documented FitNesse harness/rendering/environment limitations. That acceptance count is useful integration evidence, but it does not establish untested protocol branches.

## FitNesse v20251025 converter inventory

The authoritative registry is [`ConverterRegistry.java`](https://github.com/unclebob/fitnesse/blob/20251025/src/fitnesse/slim/converters/ConverterRegistry.java). It registers only `void`, `String`, `Date`, boxed and primitive `Double`, `Long`, `Integer`, `Character`, and `Boolean`, plus `Map`. There is no built-in `Float`, `Short`, or `Byte` converter. `getConverterForClass` additionally discovers registered superclasses/interfaces, JavaBeans property editors, enums, arrays, and collections at runtime. Those latter features require Java `Class`/generic type metadata and are not equivalent to adding a fixed alias in the Perl registry.

### Focused reference execution

The Character and Date implementations were already present before the constructor-path correction in this increment. I executed the converter classes and `ConverterSupport.convertArgs` from the pinned `/opt/fitnesse/fitnesse.jar` (manifest version `20251025`) with the JVM timezone fixed to UTC. The Java output was:

```text
char_A=0041 supplementary_first=d83d boxed_blank=null
primitive_blank=0000
date_ms=1706745600000 date_text=01-Feb-2024
bad_date=message:<<Can't convert 12-NotAMonth-2024 to date.>>
char_text=Ω surrogate_wire=[91, 48, 48, 48, 48, 48, 49, 58, 48, 48, 48, 48, 48, 49, 58, 63, 58, 93]
```

This confirms `CharConverter` uses `String.charAt(0)` (one UTF-16 code unit), `ConverterBase` maps blank boxed values to null, `PrimitiveCharConverter` maps blank input to NUL, and `DateConverter` uses the lenient default `SimpleDateFormat("dd-MMM-yyyy", Locale.US)` with the JVM default timezone. Its `parse` accepts the valid prefix `32-Jan-2024` and formats the normalized Date as `01-Feb-2024`. The Perl converter tests exercise the same input/output cases; `t/typed-constructor-conversion.t` additionally sends a supplementary character, a leap-day Date, and a blank Character through serialized `make`/`call` instructions.

The Java constructor reference is [`StatementExecutor.createInstanceOfConstructor`](https://github.com/unclebob/fitnesse/blob/20251025/src/fitnesse/slim/StatementExecutor.java): after selecting a constructor by arity, it invokes `ConverterSupport.convertArgs(args, constructor.getParameterTypes())` before `newInstance`. Perl previously passed constructor arguments directly after symbol/table substitution. It now permits a fixture to declare `slim_constructor_signature` and converts those values with the existing per-executor registry. This is explicit metadata, not Java reflection or overload selection.

For the array/collection extension I ran `/tmp/SlimArrayCollectionReference.java` directly against the pinned JAR using Java source-file mode. Java v20251025 produced:

```text
int_array=[1, 2, -3] len=3 formatted=[1, 2, -3]
string_array=[alpha, , beta] len=3 empty=0
boolean_array=[true, true, false]
blank_array=null empty_bracket_len=0 null_array=null
bad_array=message:<<Can't convert bad to integer.>>
list=[3, 1, 3] class=ArrayList empty=null null=null
collection=[4, 2, 4]
set=[1, 3]
queue=[1, 3, 2] iteration=[1, 3, 2]
bad_list=message:<<Can't convert bad to integer.>>
```

The run confirms bracket syntax, item trimming, trailing-empty removal from Java `String.split`, boxed blank elements, conversion errors, empty `[]` versus blank/null top-level input, ordered duplicate-preserving ArrayList results, and Java collection formatting. Set and Queue formatting reflects Java implementation iteration behavior; Perl intentionally does not claim to emulate those collection classes.

## Corrections made in this audit

1. **Expanded v0.4 lengths:** `List::list` accepted exactly six digits despite the v0.4 specification allowing longer fields. It now accepts six or more digits. `Server::_process` also assumed a seven-byte frame header; `_read_message` now parses the colon-terminated six-or-more digit byte length up to the Java signed-int range. `_take_utf16_units` now advances an index instead of repeatedly deleting the string prefix. Regressions cover a 1,000,000-unit list field and a 1,000,000-byte frame.
2. **Null-valued symbols:** `StatementExecutor::call` previously turned undefined results into the text `null` before `callAndAssign` stored them. The call-and-assign path now stores the original undefined result while returning the wire null token. Exact symbol references preserve null; embedded references render `null` text. Regression coverage exercises the instruction path.
3. **Library IDs:** the protocol defines libraries by the `library` prefix, but the implementation required a numeric suffix. Registration and lookup now accept any such suffix. A nonnumeric-ID library dispatch test covers it.
4. **Declared result types:** the standard boxed Boolean converter lacked `to_string`, and the registry had no `void` converter. Boolean results now serialize as `true`/`false` (null stays null), and declared void results use `/__VOID__/`, matching the installed `VoidConverter`. Focused converter tests cover these results.
5. **Character and Date conversion:** declared `Character`/`char` signatures now use integer UTF-16 code units, preserving supplementary high surrogates and isolated surrogate values without forcing them into invalid Perl Unicode strings. Declared `Date` signatures use epoch milliseconds, local-timezone parsing/formatting, US month names, and lenient Gregorian day rollover for years 1583..9999. Focused tests cover argument/result conversion and the supported boundaries; unsupported calendar/parser edges remain explicit.
6. **Constructor conversion path:** the Java executor converts constructor arguments using reflected parameter types. Perl previously passed converted symbols/table arguments directly to `new`; fixtures with type-sensitive constructors can now declare `slim_constructor_signature` and reuse the same converter registry as method calls. `t/typed-constructor-conversion.t` exercises Character, Date, blank-to-null, conversion errors, and no partially registered instance after failure. Untyped fixture constructors remain unchanged.
7. **Typed arrays and collections:** Java's `GenericArrayConverter` and `GenericCollectionConverter` compose a converter for the declared component type. Perl now resolves one-dimensional `T[]`, `java.util.List<T>`, and `java.util.Collection<T>` metadata into a shared sequence converter. It preserves existing references passed as symbol arguments; for explicitly typed sequence results, `callAndAssign` retains the raw Perl array reference while formatting the wire response. Untyped result conversion remains unchanged. Tests exercise constructor/method arguments, typed results, invalid values, aliases, null/empty values, string/boolean/integer/Double elements, typed reference identity, and preservation of the untyped path. Set, Queue, nested generic conversion, and reflective concrete collection classes remain unsupported.

## Overall assessment and remaining gaps

The Perl service now has direct evidence for FitNesse v0.5 framing over both TCP and child-process pipes, recursive lists, byte/code-unit length separation, all five instruction forms, the implemented fixture-resolution path, common symbol behavior, selected conversions, exception/stop handling, forked TCP session isolation, and diagnostic output reconstruction. The pipe mode was exercised with raw child-process tests, two existing acceptance pages, and an isolated stdout/stderr reconstruction page compared with the pinned Java service. Current CI and the 45/50 TCP acceptance baseline provide additional integration evidence. This is **partial, tested compatibility**, not complete SLiM protocol conformance.

Confirmed remaining gaps include exact Java Double edge parsing/formatting; pre-1583 and out-of-range Date behavior and some `SimpleDateFormat` parsing quirks; Set/Queue, nested generic, multidimensional array, enum, JavaBeans property-editor, and reflection-derived concrete collection behavior; Java overload selection for constructors; Java annotation discovery for arbitrary SUT field names; broader constructor/method reflection diagnostics; and FitNesse's separately documented ``$`expression` `` table feature, whose v20251025 Java service uses Nashorn and Java object semantics. The expression feature is not part of the SLiM protocol and is not implemented by the Perl core. Pipe-mode stdout/stderr tunneling is implemented against the pinned FitNesse behavior, which reverses the first/continuation prefix assignments in the published guide; exact cross-stream ordering is not guaranteed. Ignore marker emission, server-side batch stopping, and SUT delegation through the explicit Perl fixture field are now covered. Other unverified edges are listed in the matrix. The 50-page TCP acceptance baseline remains unchanged, and no upstream acceptance expectation was modified. See [`slim-pipe-transport.md`](slim-pipe-transport.md) for pipe invocation and lifecycle details.
