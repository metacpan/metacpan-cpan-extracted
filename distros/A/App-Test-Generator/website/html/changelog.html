Changes

The two most recent releases in full, then the version history. The distribution's Changes file is the authoritative record.

0.50 — 17 November 2026

Enhancements

  • Files with a helper package are extracted. extract-schemas used to die on a file that declares a second package, such as a small error class. It now analyses the first package, ignores routines owned by later ones, and marks every schema from the file skip so harnesses are not run against it, printing a note that says so.

Bug fixes

  • Constructors that need live objects are skipped. A constructor that rejects an empty arrayref, or calls methods on its elements, cannot be given a YAML fixture. Its schema now carries a skip reason and its instance methods get new: ~.
  • required => 1 is honoured in a formal Input spec, including a bare list with no outer braces, so POD stays authoritative over a validator that calls the same parameter optional. An explicit optional wins, and a flag inside a nested properties map applies only to that property.

0.49 — November 2026

Enhancements

  • Surviving mutants feed harness generation. fuzz-harness-generator --mutation-results (or mutation_results to generate()) reads test-generator-mutate's JSON report. Each surviving numeric-boundary mutant is traced to the comparison it mutated and becomes a min or max on the matching input field. Existing constraints are never replaced, and survivors that need a hand-written test are listed. Details.
  • Documented constraints are checked, not assumed. A bound, member list or pattern that came only from POD is probed from outside. A routine that contradicts its documentation is reported at the end of the run, and fuzz-harness-generator --strict-documented turns each finding into a failing test for CI.
  • Element schemas. An arrayref or hashref parameter can describe its elements with a nested schema, which can nest again and build objects from isa or can. Details.
  • Transforms can have their own input fields. One hand-written schema can cover two call shapes, such as NameCase([...]) and NameCase('A', 'B').
  • Regex-based strings are deterministic and bounded. The schema's seed drives them, generation is limited by the new regex_timeout config key (default 5 seconds), and a pattern that hangs or cannot be satisfied falls back or skips its cases instead of failing the run. A failing case names the seed and the input that was sent.
  • An existing_file semantic. A routine that only tests that a path exists (-e/-f) is no longer skipped: the harness creates a temporary file for it. Only routines that read the file's contents stay skipped.
  • Portable, repeatable schema YAML. A matches pattern is written as a plain string rather than a !!perl/regexp object, and maps and analysis notes are sorted, so repeated runs are byte-identical.
  • One provenance marker. Each parameter carries a single _source value, replacing _type_checked, _bounds_unverified and _from_input_spec; provenance is also tracked per constraint. The allowed values live in App::Test::Generator::Provenance.
  • demo_extractor is no longer installed. It ships as examples/demo_extractor. The bug tracker in the distribution metadata is now GitHub issues.

Bug fixes

  • Generated values stay inside declared bounds. Random integers, numbers and strings respect a maximum, pattern-generated strings honour min/max length, and a pattern-constrained field is never given the fixed whitespace, newline or BOM samples its own pattern excludes.
  • Length guards are read correctly. croak ... if length < 5 used to be read as max: 4; it now gives min: 5, the same as croak ... unless length >= 5. A formal Input spec's bounds are compared with the inferred ones, so an impossible range is reported instead of emitted.
  • import is called as a class method, Module->import(...), the way use invokes it.
  • Extraction reads a single documented parameter as the first positional argument when the routine reads no hash of arguments, keeps the value list from =item prose for a parameter named only by a formal spec, and drops a reference used as a parameter name instead of emitting HASH(0x...).
  • File descriptors. An object that opens a file on first use and keeps it, such as a logger, is no longer reported as a leak; a descriptor is reported when the same target is opened again.
  • generate() is documented as returning 1, which is what it has always returned.

Upgrading

cpanm App::Test::Generator

Schemas are compatible across releases: a schema that works with 0.50 has worked since the transform syntax settled. Generated harnesses are regenerated by tooling, so a stale one is replaced rather than migrated. If you keep generated .t files in version control, regenerate them after upgrading — an older harness may not know about a type or a config key that the new version accepts.
