=head1 NAME

Term::Fabulous::Cookbook::GettingStarted - Recipes: a first program, quitting and text

=head1 DESCRIPTION

This page is part of L<Term::Fabulous::Cookbook>. Previous page: L<Term::Fabulous::Cookbook>. Next page: L<Term::Fabulous::Cookbook::KeyboardAndMouse>.

This page starts the cookbook with a minimal full-screen program, the
model for the interactive programs of the other recipes, and shows how
to quit it, how to show text in any writing system (umlauts, CJK,
combining accents), how to wrap and align it, and how to leave the
mouse to the terminal. It uses L<Term::Fabulous>,
L<Term::Fabulous::Widget::Box> and L<Term::Fabulous::Widget::Text>. The
concepts are explained in
L<the first program of the manual|Term::Fabulous::Manual/YOUR FIRST PROGRAM>,
L<Term::Fabulous::Manual::Layout> and
L<Term::Fabulous::Manual::Looks> (text and colors).

The recipes on this page:

=item *

L</Show non-ASCII text (umlauts, CJK, combining accents)>

=item *

=item *

L</Let the terminal handle the mouse (select and copy text)>

=back

=head1 A minimal program to start from

Goal: a full-screen program that shows a line of text and ends when the
user presses q, Escape or Ctrl+C. The interactive programs of the
other recipes are built the same way.

This program is shipped as F<examples/cookbook/minimal-program.pl>.

=for code-from examples/cookbook/minimal-program.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(sizing_grow CLAY_TOP_TO_BOTTOM);

	my $root = Term::Fabulous::Widget::Box->new(
		layout => {
			layout_direction => CLAY_TOP_TO_BOTTOM,
			sizing           => { width => sizing_grow(), height => sizing_grow() },
			padding          => { left  => 2, right => 2, top => 1, bottom => 1 },
			child_gap        => 1,
		},
	);
	$root->add_child(
		Term::Fabulous::Widget::Text->new(
			text       => 'Hello from Term::Fabulous! Press q, Escape or Ctrl+C to quit.',
			text_color => [ 230, 230, 230, 255 ],
		)
	);

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24 );

	$root->on(
		KeyPress => sub ($event) {
			my $key = $event->key_name // return;
			$ui->loop->stop if $key eq 'q' || $key eq 'Escape';
			return;
		}
	);

	$ui->run;

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.02/screenshots/cookbook-minimal-program.svg" alt="The minimal program: one line of text on a dark background"></p>

=end html

=over

=item *

The root widget is a L<Term::Fabulous::Widget::Box> that grows to fill
the whole terminal (C<sizing_grow()> on both axes), lays its children
out from top to bottom and keeps one cell of padding at the top and
bottom and two at the sides. See L<Term::Fabulous::Manual::Layout/LAYOUT>.

=item *

C<background_color> takes C<[ $red, $green, $blue, $alpha ]>, each
0..255. Without a background, the terminal's default color shows. See
L<Term::Fabulous::Manual::Looks/COLORS>.

=item *

Always give a L<Term::Fabulous::Widget::Text> a C<text_color>: the
default is opaque black, which is invisible on a dark terminal.

=item *

C<width> and C<height> in L<Term::Fabulous/new> are only the starting
size; C<run> replaces them with the real terminal size.

=item *

C<run> opens the terminal and runs the event loop: it handles input and
draws a new frame whenever something changed (it checks 30 times per
second). When the loop stops, C<run> restores the terminal and returns.
See L<Term::Fabulous/run>.

=back

=head1 Quit with q or Escape

Goal: end the program on a key of your choice, not only on Ctrl+C.

This is the C<KeyPress> listener of the program in
L</A minimal program to start from>:

	$root->on(
		KeyPress => sub ($event) {
			my $key = $event->key_name // return;
			$ui->loop->stop if $key eq 'q' || $key eq 'Escape';
			return;
		}
	);

=over

=item *

C<< $ui->loop >> is the L<IO::Async::Loop> that C<run> is running.
Stopping it makes C<run> return after the terminal has been restored,
so code after C<< $ui->run >> runs on a normal screen. Ctrl+C, SIGINT,
SIGTERM and SIGHUP stop it in the same way. See
L<Term::Fabulous::Manual::Programs/Quitting>.

=item *

C<key_name> returns names like C<q>, C<Escape>, C<Ctrl+S> or C<F1>, or
C<undef> for a key without a name, hence the C<// return>.

=item *

Key presses go to the focused widget first and bubble up to the root.
While a text field has the focus, it uses the q (it types it), so the
root never sees it. Escape reaches the root unless a widget on the way
uses it, as an open dropdown list does to close itself or a dialog to
close the dialog. See
L<Term::Fabulous::Manual::Events/Which widget receives key presses>.

=item *

Alt plus a letter arrives as one key named C<Alt+x>, not as Escape
followed by x, so binding Escape does not catch Alt combinations.
L<The key names section of the events chapter|Term::Fabulous::Manual::Events/Key names> has the details.

=item *

The listener is registered after C<$ui> exists, because it uses C<$ui>.

=back

=head1 Show non-ASCII text (umlauts, CJK, combining accents)

Goal: show text with umlauts, CJK characters or combining accents in
L<Term::Fabulous::Widget::Text> widgets.

This program is shipped as F<examples/cookbook/non-ascii-text.pl>.

=for code-from examples/cookbook/non-ascii-text.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous::Static;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(CLAY_TOP_TO_BOTTOM);

	sub text ($string) {
		return Term::Fabulous::Widget::Text->new( text => $string, text_color => [ 230, 230, 230, 255 ] );
	}

	my $root = Term::Fabulous::Widget::Box->new( layout => { layout_direction => CLAY_TOP_TO_BOTTOM } );
	$root->add_child(
		text("Gr\x{fc}\x{df}e aus M\x{fc}nchen"),    # German umlauts and sharp s
		text("\x{3044}\x{308d}\x{306f}\x{306b}\x{307b}\x{3078}\x{3068}|"),    # Japanese, two columns each
		text("e\x{301} is one character|"),    # e and a combining acute accent
	);

	Term::Fabulous::Static->new( root => $root, width => 30 )->print( colors => 0 );

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.02/screenshots/cookbook-non-ascii-text.svg" alt="German, Japanese and a combining accent, each line aligned in its columns"></p>

=end html

The program prints three lines: the German greeting, seven Japanese
characters that take two columns each (14 columns) followed by C<|>,
and an C<e> with an acute accent followed by the rest of the line. In a
pipe or a file, it prints:

=for highlighter language=text

	Grüße aus München
	いろはにほへと|
	é is one character|

=over

=item *

Text widgets take Perl character strings, like everything else in
Term::Fabulous (canvases, input widgets, KDL layouts). See
L<Term::Fabulous::Manual::Looks/Text is character strings>.

=item *

The C<\x{...}> escapes keep this recipe's source ASCII. With
C<use utf8;> at the top of a UTF-8 encoded source file you can write
the characters directly; both give the same character strings.

=item *

Text from outside the program (a file, a command, a socket) is bytes.
Decode it with C<Encode::decode('UTF-8', ...)> before passing it to a
widget, or each byte shows as one Latin-1 character.

=item *

Wide characters take two columns, and a base character with combining
marks takes one cell. Term::Fabulous measures text with termbox2's own
width functions; see
L<Term::Fabulous::Manual::Looks/Wide characters and emoji>.

=back

=head1 Wrap, align and space text

Goal: control how a L<Term::Fabulous::Widget::Text> breaks its lines,
how it aligns them and how much room each line gets.

This program is shipped as F<examples/cookbook/wrap-and-align-text.pl>.

=for highlighter language=perl

=for code-from examples/cookbook/wrap-and-align-text.pl

	use v5.32;
	use warnings;
	use feature 'signatures';
	no warnings 'experimental::signatures';

	use Term::Fabulous::Static;
	use Term::Fabulous::Enum::BorderStyle;
	use Term::Fabulous::Widget::Box;
	use Term::Fabulous::Widget::Text;
	use Clay::XS qw(
		sizing_fixed CLAY_TOP_TO_BOTTOM CLAY_ALIGN_X_CENTER
		CLAY_TEXT_ALIGN_CENTER CLAY_TEXT_ALIGN_RIGHT CLAY_TEXT_WRAP_NEWLINES
	);

	my $words = "Text wraps at spaces to the width of its box.\nA line break starts a new line.";

	# A framed box, 24 columns wide, with a caption and a Text that gets the
	# given options. 'box_layout' replaces the layout of the box.
	sub sample ( $caption, $text, %options ) {
		my $box_layout = delete $options{box_layout} // { layout_direction => CLAY_TOP_TO_BOTTOM, sizing => { width => sizing_fixed(24) } };
		my $box        = Term::Fabulous::Widget::Box->new(
			bordered     => 1,
			border_style => Term::Fabulous::Enum::BorderStyle->Ascii,
			border_color => [ 120, 160, 220, 255 ],
			layout       => $box_layout,
		);
		$box->add_child(
			Term::Fabulous::Widget::Text->new( text => $caption, text_color => [ 255, 200, 80,  255 ] ),
			Term::Fabulous::Widget::Text->new( text => $text,    text_color => [ 230, 230, 230, 255 ], %options ),
		);
		return $box;
	}

	# Three samples side by side in each row.
	sub row (@samples) {
		my $row = Term::Fabulous::Widget::Box->new( layout => { child_gap => 2 } );
		$row->add_child(@samples);
		return $row;
	}

	my $root = Term::Fabulous::Widget::Box->new( layout => { layout_direction => CLAY_TOP_TO_BOTTOM, child_gap => 1 } );
	$root->add_child(
		row(
			sample( 'Default: wrap at words', $words ),
			sample( 'Centered lines',         $words, text_alignment => CLAY_TEXT_ALIGN_CENTER ),
			sample( 'Right-aligned lines',    $words, text_alignment => CLAY_TEXT_ALIGN_RIGHT ),
		),
		row(
			sample( 'Line breaks only',  "No wrapping at spaces,\nonly at line breaks.", wrap_mode   => CLAY_TEXT_WRAP_NEWLINES ),
			sample( 'Two rows per line', "First line\nSecond line",                      line_height => 2 ),
			sample(
				'A centered label', 'OK',
				box_layout => { layout_direction => CLAY_TOP_TO_BOTTOM, sizing => { width => sizing_fixed(24) }, child_alignment => { x => CLAY_ALIGN_X_CENTER } },
			),
		),
	);

	# Colors only when STDOUT is a terminal.
	Term::Fabulous::Static->new( root => $root, width => 76 )->print;

=begin html

<p><img src="https://raw.githubusercontent.com/davenonymous/perl-term-fabulous/v0.02/screenshots/cookbook-wrap-and-align-text.svg" alt="Six framed samples: wrapped text aligned left, centered and right, text broken only at line breaks, two rows per line, and a centered label"></p>

In a pipe or a file, the program prints the same without colors:

=for highlighter language=text

	+----------------------+  +----------------------+  +----------------------+
	|Default: wrap at words|  |Centered lines        |  |Right-aligned lines   |
	|Text wraps at spaces  |  | Text wraps at spaces |  |  Text wraps at spaces|
	|to the width of its   |  | to the width of its  |  |   to the width of its|
	|box.                  |  |         box.         |  |                  box.|
	|A line break starts a |  |A line break starts a |  | A line break starts a|
	|new line.             |  |      new line.       |  |             new line.|
	+----------------------+  +----------------------+  +----------------------+

	+----------------------+  +----------------------+  +----------------------+
	|Line breaks only      |  |Two rows per line     |  |   A centered label   |
	|No wrapping at spaces,|  |First line            |  |          OK          |
	|only at line breaks.  |  |                      |  +----------------------+
	+----------------------+  |Second line           |
	                          |                      |
	                          +----------------------+

=over

=item *

C<wrap_mode> decides where lines break. The default,
C<CLAY_TEXT_WRAP_WORDS>, breaks at spaces to fit the width of the box
and at line breaks (C<"\n">). C<CLAY_TEXT_WRAP_NEWLINES> breaks only at
line breaks (for C<CLAY_TEXT_WRAP_NONE>, see
L<Term::Fabulous::Widget::Text/new>). A line that does not fit its
box then runs past the right edge of the box (the border is drawn over
it and hides the character there) and is cut off only at the edge of
the terminal; keep such lines short or give
the box room. A single word wider than the box is
never broken, whatever the mode. See
L<Term::Fabulous::Manual::Looks/Wrapping>.

=item *

C<text_alignment> (C<CLAY_TEXT_ALIGN_LEFT>, C<CLAY_TEXT_ALIGN_CENTER>,
C<CLAY_TEXT_ALIGN_RIGHT>) aligns the lines of a text against each
other, within the width of the Text widget: the width of the box for a
text that wraps, otherwise the width of its longest line. A
single-line text is exactly as wide as its words, so there is nothing
to align. To center or right-align a short label in its box, set
C<child_alignment> on the box that holds it, as the last sample does.
See L<Term::Fabulous::Manual::Looks/Alignment> and
L<Term::Fabulous::Manual::Layout/Aligning and centering children>.

=item *

C<line_height> is the number of rows per line, an integer (0, the
default, means 1). See L<Term::Fabulous::Manual::Looks/Line height>.

=item *

C<font_id> and C<font_size> have no visible effect in a terminal.
C<letter_spacing> changes where Clay breaks the lines but is not drawn,
so do not use it. For bold, italic and underlined text, see the
C<bold>, C<italic> and C<underline> parameters of
L<Term::Fabulous::Widget::Text/new>.

=item *

The samples are printed with L<Term::Fabulous::Static>, which uses
colors only when its output goes to a terminal; see
L<Term::Fabulous::Cookbook::Output/Render a report to a file or pipe (Static)>.

=item *

All these options are accessors too, for example
C<< $text->text_alignment(CLAY_TEXT_ALIGN_RIGHT) >>; the next frame
shows the change.

=back

=head1 Let the terminal handle the mouse (select and copy text)

Goal: leave the mouse to the terminal, so that the user can select and
copy text on the screen with the terminal's own selection.

Create the L<Term::Fabulous> object of the program in
L</A minimal program to start from> with C<mouse =E<gt> 0>:

=for highlighter language=perl

	my $ui = Term::Fabulous->new( root => $root, width => 80, height => 24, mouse => 0 );

=over

=item *

With C<mouse =E<gt> 0>, Term::Fabulous does not ask the terminal for mouse
reports (see L<Term::Fabulous/new>; inline mode always works this way). The terminal then handles clicks and drags itself, usually by
selecting text. The program receives no
L<Term::Fabulous::Event::Mouse> events, clicks neither focus nor
activate widgets, buttons and input widgets can be used only with the
keyboard, and the mouse wheel does not scroll scroll boxes.

=item *

Some terminals turn the mouse wheel into Up and Down key presses while
a full-screen program runs without mouse reports.

=item *

Many terminals also let you select text while the program does use the
mouse, if you hold Shift (or another key, depending on the terminal)
while dragging.

=back
